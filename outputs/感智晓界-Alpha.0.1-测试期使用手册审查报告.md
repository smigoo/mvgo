# 感智晓界 Alpha.0.1 测试期使用手册审查报告

> 审查对象：`感智晓界 - Alpha.0.1 - 测试期使用手册.md`  
> 审查日期：2026-08-03  
> 审查方式：源文件只读；结合当前前端与 Node 后端实现核对  
> 结论：现有手册可作为“功能上手指南”，但还不能直接作为“测试期使用手册”发布。发布前应先修正 5 项高风险表述，并补齐测试范围、验收标准、问题反馈与已知限制等内容。

## 二、P0：发布前必须修正

### 1. Token 存储说明与当前实现不一致

**手册位置**：第 4.1 节、第 4.2 节、第 5.1 节。  
**当前表述**：Token 只保存在浏览器 `localStorage`，不会上传到服务器。  
**实际实现**：配置先写入浏览器 `localStorage`，随后通过 `PUT /api/config/ai` 同步到服务端，并以明文 JSON 持久化到 `backend-node/data/ai-config.json`。

代码依据：

- `frontend/src/components/generator/ConfigPanel.vue:592-607`
- `backend-node/src/config/config.service.ts:5-11, 44-53`
- `backend-node/src/config/config.controller.ts:13-21`

**建议改为**：

> 配置会保存在当前浏览器，并同步至感智晓界 Node 服务端配置文件，供组件生成、页面生成和接口绑定等后端流程使用。Token 属于敏感凭据，仅可在授权测试环境中配置。不得使用个人生产账号高权限 Token；测试结束后按管理员要求清理或轮换。清除浏览器数据不会同步删除服务端配置，如需彻底清除请联系管理员。

同时建议把“清除配置”功能改成同时清理前端和服务端，或在手册中明确当前行为。

### 2. 删除疑似真实 Token 示例

**手册位置**：第 4.2 节第 3、4 步。  
文档使用了较长的 `figd_...`、`afxp_...` 示例，外观上无法判断是否为脱敏值。测试手册不应出现任何可能有效的完整凭据。

**建议替换为**：

- `figd_xxxxxxxxxxxxxxxxxxxx`
- `afxp_xxxxxxxxxxxxxxxxxxxx`
- 截图中 Token 仅保留前 4 位和后 4 位

如原值曾经真实可用，应立即轮换。

### 3. 补充登录、测试地址和账号权限

当前手册从“进入平台”开始，没有说明：

- Alpha.0.1 测试环境访问地址
- 推荐浏览器及最低版本
- 登录入口、测试账号申请方式
- 普通成员、组管理员、平台管理员的权限差异
- 首次登录和加入项目组的流程
- 无权限、登录失效时如何处理

当前系统存在 `/login` 路由和用户/组上下文，不能省略账号与权限说明。

### 4. 区分三条生成链路的能力边界

目前手册容易让测试人员理解为 Apifox 适用于所有生成类型。当前产品边界应明确写成：

| 生成类型 | Figma | AI 模型 | Apifox 接口绑定 | 主要产物 |
| --- | --- | --- | --- | --- |
| Vue3 组件 | 必需 | 必需 | 支持，生成后通过“对接接口”使用 | ZIP、预览、workspace 组件 |
| 微码组件 | 必需 | 必需 | 不走 Apifox 绑定向导 | 微码组件包、预览 |
| 页面批量生成 | 必需，页面 URL 必须含 `node-id` | 必需 | 按子组件类型处理 | 多个子组件结果及下载 |
| 接口生成 | 非必需 | 按功能需要 | 必需 | API 函数、Mock、枚举等 |

代码依据：

- `frontend/src/views/generate/component.vue:405-412, 553-569`
- `frontend/src/views/generate/component.vue:242-279`
- `frontend/src/views/generate/page.vue:430-465`

### 5. 删除或标记尚无界面依据的参数说明

第 5.3 节列出的 `Temperature`、“详细程度”、Vue3.2/3.4/3.5 框架版本，在当前统一配置面板中未找到对应可操作控件。若这些是后端内部参数，应标注为“管理员配置”；若 Alpha.0.1 前端不开放，应删除，避免测试人员找不到入口。

同理，“下载或复制到项目”应按当前界面改为“下载组件包 ZIP / 进入 Playground / 预览 / Vue3 对接接口”。当前统一生成页有下载入口，但未发现面向用户的“复制到项目”按钮。

## 三、P1：测试期必须新增的章节

### 1. 测试说明与范围

建议放在第 1 章之后，至少写明：

- 本轮版本：Alpha.0.1
- 测试开始和截止日期
- 目标测试人员
- 本轮重点：Vue3 生成、微码生成、页面生成、预览、下载、任务恢复、接口绑定
- 本轮不测或尚未开放的功能
- 测试环境与生产环境隔离说明

### 2. 测试前置条件

建议形成一张清单：

- 已获得测试环境账号并加入正确项目组
- 使用指定浏览器，关闭可能拦截 SSE/下载的扩展
- Figma 文件有读取权限，链接带正确 `node-id`
- 使用低权限测试 Token，不使用生产凭据
- AI API Key 有可用余额和调用额度
- 页面批量生成前确认并发建议值
- 准备至少一个标准样例和一个异常样例

### 3. 核心功能验收标准

现在只有“操作步骤”，没有“怎样算成功”。建议至少增加：

| 功能 | 通过标准 |
| --- | --- |
| 配置保存 | 刷新页面后仍可用；后端流程可读取；错误凭据有明确提示 |
| Vue3 生成 | 任务完成；可预览；ZIP 可下载；组件可编译；控制台无阻断错误 |
| 微码生成 | 可预览；面板结构可识别；产物目录完整；不出现 Vue3 专属接口绑定入口 |
| 页面生成 | 正确识别全部 `cp-*` Frame；成功/失败数准确；子组件可分别预览和下载 |
| 任务恢复 | 刷新或重新进入页面后，运行中/已完成任务状态可恢复 |
| 取消任务 | 状态变为“已取消”；页面停止转圈；不再继续写入完成产物 |
| 接口绑定 | 仅 Vue3 组件可进入向导；生成后预览可刷新；绑定结果可回滚或重新生成 |

### 4. 测试用例建议

每位测试人员至少执行：

1. 正常单组件 Vue3 生成 1 次。
2. 正常微码组件生成 1 次。
3. 页面批量生成 1 次，至少包含 3 个 `cp-*` Frame。
4. 使用无 `node-id`、原型链接、无权限文件各触发 1 次错误。
5. 生成中刷新页面，验证任务恢复。
6. 生成中取消任务，验证终态。
7. 下载 ZIP 后执行依赖安装和构建验证。
8. Vue3 组件执行一次 Apifox 接口绑定；微码组件确认无该入口。

### 5. 生成结果检查清单

建议新增独立章节，不要只写“预览检查布局”：

- [ ] 布局、尺寸、间距与 Figma 基本一致
- [ ] 中文、特殊字符和长文本无截断
- [ ] 图片、图标、字体可加载
- [ ] 浅色/深色/默认主题切换无样式污染（如本轮开放）
- [ ] 组件命名、props、事件命名符合项目规范
- [ ] 无硬编码真实 Token、接口地址和个人路径
- [ ] ZIP 解压后文件齐全
- [ ] `npm run build` 或项目规定构建命令通过
- [ ] 浏览器控制台无持续报错
- [ ] 接口失败、空数据、加载中等状态可处理

### 6. 缺陷反馈模板和渠道

当前只写“联系前端技术组”，不够执行。建议明确反馈渠道、负责人、响应规则，并要求提交：

```text
【标题】[Alpha.0.1][模块] 问题简述
【环境】测试地址、浏览器及版本、操作系统
【账号/项目组】只填名称，不提交密码和 Token
【任务 Session ID】
【组件类型】Vue3 / 微码 / 页面生成 / 接口生成
【Figma URL】必要时提供，确认不含敏感信息
【复现步骤】1... 2... 3...
【实际结果】
【预期结果】
【发生频率】必现 / 偶现，出现次数/尝试次数
【附件】完整页面截图、控制台错误、生成日志
【敏感信息处理】Token、API Key、个人信息必须打码
```

建议严重程度：

- P0：数据或密钥泄露、全员不可用、产物被破坏
- P1：核心生成流程无法完成且无绕过方式
- P2：部分功能异常，有临时绕过方式
- P3：样式、文案、交互体验问题

### 7. 已知问题与限制

Alpha 文档必须明确：

- AI 生成结果需要人工评审，不能直接作为生产代码合入
- 复杂 Figma、特殊字体、图片资源、绝对定位可能降低还原度
- AI 服务限流、余额不足、网络波动会造成超时或失败
- 页面并发过高可能触发模型限流
- Token 当前会同步保存到服务端配置文件
- 刷新后的任务恢复、SSE 断连回退虽已实现，仍应列为重点测试项
- 生成产物依赖的 UI 库和版本需人工核对
- 不支持 Figma 原型链接；页面链接必须包含 `node-id`

### 8. 数据安全与测试红线

建议新增：

- 禁止上传涉密、未脱敏客户数据和生产接口凭据
- 禁止在截图、日志、缺陷单中暴露 Token/API Key
- 禁止使用生产 Figma/Apifox 高权限 Token
- 禁止将 AI 生成代码未经审查直接部署到生产
- 测试结束后的 Token 轮换与服务端配置清理责任人
- 生成任务、Figma 链接、需求文档是否留存及保留周期

### 9. 版本变更记录

文末增加：

| 文档版本 | 产品版本 | 日期 | 变更内容 | 作者/审核人 |
| --- | --- | --- | --- | --- |
| v1.0 | Alpha.0.1 | 2026-08-02 | 初版 | 待补充 |
| v1.1 | Alpha.0.1 | 待定 | 补充测试规范与安全说明 | 待补充 |

并补充“文档内容以当前测试环境为准；界面变化时同步更新截图和字段说明”。

## 四、P2：内容和表达优化

1. 标题建议改为《感智晓界 Alpha.0.1 测试期使用与反馈手册》，体现测试闭环。
2. 将所有“截图位置”占位符替换成真实截图；发布版不得保留占位文案。
3. 统一 Markdown 列表符号，建议全篇使用 `-`，避免 `+`、`-` 混用。
4. 修正 `**⚠️**** 注意**`、`✅` 等不规范强调格式。
5. “2 小时 → 10 分钟”“直接集成”“AI 直接还原设计稿”等表述过满，建议改成条件化描述。
6. “等待约 30-120 秒”应改成“时间受组件复杂度、模型和并发影响”，避免形成错误 SLA。
7. “公司主要使用通义千问”与模型表应由管理员确认，避免文档版本落后于实际配置。
8. “Token 格式”仅作示意，不应作为有效性判断依据；不同供应商格式可能不同。
9. “背景图可以删除，AI 会用 CSS 模拟”风险较高，应改成按设计要求决定，不保证能等价模拟。
10. 附录中的相对链接 `./前后端架构研究报告.md` 需要确认发布位置能访问。
