# 感智晓界前端页面设计统一化建议

> 基于当前截图与代码扫描（`frontend/src/views` 下 6 个核心页面）提出的结构化优化意见。
> 目标：让组件生成、任务中心、任务详情、接口开发、接口详情、工作台看起来像同一套产品。

---

## 一、现状诊断：一眼看得到的 7 处割裂

### 1. 全局导航下方的“第一屏”布局不统一

| 页面 | 第一屏结构 | 问题 |
|------|-----------|------|
| 工作台（AI Research） | 深色左侧边栏 + 中间聊天 + 右侧文档 | 与主站导航下的白色/浅灰页面完全两个世界 |
| 组件生成页 | 面包屑 + 白色左侧面板 + 浅灰主内容区 | 左侧是“输入面板”，视觉上像表单抽屉 |
| 任务中心 | 大标题 + 统计卡片 + 筛选栏 + 列表 | 没有左侧栏，却有一个窄筛选边栏 |
| 任务详情 | 面包屑 + 深色左侧信息栏 + 浅灰主内容区 | 左侧栏颜色与组件生成页冲突 |
| 接口开发 | 大标题 + 单栏内容 | 没有侧边栏，纯上下流 |
| 接口详情 | 返回 + 标题 + 左侧模块树 + 右侧函数列表 | 又是一个独立的两栏布局 |

**结论**：同一个产品里，同一层级的页面同时存在“三栏、两栏左白、两栏左深、单栏”四种布局框架。

### 2. 侧边栏颜色语义混乱

截图中能直接对比出的颜色：

- **工作台左侧**：深灰（`#1f2937` 左右），作为全局导航区。
- **任务中心左侧**：几乎纯白/浅灰，带汉堡菜单，作为筛选区。
- **组件生成左侧**：纯白面板，作为配置输入区。
- **任务详情左侧**：深灰蓝（接近深色模式），作为任务信息只读区。

同一位置的左侧区域，有时是“导航”、有时是“筛选”、有时是“表单配置”、有时是“只读信息”，但颜色没有对应语义，只凭历史硬编码。

### 3. 页头（Page Header）风格不一致

当前至少存在 3 种页头：

1. **组件生成 / 任务详情**：`.page-header-bar`
   - 面包屑返回 + icon + 标题 + 描述 + 右侧操作
   - 样式偏工具页，灰底条。
2. **任务中心 / 接口开发 / 工作台**：`.page-header`
   - 大标题 + 副标题 + 右侧按钮
   - 但标题字号、icon 大小、副标题颜色各不相同。
3. **接口详情**：`.detail-header`
   - 返回按钮 + 标题 + 下载按钮
   - 没有统一的 icon 和描述区。

**结果**：用户每切一个页面都要重新识别“这是标题区、那是操作区”。

### 4. 画布层级不统一（背景与卡片关系）

设计 token 已经定义了 `--bg-page / --bg-card / --bg-alt / --bg-hover`，但各页用法不一：

- 组件生成、任务详情：页面背景浅灰，卡片白色 → 正确。
- 任务中心：页面背景偏白，统计卡片白连一片 → 浮起感弱。
- 工作台：左侧深色、中间白色、右侧白色 → 三区平铺，没有主次。
- 接口详情：模块树和函数卡片颜色关系不明。

浅色模式下的正确层级应该是：**浅灰画布 → 白色浮起卡片 → 卡片内灰白次级区域**。

### 5. 统计/状态卡片风格差异

- 任务中心统计卡片：绿色/红色/灰色左边框，数字 + 标签。
- 组件生成“生成概览”卡片：白底，左侧色条，与任务中心相似但圆角/阴影不同。
- 组件生成“快速上手”卡片：icon + 标题 + 描述，可点击。
- 任务详情顶部进度条：绿色实心条。
- 接口详情函数卡片：method 颜色标签 + 边框。

这些卡片各自为政，没有共享一套“数据展示卡片”规范。

### 6. Footer 策略不一致

- 组件生成、任务详情：底部有 `AppFooter`（MICROVIDEO 大 logo + 导航列）。
- 任务中心、接口开发、接口详情、工作台：没有该 footer。

一个工具型后台，全屏滚动任务列表时突然出现大 footer 很突兀；但有的页面又有，有的没有，造成“这页是不是用完了”的疑惑。

### 7. 工作台（AI Workspace）像一个独立应用

工作台左侧导航、中间聊天、右侧文档输出的三栏布局本身没问题，但它与顶部全局导航的“组件开发/页面/接口/任务中心”在视觉语言上脱节：

- 顶部导航是白色工具栏，左侧工作台下是深色侧边栏，衔接生硬。
- 字体、按钮、徽章与主站 Ant Design 体系差异大。

## 二、根因分析

1. **没有统一页面模板（Page Shell）**
   - 每个页面自己决定：是否有 header、是否有左侧边栏、是否加 footer、主内容最大宽度。
   - 结果：同一层级页面像不同的人/不同时间写的。

2. **公共 UI 类（`ui-components.less`）定义了组件，但没有强制页面布局**
   - 有 `.badge`、`.state-chip`、`.progress-bar`、`.card-hover` 等原子类，但页面是否使用全凭自觉。
   - 很多页面仍用 `ant-card`、自定义 `.stat-card`、`.quick-card` 等私有实现。

3. **设计 token 已存在，但页面级语义未约定**
   - `--bg-sidebar` 到底代表“全局导航侧边栏”还是“页面内工具侧边栏”？没有文档。
   - 导致左侧栏一会儿深、一会儿浅。

4. **工作台与主站分属不同产品阶段/团队**
   - 工作台更像 ChatGPT / Claude 的对话产品；主站更像传统后台。
   - 如果保留两种风格，必须明确“这是两个不同子产品”，而不是让用户觉得它们应该一样。

---

## 三、优化方案

### 方案 A：统一成“单一套路后台”（推荐）

让所有工具页面共用同一套布局壳。

#### 1. 建立统一页面模板 `PageShell.vue`

强制每个工具页面使用同一套结构：

```
┌──────────────────────────────────────────────┐
│ 全局导航（已有）                                │
├──────────┬───────────────────────────────────┤
│ 页面内边栏 │ 主内容区                            │
│ （可选）  │  ┌─────────────────────────────┐  │
│          │  │ PageHeader（面包屑/标题/操作）│  │
│          │  ├─────────────────────────────┤  │
│          │  │ 内容卡片                        │  │
│          │  └─────────────────────────────┘  │
└──────────┴───────────────────────────────────┘
```

`PageShell` 提供：
- `aside` 插槽：页面内工具栏/筛选/导航，默认宽度 `260px`。
- `default` 插槽：主内容区，自动处理 `padding` 和 `max-width`。
- `showFooter` prop：控制是否显示全局 footer（建议工具页统一关闭，营销页/首页打开）。

#### 2. 明确左侧栏颜色语义

| 左侧栏类型 | 颜色 token | 用途 |
|-----------|-----------|------|
| 全局导航侧边栏 | `--bg-sidebar` | 极少数全屏应用（如工作台） |
| 页面内工具/筛选侧边栏 | `--bg-card` | 组件生成、任务详情、接口详情 |
| 页面内二级导航 | `--bg-alt` | 模块树、文件树 |

**关键规则**：
- 工具页面内边栏不再用深色。
- 深色只留给全局导航或代码编辑器这类“沉浸式”区域。

#### 3. 统一页头组件 `PageHeader.vue`

所有页面使用同一个页头：

```
[面包屑 / 返回]  [Icon]  页面标题
                页面描述（可选）
                                      [操作区]
```

Props：
- `title`、`description`
- `icon`
- `backTo` / `breadcrumb`
- `actions` slot

样式来源：`ui-components.less` 中已定义的工具类，确保字号、行高、颜色一致。

#### 4. 统一画布层级：浅灰画布 + 白色卡片

- 页面根容器背景统一使用 `--bg-page`（light: `#f0f4fa`）。
- 所有内容面板/卡片统一使用 `--bg-card`（白）。
- 卡片内次级区域使用 `--bg-alt`。
- 禁止页面直接使用 `--bg-card` 作为根背景（任务中心需要改）。

#### 5. 统一统计/数据卡片

合并为 3 种卡片类型：

| 类型 | 类名 | 用途 |
|------|------|------|
| 统计卡片 | `.stat-card` | 数字 + 标签，可点击筛选 |
| 信息卡片 | `.info-card` | icon + 标题 + 描述，用于快速上手 |
| 列表卡片 | `.list-card` | 任务项、函数项、项目项 |

统一使用：
- 圆角 `--radius-lg`
- 阴影 `--shadow-sm`，hover 时 `--shadow-md`
- 边框 `--border-light`
- 状态色仅用于状态点/徽章，不用于整张卡片背景

#### 6. 统一 Footer 策略

建议：
- **工具页面**（组件生成、任务中心、任务详情、接口开发、接口详情）：**不要大 footer**。
  - 如需版权信息，放在页面底部一条 40px 高的 `PageFooter` 细线。
- **营销/首页/介绍页**（架构介绍、文档设计）：保留 `AppFooter`。
- **工作台**：作为沉浸式应用，footer 完全不需要。

#### 7. 收敛工作台视觉

如果工作台必须保留当前三栏布局，至少做以下收敛：
- 左侧导航颜色与全局 token 对齐，使用 `--bg-sidebar`。
- 顶部不再显示与工作台重复的标题，或让全局导航在 Workbench 模式下收缩为最小化工具条。
- 按钮、徽章、标签改用 `ui-components.less` 的 `.state-chip`、`.badge`。
- 字体、圆角与主站一致。

更激进的方案：把工作台从“顶部导航下的子页面”升级为“独立工作区入口”，进入后隐藏全局导航，退出时恢复。这样视觉风格差异可以被用户理解为“进入了专注模式”。

---

### 方案 B：接受两个子产品，但明确边界

如果工作台和主站确实是两个产品阶段，可以明确：

- **主站后台**：组件生成、任务、接口。统一成方案 A。
- **AI Workspace**：工作台、研究、对话。允许有自己的深色/对话式风格，但入口上明确标识“AI WorkSpace”。

风险：长期维护两套视觉体系成本高。建议只在短期内接受，长期仍应收敛。

## 四、落地优先级

### P0（先做，改动小、见效快）

1. **统一左侧栏颜色**：把任务详情左侧深色栏、工作台左侧栏分别收敛到语义 token。
2. **统一页头**：抽一个 `PageHeader.vue`，先把组件生成、任务中心、任务详情、接口开发、接口详情套上去。
3. **统一 Footer 策略**：工具页移除/替换大 footer。

### P1（结构改造）

4. 建立 `PageShell.vue` 页面模板，逐步替换各页面根容器。
5. 统一统计/列表卡片为 `.stat-card`、`.info-card`、`.list-card`。

### P2（长期治理）

6. 工作台视觉收敛或升级为独立工作区。
7. 建立“新增页面设计准入 check”：必须走 `PageShell`、必须复用公共 UI 类、禁止页面级硬编码颜色。
