## 4. ④Vision 骨架：**不唯一（核心结论）** 🔴

### 4.1 缓存键不含内容指纹（代码实锤）

`src/ai-engine/roles/visual-parser.js:4583-4592`
```js
_buildCacheKey(fileKey, nodeId, figmaData, target) {
  if (fileKey && nodeId) {
    return `vision_${fileKey}_${nodeId}_${target || 'default'}`   // ← 无内容/时间/参数指纹
  }
  if (figmaData) {
    const hash = createHash('md5').update(JSON.stringify(figmaData)).digest('hex').substring(0, 12)
    return `vision_data_${hash}`
  }
  return null
}
```
- **主路径（fileKey+nodeId 齐备）**：键 = `vision_<fileKey>_<nodeId>_<target>`，**只有三要素**。
- 仅当 fileKey/nodeId 缺失时才退化用 `figmaData` 的 md5。
- ⇒ **同一 `<fileKey,nodeId,target>` 的不同输入（模型、温度、prompt 版本、时间）共用同名缓存文件**。

`visual-parser.js:4668-4671`
```js
const cacheKey = this._buildCacheKey(fileKey, nodeId, figmaData, target)
const cacheDir = outputPath ? join(outputPath, '.mc-gen/cache/vision-cache') : null
if (cacheKey && cacheDir && !bypassCache) {
  const cached = this._readCache(cacheKey, cacheDir)   // TTL=24h（:4606）
```
- TTL **24h**（`_readCache:4607`）；`bypassCache=true` 时强制绕过。
- 另有保护：`⚠️ 视觉分析结果为退化/空结构，跳过缓存，允许后续重试重新调用 Vision`（`:4803`）⇒ **不缓存坏结果**，好结果才落盘。

### 4.2 同名不同内容的实证（前序 12 样本，已固化）

| 观测 | 值 |
|---|---|
| 12 个同参重发样本的 cacheKey | **完全相同**（去重后 = 1 个） |
| 12 份 vision-cache 内容 md5 | **12/12 互异** |
| 12 份 `visual.json` md5 | **12/12 互异** |
| `layout.sections` 数量 | **{4, 5, 6, 8} 四种**（4 出现 2 次、6 出现 1 次、8 出现 1 次、5 出现 8 次） |
| sections=5 的 8 个样本，其 `index.vue` md5 | **仍 8/8 互异** ⇒ 分叉不止在骨架层，**下游分片生成独立叠加抖动** |
| `inlineCompositeRows`（Figma 侧注入） | **12/12 恒为 87** ⇒ **唯一稳定字段** |

⇒ **Vision 层没有形成单一事实源**：同名缓存被每轮新内容覆盖，等于「每次重算即新真值」。

## 5. 结论（逐条回答用户问题）

| 问题 | 结论 |
|---|---|
| 「事实源是一个吗？」 | **不是**。 |
| 哪些是唯一的？ | **Figma 层唯一**：`figma-node-data.json`（6/6 md5 各异、各 1 份）+ `_figma-size.json`（权威尺寸，`index.vue` 逐字引用）。 |
| 哪些不唯一？ | **Vision 层不唯一**：缓存键 `vision_<fileKey>_<nodeId>_<target>` **不含内容指纹** ⇒ 同名可被不同内容覆盖；实证「同名 12/12 内容互异」；且 2/6 组件**连缓存都没有**。 |
| 有没有「两个尺寸源打架」？ | **有**：`_figma-size.json` vs `mc-preview.png` 在 **3/6** 组件上差 +7/+13 ~ +20/+20。 |
| 唯一稳定的东西是什么？ | `inlineCompositeRows`（Figma 侧确定性注入）**12/12 恒 87** ⇒ **只有 Figma 侧注入是确定的**。 |

**推论（供 `03` 使用）**：
- 上游 Figma 是可信地基；**Vision 是概率性重算层**，把它当唯一真值 ⇒ 骨架（section 数/顺序/归属）天然抖动。
- 因此「组件根部/section 内布局问题」**不能只归因于 codegen**，至少有一半来自 **Vision 骨架每次重算**；而 codegen 分片又会在此之上**独立叠加**一轮采样。
