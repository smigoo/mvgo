## 2. 刀 A：@echarts 剔子保父（主刀）

- **位置**：`visual-parser.js#extractFigmaHints` L633。
- **现状**：`if (name && /@echarts/i.test(name)) return ''`。
- **改法**：命中 `@echarts` 时**保留自身行**（走既有渲染路径：label + [id] + 尺寸 + 颜色），追加注记 ` ⚙️图表容器：内部由 echarts 渲染，禁止把装饰矢量/柱状分片当 UI 还原`，然后**跳过 children 递归**（不进 L738 的循环）。
- **实现要点**：
  - 用早渲染 + 提前 return（`return parts.join('\n')`）实现，不改其余分支；
  - 注记文案进 `resourceAnnotation` 同一行或紧邻行，保持「一行一节点」格式不破坏 prompt 结构树解析；
  - 计数挂**模块级入参对象**：`extractFigmaHints` 顶层创建的 `budget` 对象扩为 `budget.counters = { echartsContainerShown, echartsChildrenPruned }`（顶层创建、递归累加），`buildPrompt` 取 hints 后由调用侧打日志计数行 `📐 figma-hints 计数 { echartsContainerShown: N, echartsChildrenPruned: M }`——0 也打（计数行铁律）。
- **阳性对照**：用 ca3b76de 真值 `figma-node-data.json` 离线重放 `extractFigmaHints`，断言输出含 `[2:3604]` 且不含 `2:3604` 的子节点 id。
- **阴性守卫**：d9b6f34b 真值重放输出与改前**逐字 diff 为空**（该树无 @echarts 命中深度内的节点——若命中则该节点行为变化属预期，记录之）；既有 `visual-parser.regression.spec.ts` 全绿。
- **spec**：`visual-parser.figma-hints-echarts.spec.ts`（≥6 例：自身行保留/子级剔除/注记存在/计数正确/非 echarts 不受影响/嵌套 echarts 幂等）。
- **直接治**：ca3b76de「流量预测」段锚错（模型将有 `2:3604` 378×? 可选）。

## 3. 刀 B（修订版）：深度边界一层紧凑子清单

- **位置**：`visual-parser.js#extractFigmaHints` 深度守卫 L615（`currentDepth >= maxDepth` 处）。
- **现状**：深度 4 节点静默 return ''，父节点只剩 `[layout: vertical, 6 children]` 方向行，模型对子节点存在**零感知**且无「被剪」标记（对比：预算截断有显式标记）。
- **改法**：深度守卫命中时，若该节点有 children，**不再静默返回空**，而是返回一段**一层紧凑清单**：
  - 格式：`- [⚠️ 深度截断] 下级 N 个子节点：id 名称 尺寸；id 名称 尺寸；…`（每子一条、`; ` 连接、只含 id/name/尺寸/text 前 20 字，**不递归**）；
  - 每节点子清单上限 `MAX_DEPTH_BOUNDARY_CHILDREN = 16`（超出部分 `…另省略 K 个`，常量+注释）；
  - 子清单行计入 budget（`budget.used` 累加），预算耗尽走既有 truncated 显式标记路径；
  - @echarts 子级例外：仍不列（刀 A 已把容器行保留+注记，其子级是图表内部分片，列出违反「剔子保父」意图）——例外顺序：刀 A 判据先于刀 B 判据。
- **治谁**：d9b6f34b `89:39` 的 6 个 tab 组（模型将可见 tab 组 id，锚左侧导航有真值可选）+ `2:8437` 的 12 张卡（网格段 items 有真值可选）。**同时治**所有未来深度 4+ 组件的同类盲区。
- **计数**：`depthBoundaryListed`（触发节点数）/ `depthBoundaryChildren`（列出子节点总数），与刀 A 同一 counters 通道，同一日志行恒打。
- **阳性对照**：d9b6f34b 真值重放，断言输出含 `89:39` 的直接子 id（如 `2:8825`）各恰好 1 次、含 `2:8437` 的卡 id、不含任何深度 5 节点 id。
- **阴性守卫**：浅树（深度 ≤4）重放输出与改前逐字 diff 为空。
- **spec**：≥7 例（边界触发/一层不递归/16 上限/@echarts 例外/预算交互/浅树不变/计数正确）。
- **⚠️ prompt 长度预算影响**：d9b6f34b 形态约增加 18 行紧凑清单（6+12），估算 <800 字符，预算 5000 内安全；预算不足时既有 truncated 显式标记兜底——比现状（静默盲区）严格更优。

## 4. 刀 C（收窄版）：prompt 锚点反例条款（纯静态文本）

- **位置**：`visual-parser.js` L404-410 `anchorRules` 块（紧邻规则 2「取覆盖该区域最内层的节点 id」）。
- **改法**：在规则 2 后追加一条反例规则（编号顺延，后续编号不动）：

  ```
  6. **标题节点不是段身**：名为 header / sub-title / sub-header / tit 或高度 ≤32px 的标题条，
     是段的**标签**而非段的内容容器——禁止作为覆盖图表/卡片/列表区域的 section.id。
     判别法：先看该节点的尺寸能否装下区域内容（如 21px 高的标题装不下 131px 高的图表），
     装不下就必须改用内容容器 id；区域真跨多兄弟时用最近公共父节点（见规则 3）。
  ```

- **不做**：删掉原方案的「prompt 构建时扫描候选追加警示行」——prompt 构建期（buildPrompt）没有段锚候选信息（候选来自 vision 输出，时序在后），原设计不可实现；观测兜底归 D1（可选）。
- **判据纪律**：prompt 文本里用「尺寸装不下」这个**几何语言**描述判别法，不给「名字命中正则即拒绝」的硬规则（某些组件 header 本身是合法业务段）——模型侧软约束，后处理硬判据仍是既有 LCA/祖先审计单一来源，不新增第二套。
- **spec**：`visual-parser.anchor-rules.spec.ts` 2 例（反例条款存在/条款含几何语言非命名禁令）。
- **直接治**：ca3b76de 模型选 `2:7625`(21px sub-title) 当 131px 图表段锚的模型侧错选。
