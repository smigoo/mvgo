# 15 - vision 锚点失准修复方案（2026-11-16 · ca3b76de / d9b6f34b / 80954ead 实锤）

## 0. 病灶定性（证据链见 memory/2026-11-16.md 傍晚段）

**双因**：
- 喂料侧：`extractFigmaHints` L631 把 `@echarts` 容器**连父带子整体剔除**（ca3b76de prompt 中 `2:3604` 出现 0 次）⇒ 模型对「流量预测」段**想选也没得选**；`@antd/tab` 容器在树但子清单缺失（d9b6f34b prompt 中 `89:39` 仅 1 次、5 个 tab 组全缺）⇒ 「左侧Tab导航」锚必错。
- 模型侧：prompt 菜单里明明给了正确锚（`2:3660` 统计带 ×2 次、`1744:127/128` 图表容器、`1263:38` 卡区），模型全没选，选了 header/sub-title/sub-header 标题节点——违反 prompt 明文规则「一个区域锚它自己的节点：取覆盖该区域最内层的节点 id」。

**下游现状**（已有能力，不必重造）：
- `validateVisionAnchors`（vision-anchor-validator.js）：只判 id **在不在树里**，标 `anchorValid:false`；
- `auditVisionSectionAnchors`（section-anchor-truth.js）：判「锚是否为自身内容的祖先」，按 LCA 写 `figmaAnchorId`（d9b6f34b 真机 `notAncestor:1, repaired:1` 已生效）；
- `injectIsomorphicSectionTruth`（layout-truth-healer.js）：注入 `isoSectionTruth`（同构段事实）。

## 1. 修复总原则

1. **喂料修复优先于模型修复**：菜单不全的错，模型无解；先补菜单。
2. **单一事实源**：全部判据挂 `section-anchor-truth.js` / 现有 validator，禁止新造第二套锚点判据。
3. **只增不改**：新判据一律写新字段/新计数键，不改既有 `id`/`figmaNodeId`/`anchorValid` 语义。
4. **计数行恒打**：0 也打，可区分「没跑」与「判据失效」。

## 2. 刀位清单（按依赖序）

### 刀 A（喂料｜主刀）：@echarts「剔子保父」
- 位置：`visual-parser.js#extractFigmaHints` L631。
- 改法：`@echarts` 节点**保留自身行**（name + type + bbox + 「⚙️图表容器：由 echarts 渲染，禁止静态还原内部」注记），只递归跳过其 children。
- 判据：`if (/@echarts/i.test(name)) { render 自身行 + 注记; 不递归 children }`。
- 阴性守卫：非 @echarts 节点行为逐字不变；既有 spec 全绿。
- 计数：`echartsContainerShown` / `echartsChildrenPruned`。
- 直接治：ca3b76de「流量预测」段锚错（模型将有 `2:3604` 363×140.7 可选）。

### 刀 B（喂料｜配套）：@antd/tab 子清单展开
- 位置：同函数 `@` 技术组件分支（L643-668 effectiveW/H 修正处）。
- 改法：`@antd/tab` 已有「取子级最大宽高」修正，补**子节点清单行**（每个直接子：id + name + bbox，深度 +1，仅一层，不递归）。
- 计数：`antdChildrenListed`。
- 直接治：d9b6f34b「左侧Tab导航」锚错（5 个 tab 组进菜单）。

### 刀 C（模型侧｜prompt 约束）：锚点判别反例条款
- 位置：prompt 的锚点规则段（「id 只能取自上面结构树」同段）。
- 改法：追加正反例：
  - ❌ 「sub-title / sub-header / header / 标题（TEXT、≤32px 高的标题条）是段的**标签**，禁止作为 section.id 或 figmaNodeId」；
  - ✅ 「section.id = 覆盖该段全部 body.items 的**最小内容容器**」。
- 附自动对照：prompt 构建时如段锚候选中出现 ≤32px 高且名字命中 `/sub-?title|sub-?header|header|^tit/` 的节点，附加一行警示（不是硬拦，视觉图里标题也可能是真段——保守）。

### 刀 D（模型侧｜校验兜底）：锚 bbox 覆盖校验（既有 validator 扩展）
- 位置：`vision-anchor-validator.js` 新增第二判据（与「在不在树里」并列，仍 fail-open 只标注）。
- 判据：`section.id`（或 figmaNodeId）节点的 bbox **装不下** 该段 body.items 全部命中节点的联合 bbox 时（联合高 > 锚高 × 1.5 或联合宽 > 锚宽 × 1.5），标 `anchorCoverValid:false` + `anchorCoverDetail`（锚 bbox vs 联合 bbox）。
- 消费：与 `anchorValid:false` 同通道——planner/装配读到后不拿它当段高锚（fail-open 到既有缺锚路径）。
- 直接治：ca3b76de `2:7625`（21px sub-title 装着 131px 图表）这类错锚被静默使用的窗口。
- 明确不做：不做自动改锚（那是 LCA 审计的既有职责，避免第二套纠偏口径）。

### 刀 E（下游｜装配空段守卫，最小刀）：空 body.items 顶层段不参与 flex 装配
- 位置：subcomponent-planner / resource-mounter 装配候选判定。
- 判据：顶层段 `children=0 且 body.items 全 miss`（无任何真值命中）⇒ 不参与装配、不占 flex 槽位，计数 `emptyAnchorSectionSkipped`。
