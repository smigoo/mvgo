### 1.1 关键：**段高真值的上游就是 Vision（概率层）**

`utils/figma-section-heights.js:4-7` 自述：
> *「确定性后处理：把 **Figma 真值「区块高度比例」从 vision JSON** 落到 CSS」*
> *「A4 会把 Figma 区块高度比例系数写进 **vision JSON** `sections[].styles.flexGrow`（以及审计用 `figmaHeightPx`）」*

⇒ 段高的**数值来源**经过 Vision 这一跳。**Vision 不稳定 ⇒ 段高不稳定**（`02` 已证明 Vision 不唯一）。

### 1.2 关键：**段高映射失配会 fail-open 退化**

`figma-section-heights.js` 明确记载了两条退化路径：
- `:317` 「**flexGrow 消费断链**」
- `:332-334` 「旧守卫 `>= 2` 把这档直接打进 **raw fallback**：顺序源退化为『含 header 的 vision sections』，**fail-open → 规则⑥拿不到映射 → `index.vue` 内联 `flex:1` 原样透传（code-generator 均分兜底）**」
- `:395` 「`orderedSections.length === 1` 只可能来自 `planLeaves.length === 1`」

**触发条件**（`:379-396`）：要求
```
根模板直接子元素 class 数  ===  有序 section 数
且每个 class 非空
```
否则 → 对齐失败 → 无映射可写。

另有一条硬约束（`:63 extractRootTemplate` 注释）：**解析根模板时会跳过 `#header-right` 等具名插槽**。

## 2. 归因 A：**组件根部布局问题**（6/6 命中）

### 2.1 症状：根容器尺寸策略**三分裂**，无统一契约

| 组件 | 根容器策略 | 根高 | 段高 Σ | **Δ** |
|---|---|---|---|---|
| `d04b5f2c` | `display:flex;flex-direction:column;height:100%;min-height:0`（**无固定尺寸**） | 自适应 | `27+170`(inline) `=197`（+`margin-top:11`） | **−77 → 底部留白** |
| `40c6e852` | `width:510px;height:665px`（固定 = figma） | 665 | **规则体为空（未注入）** | — |
| `68783bf6` | `display:flex;flex-direction:column;height:100%`（**无固定尺寸**） | 自适应 | `76+161+212+265 = 714`（+margin 73） | **−81 → 顶部留白** |
| `c1ac194a` | `width:414px;height:348px`（固定） | 348 | `126+200+192 = **518**` | **+170（+48.9%）→ 溢出** |
| `fdbb799d` | `width:603px;height:555px`（固定） | 555 | `493 + 14×12 = **661**` | **+106（+19.1%）→ 溢出** |
| `af0b0417` | `width:420px;height:425px`（固定） | 425 | `99+100+290 = **489**` | **+64（+15.1%）→ 溢出** |

### 2.2 环节定位

**🔴 根因环节 = ⑤ 段高真值求解（`utils/figma-section-heights.js:292 buildSectionHeightsMap`）+ ⑥ 落盘**

三点必须同时成立才叫「治本」，本轮三点**都不成立**：

1. **段高之和没有与根高做统一约束求解**。段高写成 `flex: 0 1 <px>`（可收缩），**没有任何一步把 Σ 归一化到根高**。Σ > 根高时全部段被**等比压缩** ⇒ 段间比例失真（`c1ac194a` 内容密度剖面 `[100×16]` 满屏即此表现）；Σ < 根高时**底部/顶部留白**（`d04b5f2c` −77、`68783bf6` −81）。
2. **段高数值经 Vision 一跳** ⇒ 上游不稳定直接下传。
3. **对齐失败 fail-open** ⇒ `40c6e852` 段高规则体**完全为空**（只剩注释「mvgo-layout-truth：段高真值」），退化为 `flex:1` 均分。

**🟡 放大环节 = ⑦ codegen 分片**：根容器到底写「固定 px」还是「`height:100%`」**无统一契约**（4 例固定 / 2 例自适应），且两种策略与段高 Σ 都不自洽。

**🟡 放大环节 = ⑧ 修复轮**：每轮重采（`lite.service.ts:3235` 基线 0，修复轮阶梯抬温）⇒ **同一输入可能落在不同分支**，段高/根高组合又换一组。

**环节定位**：
- **🔴 段内布局（占比/高度）错误 → ⑤ 段高求解**。`fdbb799d` 是铁证：13 个叶段里 **12 个被写成 `14px`**（`flex: 0 1 14px !important`），只有第 1 段 493px ⇒ 段高求解在该组件上**退化为常量兜底**，完全没反映 Figma 真值。这与 §1.2 的 fail-open 描述吻合（对齐失败 → `flex:1`/常量兜底）。
- **🔴 段内结构（模块增删/归属/顺序）错误 → ③ Vision 骨架 + ⑦ 分片**。`40c6e852` 的槽位错置、`af0b0417` 的数值→tab、`fdbb799d` 的顺序错乱与文本粘连，均为 **codegen 分片层面的归属判断错误**。
- **🟡 段内样式（颜色/透明度）错误 → ⑦ 分片**。`c1ac194a` 的透明数值是**样式生成缺陷**（`common.less:65-71` 给了 `text-fill-color:transparent`，但**全仓无任一规则为 `.c-c1ac19-stat-value` 提供 `background-image`** —— 机器核验 `有背景=False`，对照组 `.c-c1ac19-section-title` `有背景=True`）。

- **C1 + C2 是「根部布局问题」的共同环节**：上游 `figma-section-heights` 求解出的段高之和，与 `index.vue` 根高**从未做过一次联合约束求解**；而根高策略本身还三分裂。

- **C7 是方法论问题**：截图比对前必须剥离预览壳层，否则「产物多」的 token 里 6–8 条是壳层噪声。
