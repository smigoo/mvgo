# Figma 设计稿整理规范（基于当前 mc-gen 脚本能力）

> 当前脚本已支持绝对定位设计稿的解析，通过坐标推断、命名识别、层级分析生成代码。以下规范帮助设计师整理 Figma 文件，提升生成准确度。

---

## 一、布局方向：让脚本"看懂"排列方式

### 当前脚本能力
脚本通过计算子元素坐标的离散程度推断布局方向：
- x 方向离散大 → 推断为横向排列（`flex-direction: row`）
- y 方向离散大 → 推断为纵向排列（`flex-direction: column`）

### 整理建议

**1. 同一容器内的子元素尽量保持对齐**

```
✅ 容易识别（坐标差异明显）：
图标(x=10)    文字(x=60)     → x 差 50px → 脚本识别为横向

❌ 容易误判（坐标混乱）：
图标(x=10)    文字(x=15)     → x 差 5px, y 差 20px → 可能识别为纵向
```

**2. 图标与文字保持明显间距**

| 布局 | 建议间距 |
|------|---------|
| 图标左 + 文字右 | 水平间距 ≥ 8px |
| 图标上 + 文字下 | 垂直间距 ≥ 8px |

**3. 避免元素交叉重叠**

```
❌ 容易误判：
┌─────────┐
│ 图标     │  文字
│    文字  │
└─────────┘

✅ 清晰排列：
┌────┬────┐
│图标│文字│
└────┴────┘
```

## 二、图层命名：帮助脚本识别元素用途

### 当前脚本能力
脚本通过名称前缀识别资源类型：
- `bg-*` → 识别为背景图（CSS background-image）
- `icon-*` → 识别为图标（`<img>`）
- `text-*` / 文字内容 → 提取颜色、字号
- `tab-*` → 识别为切换控件
- `chart-*` → 识别为图表区域

### 整理建议

**1. 使用前缀命名**

| 元素类型 | 命名示例 | 脚本处理 |
|---------|---------|---------|
| 背景图/底色 | `bg-card-danger` | background-image |
| 图标 | `icon-danger-truck` | `<img :src>` |
| 文字标签 | `text-vehicle-name` | 提取样式 |
| Tab 项 | `tab-active` | 识别为控件 |
| 图表区域 | `chart-bar` | ECharts 容器 |

**2. 避免默认命名**

```
❌ 不利于识别：
- Frame 2136639043
- Group 2136638349
- Rectangle 34625532
- 3 / 2 / 1

✅ 建议改为：
- 统计卡片组 / stat-cards
- 危化品车卡片 / danger-card
- bg-card-danger
- icon-danger-truck
```

**3. 背景与内容分层**

```
✅ 推荐结构：
卡片容器
├── bg-card（背景层）
│   └── 背景图片/渐变底色
└── content（内容层）
    ├── icon-truck（图标）
    └── text-group（文字）
```

脚本会优先识别 `bg-*` 节点作为 background-image，其他节点作为内容。

## 三、组件边界：区分面板头部与内容区

### 当前脚本能力
脚本通过以下方式识别面板结构：
- `headerRelation` 字段判断内容是否在标题行
- `slot-*` 命名识别面板插槽区域
- 最外层 Frame 作为组件边界

### 整理建议

**1. 明确内容区起点**

```
✅ 推荐方式：
画板
├── slot-header（面板头部区域）
│   ├── Tab 切换
│   └── 控件
└── component-body / slot（组件内容区）
    ├── 今日累计
    └── 统计卡片
```

**2. 头部控件放入独立 Group/Frame**

```
✅ 便于识别：
Group: "header-tabs"
  ├── 江阴靖江长江隧道（激活）
  └── 江阴大桥

❌ 容易混乱：
Tab 文字直接散放在根层级
```

**3. 不要画面板外壳**

mc-gen 生成的代码**只包含内容区**：
- ❌ 不需要画：面板标题栏、边框、阴影、背景底色
- ✅ 只需要画：Tab、内容区块、卡片、图表等实际内容

## 四、层级与顺序：降低解析复杂度

### 当前脚本能力
脚本按 Figma 节点顺序和层级关系生成代码结构。

### 整理建议

**1. 同级节点按视觉顺序排列**

```
✅ 从上到下、从左到右：
  1. Tab 切换
  2. 今日累计标题
  3. 统计卡片组

❌ 混乱顺序会导致代码结构错误
```

**2. 控制嵌套深度**

```
✅ 推荐 3-4 层：
Frame（卡片）
  ├── bg（背景）
  ├── icon（图标）
  └── text-group（文字组）
        ├── text-name
        └── text-count

❌ 超过 5 层脚本难以解析：
Frame → Group → Frame → Group → Frame → ...
```

**3. 避免不必要的空容器**

```
❌ 增加解析复杂度：
Frame（空）
  └── Group（空）
        └── Frame（实际内容）

✅ 扁平化：
Frame（实际内容）
```

## 五、资源整理：提升资源引用准确度

### 当前脚本能力
脚本通过命名和层级识别资源类型，自动匹配到 DOM 节点。

### 整理建议

**1. 图标尺寸统一**

| 元素 | 建议尺寸 |
|------|---------|
| 卡片图标 | 48×48px |
| 标题图标 | 18×18px |
| Tab 图标 | 16×16px |

**2. 背景图按实际尺寸**

- 卡片背景：与卡片容器同尺寸
- 避免过大或过小的背景图

**3. 图片命名规范**

```
导出时重命名为：
- icon-danger-truck.png
- icon-heavy-truck.png
- bg-card-danger.png
- bg-tab-active.png

❌ 避免：
- jimeng-2026-03-17-5193-xxx.png
- Rectangle 34625532.png
```

## 六、检查清单（交付前）

- [ ] 子元素保持清晰对齐，避免交叉重叠
- [ ] 图标与文字保持 ≥8px 间距
- [ ] 使用语义化命名（无 Frame 21366xxx）
- [ ] 背景使用 `bg-*` 前缀，图标使用 `icon-*` 前缀
- [ ] 背景与内容分层存放
- [ ] 头部控件放入独立 Group
- [ ] 未画面板外壳（标题栏/边框/阴影）
- [ ] 同级节点按从上到下、从左到右排列
- [ ] 嵌套层级不超过 4 层
- [ ] 图标尺寸统一
- [ ] 导出资源使用语义化文件名

## 当前脚本能力边界

| 能力 | 支持情况 | 说明 |
|------|---------|------|
| 绝对定位布局 | ✅ 支持 | 通过坐标推断方向 |
| 语义化命名识别 | ✅ 支持 | 通过前缀识别资源类型 |
| 层级结构解析 | ✅ 支持 | 按 Figma 节点层级生成 |
| 颜色/字号提取 | ✅ 支持 | 从 Figma 样式读取 |
| Auto Layout | ✅ 支持 | 直接读取 layoutMode |
| 动画效果 | ❌ 不支持 | 需生成后手动添加 |
| 复杂交互状态 | ⚠️ 有限支持 | Variant 需额外说明 |

---

> **核心原则**：当前脚本已能解析绝对定位设计稿，规范的命名和清晰的层级结构能显著提升生成准确度。Auto Layout 不是必须，但清晰的排列和命名是必须的。
