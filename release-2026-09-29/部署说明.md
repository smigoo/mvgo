## ECS 上部署

### 1) Node 后端

```bash
cd /home/mvbt/mvgo/backend-node

# 校验完整性（必须与上面 sha256 一致）
sha256sum backend-node-dist-151544.tar.gz

# 备份旧 dist 后解压
mv dist dist.bak.$(date +%s)
tar xzf backend-node-dist-151544.tar.gz

# 停旧进程（按端口真实持有者杀）
pids=$(lsof -ti tcp:13030 2>/dev/null || true)
[ -z "$pids" ] || kill $pids
sleep 3
lsof -ti:13030 -sTCP:LISTEN || echo "✅ 端口已释放"

# 启动（production，加载现有 .env + .env.production；不重建 env 文件）
set -a; . ./.env; set +a
set -a; . ./.env.production; set +a
NODE_ENV=production nohup node dist/main.js >> server.log 2>&1 &

sleep 15
lsof -iTCP:13030 -sTCP:LISTEN
curl -s -o /dev/null -w 'Node /api -> %{http_code}\n' http://127.0.0.1:13030/api
```

> 这里用手动 `nohup` 而非 `deploy-cloud.sh`：生产当前就是以裸 nohup 方式运行的，手动方式**不会重建 `.env.production`**，改动面最小。
> 若坚持用 `deploy-cloud.sh`，注意它内部 `echo "NODE_ENV=production" > .env` 与 `cat > .env.production` 会整体重建这两个文件（值从旧文件 grep 复用，但任何手工新增、未固化进脚本的变量都会丢）。且必须先 `export MONGODB_URI=...`。

### 2) 前端静态资源

```bash
cd /home/mvbt/nginx/www

# 整目录替换，避免旧 hash 静态文件残留
mv mvgo mvgo.bak.$(date +%s)
mkdir -p mvgo
cd mvgo
tar xzf ../frontend-dist-151544.tar.gz

# 确认入口就位
ls -la index.html
```

> 若不想保留历史备份目录，确认无误后再清理旧 `mvgo.bak.*`。

### 3) nginx

静态文件直接读磁盘，一般无需 reload；如需清理 index.html 缓存行为：

```bash
docker exec nginx nginx -t && docker exec nginx nginx -s reload
```
