## 401 架构更正：Java 用 Token 头+门户校验，非 cookie（09:07，关键）
- 用户补充：生产登录是门户扫码（CAS/SSO），不是密码登录；站点 iframe 嵌入门户。
- Java 鉴权真实机制：`SessionGuardInterceptor.java:48` 读 `request.getHeader("Token")` → `SessionAuthService.authenticate(token)` → `verifyViaPortal` 调 `PORTAL_BASE_URL/getTokenUser?token=...`（`SessionAuthService.java:90`）。门户返回 `code=200` 且 `data.uid/account` 才放行；否则 fail-closed 返回空 → 401「未登录或登录已过期」（`SessionGuardInterceptor.java:51`）。**Java 不依赖 cookie 会话**（注释明确：express-session cookie 跨语言不共享，Java 侧不实现）。
- 前端：`core/http.js:126` 从 `getAuthToken()` 注入 `Token` 头；`utils/api-token.js:22` 经 `portlet.getParentInfo('getToken')` 向父框架要 token；`utils/portlet.js:57` 生产分支直接 `window.parent.getToken()`（同步跨帧函数调用）。
- 因此 401 真凶在「门户/Token 链路」，不在 cookie/SameSite/nginx：① `PORTAL_BASE_URL` 在 Java 环境未配/配错 → fail-closed 全 401（最可疑）；② 门户 `getTokenUser` 不返回 200+data.uid/account；③ iframe 与门户跨域致 `window.parent.getToken` 不可访问（或门户未暴露 getToken）→ 前端发不出 Token 头。
- 排查：服务器 `cat /proc/<pid>/environ|tr '\0' '\n'|grep PORTAL_BASE_URL` 与 `grep '^PORTAL_BASE_URL=' /home/mvbt/mvgo/backend-node/.env.production`；浏览器 console `typeof window.parent.getToken`、Network 看 `/api/*` 是否带 `Token` 请求头。
- 重要：`curl` 直打 `/api/auth/current` 返回 401 是「无 Token 头」的正确行为，不证明 bug；须由浏览器带 Token 头复测。Mongo 500 仅影响密码登录 `/api/auth/login` 及 Mongo 类接口，与门户扫码 401 链路正交，仍建议补 authSource=admin 修掉。

## 401 真因更正：Java 连 Mongo 鉴权失败（authSource 缺失）（09:03）
- `curl 127.0.0.1:8080/api/auth/login` 返回 **500**：`Exception authenticating MongoCredential{mechanism=SCRAM-SHA-1, userName='root', source='langgraph-server'}`。
- 根因：Java 的 `MONGODB_URI` 缺 `authSource=admin`，Mongo Java 驱动把 URI 路径里的 `langgraph-server` 当作**认证库**（默认 source=path DB），而 `root` 账号定义在 `admin` 库 → 认证抛异常 → 登录 500 → 没下发 session cookie → 后续 `/api/auth/current` 返回 401。整条 401 链是 Mongo 鉴权的下游表现，与 cookie/session/nginx 无关（浏览器 F12 那步可跳过）。
- Java 读配置：`mvgo-app/src/main/resources/application.yml:52` `uri: ${MONGODB_URI:mongodb://mongo:27017/langgraph-server}`；启动脚本 `backend-java/deploy-java.sh:12,43` 从 `/home/mvbt/mvgo/backend-node/.env.production` 提取 `MONGODB_URI` 注入。即**改 `.env.production` 的 MONGODB_URI 并带正确 env 重启 Java** 才是持久解法。

## 多变量声明漏提取 → 误判「模板引用未声明变量」（15:38 修复）
- **现象**：max 微码 mc-max-1786948073490-f02bb912 代码生成最终语义门禁失败——`package/index.vue: 模板引用了 script 中未声明的变量/组件（theme）`。但产物 script 明明合法声明了 `let attrs = {}, publishEvent = () => {}, theme = 'light';`。

- **结果**：构建 0 error，dist 含修复（grep=1），Node 重启 PID 9118。
- **教训**：语义门禁的「提取器」和「模型输出」都要正确——提取器漏提取会误杀合法产物。此类 fail-closed 先核对产物 script 是否真缺声明，再判断是模型漏写还是提取器 bug。
