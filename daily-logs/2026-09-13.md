## var() 透传破坏 lighten() 颜色函数（第五次「LESS lighten 无法求值」，快照源已生效）
- **现象**：生成跳预览报 `[LESS 编译失败] HeaderSection.vue:123 Error evaluating function 'lighten': Argument cannot be evaluated to a color`，刷新后消失。报错 URL 是 `code-snapshots/r-c7c3b9e8`——**证明上一轮 data.data 修复已生效、前端正确走快照源了**。
- **根因**：`lighten(@colorPrimary, 30%)` 里的 `@colorPrimary` 被定义成 `var(--colorPrimary, #409EFF)`（var() 透传）。LESS 的 `lighten()/darken()/fade()` 是**编译期颜色函数**，需要可求值颜色（#/rgba），不接受 CSS 运行时 `var()`。var() 透传来源两处（上一轮为治 M5-10 硬编码颜色引入）：
  1. `less-variable-checker.js` `addMissingVariables` 优先级 1（从 theme mixin 复制颜色 → var() 透传）
  2. `file-writer.js` `safeLessVarValue` 颜色型返回 `var(--colorXxx, fallback)`
- **治本（回退 var() 透传，颜色变量用真实颜色）**：两处均改回真实颜色（`#409EFF` 等）。主题切换本就该靠 `.theme-light()/.theme-dark()` mixin 提供不同真实颜色（编译期生成），而非 CSS 运行时 var()。**var() 与 LESS 颜色函数根本冲突**：var() 是运行时 CSS 变量、lighten 是编译期运算。
- **权衡**：回退后 M5-10「硬编码颜色」可能重新 warning（变量定义里的 #409EFF），但 warning ≪ lighten() 导致的 BLOCK（组件预览失败）。M5-10 应靠「样式里禁写死 #fff、用 @变量」规范约束，而非 var() 透传。
- **验证**：less-variable-checker.spec 4/4；build exit=0；后端重启 PID 36282（git=f6171b3）。
- **遗留观察**：`file-writer.js` 的 `healSlotHexToVarRefs`（① 槽位 hex→var）与 `healPresetLiteralDecls`（② 预设字面量声明→var）是 THEME 门禁自愈，**同样可能破坏 lighten()**——本次 HeaderSection.vue 无 var(-- 痕迹（未触发），但属同族风险，若再报 lighten 错误需审视这两个。

## M5-10 硬编码颜色：根因 + 治本 + 治标（2026-09-13）
### 根因
- M5-10 是 `skills/frontend-mc-check`（spec v1.0.20）的 warning 检查：扫 `resources/styles/*.less`（**排除 themes/**）+ `.vue` `<style>` 块，行内有 hex/rgb 且不含 `var(--` → 报硬编码颜色。`var(--x, fallback)` 被豁免。
