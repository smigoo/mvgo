## 组件拆分 Java 后端（对齐 Node，无 MySQL）
- 目标：组件拆分接口用 Java 实现（非 Node），且**不使用 MySQL**，与 Node 后端统一数据库方案（Node 用 MongoDB）。
- 落地：Spring Boot 3.2.5 多模块 `com.mvgo`。`application.yml` 排除 `DataSource/JPA` 自动配置 → 无 DB 也能裸启（当前解析/打包功能不需 DB）。MongoDB 接入配置已留占位（dev/prod profile 注释 `data.mongodb.uri`），与 Node 共用。
- 关键点（Java 解析真实需求文档「江苏高速」docx）：
  - 文档用 Word 自动编号，一级标题 `Heading 1`(outlineLvl=0) 顺序计数 = 4.项目功能需求描述 / 6.业务组件梳理；编号不在文本内。
  - `DocxSplitUtil` 重写为按 outlineLvl 切分章节（count 序号 key + 关键词别名 "4"/"6"）；第六章组件为 `Heading 2` 标题「名称（编码）」，其下 `Heading 3` 为字段。额外生成「字段：值」合成文本块，复用 `pickField`。
  - **致命 bug 已修**：`pickField` 正则 `(?m)^\s*LABEL\s*[:：]\s*(.+)$` 中冒号后 `\s*` 会吞换行符，导致空值字段（组件样式）跨行抓到下一行（关联功能点）。改为 `(?m)^\s*LABEL\s*[:：][ \t]*(.*)$`。
  - UC 编码为字母数字型（UC_R_ZBGK_ZLGK），`UC_PATTERN` 改为 `UC[_-]?[A-Z0-9]+(?:[_-][A-Z0-9]+)*`。
- 验证：analyze 真实文档返回 6 组件（code/name/status/funcDesc/relatedUc 正确，style 对无样式描述的组件为空）；build 返回 zip（组件MD 已嵌入第四章用例内容 + 交付说明 + 原材料）。
- 前端接线已完成：vite proxy `/api/component-split`(→8080) 排在 `/api/component` 前；components.vue docx-html 模式 DEV 开关 + analyze/build 调用；`http.download` 下载 zip。
- 运行：`JAVA_HOME=/opt/homebrew/Cellar/openjdk/23.0.2/... /bin/java -jar mvgo-app/target/mvgo-app-1.0.0-SNAPSHOT.jar --server.port=8080`（沙箱注入 SERVER__PORT=0 须用 --server.port 覆盖）。真实 payload 在 `/tmp/split-payload.json`。
