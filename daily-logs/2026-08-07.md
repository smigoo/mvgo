## 16:02 门户 iframe Token 鉴权集成方案
- **场景**：生产环境 `https://go.microvideo.cn/portlet` 通过 iframe 嵌套 mvgo frontend，QS 系统在父页面 `window.getToken()` / 缓存提供 token
- **当前机制**：frontend 已从 `window.parent.getToken()` 取 token 并注入请求头 `Token`；后端 `SessionGuard` 优先 session，无 session 则用 header token 调 `AuthService.findOrCreateByPortalToken` 建 session
- **根因**：`backend-node/.env.production` 未配置 `PORTAL_TOKEN_VERIFY_URL`，导致 portal token 校验 fail-closed，后端返回 401，前端路由守卫重定向到 `/login`，所以 iframe 显示登录页

## 17:01 鉴权会话机制澄清（用户问"删了 token 为什么没登出"）
- 根因：鉴权是**会话优先**，不是 token 优先。`SessionGuard`（session.guard.ts:16-19）只要 `request.session.userId` 存在且未过期(8h) 直接 `return true`，**根本不读 header 里的 token**。删 dev-config 的 `getToken`（现为空串）只影响"无会话时的兜底路径"，已建立的会话仍放行。
- session 存储：`main.ts:39-50` 的 `session()` **未配 store** → 默认 MemoryStore（进程内存）。故**重启后端会清空所有会话**（强制全员登出）；生产不推荐 MemoryStore（内存泄漏/多实例不共享）。
- 登出三路径：① UI 退出按钮 `AppHeader.vue:266` 调 `POST /api/auth/logout` → `session.destroy()`（已实装可用）；② 浏览器 DevTools 删 `connect.sid` cookie；③ 重启后端；④ 等 8h `tokenExpiresAt` 过期。
- ⚠️ 隐患：`SessionGuard` 会话路径只判 `session.userId` 真值 + 未过期，**不回 DB 校验用户是否仍存在**。即使从 MongoDB 删掉 `dev-local` 用户，守卫仍放行直到会话过期。生产要做"删号即失效"需在会话路径加载并校验用户存在性（可选修复）。
