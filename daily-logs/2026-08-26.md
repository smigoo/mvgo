## 预览 page「未找到组件」根因修复（loadVue3Runtime.js）

### 现象
`Error: 未找到组件：page-f4a390d917d6（已尝试 default-group）`，发生在 `loadVue3FromWorkspace` 的探测失败（line 451 throw）。后端端点本身正常（`curl ?exists=1` 返回 `{"exists":true}`，无 token 也 200）。

### 根因（与具体 page ID 无关，之前 page-9ed58e52a041 只修了 URL 没修判定，浏览器里其实一直没好）
- 预览端点 `preview.controller.ts:servePageFile` 用 `@Res()` 返回 **raw** `res.json({exists})`，**不走**全局信封。
- `loadVue3Runtime.js` 的 vue3-pages 分支（dev + prod）却用 `http.get(...)` 后判 `data?.data?.exists`。`http.get`（`core/http.js`）只做 `response.json()` 直返、不解包信封，于是 `data = {exists:true}`，`data?.data?.exists` 恒 undefined → 探测失败。
- 普通 vue3 分支用 `fetch(...).json()` 后判 `data.exists`（正确），vue3-pages 分支抄错成 `data?.data?.exists`。

### 修复
- `frontend/src/utils/loadVue3Runtime.js`：dev vue3-pages 分支（~line 412）与 prod 分支（~line 380）的探测判定由 `data?.data?.exists` 改为 `data?.exists`，与普通 vue3 分支对齐。
- 无需改后端、无需重启（前端 dev HMR 已热更，刷新即生效）。

### 验证
- Vite transform `loadVue3Runtime.js` 200 无语法错误；grep 确认 `data?.data?.exists` 已无残留，两处均 `data?.exists`。
