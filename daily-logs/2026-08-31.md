## 追加：`Cannot read properties of undefined (reading 'error')` 根因溯源（完整取证）

### 决定性证据：4 条完整堆栈（server.log L924/L947/L1227/L1790）

### 三层根因

**L1 直接触发点**：`code-parser.js` 的 `parseCodeOutput(rawOutput, logger)` 修复前把可能为 undefined 的 `logger` 直接透传给 `parseCodeOutputInner`，后者 catch 块里 `logger.error('解析代码输出失败', …)` → TypeError。

**L2 最恶劣之处：错误覆盖（error masking）**
TypeError 抛在 **catch 块内部** → 真实错误被永久丢弃。日志实证：
```

12:58:00.347Z ✅ LLM 调用完成（耗时 7.0秒）
12:58:00.348Z ❌ declare.json LLM 生成失败 {"error":"Cannot read properties of undefined (reading 'error')"}
```
**LLM 明明成功了**，真实原因（JSON 缺 files 字段 / 分隔符不匹配 / 输出截断）被吞掉，用户永远只看到这句无意义的话。

**L3 为什么「反复」：架构模式缺陷 + 反馈链断裂**
- `logger.error(` 在 `src` 共 **236 处**，其中 **126 处是裸 `logger.error(`（函数参数形态、无任何兜底）**，遍布 30+ 文件（graph-phase2 24 处、graph-vue3 17 处、figma-connector 10 处、microcode/file-writer 4 处…）。
- catch 块是**最容易踩**的位置：异常态下对象完整性最没保障，却要在里面访问可选对象的方法。
- 因原始错误被掩盖，前几轮只能「修一个点」→ 换个调用点又复现 → 用户感觉反复。

### 修复与验证
- `code-parser.js:32-38` 加 safeLogger（no-op 兜底 info/warn/error）
- `code-generator.js:803` 改 `parseCodeOutput(content, options.logger || console)`
- **时间线佐证**：错误最晚 `2026-08-30T23:46:40Z`（北京 08-31 07:46）；src 修复 08-31 10:41；dist 重建 08-31 12:00 → 之后 **0 次**。
- 运行时探针（直接 import `dist/.../code-parser.js`）：
  - `logger=undefined` → 未抛错（修复前必炸）
  - `logger 缺 error 方法` → 未抛错
  - 正常 files 输出 → 正常解析

### 结论
单点已修好；**结构性风险仍在**（126 处裸 logger.error）。治本方向：统一 `safeLogger()` 工厂 + 全面替换，属较大面改动，待授权。

### SlideDSL 关键坑（本 converter `slidep` 0.4.4-alpha，必记）
1. **`Slide` 的 padding 必须用独立数字属性**：`paddingTop={20} paddingBottom={20} paddingLeft={64} paddingRight={64}`，**不能**用 `padding={{top:20,...}}` 对象（触发 `we.split is not a function` JSX 解析崩）。
