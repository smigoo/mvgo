## P0：并行分析节点 `(intermediate value) is not iterable`（已修复并重启后端）
- 现象：设备监测 `mc-max-1787899980310-de514317` 在 Figma 第 4/7 步「并行分析」1ms 内失败；日志出现「任务已失败」后 20 秒仍打印 layout-reviewer/style-mapper 的 LLM 完成日志。
- 根因：`orchestrator.js:201` 的 `withTimeout(fn, ms, options)` 契约是**入参为函数、返回一个 `timed(state)` 异步函数**，必须再调用一次才得到 Promise。`mc-component-graph-phase2.js:2606` 误写成 `await withTimeout(Promise.all([...]), TIMEOUT, '字符串')`：
  1. 传入 Promise 而非函数，包装器内 `fn(nextState)` 从未被调用，超时/取消 signal 完全失效；
  2. `await` 一个函数会原样返回该函数 → 解构函数 → `TypeError: (intermediate value) is not iterable`，节点瞬间失败；
  3. 两个 IIFE 作为实参已被提前求值，LLM 请求在后台空转到结束（claude-opus 17.5s + 21.6s，token 全废）。
- 修复：改为 `(nextState) => Promise.all([...])` 传函数 + `{ nodeName:'parallel-analysis', onProgress }` 作为第三参，再 `const [reviewResult, styleMappings] = await runParallelAnalysis(state)`；内部统一改用 `nextState.signal`（超时/取消可真正中止在途请求）。对齐 visual-parser(693)/adversarial-checker(1339) 的既有正确写法。
- 验证：`node --input-type=module --check` 语法通过；grep 确认 `runParallelAnalysis` 定义 1 处(2616)+调用 1 处(2661)；全仓 grep `await withTimeout(`/`withTimeout( Promise` 无其他误用（vue3 图 379/798 及 phase2 693/1339 均正确，`demo.service.ts:195` 是同名类方法）；增量构建通过，dist 已同步；detached 重启（旧 PID 36836 → 新 PID 43419），Nest started。
- 教训：`withTimeout` 是「高阶函数」不是「Promise 包装器」——`await withTimeout(...)` 一律是错的，必须 `const run = withTimeout(fn,...); await run(state)`。同时避免在函数实参里放 IIFE 副作用（会提前执行且脱离超时控制）。

## 竖排文字识别：无硬编码实现（新建 utils/text-trait-detector.js）
- 需求：Figma 竖向排版文字（导航「监控」「交通诱导」等）转代码时被平铺成横排。根因是 **Figma 数据没有「竖排」显式标记**——characters 是连续字符串，竖排靠「文本框宽度受限 + 自动换行」实现。
- 关键发现（实测 mc-max-1787912301033 的 50 个 TEXT 节点）：
  - `style.textAutoResize` 与排版方向**完全对应**：`HEIGHT`（宽度固定、高度自适应 → 会换行）6 个全是竖排；`WIDTH_AND_HEIGHT`（宽高都自适应 → 单行横排）44 个全是横排，零例外。
  - 但 `HEIGHT` 不等于竖排（段落也是 HEIGHT），需再用**字体度量**判断宽度是否只够放一个字。
- 实现（无硬编码，全部由节点自身数据推导）：
  1. `textAutoResize === 'WIDTH_AND_HEIGHT'` → 直接判横排；`!== 'HEIGHT'` → 非宽度受限，横排。
  2. 单字宽由 fontSize 推算：全角（CJK/中文标点/假名）≈ 1em，半角（拉丁/数字）≈ 0.55em。
  3. 实测宽 / 单字宽 = 可容纳字数，> singleColumnFactor(默认 1.5) → 判为横排换行而非竖排。
  4. 字数 < 2 → 无方向可言。
  5. 所有阈值集中在 `DEFAULT_TRAIT_CONFIG`，**支持调用方注入覆盖**，逻辑里不散落魔数。
- 可扩展：`TEXT_TRAIT_DETECTORS` 注册表，新增文本特征（旋转/截断/字间距）只加一项，不动调用方。
- 验证：真实数据 6 竖排全检出（容纳≈1.07~1.21 字）、44 横排零误判；字号 10/14/20/32 自适应正确；段落(w=200，容纳14.29字)正确判横排；拉丁文竖排正确；单字不判；调紧容差 1.1 生效。
- 状态：模块已建并验证，**尚未接入生成链路**（检测→传 prompt→兜底补 writing-mode 三层均未接）。
