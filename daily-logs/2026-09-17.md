## 09:40 根源定位：视觉分析「字段不一致」是臆造的总根源

**三个根源（按影响排序）**：

**根源1（核心）：layout.sections 字段不一致——body.children vs body.items 未归一化**
- vision 的 schema 规定 section.body 用 `children`（vision-agent.js:713-722）
- 但 vision 模型对「设备类型统计卡片」section 输出了 `body.items`（违反 schema，含完整的 icon/label/value/bgPlaceholder 数据）
- 实测（mc-1789607082363-b36a1f3b）：header/switch/@antd/tab 用 body.children（layoutSource=inline-row），「设备类型统计卡片」用 body.items（layoutSource 空）
- prompt 铁律（layout-iron-rules）只说 `sections[].body.children[]` → LLM 忽略 items 里的数据 → 设备卡片细节丢失
- `_rebuildLayoutFromFigma`（visual-parser.js:1708-1732）用 body.children；`figma-height-ratio.js:68` 注释已暴露「vision 缓存实测用 items」

**根源2：icon/bg 节点被「无语义名」过滤**
- `_isNonSemanticName`（visual-parser.js:1762）把 "icon"/"bg"/"Frame"/"Group" 等节点名判定为「无语义名」
- 导致 header 的 icon 节点（Figma 2:8856，16×16 FRAME）不被识别为 icon，name 变成 figmaNodeId「2:8856」
- LLM 不知道它是 icon → 脑补成 icon-group（circle-outer/inner/path）+ divider

**根源3：bg 挂载语义缺失**（已修 prompt：resource-handling-guide.md 加「bg 挂父元素禁止独立 bg 子元素」）

**结论**：大模型在「事实完整处」尊重事实（switch/tab 结构对）；在「事实残缺处」（items 被忽略 + icon 无名）只能脑补 → 臆造。治本 = 字段归一化 + icon 识别，不是继续约束 LLM。
