## 模型优先级治本修复（#271，mc-max-1787798769157 失败根因）
### 现象日志
- index.vue 模板分块选中 p1786895670427_b5a4(deepseek-v4-pro) / legacy-text(deepseek-v4-flash)，各 290s+ 超时/空串，重试仍选同款，最终"空串输出已重试 2 次"失败（10:46→11:00）。
### 根因链（全部代码实证）
1. **同域双 provider 假切换**：deepseek-v4-pro 与 flash 同一 API key + 同一 host，切 provider 等于没切，仍撞同一后端。
2. **weighted-spread 均匀权重（10/10/10）**：无任何优先级，慢/挂 provider 与快 provider 等概率。
3. **60s 冷却 vs 290s 请求**：超时记录 60s 过期，空串重试时坏 provider 重新入选。
4. **空串不记熔断失败**：只 recordTimeout(60s)，永不熔断 → deepseek 反复被选。
5. **熔断默认 cooldown 仅 30s**：open 后 30s 恢复又被选。
6. 僵尸请求：180s 判超时后底层 HTTP 未中断，292s 后返回空串被当"成功"→ 空串重试与超时重试叠加（建议项，未深改）。
### 修复（provider-pool.js / microcode-engineer.js / ai-defaults.js）
- timeoutMemoryMs 60s→180s（冷却盖过 290s 长请求）。
- `_pickFrom` 同故障域排除：excludeIds 命中 provider 的 baseURL host 一并排除。
- `_weightedPick` 动态权重 = baseWeight × 健康系数(0.3+0.7×成功率) × 延迟系数(p90: ≤15s=1 / 30s=0.4 / 60s=0.15 / 120s+=0.05)，下限 0.05；降权日志 60s 节流。
- 空串：recordTimeout + breaker.recordFailure（2 次空串→熔断 open）。
- 熔断默认 cooldownMs 30s→120s（ai-defaults.js breakerCfg 兜底）。
### 验证
- scripts/verify-provider-priority.mjs 新建：11 断言全过（同域排除 60/60 落 gpt55；deepseek 权重 0.15 vs gpt55 10，300 次 pick 97% 落快模型；冷却 180s；空串熔断 open）。
