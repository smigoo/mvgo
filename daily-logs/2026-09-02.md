### 4.3 zsh 对 `--include=*.js` 报 `no matches found`（新，连续踩 2 次）

```bash

```

**根因**：zsh 默认 `NOMATCH`，未加引号的 `*.js` 会被当成 glob 在当前目录展开，
无匹配就**直接报错并中止整条命令**（不是 grep 返回空，是命令没跑）。

**解法**：① 加引号 `--include="*.js"`；② 或直接用 Grep 工具（推荐）。

> 与既有「BSD grep 不支持 `\|`」是同一类坑：**macOS/zsh 下命令行工具的静默/非静默失败，
> 都极易被误读成"文件里没有"。返回空时先怀疑命令本身。**

## 7. 🔴 P0 回归：`logger` 裸引用丢 `this` → 整个 Node 进程崩溃（我引入，已修）

### 7.1 现象

用户跑生成时后端 500，`curl /api` → HTTP 000，`lsof -ti:13030` 空（**进程已崩**）。

```
TypeError: Cannot read properties of undefined (reading 'log')
    at warn (dist/ai-engine/logger/logger.js:265)      ← this.log('warn', ...)
    at saveCheckpoint (dist/ai-engine/utils/save-checkpoint.js:78)
    at Object.saveCheckpoint [as _saveCheckpoint] (dist/.../mc-component-graph-phase2.js:4269)
    at Object.handler (dist/.../mc-component-graph-phase2.js:586)  ← state._saveCheckpoint?.('figma', ...)
```

### 7.2 根因（P2 收编引入的回归）

收编时我写成：

```js
const warn = logger && typeof logger.warn === 'function' ? logger.warn : null;   // ❌ 裸引用
```

取出的是**方法引用**，`warn(...)` 调用时 `this === undefined`；而真实 logger
（`ai-engine/logger/logger.js`）内部是 `this.log('warn', message, meta)` → 崩。
原实现是 `logger.warn(...)` 直接调用，**this 天然绑定**。

**修复**：包一层箭头函数：

```js
const warn = logger && typeof logger.warn === 'function'
  ? (...args) => logger.warn(...args) : null;
```

### 7.3 ⭐ 最该记住的教训：mock 太干净 → 测试假通过

**9 个用例全绿，首次真实生成即崩溃。** 因为测试里的 logger 是
`{ info: jest.fn(), warn: jest.fn() }` —— 普通对象方法**不依赖 this**，
裸引用照样能调通。**这是比"没写测试"更危险的假通过**。

**守则**：对"会被抽取成变量传递的回调/方法"，测试替身必须**复现真实实现的
this 依赖**（用类实例，内部 `this.log(...)`），否则测试无效。

反向验证已做：撤销修复 → 2 个新用例失败，报错与生产崩溃**逐字一致**。

### 7.4 排雷结论（全项目扫描）

| 形态 | 风险 | 数量 |
|---|---|---|
| `typeof logger.x === 'function' ? logger.x : null` | ❌ **丢 this** | 3 处（已全修：save-checkpoint ×2 + chunk-snapshot-pusher ×1） |
| `const { warn } = logger` | ❌ 丢 this | 0 处 |
| `logger?.warn?.(...)` | ✅ 安全（可选链调用保留 this） | 多处，无需改 |

> **坑中坑**：排雷用 `grep "typeof logger\.(warn|info) ... \1"` 反向引用 `\1`
> 在 ripgrep（Rust regex）**不支持** → 静默 0 结果，差点漏掉。改 `\?(warn|info)` 才命中。
