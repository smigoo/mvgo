## Vue3 生成组件报 `bg1 already declared` 根因分析

### 现象
- 前端 `loadVue3Runtime.js` 先 GET `.../package/index.vue` → **404（良性）**，回退到 `.../index.vue` 加载。
- 加载 `index.vue` 时报 `SyntaxError: [vue/compiler-sfc] Identifier 'bg1' has already been declared`。

### 404 是真因吗？
不是。`loadVue3Runtime.js:87` 的 `entryCandidates = ['package/index.vue','index.vue']` 会先探测 `package/` 子目录（该组件实际没有，文件在 session 根 `index.vue`），404 后回退成功。与崩溃无关。

### 真因：生成的 index.vue 把同一批资源 import 了两次
实测 `frontend/workspace/vue3-components/6a51f7c…/mv-1785586632303-4313bfdb/index.vue` 的 `<script setup>` 里有两个 import 块：
- 块A (60-67 行)：`import bg1 from '../resources/images/bg-126.png'` …（无注释，LLM 手写）
- 块B (71-81 行)：`// 引入背景图资源` + `import bg1 from './../resources/images/bg-126.png'` …（带注释）
两者都声明 bg1/bg2/bg3/icon1…icon5 → 撞名 → 编译器报错。

### 机理（共享后处理器无去重）
- `Vue3Engineer extends MicrocodeEngineer`（`vue3-engineer.js:22`），复用 `injectResourceImports`（`microcode-engineer.js:4374`）。
- 该后处理器扫描代码里用到的 `bg*/icon*/img*` 变量，在 `<script setup>` 之后**无条件硬插** `import ${var} from '...'`，**完全不检查变量是否已声明**。
- 同时 prompt（`vue3-engineer.js:115-122`）告诉 LLM「禁止手写 import，系统会注入」，但 LLM 仍自己写了 import 块 → 系统注入 + LLM 手写 = 重复声明。
- 注意：注入器的 `resourceRelBase='./resources/images/'`，而磁盘文件两块的路径是 `../resources` 与 `./../resources`，**均不含 `./resources/images/`**，说明本次磁盘文件疑似未经注入器处理（注入可能未落到最终 flatten 后的 index.vue，或条件 `codeResult.files['package/index.vue']` 未命中）。需进一步确认注入是否真正生效。

### 修复方向（✅ 已实施）
1. **改 `injectResourceImports`（`microcode-engineer.js:4447` 起）变幂等**：在生成 import 块后、注入前，先对 `usedVars` 中每个变量用正则剔除 LLM 手写的同名 import（默认导入 `import v from '...'` 整行删；命名导入 `import { a, v, b }` 仅剔除 v，整组都是资源变量则整行删），再插入唯一规范块。修复后单测：原损坏 index.vue 经处理后 `import bg1/bg2/icon1` 均只剩 1 次，总 import 行 9（8 资源 + 1 vue）。
2. 该函数被 Vue3 与微码共用（extends），去重是纯改进、对微码无副作用。
3. **已同步 dist 并重启**：`cp src/ai-engine/roles/microcode-engineer.js dist/...` → `bash .start-server.sh`，:13030 正常监听，日志无 SyntaxError。
4. 现存损坏组件 `mv-1785586632303-4313bfdb/index.vue` 仍在磁盘，需重新触发一次该组件生成（新逻辑会产出正确单份 import）即可覆盖。

## 🛡️ 资源 import 去重「无条件保险」（2026-08-01 续）

### 触发背景
- 用户再次贴出**完全相同**的 `bg1 already declared` 报错（同一组件 `mv-1785586632303-4313bfdb`）。
- 暴露落差：`injectResourceImports` 去重（上条）**只在 `resourceDomMapping` 非空时运行**；若为空（LLM 自己写了完整 import 且注入器压根不触发），旧损坏文件仍原样写盘 → 再次预览崩溃。

### 加固方案（✅ 已实施）
- 在 `vue3-engineer.js` 的 `execute()` 中、`writeFiles` **之前**、无论 `resourceDomMapping` 是否为空，对所有 `.vue` 文件跑一道**无条件去重**：
  ```js
  for (const filePath of Object.keys(codeResult.files)) {
    if (!filePath.endsWith('.vue')) continue
    const dedupRes = this.dedupImportsByLocalName(codeResult.files[filePath])
    if (dedupRes.modified) { codeResult.files[filePath] = dedupRes.code; logger.warn(...) }
  }
  ```
- 新增类方法 `dedupImportsByLocalName(code)`：
  - 逐 `<script>/<script setup>` 块，对 `import Name from '...'`（默认导入）按**本地名**去重，同名只保留首个声明。
  - 依据：同一模块作用域内不可存在两个同名默认导入（重复声明本身是 JS 语法错误），保留首个永远安全正确。
  - 不动命名导入 `import { a } from`，避免误删合法同名跨模块引用。
- 单测（复刻逻辑跑坏文件）：bg1/bg2/bg3/icon1 各从 2 次→1 次，输出 `modified:true` 且结构正确。

## 🐛 demo/index.vue 修复 DataCloneError（postMessage 抛错）

### 现象
`demo` 组件详情页控制台报 `Uncaught (in promise) DataCloneError: Failed to execute 'postMessage' on 'Window': [object Object] could not be cloned`，栈指向 `sendStyleToPreview`（`demo/index.vue:658`）。

### 根因（✅ 已实证）
- `sendStyleToPreview` 把 `styles.value.cssVars` 直接 `postMessage`。`styles` 是 `ref({})`，`styles.value.cssVars` 是 **Vue 响应式 Proxy**。
- `postMessage` 走结构化克隆，**结构化克隆会拒绝 Proxy 包裹的对象本身**——即使 Proxy 内的值全都是纯字符串，`structuredClone({type, cssVars: reactiveProxy})` 也抛 `#<Object> could not be cloned`（node 实测），与浏览器报错 `[object Object] could not be cloned` 完全一致。
- 数据侧排查：扫描 frontend/backend-node 全部 `declare.json`，`cssVariableConfig` 非基础类型值只有 `value: undefined`（共 22 项，且 `getStyleConfig` 已 `if (item.value===undefined) return` 跳过），`cssVars` 主题字段全是基础类型 → **声明数据里并没有对象值**，排除"声明混入对象"假设。根因就是 Proxy 本身。

### 修复（✅ 已实施 + 已实证）
- `sendStyleToPreview` 发消息前，用 `Object.entries(raw)` 把 `cssVars` 收敛为**只含 string/number/boolean 的纯对象**（同时丢弃对象/函数等非克隆值兜底），并给 `postMessage` 包 `try/catch`。
- 实证：对 reactive proxy 跑该收敛逻辑后 `isProxy? false`，`structuredClone` 成功 ✅。
- 语义正确：CSS 自定义属性本质都是字符串，非基础类型值对预览无意义，直接丢弃；预览端（`preview/index.vue:382` 的 `apply-css-vars` 监听）收到的全是合法值。
- dev transform `demo/index.vue` 返回 200，无编译错误。

### 经验
- ⚠️ Vue 响应式数据（ref/reactive 的 Proxy）**绝对不能**直接传给 `postMessage` / `structuredClone` / `IndexedDB` / `worker.postMessage`：结构化克隆会拒绝 Proxy 本身（即便内部全为字符串也炸）。跨 iframe/worker 通信前必须 `Object.entries`/浅拷贝成纯字面量对象，或 `JSON.parse(JSON.stringify())`（按需求）。

## Vue3 接口对接生成代码变量名非法字符 bug（00:09）

### 现象
Vue3 组件对接接口后报错：
```

const __res_slot-3 = await flowApi.getTodayFlow()
```

### 根因
`backend-node/src/vue3/api-binding.service.ts:442-444` 生成 onMounted 代码时直接用 `slot.slotId`（值形如 `slot-3`，含减号）拼变量名 `__res_${slot.slotId}` → `__res_slot-3`。JS 标识符不允许含 `-`（被解析为减法），所以 `const __res_slot-3 = ...` 被解析成 `const __res_slot - 3 = ...` → 报 "Missing initializer in const declaration"。

### 修复
`api-binding.service.ts` 生成变量名时把 slotId 中的非法字符替换为下划线：
```ts
const resVar = `__res_${slot.slotId.replace(/[^a-zA-Z0-9_]/g, '_')}`;
```
生成的代码变成 `const __res_slot_3 = ...`，合法。注释和文件名里的 `slot-3` 保持不变。

### 影响范围
- 只影响**新生成**的对接代码。
- 已经生成报错的 `package/index.vue` 需要：① 手动把 `__res_slot-3` 改成 `__res_slot_3`（4 处），或 ② 重新点一次「对接接口」触发 `removeInjectedCode` 清旧代码再重新注入。
