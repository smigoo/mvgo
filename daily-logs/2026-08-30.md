## 组件预览大面积失败：Identifier directly after number (17:129)

用户报「组件加载失败…为什么突然都不能预览了」。

### 根因：LLM 把 CSS 类名前缀当成 JS 变量名用（双重 bug）
```html
<!-- 错误：类名前缀被当变量 -->
:class="{ active: c-mc-max-1788056145870-6e65dc88-c-env-monitor-chartType === 'bar' }"
<!-- 正确 -->
:class="{ active: chartType === 'bar' }"
```
1. **语法崩溃**：`c-mc-max-1788056145870-6e65dc88-…` 被 JS 解析为算术表达式 `c - mc - max - 1788056145870 - 6e65dc88 …`，其中哈希段 **`6e65dc88`** 被扫描成科学计数法数字 `6e65` + identifier `dc88` → "Identifier directly after number"。
2. **静默错误（更危险）**：key 含连字符时必须方括号访问，LLM 不会。`legendState.c-monitor-beijing` 恒为 `undefined`，应写 `legendState['c-monitor-beijing']`。

### 为什么"突然"：**依赖组件哈希首字符的随机性**
- 哈希以**数字**开头（`6e65dc88`/`0d77fb56`/`6921ec8a`）→ `6e65` 触发解析错误 → **直接崩溃**
- 哈希以**字母**开头（如 `a1b2c3d4`）→ 被当普通 identifier → **不崩，但语义仍错**（静默）

### 影响面（脚本实测，非推测）
- 714 个 .vue 扫描 → **32 个文件**存在「类名前缀当变量」写法
- 其中仅 **5 个文件**触发语法级崩溃（4 个真实组件 + 1 个 .cleanup 备份副本）：
  - `mc-1787844352169-0d77fb56`：HourlyBridgeFlow.vue / HourlyTunnelFlow.vue
  - `mc-max-1787923891329-6921ec8a`：FlowPrediction.vue
  - `mc-max-1788056145870-6e65dc88`：HeaderControls.vue（+ .cleanup 副本）
- 其余 **27 个属静默错误**：能渲染但图例/激活态永远不生效

### 排查方法（可复用，比肉眼有效）
1. 先排除服务与改动：端口存活 + `find src -newermt` 确认 src 未变 + dist 构建时间 → 排除"改坏了"
2. LESS 排查：用 `frontend/node_modules/less`(4.2.2) 批量 render 所有 `resources/styles/*.less`（脚本 /tmp/lesscheck.js），实测 347 文件 69 失败**全是老组件历史问题**，新组件通过 → 排除样式
3. JS 表达式排查：正则抽 template 的 `:class/:style/v-if/@click/{{}}` 值，逐个 `new vm.Script()` 只验语法（不执行，避免 ReferenceError 干扰），捕获 `Identifier directly after number|Invalid or unexpected token` → 精确定位 5 个文件

### 待办（未执行，等用户确认）

## 【可复用】后处理器错误注入的溯源方法（本轮新建，比肉眼有效 10 倍）

判断「产物里某段代码是 LLM 写的还是后处理器注入的」+ 「是哪个注入器」：

1. **比对 chunk 原始输出 vs 落盘产物**
   - `.mc-gen/cache/code-chunks/{N}-{path}` 是 LLM 流式原始输出（按 chunk 序号 + 路径命名）
   - `chunk-meta.json` 的 `files` 字段给出「最终产物路径 → 最终 chunk 文件」的映射
   - 在 code-chunks 里 grep 目标符号（如 `bg2`）：**命中 = LLM 写的；不命中 = 后处理器注入**
2. **用注入风格指纹反查注入器**
   每个注入器有固定代码模板，grep 源码即可定位：
   - `_injectBgStyleBinding`(`microcode-engineer.js:9209`) → `backgroundImage: 'url(' + bg2 + ')'` 字符串拼接 + `backgroundSize: '100% 100%'`（无 backgroundPosition）
   - N3 bg→父容器强制挂载(`10862-10999`) → `` backgroundImage: `url(${bg2})` `` 模板字符串 + `backgroundSize: '295px 27px'`（figmaBox 实际尺寸）+ backgroundPosition
   - `_mountSubStateBackground`(`9409`) → `:style="cond ? {...} : null"` 条件式
3. **server.log 时间线定序**（决定性证据）
   `grep -n "<componentId>" backend-node/server.log` 后按时间戳读，能看到完整的后处理调用序列（孤儿剔除 → 背景兜底挂载 → T07 校验 → 落盘），直接读出 `keyword:'(root-fallback)'` 这类降级标记。
4. **离线复现兜底链**：把目标函数的实体原样搬到 `/tmp/sim_*.js`，喂真实 chunk 内容跑一遍，看降级路径实际落到哪个标签。（本轮用此法证明「模拟落到 EnvTabBar，实际落到 base-panel」→ 反推出还有一层时序因素）
   - 注意：模拟结果与产物不一致时，说明**注入发生在文件集合的某个中间状态**（如孤儿组件删除前/后），此时必须以 server.log 为准。

## ⚠️ 纠正：BSD grep 不支持 `\|` 交替（此前误记为「大文件检索失败」）

**此前记录（错误）**：「本环境 shell `grep` 对 dist 大文件检索会静默返回空，核实符号一律用 Grep 工具」。

**实测真相**（2026-08-30 15:4x 验证）：
```bash
grep -n  "ps-page\|1080px" index.vue    # exit=1，静默无输出  ← BSD grep 不认 \|
grep -nE "ps-page|1080px"  index.vue    # exit=0，正常输出 3 行
grep -c  "ps-page"         index.vue    # 2，单模式完全正常
```
- macOS 自带 **BSD grep**，`\|` 是 **GNU BRE 的扩展语法**，BSD 版不支持 → 匹配失败 → exit 1 且**无任何报错**，极易被误读成"文件里没有 / 文件太大读不动"。
- 与文件大小**无关**，src 下的小文件同样会中招。
- 正解：交替一律用 `grep -E "a|b"`（或 `egrep`）；也可拆成多次单模式 grep。
- 排查守则：shell grep 意外返回空时，**先换 `grep -E` 或拆单模式复验**，再考虑换 Grep 工具，别直接下"工具坏了"的结论。

## 17:2x 微码字体 em 化（微前端整组件等比缩放）落地

**需求**：后期每个微码组件有独立 URL 供微前端引用，宿主平台可整体改 font-size → 实际改组件根的 font-size，故**组件内全体 font-size 必须用 em**，默认视图须与原 px 设计稿像素级一致（还原不变）。

**关键技术决策**
- **用 em 而非 rem**：rem 相对文档根 html，多组件互相耦合；em 相对组件根 wrapper，每组件独立缩放 → 正解。
- **宿主覆盖机制**：组件根 `font-size: var(--fontSize, 12px)`（平台已向组件根注入 `--fontSize`，12px 为设计稿基准兜底），宿主覆写该组件根 `--fontSize` 即整体缩放。
- **默认基准 12px**（用户贴 html{font-size:12px}）；**作用范围**仅新生成组件，存量 184 不动。
- **保真要点**：默认根 12px 时 em 比例=原 px 比例，渲染像素一致；em 父级相对会复利，故 prompt 要求中间容器不自带 font-size（用 inherit），仅叶节点带 em。

**改动（backend-node/src/ai-engine/roles/microcode-engineer.js，全部 `this.componentType !== 'vue3'` 隔离）**
1. `_buildCommonLessChunkPrompt`（~3952）：注入 `fontScaleBlock`（微码专用）——根 font-size:var(--fontSize,12px)、全 em、禁 px、Npx→(N/12)em、容器用 inherit。
2. `_buildThemeVarsChunkPrompt`（3829 内联）：微码 `.common()` 须定义 `@fontSize: 12px;` 令牌。
3. `validateAndFixGeneratedFiles` 新增 1.52 块（~8921）：① 根容器 `.c-xxx-root` font-size 统一为 `var(--fontSize, 12px)`（先清旧 px 再注入）；② 其余 `font-size: Npx` → `(N/12)em`（去尾零，12→1em/14→1.1667em/16→1.3333em）；已 em 不重复处理。
