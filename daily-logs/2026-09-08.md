## Runtime latest snapshot 404 系统性分析（doc: docs/runtime-latest-snapshot-404-analysis.md）
- 问题：ensureLatestSnapshot() 用路径段 componentId 打 latest 端点 404（RUNTIME-007）
- 已回溯两轮历史修复：F3 前端(dc9d566, 09-01) + M1-1 后端(resolveSnapshotSessionId, 09-03)
- 核心发现：URL 路径段 :componentId 承载 4 种语义（sessionId A 类/componentId(c-xxx) B 类/ObjectId C 类/pageId D 类）
  - C 类(ObjectId)和 D 类(pageId) ensureLatestSnapshot 无差别发起请求 → 必 404
  - 后端 M1-1 可反查 B 类但不能反查 C 类——getTaskByComponentId 只在 task.componentId 字段匹配，ObjectId 不是业务 componentId
- 策略矛盾 4 项：getPreviewUrl 契约劈叉(后端静态 URL vs 前端路由)、resolvePreviewDescriptor fallback 链模糊、F3/M1-1 双层保险在 ObjectId 都失效、ensureLatestSnapshot 无差别请求与 ?exists=1 探测惯例相悖
- 输出方案文档 docs/runtime-latest-snapshot-404-analysis.md，含 4 个方案组合：A 启发式跳过(硬编码 ObjectId/pageId 格式)+B Set 缓存(会话级免除)+C URL 来源声明 query 参(标准化根治)+D 组合推荐
