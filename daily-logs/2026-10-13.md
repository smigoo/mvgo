## demo 画布缩放换 CSS zoom（frontend c48878c）——修「自适应打开看不到组件」
- **现象**：Playground 预览打开（自适应），画布上只有 ~25px 窄白条、组件不可见；选 100% 才恢复。
- **定位**：截图决定性线索 = 左下角画布徽标（canvas-badge 定位于画布右下角）**紧贴窄白条** ⇒ 画布本身被压成 ~25px。「100% 正常（s=1 无 transform 无负 margin）、自适应异常（s<1 走 hack）」精确指向 `transform:scale + 负 margin + flex 居中` 组合（ed0bcbb 引入）。

- **修法**：canvasStyle 改用 **CSS zoom**（布局尺寸真实变化；Chrome/Edge 全支持、Firefox 126+ 标准化）：flex 居中天然正确、无负 margin、badge/手柄自然定位；wrapper 宽度与 canvas 无关 ⇒ autoFitScale 无反馈循环；composable 的 scaleFactor 换算继续有效。TaskDetail 是显式 zoomBox 尺寸包裹的另一结构、无此问题，未动。
- **验证**：探针 68 → **69 项全绿**（新增「必须用 zoom、禁止负 margin hack」判据）；注入缺陷（退回 transform+负margin）2 项判据精确报错；vue-tsc 116；build:safe 23.59s。
- 🔴 **教训**：ed0bcbb 引入 transform+负margin 时探针/类型/构建全绿就当完成——**CSS 布局组合（flex/overflow/transform 交互）的正确性静态检查覆盖不了，必须真机渲染验证或让用户截图确认**。「静态全绿」≠「渲染正确」，与「类型检查通过≠逻辑正确」同属一类。

## 补齐 demo 预览高度链（frontend cbdc116）—— zoom 反馈循环「由大到小最后消失」
- **现象**：刷新后预览「由大到小的动画，最后看不到组件」——这是 **fit 缩放的反馈循环**在收敛。
- 🔴 **根因：c48878c 换 zoom 的副作用 + 高度链两处缺口**：
  1. zoom 让 canvas 布局高 = 1080×zoom 真实参与布局（这正是换 zoom 的目的，但引入了新的耦合）
  2. 缺口①：`.preview-wrapper` flex column 子项缺 `min-height:0`（默认 min-height:auto ⇒ 内容撑破 flex 分配）
  3. 缺口②：主链 `.ant-tabs-content(height:100%)` 里**没有 tabpane 规则**（只有 5684 拆分视图分支有）⇒ pane 高 = 内容高 ⇒ wrapper 的 flex:1 无基准
  4. 循环：zoom 小 → canvas 矮 → wrapper 矮 → updateAutoFitScale 读到更小 clientHeight → fit 更小 → …→ 0。用户看到的「动画」就是收敛过程。
- **为何 transform 时代无循环**：transform 不改布局 ⇒ canvas 布局高恒 1080 ⇒ wrapper 高恒定。zoom 把「布局参与」变成真的，缺口就爆了。
- **修法**：wrapper 补 `min-height:0`；主链 content 补 `display:flex + tabpane { flex:1; min-height:0; height:0 }`（对齐 5684 分支先例）。
- **验证**：探针 69 → **71 项全绿**（新增 2 项防循环判据）；注入 2 缺陷精确报错；vue-tsc 116；**SFC parse 0 错误**（吸取「探针绿但构建挂」教训，模板/CSS 改动先跑 parse 冒烟——compiler-sfc 需 pnpm 绝对路径 require）；build:safe 23.22s。
- 🔴 **教训（上轮刚说「无反馈循环」，本轮就打脸）**：c48878c 只验证了**宽度维度**就下了「无反馈循环」的全称结论。**引入「布局尺寸真实变化」类改动（zoom/显式尺寸）时，必须沿高度链逐层检查到视口根——任何一层 min-height:auto（flex 默认！）都会让内容反向影响可用空间形成回路。**「某一维无耦合」≠「无耦合」。
