## 二、根因（逐条实证）

### B. 重复解释（主因之一）
`section-main-content` 的 `elementCount=32`，而三个真实兄弟合计仅 `6+2+2=10` ——
它是**把整块内容区重新讲了一遍**的语义壳（`sourceNodeIds=[]`，无任何 Figma 归属）。
更关键的证据是**产物层**：

| 文件 | 重复内容 |
|---|---|
| `TabsSection.vue` | 完整 6 项 tab 列表（监控/照明/通风/消防/交通诱导/供配电） |
| `MainSection.vue` | **又画了一份**同一份 tab 列表 + 2 张切换卡（56302/5、1280/3）+ 3×4 设备网格 |
| `SwitchSection.vue` | 2 张切换卡（56302/5、1280/3）—— 与 MainSection 内的 summaryCards **同一份数据** |

→ 一份区域被画了两遍（tab 列表）甚至三遍（切换卡），内容量直接翻倍。

### C. 去重失效（主因之二）
`dedupeDuplicateSections`（`utils/section-tree.js:52`）两道判定都不命中：
- ① `sourceNodeIds` 单一归属：臆造壳 `sourceNodeIds=[]` → 无交集 → **跳过**
- ② `type|responsibility` 措辞兜底：`89:37` 是 `tabs`、臆造壳是 `body`（responsibility 也不同）→ **不命中**

→ 两个"讲同一区域"的 section 双双进入装配。

### A. 骨架方向错（直接症状）
`resources/styles/common.less` + `index.css`：
```less
.c-device-monitor-slot-con { display: flex; flex-direction: column; ... }
```

> ⚠️ **2026-09-14 更正（P2 阶段 Figma 真值实证）**：本节「A. 骨架方向错」的**结论是错的**。
> 读 `figma-node-data.json` / `_figma-size.json` 坐实：
> - `89:40` slot-con 407×380 → 含 switch(y475 **上**) + @antd/tab(y538 **下**) → **本就 column** ✅
> - `89:37` @antd/tab **46×317** → 含 tabs(x1475 46宽 **左**) + cons(x1518 367宽 **右**) → **row** ✅
>
> 设计稿 slot-con 本就是 column；「左 Tab 窄列 | 右内容区」的横向结构在 `@antd/tab` **内部**，
> 产物方向一直是对的。误判根因：只看 CSS 表象（slot-con 是 column）就断言「应为 row」，
> 没读 Figma bbox 与子节点坐标。**教训：判「方向错」前必先读 Figma bbox + 子节点 x/y。**
> 真问题只有 **B（重复解释）+ C（去重失效）**，已由 P1 判别力去重根治。
