## 23:05 组件 TDZ 渲染错误：runtimeBuilder 重复初始化
- 现象：mc-max-1787496397773 生成成功但预览报 `Cannot access 'runtimeBuilder' before initialization`。
- 根因：生成的 index.vue 把 runtimeBuilder 初始化写了两遍——第一遍(赋值 `runtimeBuilder = typeof $mcComponentBuilder...`)在 `let runtimeBuilder` 声明之前 → TDZ 死区错误。
- 诱因：prompt 里 runtimeBuilder 有两种矛盾写法：
  1. mc-builder.md(shared)：`const { runtimeBuilder } = window.$mcComponentBuilder({...})` 直接解构
  2. chart-standards.md / legend-interaction.md(dynamic, hasCharts)：`let runtimeBuilder = null; try { runtimeBuilder = typeof $mcComponentBuilder === 'function' ? ... : null }`
  模型在图表组件(hasCharts)同时看到两种写法 → 混淆生成两段。
- 已修复该组件：删重复段 + 合并 import(computed/onMounted/onUnmounted)。
- 治本方向：①统一 runtimeBuilder 写法(建议统一为 let+try-catch+typeof 保护的健壮版) ②加 TDZ 静态校验(sfc-semantics.js 检测"变量在声明前裸赋值")。
