# 2026-08-11 部署问题记录

## 遇到的问题

### 1. MongoDB 重复索引警告
**现象**: 启动日志显示 `Duplicate schema index on {"userId":1} for model "AiGitCredential"`

**原因**: `ai-git-credential.schema.ts` 中同时在 `@Prop({ unique: true })` 和 `Schema.index()` 中定义了相同索引

**解决**: 移除重复的索引定义，只保留一处
- 文件: `src/workspace/schemas/ai-git-credential.schema.ts`
- 文件: `src/ai-workspace/schemas/ai-git-credential.schema.ts`

### 2. 门户 token 配置缺失
**现象**: 日志显示 `PORTAL_BASE_URL/PORTAL_TOKEN_VERIFY_URL 未配置，门户 token 自动登录不可用`

**原因**: `.env` 文件没有包含门户配置，或者 PM2 重启时没有加载环境变量

**解决**: 
1. 在 `.env` 中添加配置：
   ```bash
   PORTAL_BASE_URL=https://go.microvideo.cn/portlet/api
   PORTAL_TOKEN_VERIFY_URL=https://go.microvideo.cn/portlet/api/getTokenUser
   ```
2. 重启时必须使用 `--update-env` 参数：
   ```bash
   pm2 restart backend-node --update-env
   ```

### 3. macOS AppleDouble 文件干扰
**现象**: 规范注册表加载失败，`._microcode.json: JSON 解析失败`

**原因**: macOS 在外部存储设备上创建的 `._*` 隐藏文件（AppleDouble 格式）被打包到 dist 目录

**解决**: 
```bash
find . -name "._*" -delete
pm2 restart backend-node --update-env
```

### 4. 端口占用冲突
**现象**: `Error: listen EADDRINUSE: address already in use :::13030`

**原因**: PM2 启动新进程时旧进程未完全退出

**解决**: 
```bash
pm2 stop all && pm2 delete all
pm2 start dist/main.js --name backend-node --update-env
```

### 5. 用户登录 duplicate key 错误
**现象**: 软删除用户重新登录时报 `E11000 duplicate key error: username_1`

**原因**: `upsert({ uid }, ...)` 在 uid 不存在时 insert 新记录，但 username 已存在（软删除用户）

**解决**: 修改 `auth.service.ts` 的 upsert 逻辑，先按 username 查找已有用户再更新

### 6. 预览服务 HTTP 404（组件不存在）
**现象**: 生成组件后，前端预览加载 declare.json / resources/styles/index.css / package/index.vue 全部 404，报「组件不存在」

**根因**: 路径不一致
- 发布器 (`workspace-preview-publisher.js`) 将组件写入 `backend-node/workspace/custom-components` 和 `frontend/workspace/custom-components`
- 但 preview 控制器只从 `projectRoot/workspace/custom-components` 读取
- 组件实际存在于 3 处：`backend-node/workspace/custom-components`、`temp-components/{groupId}`、`frontend/workspace/custom-components`

**解决**: 修改 `preview.controller.ts`，遍历多个候选根目录查找组件：
- `backendRoot/workspace/custom-components`（发布器主路径）
- `customComponentsDir`（旧路径 projectRoot/workspace）
- `resolveFrontendWorkspacePath()/custom-components`（前端 workspace）

vue3-components 同样遍历 3 个候选根。

### 7. nginx 预览路由缺失
**现象**: 截图服务访问 `https://go.microvideo.cn/preview/{componentId}?groupId=xxx` 返回 500

**根因**: 生产 nginx 容器 (`docker exec nginx`) 中：
- `gzxj.conf` 只监听 8888，未监听 80；无 `/preview/` 路由

**最终方案（重要）**: 截图服务实际访问的是 `/mvgo/preview/{componentId}?groupId=xxx`（带 /mvgo 前缀，来自 `MC_PREVIEW_BASE_URL=https://go.microvideo.cn/mvgo`），链路为：
1. nginx `/mvgo/` → SPA 静态文件（`root /www`，宿主机 `/home/mvbt/nginx/www/mvgo` 挂载到容器 `/www`）
2. 前端 Vue 路由 `/preview/:componentId` 渲染预览页
3. 预览页请求 `/api/preview/{groupId}/{componentId}/package/index.vue`
4. nginx `/api` → `proxy_pass http://192.168.112.1:13030/api`

gzxj.conf 需要做的修改：
```nginx
# 1. 同时监听 80 和 8888
listen 80;
listen 8888;

# 2. /preview/ 走 SPA fallback（不要重写到后端 API！组件没有 index.html）
location /preview/ {
    try_files $uri $uri/ /mvgo/index.html;
}
```

**注意**: 不要用 rewrite 把 `/preview/` 转发到 `/api/preview/.../index.html`，因为组件目录里没有 index.html（组件结构是 component.js + package/index.vue + resources/），会 404「文件不存在」。

**服务器拓扑**: 
- `go.microvideo.cn` → `47.111.3.56`（阿里云负载均衡/入口）
- 后端实际在 `47.98.216.206`（内网 192.168.112.1）
- nginx 容器：`docker exec nginx`，配置在 `/etc/nginx/vhost/gzxj.conf`
- 前端静态文件：宿主机 `/home/mvbt/nginx/www/mvgo/` → 容器 `/www/mvgo/`

**验证命令**（全部应返回 200）：
```bash
curl -s -o /dev/null -w "%{http_code}" "http://localhost/mvgo/preview/{componentId}?groupId={groupId}"
curl -s -o /dev/null -w "%{http_code}" "http://localhost:13030/api/preview/{groupId}/{componentId}/package/index.vue"
curl -s -o /dev/null -w "%{http_code}" "http://localhost/preview/{componentId}?groupId={groupId}"
```

## 部署最佳实践

1. **重启必须带参数**: `pm2 restart --update-env` 确保加载最新 `.env`
2. **清理隐藏文件**: 打包前执行 `find . -name "._*" -delete`
3. **端口冲突处理**: 先 `pm2 stop && pm2 delete` 再启动
4. **验证环境变量**: `pm2 env 0 | grep PORTAL` 确认配置已加载
5. **查看实时日志**: `pm2 logs backend-node --lines 50` 监控启动状态
6. **nginx 配置在容器内**: 修改后用 `docker cp` 复制回容器，`docker exec nginx nginx -t` 验证再 `-s reload`
7. **组件路径候选**: preview 控制器现在遍历 3 个根目录，改动后需重新打包部署
