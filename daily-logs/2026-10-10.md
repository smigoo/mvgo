## 修复「CSS 被浏览器静默截断」（三轮才找到的真凶）

**症状**：步骤条竖排、`.dot` 圆点变成父容器宽、表格不换行 —— 且**改 CSS 完全无效**（规则文本正确、语法正确、花括号平衡 113/113、无嵌套、控制字符为空）。

**🔴 真凶：单个 `<style>` 块超过约 5000 字符后，浏览器静默丢弃后续规则。**
证据链：
- `document.styleSheets[0].cssRules.length` = **50**，而源文件实际有 **109 条**规则
- `el.matches('.steps')` 只匹配到 `*{box-sizing:border-box}` —— `.steps` 规则压根不在样式表里
- 二分截断测试：前 4000 字符 → 45 条；**5000 字符及以上 → 恒为 50 条**（再长也不增加）
- **分段测试决定性**：把 CSS 按 1200 字符切片，每片单独放进 style 标签 → 每片都能正常解析（合计 88 条）；合并成一个 style → 只剩 50 条

**修法**：按规则边界（花括号配对）把 CSS 拆成 8 块，每块 ≤1200 字符：
```
规则数 109 → 拆成 8 块（1167/1178/1195/1202/1197/1071/1165/846 字符）
每块末尾必须完整闭合 '}'（切分点在规则边界，不能切在规则中间）
```
**验证通过**：SHEETS=8 RULES=98 DISPLAY=flex DOTW=22px STEPFLEX=1 1 0px；截图确认步骤条横排、圆点、连接线、状态色全部正常；22 个模块扫描：5 个含 `.steps` 的全为 flex、表格全为 fixed。

### 🔴 方法论教训（本轮最值钱的部分）

1. **「规则文本正确 + 语法平衡 + 数值合理」≠ 规则生效**。CSS 有浏览器侧的**静默丢弃**机制，静态检查（花括号计数、正则查规则、打印 CSS 原文）**全部无法发现**。唯一可靠判据是 `getComputedStyle()` / `cssRules.length`。

2. **排查手段要分层，且必须用「运行时证据」收口**：
   - 静态检查（花括号平衡、控制字符、注释闭合）只能排除，不能证明
   - 运行时取 `cssRules.length` 与源文件规则数对比 → 立刻暴露「丢了一半」
   - `el.matches(selector)` 枚举实际匹配规则 → 直接看到「只匹配到 `*`」
   - `--dump-dom` + `document.title` 承载探针结果（比插 DOM 节点更可靠，headless 截图里浮层可能不渲染）
   - **分段隔离测试**是定位「整块被丢弃」类问题的杀手锏

3. **headless 渲染验证的价值**：`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome --headless=new --dump-dom` / `--screenshot=... --virtual-time-budget=3000` 可以直接量 computedStyle 与出图。本轮若继续靠读代码推理，会在「CSS 明明是对的」的死胡同里绕很久。

4. 之前两轮修复（px→% 误伤、媒体查询 max-width:100% 无效）都是**真问题但不是这个症状的主因**。教训：同一症状可能有多层原因，前一层修复后必须**重新渲染验证**，不能假设「改了就该好」。

### 🔴 2026-10-12【Less 原理】为什么 var() 变量不能参与运算
Less 变量 = **编译期文本替换 + 立即求值**；`var()` 的值要到浏览器运行期宿主注入才知道。Less 想算乘法时那道门还没开。
实测（`.m(){@a:var(--x)} .m(); .c{z:@a*2}`）：
```
z: @a            ✅ var(--x)          ← 原样透传，不参与运算
z: @a * 2        ❌ invalid type
z: calc(@a * 2)  ✅ calc(var(--x)*2)  ← Less 不求值，整段交浏览器
@a: 12px + *2    ✅ 24px
```
**fallback 救不了**：`var(--x, 12px)` 参与运算照样失败 —— 那个 `12px` 是 **CSS 的 fallback**（语义「运行期 `--x` 未定义时浏览器用它」），**Less 不参与那个判断**，拿不到它去算。
颜色同理：`darken(var(--x), 10%)` ❌（`Argument cannot be evaluated to a color`）。
⇒ **唯一正解：业务统一写 `calc(@fontSize * N)`**。这样 `var()` 透传（M5-6 过 + 运行期可调字号）与编译正确性**可同时满足** —— 我先前判「二者互斥」不准确。

## 修复 M5 任务卡布局 + CSS 分块最终方案（关键规则单独成块）

### 用户截图的三个红框问题
① 筛选栏右侧空白方块 ② 任务卡右侧大片空白、按钮跑到卡片底部 ③ 勾选框与缩略图错位

**根因（两个独立问题）**：
1. **`.fld` 缺 `display:inline-block`** —— 它是 `<span>`，inline 元素上 `min-width` 与 `padding` 都不生效，所以输入框塌成一条竖线
2. **`.row` 有 `flex-wrap:wrap`** —— 任务卡是「勾选 / 内容 / 操作按钮」三列 flex，宽度不足时按钮被挤到下一行，与左侧文字叠在一起

**修法**：
```css
.fld{display:inline-block; ...; white-space:nowrap; line-height:1.5}
.row{display:flex; align-items:center; gap:7px; flex-wrap:nowrap; min-width:0}
.row.wrap{flex-wrap:wrap}       /* 需要换行的地方显式加 .wrap */
.btn{...; flex:0 0 auto}       /* 按钮不被压缩 */
```
HTML 侧把原本写内联 `flex-wrap:wrap` 的 row 改成 `class="row wrap"`。

### 🔴 CSS 分块的最终正确方案（踩了 6 轮弯路）

之前误判为「单块 5000 字符上限」。实测真相是**规则条数**：
- 200 条**简单**规则能全解析（`{width:Npx}`）
- 但**真实复杂规则**单块最多约 **54 条**，第 55 条起开始丢
- 200 条简单规则通过是因为它们太简单，开销小

各种切分方案的效果（`cssRules.length` 为实测值）：
| 方案 | 块数 | 实测规则数 | 关键规则生效 |
|---|---|---|---|
| 单块 | 1 | 50–54 | ❌ 大部分丢 |
| 按字符 1200 切 | 8 | 98 | ⚠️ 部分生效（看运气） |
| 按规则数 20 切 | 6 | 92 | ⚠️ 不稳定 |
| 每块前置 `:root` | 10 | 104 | ⚠️ 仍丢 |
| **关键规则单独成块（每块 root + 1 条）** | **68** | **174** | ✅ **全部生效** |

**最终方案**：
```
骨架规则（.layout/.side/.main/.pg/.bx/.lb/.chip/.btn/.fld/.row/.steps/.step/.dot）
  → 每块 = :root + 1 条规则（完全隔离，约 36 块）
其他规则
  → 每块 = :root + 3 条规则
```
最终实测：`SHEETS=68 RULES=174 OK=22 BAD=none` —— **22 个模块全部通过**（steps/row/fld/table 四项全对）。

**关键点**：
- 每块都前置 `:root` ⇒ 变量完全自包含，不依赖解析顺序
- 骨架规则必须**单独成块** ⇒ 不能和别的规则混，否则同样丢
- 代价：文件变大（68 个 style 块），但**可靠**
