## ECS 上部署

### 1) Node 后端

```bash
cd /home/mvbt/mvgo/backend-node
# 备份旧 dist
mv dist dist.bak.$(date +%s)
# 解压新产物（覆盖 dist + package.json + package-lock.json）
tar xzf backend-node-dist-045837.tar.gz
# 部署（脚本会复用 .env.production 已有 ADMIN_STATS_KEY，不会重新生成）
export MONGODB_URI='mongodb://root:Microvideo%402026@dds-bp13ae3414783164.mongodb.rds.aliyuncs.com:3717/langgraph-server?authSource=admin'
bash deploy-cloud.sh
```

> ⚠️ `deploy-cloud.sh` 用 `cat > .env.production` 整体重建该文件，非追加。
> `JAVA_BACKEND_URL` 需为 `http://192.168.112.1:8080/api`（内网 IP + 带 /api），
> `ADMIN_STATS_KEY` 已固化在脚本里（复用已有值，不重生成）。

### 2) Java 后端

```bash
cd /home/mvbt/mvgo/backend-java
# 删掉旧 jar（deploy-java.sh 的 ls *.jar 可能误选旧包）
rm -f mvgo-app-1.0.0-SNAPSHOT.jar
# 把上传的 jar 放好（若上传到了别处，mv 过来）
# 校验完整性（必须与本地 sha256 一致，不一致 = 截断，删掉重传）
sha256sum mvgo-app-1.0.0-SNAPSHOT.jar
# 部署（会 export ADMIN_STATS_KEY 后启动，密钥与 Node 侧配对）
export ADMIN_STATS_KEY='97e3986897905aab58e74c1ee3cba03a990b2d85f99fba35'
bash deploy-java.sh
```

> ⚠️ jar 上传后用 `sha256sum` 比对，必须 = `42a360e0...8a30`，否则是传输截断，需删掉重传。

## 发布顺序（铁律）

1. 先传 Node + Java 两个产物
2. **先起 Java，确认 `:8080` 通**（`curl -s http://localhost:8080/api/health` 返 ok）
3. 再起 Node（`deploy-cloud.sh`）
4. nginx 路由若无变化则无需改动
