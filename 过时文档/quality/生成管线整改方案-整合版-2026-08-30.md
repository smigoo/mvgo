### P0-2｜修复 `v-for` 正则误报 🔴

**问题**：R2，组件三直接死因。

```javascript
// ❌ sfc-semantics.js:124 —— 源必须是「单个纯单词 + 紧跟引号」
/v-for\s*=\s*["']([^"']*?)\s+in\s+(\w+)["']/g
```

**失败样本**（`FlowPrediction.vue`）：

```html
<span v-for="(item, idx) in currentData.accuracy" :key="idx">{{ item }}</span>
```

链路：源含点号 → 正则不匹配 → `(item, idx)` 未进 `loopVars` → 同时 `:key="idx"` 被 `:117` 规则抓进 `used` → `missing=['idx']` → 拒绝产出。
对照 `v-for="tab in tabs"`（纯单词源）正常通过，**解释了为何只报 `idx` 不报 `tab`**。

**改法**：

```javascript
for (const m of templateContent.matchAll(/v-for\s*=\s*["']([^"']*?)\s+in\s+([^"']+)["']/g)) {
  const head = m[2].trim().match(/^([a-zA-Z_$][\w$]*)/)
  if (head) used.add(head[1])            // currentData.accuracy → 要求 currentData 声明
  const vars = m[1].trim().replace(/^\(/, '').replace(/\)$/, '').split(',')
    .map(s => s.trim().replace(/^\.\.\./, ''))
  for (const v of vars) if (/^[a-zA-Z_$][\w$]*$/.test(v)) loopVars.add(v)
}
```

**回归清单**（7 种形态须全部通过）：`tab in tabs` ✅ / `(item, idx) in a.b` / `item in data.list` / `(val, key) in obj` / `i in 5`（head=null 跳过）/ `item in list.slice(0,5)` / `item in filteredList()`

### P0-4｜资源 url 归属分级 + 变量计数 + 路径规范化 🔴

> ⚠️ **定性更正（2026-08-30 实施时复核实锤）**
> 原分析判定 R4 =「CODE-016/017 误报」，**不成立**。落地前回读组件一真实产物后确认：
>
> | 原判断 | 实际 | 证据 |
> |---|---|---|
> | CODE-016 是误报 | **真阳性**，且抓的正是用户反馈的 bug | `common.less:113` 给 `.c-...-chart-section` 直写 `url(../resources/images/bg-7890.png)` = 用户说的「图表区多了一个大背景」 |
> | CODE-017 是误报 | **真阳性但漏报** | 它只数到 `index.css`/`common.less` 的 2 次直写，**漏掉了真正的错误**：`index.vue` 里 `bg2`(=bg-7890) 同时挂在 `.tabs-section` + `.tabs-bg`（用户说的「tabs-section 多了一个背景，应该挂在 tabs-bg」） |
>
> 附带发现两个**真 bug**（原分析完全没覆盖）：
> 1. **路径写错**：`resources/styles/common.less` 里写 `../resources/images/…` → 实际解析成 `resources/resources/images/…`（404，背景根本不显示）。正确应为 `../images/…`；`themes/*.less` 应为 `../../images/…`。
> 2. **我们自己制造的违规**：`microcode-engineer.js` N4 整块背景兜底同样硬编码 `'../resources/images/'`，只在 `package/index.vue` 下成立，注入到 `common.less` 即错 —— 等于「我们注入 → 我们的 CODE-016 再判 BLOCK」，自相矛盾。

**改法（三项，全部已落地）**：

**① CODE-016 归属分级**（`code-structure-validator.js`）
新增 `_extractRootContainerClass` / `_scanStyleResourceUrls` / `_findEnclosingSelector`，
让每条 `url()` 带上「所属选择器」：

- 勾在**根容器**或 **LESS 变量定义行**（`@x: url(...)`，只定义不渲染） → **WARN**（合法兜底）
- 勾在**非根容器** → **BLOCK**（背景挂错容器），message 直接点名是哪个选择器

**② CODE-017 变量计数**（同文件）
由 `import bg2 from '../resources/images/bg-7890.png'` 建立 `var → file` 映射，
把三种形态合并计数：直写路径 / `url(${var})` / `:src="var"`。

**③ 路径规范化确定性修复**（`code-fix-rules.js` 新规则 `normalize-style-resource-urls`）
按目标文件所在目录推导到 `resources/images/` 的正确相对前缀，写盘前自动重写；
N4 兜底注入点同步改用 `_imagesRelPrefixFor(targetPath)`。

```javascript
// 目录 → resources/images/ 的相对前缀推导
// resources/styles/common.less          → '../images/'
// resources/styles/themes/theme-vars.less → '../../images/'
// package/index.vue                     → '../resources/images/'
```

**实测（组件一真实产物）**：

```
[BLOCK] CODE-016 @ common.less    非根容器（.c-...-chart-section）直写 bg-7890.png
[WARN ] CODE-016 @ theme-vars.less 根容器/变量定义处直写（合法兜底）
[BLOCK] CODE-017 @ index.vue       bg-7890.png 被引用 3 次（修复前只数到 2 次）
```
