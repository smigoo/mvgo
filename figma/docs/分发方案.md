# Figma节点整理辅助工具 · 公司内部分发方案

> 目标：把插件发给公司同事用。要求**有包、有文档**，且按 **客户端 / 网页 × Windows / macOS** 拆分。
> 适用范围：自包含的 Figma 节点整理插件（选区 → AI 按规范批量改名/分组/排序，纯本地 + 直连 LLM 网关）。

---

## 〇、先说结论（最关键的一条）

**Figma 网页版（浏览器 figma.com）无法直接"导入本地插件"。** 网页用户只能用**已发布到团队/组织**的插件。
所以"网页"这条路不是多发一个 zip，而是**由管理员把同一套插件文件发布到公司 Figma 团队**；同事在网页端从团队插件列表里安装即可。

因此分发矩阵如下：

| 渠道 | 给同事的包 | 同事怎么拿到 | 备注 |
|---|---|---|---|
| **客户端 · macOS** | `mv-figma-plugin-client-mac-<日期>.zip` | 解压 → Figma 桌面端导入 manifest | 默认零安装；可选双击 `start-relay-mac.command` 兜底 CORS |
| **客户端 · Windows** | `mv-figma-plugin-client-win-<日期>.zip` | 解压 → Figma 桌面端导入 manifest | 默认零安装；可选双击 `start-relay-win.bat` 兜底 CORS |
| **网页版（团队已发布）** | `mv-figma-plugin-web-<日期>.zip` | 管理员发布到团队后，同事在网页端安装 | 文件同客户端，但**靠 Figma 团队发布**而非本地导入；CORS 兜底与桌面端同理可用 |

> 三种包里的**插件本体完全相同**（纯 JS：manifest + code.js + ui.html）。差异只在：① 客户端包多带一个对应系统的"可选本地代理"启动器；② 网页包多带一份《发布到团队插件指南》。

## 一、客户端（macOS / Windows）侧载 —— 主路径

### 给同事的话（极简版）
1. 解压对应系统的 zip。
2. 打开 **Figma 桌面端**（不是浏览器）→ 菜单 **插件 → 开发 → 导入插件** → 选 `src/cursor_mcp_plugin/manifest.json`。
3. 运行插件 → 填 **AI 接口地址 / Key / 模型名** → 点「保存设置（仅存本机）」。
4. 画布选中要整理的框架 → 点「AI 全自动整理选中框架」。
5. **零 token 工具**（仅结构化整理 / 结构方案 / 结构契约）连 Key 都不用填，纯本地跑。
6. 只有保存设置报 `Failed to fetch`（网关跨域被拦）时，才双击对应启动器 + 点「连接本地代理」。

### 分系统差异
| 系统 | 解压后双击 | 说明 |
|---|---|---|
| macOS | `start-relay-mac.command` | 首次若被 Gatekeeper 拦：右键 → 打开 → 仍要打开 |
| Windows | `start-relay-win.bat` | 双击即可，窗口保持打开 |

> 默认**直连模式完全不需要**本地代理、不需要 Node、不需要开终端。代理只是网关跨域被拦时的兜底。

完整使用说明见每个包内的 `README.md`（即《Figma节点整理辅助工具 · 使用文档》）。

## 二、网页版（发布到 Figma 团队/组织）—— 给管理员

### 为什么必须发布
Figma 网页端没有"导入 manifest"入口，只能运行**已上架**的插件。要让同事在 `figma.com` 网页里用，必须先把插件发布到公司团队。

### 发布步骤（前提：公司 Figma 为付费团队/组织，且你/管理员有插件发布权限）
1. 自己先用**桌面端**导入本包 `src/cursor_mcp_plugin/manifest.json` 验证无误（必做，发布后难改）。
2. 桌面端 → 插件菜单 → 右键本插件 → **Publish（发布）**。
3. 填名称/描述/图标；确认 `manifest.json` 里 `networkAccess.allowedDomains: ["*"]`（已设置，允许连任意 LLM 网关）。
4. 提交发布。
5. 团队成员在 **Figma 网页端** → 插件菜单 → 搜「Figma节点整理辅助工具」→ 安装/运行。
6. 更新版本：重新发布，团队成员会收到更新提示。

### 网页版须知（务必转告同事）
- **必须用 `https` 的 LLM 网关**。浏览器混合内容策略会拦截非 localhost 的 `http://` 请求。
- **CORS 兜底同样可用**：网页端插件运行在同事本机浏览器里，同样能连 `ws://localhost:3055` 本机中继（localhost 不受跨域限制），由本机 Node 代发请求绕开 CORS——与桌面端是同一套机制。若网关不允许跨域：
  - 首选：改用**允许跨域的 `https` 网关**；
  - 次选：同事在自己机器上双击 `start-relay-mac.command` / `start-relay-win.bat` 起中继，再点「连接本地代理」（web 包内已带双启动器 + `ws`）。
- 唯一硬限制：**网页端无法"导入本地 dev 插件"**，所以分发方式是团队发布，而非给 zip 让同事导入。

详见包内 `PUBLISH-TEAM.md` 与 `QUICKSTART-WEB.md`。

## 三、可选本地代理（CORS 兜底，仅客户端需要）

插件沙箱**不能**启动本地进程/监听端口，所以"在插件里跑 Node"做不到。正确做法是：
- **默认**：插件 UI 直连你填的 LLM 网关，零安装。
- **兜底**：网关跨域被拦 → 你本机双击 `start-relay-mac.command` / `start-relay-win.bat`（需 Node 18+，包内已带 `ws` 免联网装），插件内点「连接本地代理」走本机转发。

端口被占：mac `PORT=3060 node socket-server.mjs`，Windows `set PORT=3060 && node socket-server.mjs`，插件里填对应端口。

## 五、打包 / 更新流程（给维护者）

```bash
cd <本插件根目录>          # 即含 pack-dist.sh 的 mvgo/figma 目录
./pack-dist.sh            # 一次性产出三个 zip 到 dist-<时间戳>/ 目录
```

脚本只挑必要文件（插件本体 + relay + ws + 文档），不会带 `.git` / 全量 `node_modules` / 构建产物。
每次发版重跑即可；同事端"开发插件"里 Remove 旧插件再重新 Import 新包（Figma 会缓存旧 manifest）。

## 六、FAQ（分发视角）

- **同事没有 Node 能用吗？** 能。默认直连模式零安装。只有网关跨域才需 Node 跑代理。
- **Mac 和 Win 插件文件一样吗？** 一样，纯 JS。区别只在可选代理的启动器后缀。
- **网页版为什么没有单独的"装包"动作？** 因为它走 Figma 团队发布，同事在网页端"安装插件"即可，无需解压文件。
- **内网网关不允许跨域怎么办？** 桌面/网页端都可在本机起本地代理兜底（双击启动器 + 点「连接本地代理」）；或在网关侧放开跨域。
- **Key 安全？** AI 设置只存在同事本机浏览器（clientStorage），换机需重填；走本地代理时 Key 不暴露在浏览器侧。
