# mvgo-figma-structure · 使用文档

> 适用对象：自己测试 / 打包发给同事使用
> 核心能力：在 Figma 里**选中一个框架 → 点一下 → 按规范批量改名、分组、排顺序**，全程不离开 Figma。

插件把设计稿里默认的图层名（`Frame 2136`、`Rectangle 8` 之类）改成看得懂的名字，按模块分组，并给图片、图标标上导出设置；整理完可以导出一份结构清单，贴给 AI 当生成代码的参考。名字、分组、导出设置会改，样式不动。同样的说明也写在插件「关于」页里；零 token 工具（仅结构化整理 / 结构方案 / 结构契约）不需要填 Key。

---

## 〇、30 秒上手（给同事的极简版）

**默认零安装：不需要 Node、不需要开终端、不需要启动任何服务。** 插件 UI 直接请求你填的 LLM 网关；mac / Windows 行为完全一致。

1. 解压 zip → Figma 桌面端「插件 → 开发 → 导入插件」→ 选 `src/cursor_mcp_plugin/manifest.json`。
2. 运行插件 → 填 **AI 接口地址 / Key / 模型名** → 点「保存设置（仅存本机）」（自动探测）。
3. 画布选中要整理的框架 → 看「当前选区」变绿 → 点 **AI 全自动整理选中框架**。
4. 等 AI 分析完（大文件约 1–3 分钟）→ 回画布刷新看新命名。
5. 只用**零 token 工具**（仅结构化整理 / 结构方案 / 结构契约 → mvgo）时，连 Key 都不用填，纯本地运行。

> 仅当保存设置报 `Failed to fetch`（网关跨域 CORS 被拦）时，才需要 §四 的可选本地代理：mac 双击 `start-relay-mac.command`、Windows 双击 `start-relay-win.bat`，再展开「⚙️ 高级设置」点「连接本地代理」。默认直连态不需要展开、不需要点任何按钮。

## 一、Zip 包里应该有什么

打包脚本 `pack-dist.sh` 会自动产出下面这份结构（直接 `./pack-dist.sh` 即可，无需手动挑；旧版单包脚本 `pack.sh` 仍保留）：

```
mvgo-figma-structure/
├── src/cursor_mcp_plugin/
│   ├── manifest.json          # 插件清单（Figma 导入用）
│   ├── code.js                # 插件主逻辑（扫描 / 执行）
│   └── ui.html                # 插件界面（AI 配置 / 连接 / 整理按钮）
├── socket-server.mjs          # 可选本地代理（WebSocket 中继 + LLM 转发）
├── start-relay-mac.command    # macOS 双击启动代理（可选）
├── start-relay-win.bat        # Windows 双击启动代理（可选）
├── package.json               # 依赖声明（ws）
├── node_modules/ws/           # 已附带，免联网安装
└── README.md                   # 本文件（zip 内为 ASCII 名，避免 Windows 乱码）
```

> 默认零安装路径**完全用不到** `socket-server.mjs` / `ws` / 两个启动器。它们只是网关跨域被拦时的可选兜底；此时本机需 Node 18+，而 `node_modules/ws` 已随包附带，无需联网 `npm install`。

## 二、环境要求

| 项目 | 要求 | 备注 |
|---|---|---|
| 操作系统 | macOS / Windows / Linux | 插件本体是纯前端 JS，两端行为一致；可选代理是纯 Node |
| Node.js | **默认不需要**；仅可选本地代理需 18+ | `node -v` 自查；低于 18 没有内置 fetch，代理会报错 |
| Figma | **桌面端**（不是网页版） | 插件「开发模式导入」需要桌面端 |
| 网络 | 能访问 LLM 接口，且**网关允许跨域** | 云端 API（DeepSeek/通义/OpenAI 等）一般已允许；内网网关若不允许 → 走 §四 可选代理。建议用 `https://` 地址，非 localhost 的 `http://` 可能被插件 iframe 混合内容策略拦 |

## 三、导入插件到 Figma

1. 打开 **Figma 桌面端**（不是浏览器里的网页版）。
2. 顶部菜单：**插件（Plugins） → 开发（Development） → 导入插件 / Import plugin from manifest…**
3. 文件选择框里，定位到 zip 解压目录中的：
   ```
   src/cursor_mcp_plugin/manifest.json
   ```
4. 导入成功后，在「开发」子菜单里就能看到 **「mvgo-figma-structure」**。

> 插件名由 `manifest.json` 的 `name` 决定，菜单里应显示 `mvgo-figma-structure`。若仍是旧名，先 **Remove 旧插件 → 重新 Import** 本包（v20261110.64），Figma 会缓存旧清单；插件 UI 底部应显示 `v20261110.64（最后更新于 2026-11-11 23:58）`。
>
> **v20261110.64 起新增柱状图确定性识别与 `@` 前缀叶子护栏**：≥6 根等宽等距窄柱 + 等距网格 + 双轴刻度自动升 `@echarts/bar`；被 AI 误命名成 `@echarts/bar` 的全屏背景叶子按几何降级回 `bg-panel` 并恢复 `PNG@2x`（见 §8.4）。
>
> **v20261110.63 起结构契约自动折叠空壳层**：单子默认名容器不再占契约行、纯装饰矢量组压成 `[icon:N 矢量 · 整体导出]`；Figma 图层面板不变，只是返喂 mvgo 的清单更浅（见 §8.3）。
>
> **v20261110.62 起界面精简**：「整理模型」与「本地代理」的按钮 / 端口都收进默认折叠的 **「⚙️ 高级设置」**，主界面只留一行蓝色直连状态。要用这两项时点开折叠区即可，配置保存 / 回填 / 事件完全不变。

> 插件清单已声明可在普通编辑模式和 **Dev Mode（开发模式 inspect 面板）** 下运行。Dev Mode 下它会出现在右侧 inspect 面板里。

## 四、可选：启动本地代理（仅网关跨域被拦时）

> **Figma 插件沙箱（mac / Windows 一样）不能启动本地进程、不能监听端口** —— 没有 `child_process` / `fs` / `net.listen`。所以「在插件里执行 `node socket-server.mjs`」字面意义做不到；正确解法已经落地为：**插件默认直连，不再需要那个进程**。

判断标准：点「保存设置」若报 `Failed to fetch` / CORS，才启用代理。三种启动方式任选其一：

| 平台 | 双击 / 命令 | 说明 |
|---|---|---|
| macOS | `start-relay-mac.command` | 首次若被 Gatekeeper 拦：**右键 → 打开 → 仍要打开**；或终端 `bash start-relay-mac.command` |
| Windows | `start-relay-win.bat` | 双击即可，窗口保持打开 |
| 任意（手动） | `node socket-server.mjs` / `./start.sh` | 需先 `cd` 到解压目录 |

看到下面输出即成功：
```
WebSocket relay listening on ws://localhost:3055
Open the mvgo-figma-structure plugin in Figma and join a channel.
```

> 保持窗口开着（Ctrl+C 停止），回插件**展开「⚙️ 高级设置」**点「连接本地代理（可选）」，状态变绿后 AI 请求改走本机转发。端口被占：mac `PORT=3060 node socket-server.mjs`，Windows `set PORT=3060 && node socket-server.mjs`，插件里填对应端口。
>
> 除绕 CORS 外，代理还有两个附带作用：不在浏览器侧暴露 Key、以及用 Node 的 HTTP/2 + 强制 IPv4 转发（部分网关 ALPN 只接受 h2，见排错 §C）。直连一切正常时无需启用。

## 五、在插件里连接 + 配置 AI

1. Figma 里 **运行插件**（开发菜单 → mvgo-figma-structure）。
2. 默认在 **「整理」** Tab。
3. **（默认可跳过）连接本地代理**：初始状态是蓝色「直连模式 · 无需启动终端」，AI 请求由插件 UI 直接发往网关。**这个「连接本地代理」按钮不是启用直连用的**，它是「切换到本机转发」的开关（连上后 `llmFetch` 改走 `http://localhost:3055/llm-proxy`），所以 v20261110.62 起与「服务端口」「整理模型」一起收进默认折叠的 **「⚙️ 高级设置」**。仅当网关跨域被拦，才按 §四 启动代理后展开高级设置点它，状态变绿「已连接本地代理」。
4. **AI 设置**（OpenAI 兼容接口），填三项：
   - **接口地址 Base URL**：以 `/v1` 这类基路径结尾，**不要**带 `/chat/completions`
     - DeepSeek：`https://api.deepseek.com/v1`
     - 通义千问：`https://dashscope.aliyuncs.com/compatible-mode/v1`
     - OpenAI：`https://api.openai.com/v1`
     - 本地网关：`http://localhost:端口/v1`（按你网关实际路径）
   - **API Key**：服务商给的密钥（密码框，不显示明文）
   - **模型名**：`deepseek-chat` / `qwen-plus` / `gpt-4o-mini` 等（纯文本对话模型）
   - **视觉模型名**（可选）：仅当你要开启「视觉定层级」时才填，填**多模态/视觉模型**，如 `qwen-vl-max` / `gpt-4o`（通义视觉版）、`glm-4v` 等。**不填则视觉模式不可用**，整理退化为纯文本改名。
   - **勾选「导出渲染图并用视觉模型定层级/顺序」**（可选）：开启后整理会**导出选中框架的渲染 PNG** 发给视觉模型，对照渲染稿定层级、顺序、成组、命名；不勾则为现有**纯文本改名**（零影响）。
   - **勾选「关闭思考模式」**（默认勾选，推荐）：部分推理/多模态模型（如 **DeepSeek V4.1 Flash**）**思考模式默认开启**，思考 token 计入 `max_tokens`，预算太小会把全部 token 花在思考上导致**正文返回为空**（插件报「AI 返回为空」）。整理任务不需要思考。v20261110.36 起插件按**模型族 / 网关**自动选择关思考方言（与 mvgo `model-config.js` 同一套路由）：deepseek / kimi / 豆包 → `thinking:{type:"disabled"}`；qwen / GLM / 混元 → `enable_thinking:false`；Gemini → `thinking:{level:"off"}`；OpenRouter 系 → `chat_template_kwargs`；未知模型不注入任何参数。若上游拒收（典型：GLM 报「该模型始终思考，不支持关闭思考；请使用 low、high 或 max」），会**自动降级到最低思考强度** `thinking:{type:"low"}` / `reasoning_effort:"low"` 并缓存生效方言（按「模型|网关」记忆，后续分段不再重复试错）；正文为空但有 `reasoning_content` 时也会自动换方言重试。⚠️ **始终思考的模型无法真正关闭，只能降到 low**。若你的模型确实需要完整思考，可取消勾选。
      - **v20261110.45 起的三点变化**：① 正文为空时**先用同一方言加预算重试一次**（`max_tokens × 3`，上限 24000）——实测部分网关会静默忽略 `thinking` / `enable_thinking`，只换方言永远救不回来，根因是思考吃光预算；② 试完所有候选仍拿不到正文时**不再把空结果当成「生效方言」缓存**（旧版会因此让后续每个分段都只返回思考内容且永不重试）；③ 每段实际使用的**方言 / 预算 / 正文与思考字数 / finish_reason / 思考 tokens** 会写进「📋 分析日志」的 **【关思考诊断】** 段，排查不必再靠猜。
      - **本地判定方言**（推荐，Key 不出本机）：`node diag-thinking.mjs <baseUrl> <apiKey> <model>`（或用 `LLM_API_KEY=sk-xxx` 避免出现在命令历史里）。它会按插件同序把每个方言真发一次，输出各方言的正文/思考字数与 finish_reason，并在末尾给出「哪个方言真能关掉思考」的结论；加 `--nostream` 可用非流式对比。
      - **v20261110.46 起：应对「网关静默忽略所有关思考参数」**。实测某网关（`enable_thinking:false` 等全部被忽略）下：模型始终思考，且**思考长度随预算与输入一起膨胀**（1234 预算→思考 3841 字；3702→13203；10722→37082，全部 `finish=length`），因此换方言、加预算都拿不到正文。新策略：① **只有思考字数为 0 才把该方言缓存为首选**（正文拿到但思考>0 不再缓存，避免后续更大分段被锁死在无效方言上）；② 一旦某次响应出现思考内容，即认定「该网关忽略关思考参数」，之后**单次请求 + 预算提到 12000**，不再逐方言试错（省掉每段 ×8 的无效请求）；③ 思考已超过 4000 字的段**跳过加预算重试**（重试只会让它想更久）；④ **剩余分片自动重切为 40 节点/段**，让小分片能在预算内思考完并输出正文。分析日志的【关思考诊断】会标出「网关忽略关思考参数」。
      - **若诊断结论是「所有方言都关不掉」**：不要继续试参数，改用下面两条（v20261110.47 已内置）。
      - **v20261110.47：实现「不要思考」的三条路**：① **提示词级软开关**：候选里新增 `/no_think`（Qwen3 官方支持，写在消息里，不受网关参数白名单限制）；只要它生效（思考字数为 0）就会被缓存为生效方言，后续分段直接复用。② **整理模型**：AI 设置里新增「整理模型（可选）」输入框，填一个**不思考的模型**（如 `qwen-plus`）即可彻底绕开思考——纯文本整理优先用它，视觉模式仍用视觉模型；这是最省时间的一招。③ **熔断**：连续 2 段拿不到正文就提前结束，不再把剩余分段跑完空等。【关思考诊断】现在还会显示**每段耗时**，便于判断时间花在哪一段。
      - **v20261110.48：关思考策略整体对齐 mvgo**（`backend-node/src/ai-engine/utils/model-config.js`、`ai-defaults.js`、`ai-request-gateway.js`）：
        - **路由顺序**改为 mvgo 同序——`/^deepseek-v4/` 名级兜底优先（→ `thinking:{type:"disabled"}`），其次模型族/网关（qwen·GLM·混元 → `enable_thinking:false`；kimi·豆包 → `thinking:{type:"disabled"}`；Gemini → `thinking:{level:"off"}`；OpenRouter/vLLM → `chat_template_kwargs`）。
        - **推理模型判定**：移植 mvgo `isReasoningModel()`（`kimi-k*`／`*thinking*`／`*reasoner*`／`qwq*`／`o1*`／`o3*`／`*reasoning*`）。**mvgo 对这类关不掉思考的模型直接弃用**（provider 标记 `skip`）；插件无法换 provider，改为在【关思考诊断】显式提示「请改用非推理模型」。想真正对**所有**模型不思考，就把「整理模型」填成非推理模型（如 `qwen-plus`）——这与 mvgo 的做法一致。
        - **确定性熔断**：空正文 + `finish_reason=length` 视为确定性故障（同 provider 必复现）→ 立即停止，不再逐个试方言，也不再空等；`reasoning_tokens>0` 记为「推理烧光输出预算」。
        - **推理模型强制 `temperature=1`**（mvgo `normalizeRequestTemperature`），否则服务端返回 400 invalid temperature。
        - **输出上限表**：移植 mvgo `MODEL_MAX_OUTPUT_TOKENS`，大预算不再超过模型真实输出上限（如 `qwen-plus` 8192、`qwen3-max` 32768）。
      - **v20261110.49：预算下限 + 熔断修正 + 确定性循环命名（v-for 不再只依赖 AI）**。
        - **每个候选都给足预算**：关思考模式下所有候选的 `max_tokens` 下限提到 **8000**。旧版只抬「最后一个候选」，导致排在前面的 `/no_think` 候选以 1054 预算起跑、思考到 3890 字被 `length` 截断——实测只差一点预算就能出正文。
        - **熔断不再过度矫正**：mvgo 熔断后能换 provider，插件不能 ⇒ 只有「**已经给到 12000 仍然 `length` + 空正文**」才判定为确定性烧预算；只要还有预算更大的候选没试，就先继续。同时删掉与候选升级重复的「就地加预算重试」，同一段请求数从最多 4 次降到 2 次。
        - **确定性循环命名（重点）**：插件在几何建组阶段，对**同规格兄弟集合**（≥3 个同类型、尺寸相近）中**仍是默认名**的成员，按视觉顺序改名 `item-<语义>-1..N`。这样即使 AI 一段正文都没产出，结构契约里也会出现 `[循环 ×N，首项即模板]`，下游就能生成 `v-for`。规则：只动默认名，AI 已给的语义名绝不覆盖；重复整理幂等。「📐 生成结构方案」会**预告**将命名的结果（如 `list-event → 确定性命名 item-event-1 … item-event-6（6 项，v-for 信号）`），结果面板新增「循环命名 N」计数。
      - **v20261110.50：分片波次并发（提速 ~2.5×）**。此前分片严格串行（`for + await`），8 段 = 8 次单段耗时相加，每段 15~60 秒 ⇒ 整理动辄几分钟。现在每波并发 **3 路**请求，8 段只需 3 波；结果仍按段序处理（日志/诊断顺序不变），「连续 2 段空正文熔断」在波与波之间生效——已发出的请求不浪费，只停止发射新波。关思考的方言缓存/忽略标记都在同步段读写，并发安全（46 项仿真含专门的并发测试）。若你的网关有限流（429），把 ui.html 顶部 `SHARD_CONCURRENCY` 调回 1 即可。
      - **v20261110.51：请求硬超时 + 单段失败不再拖死整轮 + 视觉改串行 + 进度计时（治「一直卡着」）**。
        - **每次请求 150s 硬超时**：浏览器侧用 `AbortController` 真正掐断连接，另加 `Promise.race` 兜底计时——即使运行环境没有 `AbortController` 也一定在 150s 内失败，绝不退回「永久挂起」。旧版 `llmRequest` 完全没有超时，网关「收下请求但不回包」时插件会永远停在进度条上（实测卡 5 分钟以上；本地代理侧也要等满写死的 300s 才报错）。
        - **本地代理上游超时可配置**：`socket-server.mjs` 里写死的 300s 改为环境变量 `LLM_PROXY_TIMEOUT_MS`（默认 180s，比插件的 150s 略长，保证是插件先失败）；并且**插件侧一断开就立刻取消上游请求**，不再挂着空等。
        - **单段失败不再整轮抛出**：某段超时/网络失败只记入「分析日志 + 关思考诊断」并跳过，**其余分段与确定性后处理照常完成**（旧版 `throw r.err` 会让一次抖动白扔掉整轮结果）；连续 3 段失败才停发新波；若所有分段都失败则明确报错，不再静默「完成但一条都没改」。
        - **视觉模式改回串行**（`SHARD_CONCURRENCY_VISION = 1`）：视觉模式每个分段都要重复上传同一张 base64 渲染图，实测该网关 3 路并发多模态会长时间不回包（第一波仅 9 节点却卡 5 分钟）。纯文本请求轻，仍保持 3 路并发。
        - **进度条每秒刷新「已等待 Ns」**：一眼区分「模型正在思考」和「真的卡死」。

### 6.1 视觉模式（对照渲染稿定层级 / 顺序 / 成组）

当你勾选了「导出渲染图并用视觉模型定层级/顺序」（详见 §五），整理会多执行一步：

1. 扫描时一并 **导出选中框架的渲染 PNG**（自动按宽度等比缩到 ≤900px，控制请求体体积）。
2. 把 **渲染图 + 图层树** 发给**视觉模型**。为避免一棵大树一次性返回巨型 JSON 被网关 `max_tokens` 截断（曾导致「AI 返回无法解析为 JSON（长度 3051）」），视觉模式**按顶层分区切片（每片 ≤100 节点）**：每张切片带**同一张完整渲染图**单独请求，模型只针对该片区输出 `ops`。各片结果汇总去重后得到四类操作集合。
3. 视觉模型对照渲染稿，逐片输出四类操作（纯文本模式只有 `rename`）：

   | 操作类型 | 含义 | Figma 执行方式 |
   |---|---|---|
   | `rename` | 改名（rename 既有，命名按规范） | `node.name = 新名` |
   | `reparent` | 调整父级（把节点移到目标容器下） | `target.appendChild(node)`（Figma 原生保持绝对坐标，不跳位） |
   | `reorder` | 重排序（按视觉从上到下 / 从左到右） | `parent.insertChild(index, node)` |
   | `group` | 同级多个零散节点合成新组 | `figma.group(nodes)`（保持各自绝对坐标） |
   | `delete` | 删除指定节点（隐藏节点 / 完全冗余重复的背景矩形） | `node.remove()` |

4. 插件逐条执行并**汇总计数**回显：`改名 N / 归父 M / 排序 K / 成组 G / 删除 D`，失败项单独列出。

> **自动删除隐藏节点**：整理时会先扫描选中框架内所有 `visible=false` 的节点（含其隐藏子树），统一作为 `delete` 操作删掉——你无需手动清理隐藏图层。执行结果里的「删除 D」即为此项。
> **背景整合**：提示词会识别铺满框架、位于最底层的主背景矩形并命名为 `bg`；对**完全冗余重复**的背景矩形输出 `delete` 删除冗余副本；而 `bg-glow`/`bg-panel`/`bg-card`/`bg-rising-light` 等有独立视觉角色的装饰保留并规范命名；**多个同级背景矩形会用 `group` 归拢成一个名为 `bg` 的组**（保持绝对坐标、不跳位），实现"合并成一个大 bg"。
> **图标识别**：提示词把默认名（Frame/Group/INSTANCE + 数字）且尺寸小、子节点为矢量/图形的容器判定为图标，强制命名为 `icon-<语义>`（如 icon-building / icon-alarm）；文本模式无法判断语义时退化为 `icon-<区域>-<序号>` 也**务必消除默认名**。**视觉模式**（勾选导出渲染图）因能看到渲染稿，图标/背景的语义命名最准——强烈建议整理图标/背景密集的模块时开启。
> **锁定节点自动解锁**：被锁定的节点（如某些图标实例）整理时会先解除锁定再执行改名/重组，避免"默认名图标没被处理"的假象。
5. 回画布刷新查看：层级、顺序、成组、命名是否对齐渲染稿。

> 适用场景：图层面板里一堆**默认名子层**（如 `Frame 2136637713`），想按**渲染出来的视觉结构**（标题条在上、图表居中、图标在角）重新定层级与顺序，单靠文本改名做不到——视觉模式就是为此设计。
> 注意：视觉模式需要网关有**可用的视觉模型**（如 `qwen-vl-max`），且会比纯文本模式多消耗 token（图 + 树）。若只需改名、不需要动结构，请保持**不勾选**。

### 8.1 图表 vs 静态图形（v20261110.64）

| 判据 | 结果 | 命名 |
| --- | --- | --- |
| 有坐标轴 / 图例 / 多组数据系列 | 真图表 | `@echarts/bar`、`@echarts/line` |
| **多个 ELLIPSE 带 `arc:[innerRadius>0,起角,止角]` 且起止角不同 + 中心数值 TEXT 或同级色块图例** | **真环形/饼图** | **`@echarts/pie`**，弧段容器 `series-arcs`（不导出） |
| **宽扁 VECTOR（`w/h≥6`）带 `vp:[…,C段数≥3,…]` + ≥3 条等距水平网格 + ≥4 个数字刻度** | **真折线/面积图** | **`@echarts/line`**，`series-line`（曲线）/ `axis-grid`（网格）均不导出 |
| **≥6 根等宽（w 6–40）窄高柱体、x 等距且底边对齐 + ≥3 条等距水平网格 + ≥4 个数字刻度** | **真柱状图（.64）** | **`@echarts/bar`**，`series-bar`（柱体）/ `axis-grid`（网格）均不导出 |
| 零散 VECTOR 弧线 / 光晕，单段或无数值、无等距网格 | 静态仪表 / 装饰 | `graphic-<语义>` 或 `bg-*`（内部合并为 `img-*` 并导出） |
| 与图表同级或子级的「色块 + 文字 + 数值」行 | 图例 | `legend-<语义>` → `legend-item-N` → `legend-swatch-N` |

> **刻度不是「假图表」的证据**：y/x 轴数字 TEXT 必须保留为独立节点，下游要绑定动态数据。`@echarts/*` 容器内部**一律不导出位图**（硬门禁，AI / 视觉 / 零 token 三种路径都生效）。
> 图例**不要用** `list-*/item-*`：下游会把图例当成独立列表再渲染一份，且与图表数据脱钩。结构契约里 `@echarts/*` 行尾 `[chart:pie legend:legend-xxx]`、`legend-*` 行尾 `[legend→ @echarts/pie]` 会写明关联。
> **`@echarts/*` / `@antd/*` 只命名有子节点的容器**：背景 VECTOR、色块、图标等叶子出现 `@` 前缀一律是误命名，按背景 / 静态资源实现，不要按图表库重建（见 §8.4）。


### 8.2 面板主标题 / 根级 header 的几何判定（v20261110.61）

判据按组件根绝对坐标计算，四条件**同时**满足才提升（多个命中取 y 最小、同 y 取最宽）：

| 条件 | 阈值 | 53:34075 标题带 | 反例（同一棵树里） |
| --- | --- | --- | --- |
| ① 最顶部 y | `relY ≤ 8%·H`（28.6px） | `y=10` ✅ | 「分时分布图」小标题 `y=181` ❌ |
| ② 横跨整宽 | `w ≥ 80%·W`（336px） | `394` ✅ | 标题 TEXT `64px` / 右上 icon `12px` ❌ |
| ③ 薄标题带 | `h ≤ 15%·H`（53.7px） | `32` ✅ | `bg-panel` `358px` / `section-traffic` `164px` ❌ |
| ④ 短标题文本 | 子树含 1–12 字、非纯数值 TEXT | 「交通态势」✅ | 纯矢量装饰组 ❌ |

背景 / 资源 / 图表 / 图例 / 列表前缀一律排除；`slot-con` 本身也排除。
> **y 是主排序键，但不能单独用**：只按 y 会把全屏背景、第一段内容容器也判成 header，宽/高/文本三道护栏缺一不可。

> 视觉模式推荐命名骨架（来自「重点车辆监测」类大屏参考）：`header-xxx`（标题条）→ `slot-con`（内容总槽）→ `slot-xxx`（每个内容单元）→ `icon-xxx`（角标/小图标）→ 图表内部用 `chart-*` / `tooltip-*` / `ratio-*`。可在 §五「命名规范参考」框里粘贴这套示例，AI 会严格对齐。

### 8.3 结构契约的虚拟 unwrap / 装饰叶子压行（v20261110.63）

`walkNode` 输出时五道判据**同时**满足才折叠（最多连跳 4 层）：

| 条件 | 判据 | 反例 |
| --- | --- | --- |
| ① 唯一子节点 | `visibleChildren(n).length === 1` | 有 2 个子节点的内容容器 ❌ |
| ② 默认名 | `isDefaultGraphicName`（`Frame 12` / `Group 73` / `Vector 5028`…） | `section-*` / `header` / `list-*` 等语义名 ❌ |
| ③ 无危险属性 | 无 fills / strokes / effects / exportSettings / `layoutMode`(非 NONE) / `clipsContent` / `rotation` / `opacity≠1` / `cornerRadius` | FRAME 常带 layout / clip / fills ⇒ 多数被挡 ❌ |

装饰叶子组压行：`bg-/icon-/img-/graphic-` 或默认名，子树全是纯图形叶子（≥2）、无 TEXT、无语义子容器 ⇒ 输出 `- <名字>  [icon:N 矢量 · 整体导出]`，不再逐行展开 VECTOR。**含 TEXT 的组绝不压行**（动态数值必须留在契约里），`@echarts/*` 图表容器也不压。

### 8.4 `@` 前缀叶子护栏与柱状图识别（v20261110.64）

两条确定性后处理都挂在**两条主流程**（纯文本整理 / AI·视觉 ops）上，零 token 生效、不依赖模型命名：

| 步骤 | 位置 | 判据 | 动作 |
| --- | --- | --- | --- |
| ① `demoteLeafCharts` | AI ops 之后 / `organizeGraphicContainers` 之前 | 名字 `^@(echarts\|antd)/` 且**无 children** | 全屏(≥90% W&H) + 有 fills → `bg-panel`，提回组件根 idx0、恢复 `PNG@2x`；否则 → `img-<原名>` |
| ② `promoteBarCharts` | `promoteLineCharts` 之后 / `applyAssetExports` 之前 | ≥6 根等宽(±2)、同底(±3)、x 等距(±1.8) 的窄柱 + `hasEvenGrid` + ≥4 个数字刻度 + 子树无 `@echarts/*` | 最内层容器 → `@echarts/bar`；内部 `img-*/bg-*` → `series-bar` / `axis-grid`；清全部位图导出；TEXT 保留 |

> 契约头已声明「`@` 前缀只能是有 children 的容器」：即使 Figma 里还留着历史误命名、只导契约不重跑整理，下游也会把该叶子当背景 / 静态资源，而不是重建一张 bar 图。

## 九、常见问题 / 排错

### A. 「当前选区：未检测到」
- 先在**画布里点选**节点（确保是真选中，不只是图层面板高亮），再点 **「重新捕获选区」**。
- Dev Mode 下：选中要落在画布的「选择」上，而不只是 inspect 预览。
- 若仍为空，把指示块显示的 `#id` / 「未检测到」截图反馈。

### B. 保存设置报「Failed to fetch」
- 浏览器跨域(CORS)限制：插件 UI 直连第三方 LLM 被拦；或 Base URL 用了非 localhost 的 `http://`，被插件 iframe 的混合内容策略拦。
- 优先改：换用 `https://` 的网关地址（多数云端 OpenAI 兼容网关已允许跨域）。
- 仍不行 → 按 §四 双击 `start-relay-mac.command` / `start-relay-win.bat` → 展开「⚙️ 高级设置」点「连接本地代理」→ 重新保存。
- v20261110.39 起直连只发标准 OpenAI 字段（`baseUrl` / `apiKey` 已从请求体剥离）；若报 400 且提示未知字段，贴回原始错误文本。

### C. 保存/整理报「本地代理错误 502：代理转发失败…」
- 含义：本地服务去连你填的 LLM 地址失败。运行 `socket-server.mjs` 的终端会打印 `[llm-proxy] … 转发失败 / 响应` 行，据此判断真实原因（下面列出）。
- **当前版本转发方式**：
  - **HTTPS 目标（公网/内网网关，如 `token.microvideo.cn`）**：自动改用 **HTTP/2**（`node:http2` 模块，ALPN 协商 h2）+ **强制 IPv4（`family:4`）**。两处都要修：①这类网关 ALPN 仅接受 h2，Node 旧版 `https.request` 发 HTTP/1.1 会被「收下不回包」→ 卡满超时；② **Node 20 的 `http2.connect` 不继承 `dns.setDefaultResultOrder`，不显式 `family:4` 会在你 Mac 上卡死**（诊断脚本加了 `family:4` 立刻通，实测真实 Key 返回 200）。curl 默认协商 h2 所以正常，本服务现在走同一条成功路径。
  - **HTTP 目标（`http://localhost:…` 本地网关/mock）**：仍用 Node 内置 `http` 转发，强制 IPv4（`family:4`）+ 超时，规避 macOS 双栈 IPv6 挂起。
  - **不依赖 undici**（undici 在部分 Node 构建上导入即崩溃），也不经任何外部代理。
- 终端日志对应处理：
  - 之前常见的「`request timeout (120s/300s)`」——早期是 HTTP/1.1 被网关丢弃；若加了 `family:4` 仍 504，则是出网需代理或网关抖断。换 HTTP/2 + `family:4` 后正常返回（如 `401 Invalid token` / `200` 表示连通，Key 无效属预期）。
  - `ETIMEDOUT` / `timeout` / `GOAWAY` / `closed` → H2 握手或响应在 300 秒内未完成（域名不可达 / 网络需代理 / 网关抖断）
  - `ENOTFOUND` → Base URL 域名拼错（检查是否带多余空格）
  - `ECONNREFUSED` → 目标端口未监听 / 本地网关没起
  - `CERT…` / `SSL` / `TLS` / `PROTOCOL` → TLS/ALPN 协商失败或自签证书
- 若你的网络**必须走代理**才能出网（公司内网 / Clash / Surge），当前版本直连会失败；请告知我，我再加轻量代理支持（用原生 CONNECT，不引 undici）。
- **仍报「H2 请求/会话 300s 超时」且查不出原因**：仓库根目录有 `diag-h2.mjs`，在**本机**跑 `node diag-h2.mjs <BaseURL> <真实Key> <模型名>`，它会打印 DNS 解析、TLS 探测、H2 连上(ALPN)、是否收到响应头、HTTPS_PROXY 等，据此可定位是「连不上（代理/解析）」还是「连上但不回包（网关对 Node h2 头敏感）」。把输出贴回即可。
- **查看 AI 分析 / 改名方案**：① 服务端终端会打印 `[llm-proxy] 请求: model=…` 与 `[llm-proxy] 响应: status=… | 预览: …`（含 AI 返回前 400 字，不含 API Key）；② 插件「整理」Tab 底部有「📋 分析日志」折叠区，展示 **AI 原始返回 + 解析出的改名方案 JSON**，无需看终端即可核对 AI 改了什么。
- **大文件整理卡住 / 出现 `502`**：**根因 + 已修**。早期是 HTTP/1.1 被网关丢弃（已改 H2 + `family:4`）；后来 613 节点仍 502，根因是**单次把整棵图层树（~90KB）发给推理模型，模型长链路思考超过网关上游预算（~5min）→ 网关返 502**。**当前版本已按「顶层分区」自动分段**（每段 ≤100 节点、带 `path` 祖先上下文、各自独立调用、最后汇总去重），每段都落在超时预算内，杜绝单请求超时。流式为辅（`stream:true`）、`max_tokens` 按段动态上限。若个别超大分区仍慢，可换更快模型或缩小选中范围。
- Base URL 不要带 `/chat/completions`（会自动拼）。

### F. 关闭插件清理缓存
- 关闭/退出插件时自动清理：UI 会断开本地服务 WebSocket 并通知清空**选区回退缓存**；服务端 channel 随 WebSocket 断开自动从 `channels` 移除。
- **AI 设置（Base URL / Key / 模型）属「配置」而非缓存，会保留在 clientStorage**，下次打开免重填——这是设计意图。若你希望连配置也清掉，关闭前手动清空三个输入框即可。
- 选区回退缓存是内存态，插件进程退出即销毁，无需手动清。

### D. 连接本地代理一直「连接中」/ 连不上
- 这是**可选功能**，连不上不影响直连模式（状态保持蓝色「直连模式」即可正常整理）。
- 确认已双击对应平台启动器且窗口有 `listening on ws://localhost:3055`；端口被占就改 `PORT` 环境变量，插件里填对应端口。

### E. 插件在 Dev Mode 下位置
- 插件清单已启用 Dev Mode（inspect 面板）。Dev Mode 右侧 inspect 面板里点开插件即可；普通编辑模式也从「插件 → 开发」运行。

### G. 视觉模式专属问题

- **勾了视觉但整理提示「视觉模型不可用 / 已退化为纯文本」**：说明「视觉模型名」输入框**没填**，或填的模型不是多模态（如填了 `qwen-plus` 文本版）。填一个真正支持 `image_url` 的视觉模型（如 `qwen-vl-max` / `gpt-4o` / `glm-4v`），保存后重跑。
- **视觉模式整理比纯文本慢 / token 消耗高**：正常——视觉模式要导出并发送渲染图（已自动 ≤900px 宽）。若仍超网关预算，缩小选中范围、或确认视觉模型本身响应快。
- **回显有 `归父 M / 排序 K / 成组 G` 但画布没变化**：看回显里的「失败项」。`reparent` 用 `appendChild`（Figma 保持绝对坐标）；若目标父级 `parentId` 不存在/被合并，该项会失败并单列。属 AI 给的父级 id 失真，可重跑或缩小范围。
- **导出渲染图失败（日志 `exportFramePng` catch）**：通常是选中节点类型不支持 `exportAsync`（如纯 Section 或某些特殊节点）。插件已容错——导出失败就跳过图、退化为纯文本改名，不影响主流程；若你确实需要视觉，改选一个常规 FRAME 再跑。
- **「命名规范参考」怎么填**：把你的参考图里的命名骨架（如 `header-xxx` / `slot-con` / `slot-xxx` / `icon-xxx`）整段粘进 §五 那个文本框即可，AI 改名/成组会严格对齐；留空用内置默认规范。
- **视觉/普通整理报「AI 返回为空」**：最常见是**模型思考模式默认开启**（如 **DeepSeek V4.1 Flash**）把 `max_tokens` 预算全耗在思考上、正文被挤空。✅ 解法：在 §五 勾选 **「关闭思考模式」**（默认已勾），插件按模型族发送对应关思考方言（见 §五）；若正文为空且有 `reasoning_content`，会自动换下一个方言重试。若已勾仍为空，再排查：① 该模型是否真支持图像（点「列出可用模型」看 👁 标记）；② 网关/Key 对该模型权限；③ 网络。
- **「本地代理错误 502：… 该模型始终思考，不支持关闭思考；请使用 low、high 或 max」**：这类 GLM 是**始终思考模型，不存在「关成 0」**。v.36 起按模型族分流，但 v.46 的「网关忽略参数」分支会把 low 降级跳过；**v20261110.58 起**上游一报这句就按 `model|网关` 记住，后续首选直接发 `reasoning_effort:"low"`（降低强度，不是关闭），不再逐条试必然被拒的关闭参数。⚠️ 这只能让它少想一点，**要真正零思考 + 保留视觉，请按 §5.1 换一个本来不思考的多模态模型**。**两端都要更新**：① Figma 里 Remove 旧插件 → Import `.58` 包；② 若仍用本地代理，重启 `:3055`（`socket-server.mjs` 旧版只透传 `reasoning_effort` / `thinking`，会丢掉 `enable_thinking` / `reasoning` / `chat_template_kwargs`）。只更新一端仍会失败。

- **「环形图 / 图例没被识别出来，变成了 `graphic-*` 和 `list-*`」**：见 §8.1。v20261110.59 起按 ELLIPSE 的 `arcData.innerRadius` 几何判定，与是否勾视觉分析无关（零 token 整理同样生效）。若当前 Figma 里仍是 `.58` 及更早的结果，需 **Remove 旧插件 → Import `.59` 包 → 直接重跑一次整理**（不必撤销）。
- **「折线 / 面积图没被识别，变成 `img-line` 并挂了 `PNG@2x`」**：见 §8.1。v20261110.60 起按 VECTOR 路径特征 `vp` + 等距网格 + 双轴数字刻度做三条件确定性判定（零 token 整理同样生效），并把 `@echarts/*` 内部位图导出列为硬门禁。**开视觉只能改善语义命名，不能根治**：视觉 ops 不含导出指令、零 token 契约也不经过视觉。若当前 Figma 里仍是 `.59` 及更早的结果，需 **Remove 旧插件 → Import `.60` 包 → 直接重跑一次整理**（不必撤销）。
- **「背景变成了 `@echarts/bar`，柱状图没识别（`section-03-block-03`）」**：见 §8.1 / §8.4。**v20261110.64 起**两条确定性后处理一起生效：`demoteLeafCharts` 按几何把误命名的 `@` 前缀叶子降级回 `bg-panel`/`img-*` 并恢复导出，`promoteBarCharts` 按柱体几何把最内层容器升为 `@echarts/bar`。零 token 整理同样生效，与是否勾视觉分析无关。若当前 Figma 里仍是 `.63` 及更早的结果，需 **Remove 旧插件 → Import `.64` 包 → 直接重跑一次整理**（不必撤销）。
- **「列出可用模型」查不到 / 报 404**：部分网关不开 `/v1/models` 端点，属正常；那就手动填已知视觉模型名（如 `deepseek-v4.1-flash` 本身即多模态，可直接填进「视觉模型名」）。
- **视觉模式报「AI 返回无法解析为 JSON（长度 30xx / 被截断）」**：这是旧版**整棵树一次性发给视觉模型**、要求一次性返回全部 `ops` 的巨型 JSON 撞上网关 `max_tokens` 输出上限被截断所致（不是模型问题）。✅ 新版已**按顶层分区切片（每片 ≤100 节点）**，每张切片带完整渲染图单独请求、各自返回小 JSON，彻底规避截断；若仍报「无法解析」，多为模型返回了非 JSON 散文（见上一条排查思考模式 / 模型是否真多模态）。

### H. 怎么回到直连？

**答：不用操作。未连接本地代理 = 直连模式，插件默认就是这个状态。**

- 状态栏显示蓝色「直连模式 · 无需启动终端」或「已断开本地代理 · 当前直连模式」都表示**已经在直连**，AI 请求直接发往你填的网关，不需要再点任何按钮。
- 之前连过代理时：按钮变成 **「断开代理，回到直连」**，点一下即可；点完状态栏出现「当前直连模式」就是终态。
- 想确认直连真的生效：点「保存设置（仅存本机）」或「列出可用模型」，能返回模型列表就说明直连通了；零 token 工具（仅结构化整理 / 结构方案 / 结构契约）不填 Key 也能跑，本身完全不依赖任何服务。
- ⚠️ v20261110.40 及以前：断开后按钮会被设成**蓝色主按钮**，看起来像「还要再点一次」，其实已经回直连了。v20261110.41 起代理按钮恒为次要样式，文案直接标明当前状态。
- 只有网关报 `Failed to fetch` / CORS 时才需要反过来**展开「⚙️ 高级设置」**点「连接本地代理（可选）」，见 §四。v20261110.62 起主界面看不到这个按钮是正常设计，不是功能缺失。

### I. 面板标题被收进 `slot-con`（v20261110.61）

**答：AI 把主标题改名成了 `section-title-*`，而 `.60` 及以前只按名字认 header。** `.61` 起改为按 y 几何判定（见 §8.2）：最顶整宽薄标题带会被确定性提升回 `cp-` 根直属 `header`，**直接重跑一次整理即可恢复**，不必手动改名或撤销。

- 结果里 `rootHeaderPromoted=1` = 本次从 `section-title-*` 提升成功；`rootHeaderAlready=1` = 当前树已有根级 header，属正常幂等。
- `rootHeaderNoCandidate=1` = 该组件没有符合四条件的标题带（标题在右侧 / 宽不足 80% / 无短文本），此时在 Figma 里手工把标题组命名 `header` 并拖到组件根下即可。
- 结构契约（零 token 导出）同样按几何归一化，未整理过的稿子返喂 mvgo 时也是 `cp → header / bg / slot-con` 三段式。

### J. 契约比 Figma 图层树浅 / 出现 `[icon:N]`（v20261110.63）

**答：正常，是契约层虚拟折叠，不是插件删了图层。** 满足 §8.3 五道判据的空壳容器不会出现在契约里，纯装饰矢量组压成一行 `[icon:N 矢量 · 整体导出]`；`raw` 镜像导出可以看到未折叠的原样树。

- 只有契约行数 / 缩进变浅；`loops / slots / sections`、`[data:]` / `[chart:]` / 循环折叠标注数量不变。
- 若某个语义容器被误折叠，说明它名字撞了默认名（如 `Frame 12`），在 Figma 里给它改成语义名即可。
- FRAME 仍留在 Figma 图层面板里 —— 契约层 unwrap 等价于「unframe 的文本效果」，不是真 unframe（见 §8.3）。
