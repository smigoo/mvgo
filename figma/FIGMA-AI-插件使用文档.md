# mv-figma 文件自动整理插件 · 使用文档

> 适用对象：自己测试 / 打包发给同事使用
> 核心能力：在 Figma 里**选中一个框架 → 点一下 → AI 自动按规范批量重命名、整理图层**，全程不离开 Figma。

---

## 〇、30 秒上手（给同事的极简版）

1. 装好 **Node.js 18+**（已带 `node` 命令即可）。
2. 解压 zip，终端进目录：`npm install`（zip 若已含 `node_modules` 可跳过）→ `node socket-server.mjs`。
3. Figma 桌面端 → 菜单「插件 → 开发 → 导入插件」→ 选 zip 里的 `src/cursor_mcp_plugin/manifest.json`。
4. 运行插件 → **连接服务**（端口 3055）→ 填 **AI 接口地址 / Key / 模型名** → 保存（自动探测）。
5. 画布选中要整理的框架 → 看「当前选区」变绿 → 点 **AI 全自动整理选中框架**。
6. 等 AI 分析完（大文件约 1–3 分钟）→ 回画布刷新看新命名。

---

## 一、Zip 包里应该有什么

打包脚本 `pack.sh` 会自动产出下面这份结构（直接 `./pack.sh` 即可，无需手动挑）：

```
mv-figma-plugin/
├── src/cursor_mcp_plugin/
│   ├── manifest.json          # 插件清单（Figma 导入用）
│   ├── code.js                # 插件主逻辑（扫描 / 执行）
│   └── ui.html                # 插件界面（AI 配置 / 连接 / 整理按钮）
├── socket-server.mjs          # 本地服务：WebSocket 中继 + LLM 代理（AI 整理必须）
├── package.json               # 依赖声明（ws）
├── node_modules/ws/           # 已附带，免联网安装
└── README.md                   # 本文件（zip 内为 ASCII 名，避免 Windows 乱码）
```

> 说明：`socket-server.mjs` 只依赖 `ws`，且 `node_modules/ws` 已打进包，所以**同事不需要联网 `npm install`**，只要本机有 Node 即可。

## 三、导入插件到 Figma

1. 打开 **Figma 桌面端**（不是浏览器里的网页版）。
2. 顶部菜单：**插件（Plugins） → 开发（Development） → 导入插件 / Import plugin from manifest…**
3. 文件选择框里，定位到 zip 解压目录中的：
   ```
   src/cursor_mcp_plugin/manifest.json
   ```
4. 导入成功后，在「开发」子菜单里就能看到 **「mv-figma文件自动整理插件」**。

> 插件清单已声明可在普通编辑模式和 **Dev Mode（开发模式 inspect 面板）** 下运行。Dev Mode 下它会出现在右侧 inspect 面板里。

## 四、启动本地服务（AI 整理必须）

AI 整理功能依赖一个**本地中继+代理服务** `socket-server.mjs`（原因见排错章节：浏览器跨域限制）。启动方式二选一：

```bash
# 方式 A：直接用 node
cd <zip 解压目录>
node socket-server.mjs

# 方式 B：用自带脚本（等价）
./start.sh
```

看到终端输出即成功：
```
WebSocket relay listening on ws://localhost:3055
Open the mv-figma 文件自动整理 plugin in Figma and join a channel.
```

> 保持这个终端窗口开着（Ctrl+C 停止）。每次用插件前都要先启动它。

## 五、在插件里连接 + 配置 AI

1. Figma 里 **运行插件**（开发菜单 → mv-figma文件自动整理插件）。
2. 默认在 **「整理」** Tab。
3. **连接服务**：端口填 `3055` → 点「连接服务」→ 状态变绿「已连接本地服务（AI 代理已启用）」。
4. **AI 设置**（OpenAI 兼容接口），填三项：
   - **接口地址 Base URL**：以 `/v1` 这类基路径结尾，**不要**带 `/chat/completions`
     - DeepSeek：`https://api.deepseek.com/v1`
     - 通义千问：`https://dashscope.aliyuncs.com/compatible-mode/v1`
     - OpenAI：`https://api.openai.com/v1`
     - 本地网关：`http://localhost:端口/v1`（按你网关实际路径）
   - **API Key**：服务商给的密钥（密码框，不显示明文）
   - **模型名**：`deepseek-chat` / `qwen-plus` / `gpt-4o-mini` 等（纯文本对话模型）
   - **视觉模型名**（可选）：仅当你要开启「视觉定层级」时才填，填**多模态/视觉模型**，如 `qwen-vl-max` / `gpt-4o`（通义视觉版）、`glm-4v` 等。**不填则视觉模式不可用**，整理退化为纯文本改名。
   - **勾选「导出渲染图并用视觉模型定层级/顺序」**（可选）：开启后整理会**导出选中框架的渲染 PNG** 发给视觉模型，对照渲染稿定层级、顺序、成组、命名；不勾则为现有**纯文本改名**（零影响）。
   - **勾选「关闭思考模式」**（默认勾选，推荐）：部分推理/多模态模型（如 **DeepSeek V4.1 Flash**）**思考模式默认开启**，思考 token 计入 `max_tokens`，预算太小会把全部 token 花在思考上导致**正文返回为空**（插件报「AI 返回为空」）。整理任务不需要思考，勾选后发 `reasoning_effort:"none"` 关闭它，确保返回 JSON。若你的模型确实需要思考，可取消勾选。
   - **命名规范参考**（可选文本框）：粘贴你的命名规范示例（如 `header-xxx` / `slot-con` / `slot-xxx` / `icon-xxx`），AI 改名/成组时会严格对齐。留空用内置默认规范。
   - **「列出可用模型」按钮**（可选）：点一下会查询网关 `/v1/models` 并列出所有模型，对**疑似支持视觉**的模型打 `👁` 标记（启发式，按模型名含 `vl`/`vision`/`gpt-4o`/`deepseek-v4.1-flash` 等判断），方便你确认该填哪个「视觉模型名」。无需保存设置即可用。
5. 点 **「保存设置（仅存本机）」** → 插件会发一次**真实探测请求**（用「模型名」那个文本模型）校验接口/Key/模型名：
   - 通过 → 「✅ 已保存并验证可用」
   - 不通过 → 红字报错（见排错），**不会保存**
6. 配置只存在本机浏览器（clientStorage），换机需重填。

> **两种整理模式**
> - **纯文本模式（默认，不勾视觉）**：只依赖图层树结构 + 文本，把整棵树分段发给**文本对话模型**做 `rename`。无需视觉模型，最省 token、最快。
> - **视觉模式（勾选）**：额外导出选中框架的渲染图（自动降分辨率到 ≤900px 宽，避免请求体过大重蹈 504），连同图层树 JSON 一起发给**视觉模型**，由它对照渲染稿推断**层级（reparent）/ 顺序（reorder）/ 成组（group）/ 命名（rename）** 四类操作。适用于「默认名子层需要按视觉结构重新定层级与顺序」的场景（见 §六、§八）。

## 六、整理一个框架（测试 / 实际使用）

1. 在画布里**选中要整理的框架**（选最外层 FRAME / 组 / Section；多选会自动取共同父级）。
2. 看插件里的 **「当前选区」** 指示块：
   - 绿色 = 实时选区：`节点名（类型）#id`
   - 黄色 = 缓存选区（焦点在插件 UI 时），也可用
   - 红色 = 未检测到：先回画布选中，再点 **「重新捕获选区」**
3. 确认变绿后，点 **「AI 全自动整理选中框架」**。
4. 进度条：扫描 → AI 分析（大文件约 1–3 分钟）→ 执行改名 → 完成提示。
5. 回画布**刷新 / 选中节点**查看新命名。

完成提示示例：`✅ 整理完成！扫描 1735 节点，重命名 255 个`。

### 6.1 视觉模式（对照渲染稿定层级 / 顺序 / 成组）

当你勾选了「导出渲染图并用视觉模型定层级/顺序」（详见 §五），整理会多执行一步：

1. 扫描时一并 **导出选中框架的渲染 PNG**（自动按宽度等比缩到 ≤900px，控制请求体体积）。
2. 把 **渲染图 + 图层树** 发给**视觉模型**。为避免一棵大树一次性返回巨型 JSON 被网关 `max_tokens` 截断（曾导致「AI 返回无法解析为 JSON（长度 3051）」），视觉模式**按顶层分区切片（每片 ≤100 节点）**：每张切片带**同一张完整渲染图**单独请求，模型只针对该片区输出 `ops`。各片结果汇总去重后得到四类操作集合。
3. 视觉模型对照渲染稿，逐片输出四类操作（纯文本模式只有 `rename`）：

   | 操作类型 | 含义 | Figma 执行方式 |
   |---|---|---|
   | `rename` | 改名（rename 既有，命名按规范） | `node.name = 新名` |
   | `reparent` | 调整父级（把节点移到目标容器下） | `target.appendChild(node)`（Figma 原生保持绝对坐标，不跳位） |
   | `reorder` | 重排序（按视觉从上到下 / 从左到右） | `parent.insertChild(index, node)` |
   | `group` | 同级多个零散节点合成新组 | `figma.group(nodes)`（保持各自绝对坐标） |
   | `delete` | 删除指定节点（隐藏节点 / 完全冗余重复的背景矩形） | `node.remove()` |

4. 插件逐条执行并**汇总计数**回显：`改名 N / 归父 M / 排序 K / 成组 G / 删除 D`，失败项单独列出。

> **自动删除隐藏节点**：整理时会先扫描选中框架内所有 `visible=false` 的节点（含其隐藏子树），统一作为 `delete` 操作删掉——你无需手动清理隐藏图层。执行结果里的「删除 D」即为此项。
> **背景整合**：提示词会识别铺满框架、位于最底层的主背景矩形并命名为 `bg`；对**完全冗余重复**的背景矩形输出 `delete` 删除冗余副本；而 `bg-glow`/`bg-panel`/`bg-card`/`bg-rising-light` 等有独立视觉角色的装饰保留并规范命名；**多个同级背景矩形会用 `group` 归拢成一个名为 `bg` 的组**（保持绝对坐标、不跳位），实现"合并成一个大 bg"。
> **图标识别**：提示词把默认名（Frame/Group/INSTANCE + 数字）且尺寸小、子节点为矢量/图形的容器判定为图标，强制命名为 `icon-<语义>`（如 icon-building / icon-alarm）；文本模式无法判断语义时退化为 `icon-<区域>-<序号>` 也**务必消除默认名**。**视觉模式**（勾选导出渲染图）因能看到渲染稿，图标/背景的语义命名最准——强烈建议整理图标/背景密集的模块时开启。
> **锁定节点自动解锁**：被锁定的节点（如某些图标实例）整理时会先解除锁定再执行改名/重组，避免"默认名图标没被处理"的假象。
5. 回画布刷新查看：层级、顺序、成组、命名是否对齐渲染稿。

> 适用场景：图层面板里一堆**默认名子层**（如 `Frame 2136637713`），想按**渲染出来的视觉结构**（标题条在上、图表居中、图标在角）重新定层级与顺序，单靠文本改名做不到——视觉模式就是为此设计。
> 注意：视觉模式需要网关有**可用的视觉模型**（如 `qwen-vl-max`），且会比纯文本模式多消耗 token（图 + 树）。若只需改名、不需要动结构，请保持**不勾选**。

## 八、命名规范（AI 自动遵循）

| 前缀 / 形式 | 含义 | 例子 |
|---|---|---|
| `cp-xxx` | 业务组件 | `cp-energy-overview` |
| `@echarts/类型` | 图表占位（折线/柱状/环形…） | `@echarts/折线图` |
| `bg-xxx` | 背景图 | `bg-header` |
| `img-xxx` | 内容静态图 | `img-title-bar-bg` |
| `icon-xxx` | 小图标（≤40×40） | `icon-dimming-card-sm-1` |
| `header-xxx` | 标题条容器 | `header-brightness` |
| `slot-con` | 内容槽主容器（承载多个 slot 的父） | `slot-con` |
| `slot-xxx` | 内容槽单元（卡片 / 分区 / 列表项） | `slot-key-vehicle` / `slot-chart` |
| `icon-xxx` | 小图标（≤40×40），也含角标图标 | `icon-dimming-card-sm-1` |
| `chart-*` / `tooltip-*` / `ratio-*` | 图表内部结构 | `chart-legend` / `tooltip-row-1` |

判定原则：结合父级路径与子树文本推断语义；只改有语义价值的容器；图表柱体内部的最小装饰（小 Vector/Frame）跳过；文本节点不改名；拿不准的宁可跳过。

> 视觉模式推荐命名骨架（来自「重点车辆监测」类大屏参考）：`header-xxx`（标题条）→ `slot-con`（内容总槽）→ `slot-xxx`（每个内容单元）→ `icon-xxx`（角标/小图标）→ 图表内部用 `chart-*` / `tooltip-*` / `ratio-*`。可在 §五「命名规范参考」框里粘贴这套示例，AI 会严格对齐。

## 九、常见问题 / 排错

### A. 「当前选区：未检测到」
- 先在**画布里点选**节点（确保是真选中，不只是图层面板高亮），再点 **「重新捕获选区」**。
- Dev Mode 下：选中要落在画布的「选择」上，而不只是 inspect 预览。
- 若仍为空，把指示块显示的 `#id` / 「未检测到」截图反馈。

### B. 保存设置报「Failed to fetch」
- 浏览器跨域(CORS)限制：插件 UI 直连第三方 LLM 被拦。**先「连接服务」**（本地服务会代理转发，绕开跨域），再保存/整理。

### C. 保存/整理报「本地代理错误 502：代理转发失败…」
- 含义：本地服务去连你填的 LLM 地址失败。运行 `socket-server.mjs` 的终端会打印 `[llm-proxy] … 转发失败 / 响应` 行，据此判断真实原因（下面列出）。
- **当前版本转发方式**：
  - **HTTPS 目标（公网/内网网关，如 `token.microvideo.cn`）**：自动改用 **HTTP/2**（`node:http2` 模块，ALPN 协商 h2）+ **强制 IPv4（`family:4`）**。两处都要修：①这类网关 ALPN 仅接受 h2，Node 旧版 `https.request` 发 HTTP/1.1 会被「收下不回包」→ 卡满超时；② **Node 20 的 `http2.connect` 不继承 `dns.setDefaultResultOrder`，不显式 `family:4` 会在你 Mac 上卡死**（诊断脚本加了 `family:4` 立刻通，实测真实 Key 返回 200）。curl 默认协商 h2 所以正常，本服务现在走同一条成功路径。
  - **HTTP 目标（`http://localhost:…` 本地网关/mock）**：仍用 Node 内置 `http` 转发，强制 IPv4（`family:4`）+ 超时，规避 macOS 双栈 IPv6 挂起。
  - **不依赖 undici**（undici 在部分 Node 构建上导入即崩溃），也不经任何外部代理。
- 终端日志对应处理：
  - 之前常见的「`request timeout (120s/300s)`」——早期是 HTTP/1.1 被网关丢弃；若加了 `family:4` 仍 504，则是出网需代理或网关抖断。换 HTTP/2 + `family:4` 后正常返回（如 `401 Invalid token` / `200` 表示连通，Key 无效属预期）。
  - `ETIMEDOUT` / `timeout` / `GOAWAY` / `closed` → H2 握手或响应在 300 秒内未完成（域名不可达 / 网络需代理 / 网关抖断）
  - `ENOTFOUND` → Base URL 域名拼错（检查是否带多余空格）
  - `ECONNREFUSED` → 目标端口未监听 / 本地网关没起
  - `CERT…` / `SSL` / `TLS` / `PROTOCOL` → TLS/ALPN 协商失败或自签证书
- 若你的网络**必须走代理**才能出网（公司内网 / Clash / Surge），当前版本直连会失败；请告知我，我再加轻量代理支持（用原生 CONNECT，不引 undici）。
- **仍报「H2 请求/会话 300s 超时」且查不出原因**：仓库根目录有 `diag-h2.mjs`，在**本机**跑 `node diag-h2.mjs <BaseURL> <真实Key> <模型名>`，它会打印 DNS 解析、TLS 探测、H2 连上(ALPN)、是否收到响应头、HTTPS_PROXY 等，据此可定位是「连不上（代理/解析）」还是「连上但不回包（网关对 Node h2 头敏感）」。把输出贴回即可。
- **查看 AI 分析 / 改名方案**：① 服务端终端会打印 `[llm-proxy] 请求: model=…` 与 `[llm-proxy] 响应: status=… | 预览: …`（含 AI 返回前 400 字，不含 API Key）；② 插件「整理」Tab 底部有「📋 分析日志」折叠区，展示 **AI 原始返回 + 解析出的改名方案 JSON**，无需看终端即可核对 AI 改了什么。
- **大文件整理卡住 / 出现 `502`**：**根因 + 已修**。早期是 HTTP/1.1 被网关丢弃（已改 H2 + `family:4`）；后来 613 节点仍 502，根因是**单次把整棵图层树（~90KB）发给推理模型，模型长链路思考超过网关上游预算（~5min）→ 网关返 502**。**当前版本已按「顶层分区」自动分段**（每段 ≤100 节点、带 `path` 祖先上下文、各自独立调用、最后汇总去重），每段都落在超时预算内，杜绝单请求超时。流式为辅（`stream:true`）、`max_tokens` 按段动态上限。若个别超大分区仍慢，可换更快模型或缩小选中范围。
- Base URL 不要带 `/chat/completions`（会自动拼）。

### F. 关闭插件清理缓存
- 关闭/退出插件时自动清理：UI 会断开本地服务 WebSocket 并通知清空**选区回退缓存**；服务端 channel 随 WebSocket 断开自动从 `channels` 移除。
- **AI 设置（Base URL / Key / 模型）属「配置」而非缓存，会保留在 clientStorage**，下次打开免重填——这是设计意图。若你希望连配置也清掉，关闭前手动清空三个输入框即可。
- 选区回退缓存是内存态，插件进程退出即销毁，无需手动清。

### D. 连接服务一直「连接中」/ 连不上
- 确认 `socket-server.mjs` 已启动且终端有 `listening on ws://localhost:3055`；端口被占就改 `PORT` 环境变量：`PORT=3060 node socket-server.mjs`，插件里填对应端口。

### E. 插件在 Dev Mode 下位置
- 插件清单已启用 Dev Mode（inspect 面板）。Dev Mode 右侧 inspect 面板里点开插件即可；普通编辑模式也从「插件 → 开发」运行。

### G. 视觉模式专属问题

- **勾了视觉但整理提示「视觉模型不可用 / 已退化为纯文本」**：说明「视觉模型名」输入框**没填**，或填的模型不是多模态（如填了 `qwen-plus` 文本版）。填一个真正支持 `image_url` 的视觉模型（如 `qwen-vl-max` / `gpt-4o` / `glm-4v`），保存后重跑。
- **视觉模式整理比纯文本慢 / token 消耗高**：正常——视觉模式要导出并发送渲染图（已自动 ≤900px 宽）。若仍超网关预算，缩小选中范围、或确认视觉模型本身响应快。
- **回显有 `归父 M / 排序 K / 成组 G` 但画布没变化**：看回显里的「失败项」。`reparent` 用 `appendChild`（Figma 保持绝对坐标）；若目标父级 `parentId` 不存在/被合并，该项会失败并单列。属 AI 给的父级 id 失真，可重跑或缩小范围。
- **导出渲染图失败（日志 `exportFramePng` catch）**：通常是选中节点类型不支持 `exportAsync`（如纯 Section 或某些特殊节点）。插件已容错——导出失败就跳过图、退化为纯文本改名，不影响主流程；若你确实需要视觉，改选一个常规 FRAME 再跑。
- **「命名规范参考」怎么填**：把你的参考图里的命名骨架（如 `header-xxx` / `slot-con` / `slot-xxx` / `icon-xxx`）整段粘进 §五 那个文本框即可，AI 改名/成组会严格对齐；留空用内置默认规范。
- **视觉/普通整理报「AI 返回为空」**：最常见是**模型思考模式默认开启**（如 **DeepSeek V4.1 Flash**）把 `max_tokens` 预算全耗在思考上、正文被挤空。✅ 解法：在 §五 勾选 **「关闭思考模式」**（默认已勾），插件会发 `reasoning_effort:"none"`。若已勾仍为空，再排查：① 该模型是否真支持图像（点「列出可用模型」看 👁 标记）；② 网关/Key 对该模型权限；③ 网络。
- **「列出可用模型」查不到 / 报 404**：部分网关不开 `/v1/models` 端点，属正常；那就手动填已知视觉模型名（如 `deepseek-v4.1-flash` 本身即多模态，可直接填进「视觉模型名」）。
- **视觉模式报「AI 返回无法解析为 JSON（长度 30xx / 被截断）」**：这是旧版**整棵树一次性发给视觉模型**、要求一次性返回全部 `ops` 的巨型 JSON 撞上网关 `max_tokens` 输出上限被截断所致（不是模型问题）。✅ 新版已**按顶层分区切片（每片 ≤100 节点）**，每张切片带完整渲染图单独请求、各自返回小 JSON，彻底规避截断；若仍报「无法解析」，多为模型返回了非 JSON 散文（见上一条排查思考模式 / 模型是否真多模态）。
