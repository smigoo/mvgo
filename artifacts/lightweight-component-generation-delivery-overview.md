# 轻量组件生成落地方案总览

> 项目：mvgo 组件生成平台  
> 目标：把 Figma 高保真生成之外的轻量路径落到可评审、可实现、可验收的方案  
> 适用对象：微码组件、普通 Vue3 组件  
> 核心原则：先快速得到可运行初版，再按需升级为 Max / Full

## 1. 方案结论

产品维持两个稳定维度：

- **组件类型**：`Vue3` / `微码`
- **生成档位**：`Lite` / `Max`

不要再把第二个维度也叫“类型”，否则会和组件类型混淆。

### 默认映射

| 输入来源 | 默认档位 | 说明 |
|---|---|---|
| Figma URL | Max / 可切 Lite | 信息最完整，默认推荐 Max，但允许手动切到 Lite |
| 截图 | Lite | 优先快速出初版，允许推断和占位 |
| 原型 HTML | Lite | 以结构还原为主，先保证可运行 |
| 文档 | Lite | 以业务规则和结构为主 |
| 截图 + 文档 | Lite / 可升 Max | 证据更完整，视完整度决定 |
| HTML + 资源 | Lite / 可升 Max | 资源完整、结构稳定时可升档 |

结论：**Figma 默认 Max，截图和 HTML 默认 Lite**，但不能硬绑定死。最终档位应由输入完整度、置信度和质量门禁共同决定。

## 2. 需求范围

### 2.1 目标

1. 允许用户不依赖 Figma URL，也能开始生成。
2. 支持截图、文档、截图+文档、HTML / HTML+资源 的轻量初版生成。
3. 继续保留完整 Figma 高保真路径，不影响现有主流程。
4. 同一入口支持 `Vue3` 和 `微码` 两类目标产物。
5. 支持单组件与批量任务。
6. 轻量结果可进入 Playground 继续修改，并可升级到更完整版本。
7. 结果页必须让用户清楚知道：这是 Lite、Migrated 还是 Full。

### 2.2 非目标

- Lite 阶段不追求像素级还原。
- 不承诺截图直接得到真实接口、事件和微码完整配置。
- 不把 HTML 原样塞进 Vue 模板。
- 不在轻量路径里复制一套新的 AI 调度器。
- 不让批量任务绕过配额、限流和权限控制。

## 3. 功能结构

### 3.1 输入入口

统一为一个“选择输入来源”的入口，来源包括：

1. Figma 设计稿
2. 上传 / 粘贴截图
3. 上传 / 粘贴文档
4. HTML 还原
5. 截图 + 文档

### 3.2 生成目标

所有来源最终都只落到两种目标：

- `Vue3`
- `微码`

### 3.3 结果等级

建议保留三种可见等级：

- `Lite / Draft`：快速初版，可运行，但允许推断和占位
- `Migrated`：HTML 迁移类结果，结构和样式主要来自原始 HTML
- `Full / Verified`：完整高保真结果，沿用现有 Figma 流程

## 4. 推荐原型流程

### 4.1 主入口页

原型页需要先解决“选什么”和“会生成什么”的问题。

建议页面结构：

- 顶部：组件类型切换 `Vue3 / 微码`
- 中部：输入来源卡片
- 右侧或下方：当前档位说明、默认推荐、风险提示
- 底部主按钮：
  - `快速生成初版`
  - `开始完整生成`
  - `开始还原组件`
  - `创建批量任务`

### 4.2 单组件流程

1. 选择组件类型。
2. 选择输入来源。
3. 上传截图 / 文档 / HTML，或粘贴 Figma URL。
4. 预检：文件格式、大小、资源完整性、安全扫描。
5. 生成：先走确定性解析，再走必要的 AI 补缺。
6. 结果页：展示档位、置信度、缺失项、可继续编辑入口。
7. 进入 Playground 或升级为更高档位。

### 4.3 批量流程

批量任务必须是一个批次下的多个子任务，不是循环单次接口。

批量原型需要展示：

- 总数、已完成、排队数、失败数
- 每项的输入类型、目标类型、状态、失败原因
- 支持暂停、取消剩余、仅重试失败项
- 已完成项可先下载或进入 Playground
- 后端重启或页面刷新后可恢复进度

### 4.4 HTML 还原流程

HTML 还原原型必须明确“还原”不是“照抄”。

需要展示的步骤：

1. 上传 HTML / ZIP
2. 安全扫描
3. DOM / CSS / 资源解析
4. 结构还原
5. 首屏渲染校验
6. 迁移报告
7. 输出 `Lite` 或 `Migrated` 结果

结果页要列出：

- 已还原内容
- 已降级内容
- 已清洗内容
- 需要人工补充内容
- 缺失资源列表

## 5. 原型页面清单

建议至少做 6 个页面：

| 页面 | 目的 | 关键内容 |
|---|---|---|
| 入口页 | 选择类型和来源 | Vue3/微码、输入来源卡片、档位提示 |
| 截图上传页 | 快速初版生成 | 文件预览、尺寸、提示、提交按钮 |
| 文档输入页 | 业务规则驱动生成 | 文档输入、字段识别、规则预览 |
| HTML 还原页 | 还原与清洗 | HTML/ZIP 上传、资源清单、风险提示 |
| 生成中页 | 执行态可见 | 进度、队列、可取消、失败重试 |
| 结果页 | 结果确认与升级 | 档位、预览、下载、Playground、升级入口 |

## 6. 分阶段落地

### Phase 1：Lite MVP

优先做：

- 截图 → Lite
- 文档 → Lite
- 截图 + 文档 → Lite
- 单组件生成
- 结果页 + Playground

### Phase 2：HTML 还原

补齐：

- HTML 单文件 / ZIP
- 资源清洗和迁移报告
- Migrated 状态
- HTML 与文档 / 截图融合

### Phase 3：批量与升级

补齐：

- 批量任务
- 失败重试、暂停、恢复
- Lite 升 Max / Full
- 统一质量门禁和验收

## 7. 验收标准

### 功能验收

- 用户能从截图、文档或 HTML 开始生成，不必须先填 Figma URL。
- 结果页能明确标识 `Lite / Migrated / Full`。
- `Vue3 / 微码` 目标可正确切换。
- 批量任务支持进度、失败项、恢复和重试。
- HTML 还原输出迁移报告，而不是伪装成原样复制。

### 体验验收

- 用户能看懂当前档位和可继续升级的路径。
- 生成中状态、失败状态、排队状态都清晰可见。
- 键盘可操作，焦点和状态表达可访问。
- 轻量路径不会让用户误以为已经是最终交付。

### 风险验收

- 不把推断字段当成事实字段。
- 不把 Lite 产物包装成 Full。
- 不允许 HTML 脚本、外链和危险资源直接进入运行时。
- 不让批量任务绕过限流和配额。

## 8. 需要补齐的原型重点

1. 组件类型与生成档位的区分。
2. 输入来源和默认档位的自动推荐逻辑。
3. Lite 与 Full 的文案边界。
4. HTML 迁移报告的表现方式。
5. 批量任务的恢复、重试、取消机制。
6. 结果页如何把“可运行初版”和“可交付成品”分开表达。

## 9. 当前建议

如果你要尽快推进落地，我建议按这个顺序评审：

1. 先定字段：`组件类型`、`生成档位`、`输入来源`、`目标类型`
2. 再定原型：入口页、生成中页、结果页、批量页
3. 再定阶段：Lite MVP → HTML 还原 → 批量升级
4. 最后定验收：可用性、安全、质量门禁

这份总览适合作为评审入口，详细技术实现继续放在现有的需求方案和研究方案里。
