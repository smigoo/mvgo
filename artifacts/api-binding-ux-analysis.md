# 接口对接交互分析

## 结论
当前对接功能的能力是够的，问题主要在交互模型：它把“找目录、看槽、选接口、配参数、确认绑定”全部塞进了一个全屏弹窗向导里。对于第一次使用的人，这个模型能引导；对于反复对接的人，它会制造不必要的中断和重复操作。

## 主要痛点
1. 上下文被打断
   - 从组件预览切到全屏弹窗，用户要在两个空间之间来回切。
   - 绑定完成后再回到组件，需要重新建立“我刚在处理哪个槽”的记忆。

2. 第一屏门槛太高
   - 先选 API 目录，再下一步，才能开始绑定。
   - 这一步对老用户是重复劳动，对新用户也是信息负担，因为他们往往更关心“这个槽该接哪个接口”。

3. 数据槽和 API 目录并列过重
   - 左侧槽、右侧目录、下方参数一起出现，信息密度高但决策顺序不清楚。
   - 用户需要自己判断先看哪边，界面没有给出明确的默认路径。

4. 绑定结果反馈太弱
   - 当前更像“提交一次操作”，而不是“逐个槽完成对接”。
   - 用户缺少已绑定、待处理、跳过、桩函数的清晰进度感。

5. 重复决策太多
   - 同一项目下的目录、默认匹配、常见参数可以复用，但现在每次都像重新开始。

## 更方便的对接方式
### 1. 从全屏弹窗改为“上下文内联面板”
- 在组件预览页右侧固定一个对接侧栏。
- 用户看着组件时就能直接对接，不离开当前页面。
- 只在需要“全量重做”或“高级模式”时再打开全屏。

### 2. 先给默认答案，再让用户修正
- 进入页面后直接展示推荐绑定结果。
- 默认先自动匹配一个最可能的接口，而不是先要求用户选目录、选槽、再选接口。
- 用户只处理少量例外项。

### 3. 把步骤改成“浏览 → 校正 → 提交”
- 浏览：看系统已识别的槽和推荐接口。
- 校正：只改不合理的槽、参数或跳过项。
- 提交：一次性确认并生成绑定。
- 这个顺序比“目录 → 槽 → 接口 → 参数”更符合实际操作习惯。

### 4. 让绑定状态一直可见
- 每个槽显示明确状态：未绑定、已推荐、已跳过、桩函数、已确认。
- 绑定完成后不要把结果藏进弹窗历史里，而是留在组件页上。

### 5. 复用历史选择
- 同一组件再次打开时，优先恢复上一次目录、槽选择和参数。
- 同一项目里可记住常用 API 目录和常见绑定规则。

## 推荐改造方案
### 方案 A：最小改造
- 保留弹窗。
- 把 Step 0 取消，直接进入“自动推荐绑定”页。
- 目录选择改为顶部可折叠区域。
- 这是最容易落地的一版。

### 方案 B：中等改造，推荐
- 预览页右侧加入固定对接侧栏。
- 首屏直接展示已识别的数据槽和推荐接口。
- 顶部只保留“切换目录 / 重新分析 / 提交绑定”。
- 对老用户最友好，交互成本最低。

### 方案 C：完整改造
- 组件预览页内联对接侧栏 + 左右分栏。
- 槽为主，接口目录为辅，参数只在选中槽时显示。
- 支持快捷批量接受、单槽修正、回滚快照。
- 这是长期最好的形态，但改动面最大。

## 我的判断
如果你现在要提升“好用程度”，优先做 **方案 B**。

原因很直接：
- 不改变用户当前任务流。
- 直接去掉“全屏弹窗 + 步进式确认”的摩擦。
- 最能体现“我在看组件时顺手把接口接了”的感觉。

## P0 / P1 优先级
### P0
- 去掉 Step 0 的强制目录前置。
- 打开对接时默认展示推荐绑定结果。
- 把“当前组件、当前槽、当前推荐接口”固定在同一视野内。

### P1
- 引入上次绑定结果复用。
- 参数区按选中槽懒加载。
- 支持批量接受推荐。

### P2
- 目录收藏、常用接口模板、按项目记忆默认目录。
- 更细的自动推荐权重和快捷键。

## 一句话结论
现在的问题不是“功能少”，而是“操作被弹窗和步骤切碎了”；更方便的方向是把对接从“强制流程”改成“在组件上下文里完成的校正任务”。
