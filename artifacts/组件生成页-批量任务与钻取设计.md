## Q1 · 最近任务里如何表示批量任务

**结论**：批量任务 = "1 个任务聚合 N 个组件"。不能退化成 N 行，也不能和单任务视觉割裂。采用 **2×2 缩略图网格（代表"多"）+ 聚合名 + 四色分布条 + 聚合状态胶囊**。

### 最近任务列表（含批量）ASCII 原型
```
┌──────────────────────────────────────────────────────────────────┐
│ 最近任务                                                            │
├──────────────────────────────────────────────────────────────────┤
│ ┌────┐ 批量生成 · 8 个组件                    ⬤ 6/8 完成            │  ← 批量项
│ │▦▦ │ #T-2087 · 2 分钟前                                            │
│ │▦▦ │ ▓▓▓▓▓▓▓░░░░░░░  (完成132 运行33 排队16 失败16 = 220px)        │
│ └────┘  ↑2×2网格代表"多"               ↑四色分布条   ↑聚合状态胶囊 │
├──────────────────────────────────────────────────────────────────┤
│ ▢   c-start-card                              ⬤ 完成                │  ← 单任务项(对照)
│     3 分钟前                                                         │
├──────────────────────────────────────────────────────────────────┤
│ ▢   c-modal-dialog                            ● 失败 · 重试         │  ← 单任务失败(对照)
│     12 分钟前                                                        │
└──────────────────────────────────────────────────────────────────┘
```

**关键决策**
- **不要用重叠相册堆**（Ardot `layoutMode:NONE` 不被解析器接受，且移动端不可点）。2×2 网格更稳、更可读。
- 分布条按真实比例渲染四色：完成 `#22C55E` / 运行 `#22C55E`（活跃，可加呼吸）/ 排队 `#F59E0B` / 失败 `#EF4444`。
- 聚合胶囊文字随状态变：`运行中` / `6/8 完成` / `部分失败(1)`。
- 点击批量项 → 进入状态三（批量运行总览）或"批量任务详情页"；点击单任务项 → 进入状态二/四（单组件详情）。

## Q2 · 生成中的代码框只有一点小吗？

**结论**：当前状态二右侧**只有进度条 + 四阶段 + 日志终端，根本没有代码预览区**——这是设计缺口。对"代码生成产品"，生成中应以**实时代码流为主体**，而不是角落小框。

**正确做法**：生成中右侧分三层——
1. **顶部 sticky 小结**（始终可见）：组件名 + 状态胶囊 + 迷你进度条（72%）
2. **中部 实时代码区（主体，占 ~60% 高度）**：语法高亮、可滚动、自动滚到底、带闪烁光标 `▍`；代码**随生成从少量行增长到占满面板**（开始时确实少，但它是主区域不是小框）
3. **底部 执行日志（可折叠）**：复用状态二的终端样式

### 生成中详情（含实时代码）ASCII 原型
```
左侧(置灰锁定)                    右侧(生成中详情)
┌────────────┐  ┌──────────────────────────────────────────────┐
│ 生成配置   │  │ ← 返回总览   批量任务 #T-2087 › c-chart-ring   │
│ (半透明锁定)│  │ 状态:生成中   ▓▓▓▓▓▓▓▓▓▓▓░░░  72%              │
│            │  ├──────────────────────────────────────────────┤
│ [Vue3]微码 │  │ /* 实时代码流 · 语法高亮 · 自动滚动到底 */      │
│ 🖼 已识别… │  │ <template>                                    │
│ Lite  Max  │  │   <div class="ring-chart">                    │
│ c-chart…   │  │     <svg viewBox="0 0 100 100">               │
│            │  │       <circle ... />                          │
│ [生成中…]  │  │     </svg>                                    │
│ 取消       │  │   </div>                                      │
│            │  │ </template>                                   │
│            │  │ <script setup lang="ts">                      │
│            │  │   const props = defineProps<{                 │
│            │  │     value: number                             │
│            │  │   }>()                                        │
│            │  │   ▍  ← 光标闪烁，行数持续增长                  │
│            │  │   (此区域占满面板，绝非"一点小")               │
│            │  ├──────────────────────────────────────────────┤
│            │  │ 📜 执行日志 (点击折叠)  [12:04:31] 生成 index… │
│            │  └──────────────────────────────────────────────┘
```
**为什么这样**：用户想"看见 AI 在写代码"，实时代码流提供进度感与信任感，比纯进度条强得多（Nielsen：过程可见性降低感知等待 30%+）。

## Q3 · 点击到某个任务时样式如何？

**结论**：钻取是**面板内切换**（非整页跳转），保留左侧配置作上下文（置灰锁定），右侧从"列表"换为"详情"，顶部加**面包屑导航**。

**钻取交互流**
```
批量总览(状态三)
   │  点组件行 "查看" / 点最近任务的批量项
   ▼
右侧面板替换：
   ┌─ 面包屑: 批量任务 #T-2087  ›  c-chart-ring   [← 返回总览]
   ├─ 单组件详情(复用 Q2 视图: sticky小结 + 实时代码 + 日志)
   └─ 操作: 重试 / 取消该组件 / 下载(完成后)
   │  点 [← 返回总览]
   ▼
回到 批量总览(状态三)
```

**样式要点**
- **面包屑**置于右侧面板顶部，层级：任务ID › 组件名，左有"← 返回总览"（返回总览是高频操作，必须一键可达）。
- **左侧配置保持可见但置灰**（opacity 0.6），让用户知道"当前在看某个子组件，根配置在此"，而非突然消失造成迷失。
- **单组件详情 = 状态二/四视图**（进度 + 实时代码 + 日志），只多一层面包屑上下文。
- **钻取深度限制 1 层**（任务 › 组件），不再下钻组件内部，避免迷宫。

## ⚠️ 状态色一致性提醒（跨状态统一）
| 语义 | 颜色 | 现状 |
|---|---|---|
| 运行/活跃(生成中) | 绿 `#22C55E` + 呼吸 | 状态二用了**橙**(错)，状态三已改对 |
| 排队 | 橙 `#F59E0B` | 一致 |
| 完成 | 深绿 `#14794A` | 一致 |
| 失败 | 红 `#EF4444` | 一致 |
| 取消/暂停 | 灰 `#9CA3AF` | 一致 |

**建议**：回改状态二（单件生成中）的进度/徽章配色为绿色，与状态三及既定「状态色系统规范」对齐。
