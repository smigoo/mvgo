# 轻量组件生成前端原型结构

> 范围：首批截图输入，目标产物覆盖 Vue3 / 微码
> 目标：把输入、档位、结果和回退流程做成可直接试用的前端页面
> 原则：输入来源与生成档位分离，默认规则清晰，失败可回退

## 1. 原型目标

原型不是为了展示所有能力，而是验证四件事：

1. 用户能否快速理解当前支持什么输入。
2. 用户能否看懂组件类型和生成档位的区别。
3. 用户能否在失败后继续返回分析并重新尝试。
4. 用户能否从结果页进入预览、下载和继续优化。

## 2. 页面结构

### 2.1 入口页

入口页是首个主页面，负责建立心智模型。

必须包含：

- 页面标题与简短说明。
- 组件类型切换：`Vue3 / 微码`。
- 输入来源选择：当前首批仅支持截图。
- 生成档位切换：
  - 截图默认 `Lite`。
  - Figma 预留 `Max / Lite`，但首批不作为主流程。
- 主按钮：`快速生成初版`。
- 次按钮：`查看规则` 或 `查看示例`。
- 风险提示：截图结果为初版，可能包含推断和占位。

### 2.2 上传与预检页

上传后先做基础校验，再进入生成。

必须包含：

- 文件上传区或粘贴区。
- 文件预览缩略图。
- 文件格式、大小、分辨率提示。
- 去重提示。
- 预检错误展示。
- `返回重新选择` 按钮。

### 2.3 分析页

分析页用于让用户知道系统正在看什么。

必须包含：

- 截图大图预览。
- 识别到的区域摘要。
- 当前档位标识。
- 分析状态条。
- 预估耗时。
- 可展开的证据说明。

### 2.4 生成中页

生成中页用于承接等待、排队和失败。

必须包含：

- 生成进度。
- 当前任务状态。
- 当前目标类型：Vue3 或微码。
- 当前档位：Lite 或 Max。
- 取消或返回入口。
- 失败后进入分析页的入口。

### 2.5 结果页

结果页是这条流程的核心收口。

必须包含：

- 组件预览区。
- 结果档位标签。
- 证据提示区：哪些内容是推断，哪些是明确识别。
- 缺失项或警告项。
- `继续优化` 按钮。
- `下载代码` 按钮。
- `重新生成` 按钮。

### 2.6 失败页

失败页必须提供可恢复路径，而不是只给一句错误。

必须包含：

- 失败原因摘要。
- 失败发生在哪个阶段。
- 是否可重试。
- `返回分析` 按钮。
- `重新上传` 按钮。

## 3. 状态流

建议前端状态机如下：

```text
idle
  -> precheck
  -> analyzing
  -> generating
  -> success
  -> failed
```

其中：

- `precheck`：文件格式、大小、重复、分辨率检查。
- `analyzing`：截图解析、区域识别、证据摘要生成。
- `generating`：组件代码生成与校验。
- `success`：进入结果页。
- `failed`：进入失败页，可返回分析或重新上传。

## 4. 关键文案

### 4.1 主按钮

- 默认：`快速生成初版`
- 当用户选择更高完整度时：`生成更完整版本`

### 4.2 档位文案

- `Lite`：`快速初版，允许推断`
- `Max`：`更完整生成，建议检查细节`

### 4.3 风险提示

- `截图信息不足时，部分内容会使用默认布局或占位内容。`
- `当前结果是初版，不等于最终交付。`
- `Max 不是百分百准确，只是比 Lite 更完整。`

## 5. 交互规则

1. 截图输入必须默认 `Lite`。
2. `Vue3 / 微码` 作为独立目标切换，不和档位混用。
3. 如果预检失败，不能进入生成中页。
4. 如果生成失败，必须能返回分析页。
5. 结果页必须明确显示是否存在推断项。
6. 首批不暴露 HTML 还原入口，避免范围扩散。

## 6. 页面草图顺序

建议原型按这个顺序画：

1. 入口页
2. 上传与预检页
3. 分析页
4. 生成中页
5. 结果页
6. 失败页

## 7. 验收口径

- 用户能在 30 秒内理解入口页面的规则。
- 用户能明确区分组件类型和生成档位。
- 用户知道截图结果默认是 Lite。
- 用户在失败后能回到可恢复路径。
- 用户在结果页能下载或继续优化。
