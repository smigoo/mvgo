# 轻量组件生成实施蓝图

> 范围：首批做截图输入，目标产物先落 Vue3 与微码两条规范
> 目标：先做可试用版本，再逐步扩展到文档、HTML、批量和 Max
> 原则：先出可运行初版，再逐步补齐完整度

## 1. 这次实施的边界

### 1.1 只做什么

- 截图输入
- 输出普通 Vue3 组件和微码组件
- 生成档位遵循来源规则：截图固定 `Lite`，Figma 默认 `Max` 且可切 `Lite`
- 结果页支持预览、下载、继续优化
- 生成过程可见，失败可返回分析

### 1.2 先不做什么

- 不做 HTML 还原
- 不做批量生成
- 不做 HTML 还原
- 不做完整 Figma 高保真流程替换
- 不做复杂的多入口并行编排

## 2. 产品规则

### 2.1 两个稳定维度

| 维度 | 可选值 | 说明 |
|---|---|---|
| 组件类型 | `Vue3` / `微码` | 目标产物类型 |
| 生成档位 | `Lite` / `Max` | 生成深度和完整度 |

不要把“生成档位”再命名成“类型”，避免和组件类型混淆。

### 2.2 默认规则

- Figma URL 默认推荐 `Max`
- 允许用户手动切换到 `Lite`
- 截图默认 `Lite`
- 本次首批只做截图 + Vue3，因此入口默认推荐 `Lite`
- 当截图证据足够完整时，可以在结果页提示“可升级到 Max”

### 2.3 档位解释

- `Lite`：快速初版，允许推断、占位和设计系统默认值
- `Max`：更完整的结构、样式、交互补全，但仍不是最终高保真替代品

前端文案必须明确：`Max` 不是“绝对最终稿”，只是比 `Lite` 更完整。

## 3. 首批原型流程

### 3.1 入口页

页面结构建议如下：

- 顶部：标题、说明、当前档位
- 中间：截图上传区
- 右侧或下方：生成规则说明
- 底部：主按钮 `快速生成初版`
- 档位切换：`Lite / Max` segmented control

页面要让用户立刻明白：当前只支持截图生成 Vue3，其他路径是后续扩展。

### 3.2 上传与预检

上传后先做这些检查：

1. 文件格式是否支持
2. 文件大小是否超限
3. 是否重复上传
4. 是否能识别宽高
5. 是否需要压缩

如果预检失败，直接在上传区给出错误，不进入生成队列。

### 3.3 生成过程

建议分 4 个可见状态：

- `待提交`
- `分析中`
- `生成中`
- `生成完成` / `失败`

分析中显示：

- 截图尺寸
- 识别到的主要区域
- 是否有文字、按钮、表单、卡片、表格等结构

生成中显示：

- 当前档位
- 预估耗时
- 是否正在补缺字段或样式

### 3.4 结果页

结果页需要包含：

- 预览区
- 生成档位标识
- 结果说明
- 缺失项 / 推断项提示
- `继续优化` 入口
- `下载代码` 入口

如果当前是 `Lite`，要明确告诉用户可以切换到 `Max` 重新生成。

## 4. 首批原型页面清单

### 必做页面

| 页面 | 用途 | 必备内容 |
|---|---|---|
| 入口页 | 上传截图并选择档位 | 上传区、档位切换、主按钮 |
| 分析页 | 看清识别过程 | 截图预览、识别摘要、状态条 |
| 结果页 | 看见生成结果 | 预览、缺失项、升级入口、下载 |
| 错误页 | 处理失败 | 错误原因、返回分析、重新上传 |

### 可后置页面

- 历史记录页
- 批量任务页
- HTML 还原页
- 文档输入页
- 微码目标页

## 5. 文案建议

### 5.1 主按钮

- 首批主按钮建议：`快速生成初版`
- 档位较高时可变为：`生成更完整版本`

### 5.2 状态文案

- `Lite`：`快速初版，允许推断`
- `Max`：`更完整生成，建议检查细节`
- `失败`：`本次未完成，可查看原因并重新尝试`

### 5.3 风险文案

必须保留的提示：

- 截图信息不足时，结果会使用默认布局或占位内容
- 图片过于模糊时，部分文本和边界可能需要手动补齐
- Max 不是保证百分百准确，只是更完整

## 6. 实施步骤

### Phase A：文档和原型先行

1. 固定产品规则
2. 画入口页、分析页、结果页
3. 确认文案和状态模型
4. 确认档位切换逻辑

### Phase B：前端试用版

1. 做截图上传
2. 接入生成请求
3. 做生成中状态
4. 做结果预览与下载
5. 做失败回退和重新分析

### Phase C：能力增强

1. 补 Max 档逻辑
2. 补结果升级入口
3. 补微码目标
4. 再扩展到文档和 HTML

## 7. 验收标准

### 可试用标准

- 用户能上传截图并生成 Vue3 初版
- 用户能切换 Lite / Max
- 失败时能看到原因并重新尝试
- 结果页能看到预览和下载入口
- 文案能让用户看懂当前是初版，不误以为已最终交付

### 体验标准

- 上传、生成、结果三个阶段状态清楚
- 档位切换不会和组件类型混淆
- 错误提示不阻断理解
- 结果页明确指出哪些地方是推断或占位

### 质量标准

- 页面不出现两个“类型”概念混用
- `Lite` / `Max` 默认规则明确
- 结果页能承接后续升级
- 首批不引入批量和 HTML 复杂度

## 8. 风险与回退

### 主要风险

- 用户把 `Max` 理解成最终交付
- 用户误把截图 Lite 当作高保真结果
- 入口页信息过多，降低首次提交率
- 分析过程过慢，导致用户中途放弃

### 回退方式

- 如果 `Max` 认知混乱，先只保留 `Lite` 默认，隐藏高级切换
- 如果入口复杂，减少为单一上传区 + 结果说明
- 如果生成慢，先缩短分析展示内容，保留关键状态

## 9. 推荐下一步

如果你认可这份边界，我下一步应该做的是：

1. 把这份蓝图拆成前端原型稿
2. 再拆成接口清单和状态机
3. 然后才进入实现

这能避免一上来就把实现和文档混在一起。
