# 轻量组件生成：前后端循环执行流程（Phase-Gated Loop）

> 目标：把“截图 → Vue3 / 微码 Lite”及相关能力，按“阶段门 + 测试门禁 + 失败回退 + 分支分析”的方式推进，跑通就继续，跑不通就回退到分析分支，直到首批前后端完成。
> 本流程不修改业务代码，只定义执行模型、门禁和分支规则。

---

## 0. 已锁定的产品边界（所有阶段共用）

| 维度 | 取值 | 规则 |
|---|---|---|
| 输入来源 | 截图 / Figma | 首批只做截图输入；Figma 为后续接入 |
| 组件类型 | Vue3 / 微码 | 两套代码规范，不引入第三套 |
| 生成档位 | Lite / Max | 截图固定 Lite；Figma 默认 Max 但可切 Lite |
| 首批范围 | 截图 → Vue3 + 微码 | 不做 HTML 还原、不做批量生成 |
| 试用标准 | 主流程可跑通 | 结果可生成、预览、下载、Playground 编辑 |

## 1. 循环模型

每个阶段执行同一个闭环：

```text
┌─────────────────────────────────────────────┐
│  Plan（计划）                                │
│  - 明确本阶段目标、接口、字段、验收口径        │
└───────────────┬─────────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────────┐
│  Implement（实现）                           │
│  - 后端接口 / 前端页面 / 状态机 / 联调        │
└───────────────┬─────────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────────┐
│  Test（测试）                               │
│  - 单元测试 / 接口测试 / 原型走查 / 构建验证  │
└───────────────┬─────────────────────────────┘
                │
                ▼
        ┌───────────────┐
        │ Pass?         │
        └───┬───────┬───┘
            │       │
           Yes      No
            │       │
            ▼       ▼
   ┌────────────┐  ┌──────────────────────────┐
   │ Next Phase │  │ Analyze（分析）            │
   └────────────┘  │ - 定位根因：需求/设计/实现 │
                   │ - 是否需新方案分支          │
                   │ - 是否需回退上一阶段        │
                   └──────────┬───────────────┘
                              │
                              ▼
                    ┌──────────────────┐
                    │ Branch Decision  │
                    │ 继续修 / 回退 / 新分支 │
                    └──────────┬───────┘
                               │
                               ▼
                         回到 Plan 或 Implement
```

原则：
1. **不盲目重试**：同一错误重试超过 2 次仍未通过，必须进入 Analyze，不允许机械循环。
2. **先小闭环后大闭环**：单接口/单页面先自测通过，再做跨端联调。
3. **门禁前置**：进入下一阶段前，当前阶段所有“完成标准”必须全绿。
4. **分支留痕**：任何导致方案变更的 analyse 结论，写入当天工作记忆与对应文档。

## 2. 阶段划分

### Phase 0 — 基础协议对齐
- 目标：统一字段命名、状态机、错误码、SSE 事件。
- 实现清单：
  - `sourceType`：`screenshot` / `figma`
  - `componentType`：`vue3` / `microcode`
  - `generationTier`：`lite` / `max`
  - 任务状态：`precheck → analyzing → generating → success → failed`
  - 错误码：配额超限、图片无效、模型超时、解析失败、内部错误
- 测试清单：字段定义被前端/后端共用，无歧义。
- 完成标准：DTO / 状态枚举 / 错误码已落文档并评审通过。
- 失败回退：若字段冲突，回退到原型结构文档复核。
- 分支规则：若发现截图必须支持 Max，则回到产品边界确认，不开新分支。

### Phase 1 — 截图 → Vue3 Lite 后端最小链路
- 目标：上传截图 → 预检 → 分析 → 生成 Vue3 Lite 组件 → 返回结果。
- 实现清单：
  - 截图上传接口
  - 预检：图片格式、尺寸、空图、模糊度基础校验
  - 分析：视觉模型提取结构/样式/文本
  - 生成：Vue3 SFC 初版
  - 结果：代码、预览所需元数据、置信度
- 测试清单：
  - 上传非法图片返回明确错误
  - 正常截图返回可编译 Vue3 代码
  - 超时/模型失败进入 `failed` 并可重试
- 完成标准：`vite build` 不要求，但后端构建通过；接口可用 Postman/curl 跑通。
- 失败回退：若生成质量差，先回退分析 prompt，不立即改产品边界。
- 分支规则：若截图分析长期低质量，开“截图分析增强”分支，记录样本。

### Phase 2 — 截图 → Vue3 Lite 前端原型联调
- 目标：入口页 → 上传 → 预检 → 生成中 → 结果页 全链路可试用。
- 实现清单：
  - 入口选择组件类型 Vue3
  - 截图上传/粘贴
  - 预检反馈
  - 生成中状态与进度
  - 结果预览 + 下载 + Playground 打开
  - 失败页与重试
- 测试清单：
  - 走查 prototype-structure 中每个页面状态
  - 断网/超时/空结果有兜底
  - 档位固定显示 Lite，不允许切 Max
- 完成标准：内部可试用主流程，无白屏、无死状态。
- 失败回退：若状态机卡死，回退到 api-state-map 对齐。
- 分支规则：若 Playground 集成成本过高，先出“只读预览 + 下载”，Playground 编辑入下一阶段。

### Phase 3 — 截图 → 微码 Lite 后端
- 目标：同 Phase 1，但产物为微码组件。
- 实现清单：
  - 微码 declare.json / component.js / styles 生成
  - 事件名、字段、样式作用域符合微码规范
  - 与 Vue3 共用分析层，仅目标转换器不同
- 测试清单：
  - 产物可被既有微码运行时识别
  - 声明事件与实际事件一致
  - CSS/Less 同步正确
- 完成标准：后端构建通过，微码产物可落入 workspace。
- 失败回退：若微码契约不通过，回退到微码规范校验。
- 分支规则：若微码与 Vue3 差异过大，开“微码转换器适配”分支。

### Phase 4 — 截图 → 微码 Lite 前端
- 目标：复用 Phase 2 页面，组件类型切换为微码。
- 实现清单：
  - 组件类型切换 UI
  - 微码结果预览/下载
  - 微码专用提示（事件、字段、预览图标准）
- 测试清单：
  - 同 Phase 2 走查
  - 微码与 Vue3 切换不串状态
- 完成标准：截图 + 两种组件类型均可试用。
- 失败回退：若类型切换污染状态，回退到状态机隔离。
- 分支规则：无。

### Phase 5 — 来源与档位扩展（Figma + 切换）
- 目标：接入 Figma 来源，支持 Max 默认与 Lite 切换。
- 实现清单：
  - Figma URL 解析
  - Figma → Max 默认
  - 用户可切 Lite
  - 截图侧保持 Lite only
- 测试清单：
  - Figma 缺权限/无效节点有清晰错误
  - 档位切换触发重新生成或提示
- 完成标准：Figma 与截图两条来源均可走通，档位规则符合边界。
- 失败回退：若 Figma 慢点影响体验，先限制并发/加队列，不回退产品规则。
- 分支规则：若 Figma 与截图共用管线冲突，开“来源适配器”分支。

### Phase 6 — 结果中心与可恢复性
- 目标：任务列表、进度恢复、取消、重试、SSE 断线恢复。
- 实现清单：
  - 任务中心列表
  - 页面刷新恢复
  - 取消/重试失败项
  - SSE 断线重连
- 测试清单：
  - 刷新后任务状态不丢
  - 后端重启后可恢复或明确失败
- 完成标准：用户可管理历史任务，不卡死。
- 失败回退：若持久化缺失，回退到任务存储设计。
- 分支规则：若恢复成本高，先支持“重新生成”，延后自动恢复。

### Phase 7 — 限流、配额与体验兜底
- 目标：接入之前已设计的配额/限流协议。
- 实现清单：
  - 每小时/每日配额
  - 队列超时与取消
  - 限流提示与重试建议
- 测试清单：
  - 配额满有预约/分批提示
  - 超时任务可恢复
- 完成标准：批量/高频场景不雪崩。
- 失败回退：若网关死锁复发，回退到 AI 网关单层调度方案。
- 分支规则：无。

## 3. 每阶段门禁检查表

进入下一阶段前，必须全绿：

- [ ] 本阶段目标已实现
- [ ] 后端构建通过（如涉及后端）
- [ ] 前端构建通过（如涉及前端）
- [ ] 接口/页面按原型与状态机走查通过
- [ ] 错误路径有兜底
- [ ] 档位/来源规则未被破坏
- [ ] 工作记忆已记录关键结论

---

## 4. 失败分类与处理

| 失败类型 | 处理 |
|---|---|
| 配置/构建错误 | 直接修复，记录命令与产物路径 |
| 接口 4xx | 查 DTO 与路由，回到 Phase 0 对齐 |
| 模型超时/限流 | 走配额/队列/重试，不立即改产品边界 |
| 生成质量差 | 先调分析 prompt，样本积累后开增强分支 |
| 状态机卡死 | 回到 api-state-map 对齐状态流转 |
| 产品规则冲突 | 回到已锁定边界，不开随意分支 |
