# 组件生成页 · 用户研究计划与功能分析

> 文档角色：UX Researcher（用户体验研究员）
> 目标：用科学方法验证「组件生成页」的设计假设，明确功能优先级与最佳查看方式
> 状态：研究计划已定稿；功能分析为**基于 UX 启发式 + 已有设计迭代的假设**，需研究验证

---

## 一、研究背景与目的

组件生成页当前的形态是一个「配置表单 + 大画布」的页面，但实际功能仅为「生成一个组件」。前期已在画布上完成三版布局探索（A 居中表单 / B 左表单+右预览 / C 左表单+右引导）与标签系统（V3/MC 方块 + Lite/Max 胶囊 + 来源描边），但这些都是**设计假设**，尚未经过真实用户验证。

本次研究要解决三个核心问题：
1. 用户到底需要组件生成页提供哪些功能？
2. 用户最习惯、最高效的查看方式是什么（布局/信息密度）？
3. 任务列表中的元信息（类型/来源/等级）哪些真正影响决策？

---

## 二、研究问题（Research Questions）

| 编号 | 研究问题 | 对应设计决策 |
|---|---|---|
| RQ1 | 用户使用组件生成页的核心任务与目标是什么？ | 决定页面是「纯生成入口」还是「生成+管理一体化」 |
| RQ2 | 当前生成流程中最大的痛点在哪里？ | 定位首要优化点（等待焦虑？配置复杂？结果找不到？） |
| RQ3 | 用户偏好如何查看生成结果与历史？ | 验证 A/B/C 三版布局哪个更符合心智 |
| RQ4 | 任务列表中哪类元信息（类型/来源/等级）最影响决策？ | 验证标签系统优先级（V3/MC vs Lite/Max vs 来源） |
| RQ5 | Lite / Max 等级如何影响用户预期与行为？ | 决定等级标签是否需突出为独立徽章 |

## 三、研究方法（Mixed Methods · 三角验证）

**核心逻辑**：定量找「什么」（行为数据），定性找「为什么」（动机/痛点），可用性测试验证「哪种更好」（方案对比）。

### 3.1 定量研究
- **使用数据分析（Analytics / 埋点日志）**
  - 指标：各功能入口点击率、生成完成率、失败率、重试率、来源类型分布（Figma/截图/HTML）、平均生成耗时、结果操作频次（查看/下载/删除）
  - 样本：全量现有用户行为数据（≥ 2 周）
- **问卷调研（Survey）**
  - 目标：n ≥ 50，覆盖不同使用频率用户
  - 内容：功能重要性评分（Likert 5 点）、布局偏好选择、等级使用习惯、开放题收集痛点
  - 招募：产品内弹窗 + 用户群推送

### 3.2 定性研究
- **深度访谈（In-depth Interview）**：8–12 人
  - 筛选：按使用频率分层抽样（高频 4–5 人 / 中频 4–5 人 / 新用户 4–5 人）
  - 主题：典型工作任务流、当前痛点、对「类型/来源/等级」标签的直觉理解、期望的查看方式
  - 产出：用户画像（Persona）、任务旅程图（User Journey Map）、痛点聚类
- **情境访谈（Contextual Inquiry）**：可选 3–5 人
  - 观察用户真实使用组件生成页的过程，记录卡点

### 3.3 可用性测试（Usability Testing）
- **A/B/C 布局对比测试**（直接复用画布上已设计的三版）
  - 任务场景：① 首次生成组件 ② 找到上周生成的某组件 ③ 判断某任务用的是 Vue3 还是微码
  - 指标：任务完成率、完成任务时间（Time on Task）、错误次数、SUS 系统可用性量表评分
  - 分组：每组 6–8 人，轮转分配避免学习效应
- **标签系统可读性测试**
  - 验证 V3/MC 方块、Lite/Max 胶囊、来源描边在列表密集场景下的扫视效率

### 3.4 样本与偏差控制
- **样本量依据**：定性访谈 8–12 人可达理论饱和；可用性测试每组 5–8 人可检出主要可用性问题（Nielsen 基准）
- **分层抽样**：按使用频率分层，避免只看高频用户
- **偏差缓解**：访谈避免引导性提问（如不问「你是不是觉得预览很有用」，改问「生成后你一般会做什么」）；测试任务用真实场景而非演示脚本

## 五、功能优先级矩阵（UX 假设，待研究验证）

> 以下为基于 UX 启发式评估与已有设计迭代的**初步假设**，最终优先级由研究数据校准。

| 功能 | 优先级 | 用户价值 | 研究验证方式 |
|---|---|---|---|
| 生成配置表单（模式/来源/类型/等级/标识） | **P0** | 高 | 任务完成基础路径，所有用户必经 |
| 生成状态反馈（进度/成功/失败/重试） | **P0** | 高 | 埋点验证失败率与重试率，减少等待焦虑 |
| 任务列表 + 标签（V3/MC · 来源 · Lite/Max） | **P0** | 高 | 回溯管理核心，标签可读性需可用性测试 |
| 结果操作（查看/下载/删除/重试） | **P0** | 高 | 生成闭环落地，问卷验证操作频次 |
| 实时预览（方案 B 左表单+右预览） | **P1** | 中高 | A/B 测试：对比 A vs B 任务完成时间 |
| 最近任务 / 快速上手引导（方案 C） | **P1** | 中 | 新用户分组测试首次生成完成率 |
| 来源切换（Figma / 截图 / HTML） | **P1** | 中 | 访谈 + 埋点验证三种来源实际使用占比 |
| 模板 / 预设（常用配置复用） | **P2** | 中 | 问卷验证需求强度，高频用户更关注 |
| 批量生成（多组件并发） | **P2** | 低 | 低频验证，优先级最低，可后续迭代 |

**假设解读**：
- P0 四项构成「生成闭环」的最小可用集——没它们用户连基本任务都完不成。
- P1 的实时预览和引导是「体验分水岭」：熟练用户可能更看重预览（方案 B），新用户更看重引导（方案 C）。这正是 A/B/C 测试要回答的。
- P2 属于「锦上添花」，在研究确认需求强度前不急于投入。

## 六、怎么看比较方便（查看方式分析）

基于已有三版布局探索与 UX 原则，给出分场景建议：

### 6.1 按用户分层的查看策略
| 用户类型 | 推荐布局 | 理由 |
|---|---|---|
| **新用户 / 低频** | 方案 C（左表单 + 右引导/历史）或方案 A（居中表单 + 底部引导） | 降低认知负荷，右侧「快速上手」+「最近任务」提供安全感 |
| **熟练用户 / 高频** | 方案 B（左表单 + 右实时预览） | 生成后即时看结果，减少跳转，缩短反馈回路 |
| **列表密集浏览** | 紧凑行内标签（V3/MC 方块 + Lite/Max 胶囊 + 来源描边） | 一行扫完所有元信息，信息密度高且不杂乱 |

### 6.2 标签系统的查看层级（已定稿方向）
```
任务号  [已完成]
组件：c-panel-login  [V3]  Figma  [● Lite]
8/5 09:42 · 2.8min                    [查看] [↓]
```
- **第一梯队（最醒目）**：V3 / MC 方块 —— 一眼区分组件类型（Vue3 绿 / 微码蓝）
- **第二梯队（中权重）**：Lite / Max 胶囊 —— 沿用现有渐变风格，区分生成等级
- **第三梯队（轻量）**：来源描边灰 pill —— 不抢注意力，需要时可见

### 6.3 关键 UX 原则
1. **渐进呈现（Progressive Disclosure）**：首屏只放生成必需项，引导/历史/高级选项降级或折叠
2. **即时反馈（Immediate Feedback）**：生成中必须有进度/状态，避免「点了没反应」的焦虑
3. **可回溯（Recoverability）**：每次生成都进任务列表，支持查看/下载/删除，结果不丢
4. **扫视效率（Scannability）**：列表用色彩+形状双编码（方块=类型、胶囊=等级），不依赖纯文字

## 七、预期产出与成功指标

### 量化指标（研究后设定基线，迭代后对比）
- 生成任务完成率：目标提升 ≥ 15%
- 平均生成耗时（含查找结果）：目标降低 ≥ 20%
- 生成失败率 / 重试率：目标降低 ≥ 30%
- SUS 系统可用性评分：目标 ≥ 80（良好）

### 质性指标
- 用户访谈中「找不到结果」「不知道生成中」类痛点显著减少
- 标签系统测试中类型/等级识别准确率 ≥ 95%
- 新用户首次生成完成率（有引导 vs 无引导）差异可量化
