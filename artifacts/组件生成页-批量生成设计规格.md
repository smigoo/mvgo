# 组件生成页 · 批量生成模式 设计规格

> 画布文件 `711471848779107`，节点 `42:1`（状态三 · 批量生成中）
> 设计日期：2026-08-05

## 1. 设计问题

当前「单任务 = 单组件」模型无法支撑批量场景。一个批量任务聚合 N 个独立组件，每个组件有**异步异构生命周期状态**——右侧面板不能给每个画一个全尺寸进度条。需要升级为**两级状态模型**：任务级聚合 + 组件级列表。

## 2. 状态模型

### 2.1 任务级（聚合态）

| 状态 | 触发条件 | 右侧主视图 |
|---|---|---|
| 配置中 | 用户正在添加源/调参 | 配置预览 + 「开始批量生成」按钮 |
| 运行中 | 至少 1 个组件在处理 | **任务总览卡** + 组件列表（本原型） |
| 完成(全部) | 所有组件 done | 结果汇总 + 批量下载/预览 |
| 部分失败 | 有失败项 | 同运行中 + 失败高亮 + 重试入口 |

### 2.2 组件级（每行独立）

| 状态 | 色值（对齐状态色系统） | 行内表现 |
|---|---|---|
| 排队中 | 橙 `#F59E0B` / 文字 `#B45309` / 底色 `#FFF7ED` | 橙 chip "排队中" + [取消] |
| 分析/生成/校验中（活跃） | 绿 `#22C55E` / 文字 `#14794A` / 底色 `#E7F6EE` | 绿 chip "生成中" + 迷你进度条 + [查看] |
| 完成 | 深绿 `#14794A` / 底色 `#E7F6EE` | 绿 chip "完成" + [查看] |
| 失败 | 红 `#EF4444` / 底色 `#FEE2E2` | 红 chip "失败" + [重试] |
| 已取消 | 灰 `#9CA3AF` / 底色 `#F3F4F6` | 灰 chip "已取消" |

> ⚠️ **一致性修正**：此前状态二（单件生成中）使用了橙色表示"进行中"，但按既定状态色系统橙色=排队、绿色=运行/活跃。批量模式严格遵循此规范；建议回改状态二配色以统一。

## 4. 关键交互

### 4.1 聚合操作
| 操作 | 触发位置 | 行为 |
|---|---|---|
| 重试失败 | 操作条 [重试失败(N)] 按钮 | 仅重试 status=failed 的组件 |
| 取消全部 | 操作条 / 左栏 CTA | 中断整个任务，所有进行中→已取消，排队→不启动 |
| 查看详情 | 每行 [查看] | 右侧下钻为该组件的详细日志（复用状态二视图） |

### 4.2 筛选
列表头提供快速筛选 pill：全部 / 失败(N) / 进行中(N)。点击后列表过滤显示对应状态的行。默认「全部」。

### 4.3 钻取（Drill-down）
点击某行的「查看」→ 右侧面板从总览切换为该组件的详细进度（四阶段 + 日志），左上角提供「← 返回总览」。
这是**渐进披露**策略：默认只看列表摘要，按需深入单个组件。

## 5. 与单件模式的关系

| 维度 | 单件模式 | 批量模式 |
|---|---|---|
| 输入 | 单个拖入区 | 多源列表（可追加/移除） |
| 右侧空闲态 | 预览区+最近任务+快速上手 | （同，或替换为批量历史） |
| 右侧运行态 | 单组件进度条+四阶段+日志 | 任务总览+组件列表 |
| CTA | 「开始生成」/「取消」 | 「批量生成中…」/「取消全部」 |
| 状态色 | — | 严格五色（绿/深绿/橙/红/灰） |
| 切换方式 | 同页面，由输入数量自动判定 或 模式开关 | — |

## 6. 技术要点

- **前端数据结构**: Task { id, status, components: [{id, name, status, progress, error}] }
- **聚合进度算法**: `overallProgress = Σ(component.progress) / N` 或加权平均
- **实时更新**: SSE 推送每个组件的状态变更 → 前端更新对应行（keyed by component.id）
- **取消传播**: AbortController 从 task 级 cancel → 广播到所有子组件 signal
- **宽度坑**: Ardot `fill_container` 在此版本返回固定值 100，需用显式 px 宽度或依赖父级 STRETCH layoutAlign
