# Background Brightness 4 步量化识别流程

## 目标

将设计稿的背景亮度准确分类为 `"dark"` 或 `"light"`，准确率目标 > 95%。

## 4 步量化流程

### Step 1: 采集主背景色

选取设计稿中**占比最大**的区域背景色：
- 通常是最外层容器的背景
- 排除：图表绘制区、卡片内部、图片内容

### Step 2: 转换为亮度值

使用相对亮度公式：

```
L = 0.299 * R + 0.587 * G + 0.114 * B

其中 R/G/B 为 0-255 范围的整数值
```

### Step 3: 阈值判定

| L 值范围 | 判定结果 | 典型场景 |
|---------|---------|---------|
| L ≥ 128 | `"light"` | 白底、浅灰底 (#f0f5ff, #fafafa) |
| L < 128 | `"dark"` | 深蓝底、黑底 (#0a1628, #1a1a2e) |

### Step 4: 交叉验证（防误判）

用以下辅助信号验证判定：

| 辅助信号 | dark 的特征 | light 的特征 |
|---------|------------|------------|
| **主文字颜色** | 白/浅色 (#fff, rgba(255,255,255,0.85)) | 深/黑色 (#333, rgba(0,0,0,0.85)) |
| **边框颜色** | 浅色半透明 (rgba(255,255,255,0.1)) | 深色 (#e8e8e8, #d9d9d9) |
| **对比度感知** | 文字"浮"在背景上 | 文字"沉"入背景 |

**矛盾时以亮度公式为准**，但记录 warning。

## 常见错误案例

### 错误案例 1：渐变背景误判
```
背景是从 #0a1628 到 #1a2744 的垂直渐变
❌ 错误：随机取一个采样点判断
✅ 正确：取渐变中间值或起始值的加权平均
```

### 错误案例 2：卡片式布局误判
```
外层是深色(#0a1628)，但卡片内部是浅白(#ffffff)
❌ 错误：采样的卡片内部背景，判断为 light
✅ 正确：采样主容器/外层背景，判断为 dark
```

### 错误案例 3：半透明覆盖层
```
背景有 60% 黑色透明遮罩
❌ 错误：忽略透明度，按底层颜色判断
✅ 正确：考虑透明度后的实际视觉亮度
```
