# 布局分析工作流

## 核心原则

**必须自上而下、逐层拆解整个组件**。不要只识别一个元素就停止，必须完整分析所有可见区域。

## 分析流程（按顺序执行）

### 第1步：识别整体布局类型

观察整个组件，判断是：
- **单一面板** - 一个完整的数据展示区域
- **多面板组合** - 多个并排或堆叠的面板
- **纯控件** - 只有一个简单的控件（极少见）

**⚠️ 重要：大多数组件都是"单一面板"或"多面板组合"，不要误判为"纯控件"**

### 第2步：拆解主要区域（sections）

从上到下观察，将组件划分为多个独立的区域（section）：

- **面板标题区** - 最顶部的标题文字
- **header 插槽区** - 与标题同行的控件（tab、按钮等）
- **内容区1** - 第一个数据展示区域
- **内容区2** - 第二个数据展示区域（如果有）
- **更多内容区** - 继续向下识别

**✅ 正确做法：**
```
发现组件包含：
1. 标题"重点车辆监测"
2. 右侧切换按钮
3. 下方"今日累计"小节
4. 三个数据卡片

→ 至少需要2个section：标题区 + 数据展示区
```

### 第3步：逐个分析每个 section 的内部结构

对于每个 section，必须拆解为 **header + body** 两层：

#### section 的 header（可选）
- 小节标题文字（如"今日累计"）
- 标题行右侧的控件（下拉框、刷新按钮等）

#### section 的 body（必须）
- 布局类型（horizontal、vertical、grid等）
- 具体元素列表（children数组）

**✅ 示例：**
```json
{
  "sections": [
    {
      "id": "today-stats",
      "name": "今日累计",
      "header": {
        "title": "今日累计"
      },
      "body": {
        "layout": "horizontal-3-columns",
        "children": [
          { "type": "data-card", "label": "危化品车", "value": "51" },
          { "type": "data-card", "label": "重型货车", "value": "2" },
          { "type": "data-card", "label": "超高车辆", "value": "19" }
        ]
      }
    }
  ]
}
```

### 第4步：识别所有子元素

在 body.children 数组中，必须列出**所有可见的元素**：
- **数据卡片** - 显示数值和标签
- **图表** - 折线图、柱状图、饼图等
- **列表** - 表格、列表项
- **表单控件** - 输入框、下拉框等

**不要遗漏任何元素！**

## 常见错误模式（一票否决项）

**`sections` 数组、每个 section 的 `body.children` 都不能为空**——即使只有标题也要建 section 描述；不要只识别一个控件就停止，必须自上而下完整列出标题、控件、内容区、卡片、图表、列表。

## 自检清单

分析完成后，**逐项执行下方「强制自检 Checklist（10 项）」模块**（self-checklist），此处不重复列出。

## 分析优先级

1. **完整性 > 细节准确性** - 先保证所有区域都识别到，再优化细节
2. **结构层次 > 元素属性** - 先建立正确的 section 层级，再填充具体属性
3. **可见元素 > 推测功能** - 只描述看到的，不要臆造不存在的元素
