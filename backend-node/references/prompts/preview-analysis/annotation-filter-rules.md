# 注释过滤规则

## 设计师注释识别（CRITICAL）

以下文本节点属于设计师注释/标注，**不应**识别为 UI 内容或插槽元素：

### 排除规则

1. **符号标注**
   - 以 `*` 或 `#` 开头的文本（如 `*数据实时更新`、`#待确认` 形式的标注）
   - 纯重复符号（如 `***` / `---` / `===`）

2. **关键词标注**
   - 包含 `TODO` / `FIXME` / `注` / `标注` / `备注` 的文本
   - 包含 `待定` / `待确认` / `占位` 的文本

3. **尺寸判断**
   - 字号小于 10px 且内容少于 10 个字符的文本节点（通常是设计标注）
   - ⚠️ 注意：<10px 的文本如果是有意义的 UI 元素（如图表刻度、小标签），仍需识别

4. **位置判断**
   - 画板边缘的文本（通常是设计说明）
   - 被明显标记为注释层的文本

## 应用场景

- **插槽识别**：headerSlots 不应包含注释文本
- **布局分析**：section 的 label/value 不应包含注释
- **资源映射**：resourceFile 的描述不应来自注释
- **图表分析**：图例、坐标轴不应包含设计师标注

## 示例

### ❌ 错误识别（注释被当作 UI 元素）

```json
{
  "headerSlots": [
    { "content": "*数据实时更新" }  // 错误：这是注释
  ]
}
```

### ✅ 正确识别（过滤注释）

```json
{
  "headerSlots": [
    { "content": "设备类型 28" }  // 正确：这是真实 UI 元素
  ]
}
```

## 边界情况

### 特殊字符但非注释

- `*` 作为乘号：如 "2*3" → 识别
- `#` 作为标签：如 "#标签1" 在用户内容中 → 识别（但设计稿中通常是注释）
- 小字号的重要信息：如图表坐标轴刻度值 → 必须识别

### 判断优先级

1. 结合内容语义判断（是否有实际业务含义）
2. 结合位置判断（是否在 UI 元素内部）
3. 有疑问时倾向于识别（宁可多识别也不要遗漏真实元素）
