## 一、微码组件开发注意事项

### 🎯 核心原则

微码组件是微码平台的基础构建单元，开发时需遵循以下核心原则：

1. **标准化**：严格遵循命名规范、文件结构规范，确保组件可被平台正确识别和加载
2. **主题化**：支持多主题切换（至少包含 dark 深色主题），使用 CSS 变量实现主题配置
3. **响应式**：使用相对单位（em/rem），避免硬编码尺寸，适配不同屏幕
4. **隔离性**：样式隔离（scoped）、禁用直接 HTTP 请求，通过平台 API 与外部交互
5. **一体化**：业务组件需适配一体化平台，支持内容布局、深色主题、背景色统一管理

---

### 📦 组件基础结构

```
c-mc-your-component/           # 组件目录（kebab-case）
├── package/
│   └── index.vue              # ✅ 必须：组件入口，顶层用 <base-panel> 包裹
├── resources/
│   ├── config/
│   │   └── css-vars.js        # ✅ 必须：CSS 变量默认值（导出 common + 主题对象）
│   ├── images/
│   │   └── mc-preview.png     # ✅ 必须：组件预览图
│   └── styles/
│       ├── index.less         # ✅ 必须：样式入口
│       ├── common.less        # 通用样式
│       └── themes/
│           ├── theme-vars.less  # ✅ 必须：主题变量定义
│           ├── dark.less        # ✅ 业务组件必须：深色主题
│           └── light.less       # 浅色主题
├── declare.json               # ✅ 必须：组件声明（JSON 格式）
├── declare.js                 # ✅ 必须：声明构建脚本
└── component.js               # ✅ 必须：组件导出
```

### 🔖 组件类型说明

微码组件分为**两种类型**，不同类型适用不同的检查规范：

| 类型         | 标识方式                          | 适用场景                                       | 检查特点                     |
| ------------ | --------------------------------- | ---------------------------------------------- | ---------------------------- |
| **业务组件** | 默认                              | 数据看板、统计图表、业务展示类组件             | 必查项 25 项 |
| **服务组件** | 配置 `"componentCategory": "service"` | 纯逻辑服务、后台任务、数据处理等无 UI 界面组件 | 必查项 21 项 |

**在 `declare.json` 中配置组件类型**：

```json
{
  "componentId": "c-mc-your-component",
  "componentName": "你的组件",
  "componentCategory": "business",
  ...
}
```

**说明**：

- **业务组件**：

  - 包含常规业务组件（数据看板、图表等）
  - 面向终端用户的可视化展示，需要支持布局、主题、背景色管理等一体化特性
  - 额外执行 `business` 适用范围的检查项（内容布局、dark 主题、背景色限制等）

- **服务组件**：
  - 纯逻辑组件，不涉及 UI 展示（如数据处理、后台任务）
  - 不执行 `business` 适用范围的样式和主题相关检查项

**不配置 `componentCategory` 字段时，默认视为业务组件。**

### ⚠️ 开发时必须注意

#### 1. 命名规范

- **组件 ID**：`c-` 开头，全小写+连字符，如 `c-mc-data-board`
- **组件名称**：2-50 字符，如 "数据看板"
- **版本号**：语义化版本 `v1.0.0`

#### 2. 主题支持

- **所有组件**：至少支持 1 个主题（推荐 light + dark）
- **业务组件**：**必须**支持 dark 深色主题
- **CSS 变量**：使用 `@fontSize`、`@colorTextBase` 等框架预设变量
- **字体大小**：必须使用 `@fontSize` 变量，不得硬编码 >5px 的字体大小

**框架预设 CSS 变量**（以下 8 个变量无需在 `cssVariableConfig` 中声明）：

- `fontSize`：基础字体大小
- `fontWeightStrong`：加粗字体
- `colorTextBase`：文字基础色
- `colorPrimary`：主色调
- `colorPrimaryHover`：主色调悬浮态
- `colorPrimaryActive`：主色调激活态
- `colorPrimaryBg`：主色调背景
- `colorPrimaryBgHover`：主色调背景悬浮态

#### 3. 样式规范

- **响应式单位**：优先使用 `em`，避免固定 `px` 值（>5px）
- **字体变量**：`css-vars.js` 中字体变量必须用 `$mcCssBuilder.getCssSize()`
- **背景色限制**（业务组件）：`<base-panel>` 及其第一个子元素不得设置内联背景色

#### 4. 配置声明

- **cssVariableConfig**：自定义变量必须声明（框架预设 8 个变量无需声明）
- **layoutConfig**（业务组件）：至少配置 1 个内容布局，预览图名称不得重复
- **themeConfig**：至少配置 1 个主题，业务组件必须包含 `key='dark'`

#### 5. 代码约束

- **禁用 API**：不得使用 `createRequest`、`axios`、`this.$http`、`.fetch()`
- **事件一致性**：`publishEvent` 必须在 `businessEvents` 中声明，`listenEvent` 必须在 `businessStatuses` 中声明
- **组件构建器**：`$mcComponentBuilder` 全局只能调用 1 次

#### 6. 深色主题（业务组件）

**核心变量**（3 个，必须配置）：

- `colorTextBase`：文字基础色
- `colorPrimary`：主色调
- `colorPrimaryBg`：主色调背景

**可选变量**（如配置需符合枚举）：

- `colorTextSecondary`：次要文字颜色
- `colorPrimaryHover`：主色调悬浮态
- `colorPrimaryActive`：主色调激活态
- `colorPrimaryBgHover`：主色调背景悬浮态

**色值要求**：必须使用规定的色值枚举（不区分大小写），详见附录。

> **说明**：深色主题色值枚举已与公司质量管控部/设计部确认，作为后期微码组件设计的默认深色主题（dark）的默认色值标准。

### 🔍 常见错误与解决

| 错误                            | 原因                                                            | 解决方案                                                                                |
| ------------------------------- | --------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| M2-3 失败：css-vars.js 不存在   | 缺少必要文件                                                    | 创建 `resources/config/css-vars.js`，导出 `common` + 主题对象                           |
| M3-8 失败：自定义变量未声明    | `css-vars.js` 定义了自定义变量但未在 `cssVariableConfig` 中声明 | 在 `declare.json` 的 `cssVariableConfig` 中添加该变量声明                               |
| M5-6 失败：@fontSize 声明/使用缺失 | `css-vars.js` 定义了 `fontSize`，但 `theme-vars.less` 缺少映射声明或样式未使用变量 | `theme-vars.less` 添加 `@fontSize: var(--fontSize);`，业务样式中至少使用一次 `font-size: @fontSize;` |
| M5-7 失败：硬编码字体大小       | 使用了 `font-size: 16px;` 等固定值                              | 改用 `font-size: @fontSize;` 或 `font-size: calc(@fontSize * 1.14);`                    |
| M3-13 失败：缺少 dark 主题     | 业务组件未配置 dark 主题                                        | 在 `themeConfig.list` 中添加 `{key: 'dark', name: '深色'}`                              |
| M4-9 失败：dark 核心变量缺失   | dark 对象缺少核心变量                                           | 在 `css-vars.js` 的 `dark` 对象中添加 `colorTextBase`、`colorPrimary`、`colorPrimaryBg` |
| M5-8 失败：base-panel 有背景色  | 直接在 `<base-panel>` 上设置了背景色                            | 移除 `style="background: ..."`，由框架统一管理                                          |

## 二、健康度检查报告说明

### 📊 检查体系概述

微码组件健康度检查按「检查对象」划分五大系列（M1~M5），根据组件类型和配置情况动态执行检查项。

#### 检查项总览

检查脚本共定义 **45 个检查项**（M1~M5 全系列）。每个检查项由「规则内容 + 适用范围 + 触发条件 + 结果」四要素定义：

**执行维度**：

- **必查项**：无论组件如何配置，必定执行
- **可选项**：仅在触发条件满足时执行

**检查结果**（三态，非分类依据）：

- **pass（通过）**：满足规则，无影响
- **error（阻断）**：必须修复，否则阻断上线
- **warning（提醒）**：建议修复，不阻断上线

#### 检查结果判定

**通过条件**：所有执行的检查项未产生 `error` 级结果

- 检查项执行后，如产生 **error** 级结果，即判定为**不通过**，阻断上线
- 产生 **warning** 级结果，不影响通过，允许放行

**说明**：

- 结果为 `error` 的检查项（不通过）→ 阻断上线
- 结果为 `warning` 的检查项（M3-14、M5-10）发现问题 → 提醒但不阻断

---

### ✅ 通过条件

**判定规则**：不产生 `error` 级结果

- 所有执行的检查项（必查 + 触发的可选项）均未产生 `error` 级结果
- 允许存在 `warning` 级结果（M5-10 硬编码颜色、M3-14 废弃字段），不阻断上线

**不通过情况**：

- 任何一个检查项产生 `error` 级结果

---

### 📝 如何生成健康度检查报告

1. **执行检查脚本**（仓库根目录，推荐使用 `package.json` 中定义的 `mc-check` 脚本）：

```bash
# 检查全部组件（推荐）
npm run mc-check

# 检查单个组件
npm run mc-check -- <组件名>

# 等价的原生命令（直接调用脚本）
node aidocs/skills/frontend-mc-check/scripts/mc-check.cjs
node aidocs/skills/frontend-mc-check/scripts/mc-check.cjs <组件名>
```

2. **查看报告产物**，脚本自动生成到 `aidocs/output/reports/<日期_时间>/`：

| 文件                 | 说明                                    |
| -------------------- | --------------------------------------- |
| `check-result.json`  | 检查结果数据（各检查项 pass/error/warning） |
| `mc-report.html`     | 可视化检查报告                          |
| `mc-report.md`       | Markdown 检查报告                       |

3. **解读结论**：所有执行检查项均未产生 `error` 级结果，即判定通过，允许上线。
