# Figma 管线规范检查插件

> 一键检查 Figma 设计稿是否符合管线规范，降低整理成本从 5-15 分钟到 2-3 分钟

## 功能特性

### ✅ 6 项核心检查

检查项分为三个级别：
- ** Error（错误）**：必须修复，否则生成会失败或严重错乱
- **⚠️ Warning（警告）**：建议修复，否则还原度降低
- ** Info（建议）**：可选优化，不影响生成，仅提升代码质量

#### 必查项（Error/Warning）

1. **根容器命名检查**（ Error）
   - 检测无意义命名：`Frame 123` / `Group 456` / `Rectangle 789`
   - 修复：用语义化命名，如 `cp-流量监测` / `cp-traffic-monitor`

2. **背景图命名检查**（⚠️ Warning）
   - 检测含图片填充的节点是否规范命名
   - 有效命名：`bg` / `bg-*` / 含「背景」关键词
   - 不修复后果：背景图不下载

3. **图标命名检查**（⚠️ Warning）
   - 检测 VECTOR/COMPONENT 节点是否规范命名
   - 有效命名：`icon` / `icon-*` / 含「图标」「箭头」关键词
   - 自动跳过 ≤12px 的装饰性元素
   - 不修复后果：图标不下载

4. **图表区域标记检查**（⚠️ Warning）
   - 检测图表容器是否标记 `@echarts` / `@chart`
   - 不修复后果：导出 3~4px 宽的柱子/坐标轴碎片 → 资源爆炸

5. **根容器 Auto Layout 检查**（❌ Error）
   - 根容器必须有 Auto Layout
   - 检查 `layoutMode` 是否为 `HORIZONTAL` 或 `VERTICAL`
   - 不修复后果：布局方向不确定 → 元素重叠

#### 优化项（Info · 可选）

6. **子容器 Auto Layout**（💡 Info）
   - 建议子容器也添加 Auto Layout
   - 不修复影响：布局还原度略降，但能正常生成

7. **按钮/Tab 命名**（💡 Info）
   - 建议按钮命名为 `btn-*`，Tab 命名为 `tab-*`
   - 不修复影响：代码可读性略降，不影响生成

8. **节点层级深度**（⚠️ Warning）
   - 检测节点树深度是否 > 4 层
   - 建议扁平化结构

## 安装方法

### 方法 1：本地开发模式（推荐）

1. 打开 Figma → 菜单 → 开发 → 开发插件
2. 点击「导入插件」
3. 选择 `manifest.json` 文件
4. 插件安装完成

### 方法 2：发布到 Figma Community（可选）

1. 在 Figma 中打开插件
2. 点击「发布到 Community」
3. 填写插件描述和截图
4. 提交审核

## 使用方法

### 基本使用

1. **选中要检查的 Frame 或组件**（不选中则检查整个页面）
2. 运行插件：**Figma 菜单 → 插件 → Figma 管线规范检查**
3. 查看检查结果面板

### 检查结果说明

#### ✅ 检查通过
- 所有必查项均已符合规范
- 可以直接提交 Figma URL 生成代码

#### ❌ 检查未通过
- 发现错误，需要修复后才能提交生成
- 插件会自动高亮第一个问题的节点
- 点击错误项可查看具体问题和修复建议

#### ⚠️ 警告
- 不影响生成，但可能降低还原度
- 建议修复以提升生成质量

#### 💡 建议
- 优化建议，不影响生成
- 修复后可提升代码可读性和可维护性

### 检查结果操作

- **📋 复制检查报告**：将检查结果复制为 Markdown 格式，方便分享和记录
- ** 重新检查**：修复问题后重新运行检查
- **自检清单**：逐项核对提交前的必查项

## 检查规则详解

### 命名规则

| 元素类型 | 有效命名模式 | 级别 | 不修复后果 |
|---------|------------|------|-----------|
| 根容器 | `cp-*` / 语义化英文 | ❌ Error | 代码可读性差 |
| 背景图 | `bg` / `bg-*` / 含「背景」 | ⚠️ Warning | 背景图不下载 |
| 图标 | `icon` / `icon-*` / 含「图标」「箭头」 | ⚠️ Warning | 图标不下载 |
| 图表 | `@echarts/*` / `@chart/*` | ️ Warning | 资源爆炸 |
| 按钮 | `btn-*` / `button-*` | 💡 Info | 代码可读性略降 |
| Tab | `tab-*` |  Info | 代码可读性略降 |

### Auto Layout 要求

| 容器类型 | `layoutMode` | `padding` | `itemSpacing` | 级别 |
|---------|------------|----------|--------------|------|
| **根容器** | 必须 HORIZONTAL/VERTICAL | 至少一边 ≥ 8px | ≥ 8px | ❌ Error |
| **子容器** | 建议 HORIZONTAL/VERTICAL | 建议 ≥ 8px | 建议 ≥ 8px | 💡 Info |

**快速添加 Auto Layout**：选中节点 → 按 `Shift+A`

**说明**：
- 根容器缺少 Auto Layout →  **布局重叠**（必须修复）
- 子容器缺少 Auto Layout →  **还原度略降**（可选修复，Vision 可兜底推断）

### 层级深度要求

- **推荐**：≤ 4 层（根容器 → 模块 → 子模块 → 元素）
- **警告**：> 4 层
- **风险**：生成代码可读性差，嵌套过深

## 修复流程

### 发现错误后的修复步骤

1. **查看错误详情**：阅读错误描述和建议
2. **定位问题节点**：插件会自动高亮问题节点
3. **修复命名**：双击节点名称 → 修改为规范命名
4. **添加 Auto Layout**：选中节点 → `Shift+A` → 设置属性
5. **重新检查**：点击「🔄 重新检查」按钮
6. **确认通过**：所有错误修复后，检查通过即可提交

### 常见修复操作

#### 修复根容器命名
```
Frame 123 → cp-流量监测
Group 456 → cp-traffic-monitor
```

#### 添加 Auto Layout
1. 选中根容器
2. 按 `Shift+A`
3. 设置 `layoutMode` 为 `HORIZONTAL` 或 `VERTICAL`
4. 设置 `padding` ≥ 8px
5. 设置 `itemSpacing` ≥ 8px

#### 修复背景图命名
```
Rectangle 45 → bg-header
Background → bg-card
```

#### 修复图标命名
```
Vector 78 → icon-close
Component 9 → icon-arrow-right
```

#### 标记图表区域
```
Group 345 → @echarts/bar
Frame 567 → @echarts/pie
```

## 技术实现

### 检查逻辑

插件通过 Figma Plugin API 读取节点树数据：

```typescript
// 示例：检查根容器命名
if (path.length === 0 && node.type === 'FRAME') {
  if (isMeaninglessName(node.name)) {
    results.errors.push({
      id: 'root-naming',
      name: '根容器命名不规范',
      severity: 'error',
      message: `根容器使用了无意义命名：${node.name}`,
      suggestion: '建议：使用语义化命名',
    })
  }
}
```

### 判定算法

- **无意义命名**：正则匹配 `Frame \d+` / `Group \d+` 等模式
- **背景图检测**：检查 `fills` 数组中是否有 `IMAGE` 类型
- **图标检测**：节点类型为 `VECTOR` / `COMPONENT` 且尺寸 > 12px
- **图表检测**：检测子节点中是否有窄而高的矩形（柱状图特征）
- **Auto Layout**：直接读取 `layoutMode` 属性

## 常见问题

### Q: 为什么检查不通过？
A: 检查不通过（Error）通常是因为：
- 根容器使用了无意义命名（如 `Frame 123`）
- 根容器缺少 Auto Layout（`Shift+A` 添加）
- 这两项必须修复，否则生成会失败或严重错乱

### Q: 警告项（Warning）必须修复吗？
A: 警告项不影响生成成功率，但修复后可提升还原度：
- **背景图/图标命名**：不修复 → 资源不下载 → 元素消失
- **图表标记**：不修复 → 资源爆炸（100+ 碎片）
- **建议**：优先修复 Error，时间充裕再修复 Warning

### Q: 建议项（Info）需要修复吗？
A: Info 项完全可选，不影响生成：
- **按钮/Tab 命名**：不修复 → 代码可读性略降（生成代码中保留 `Button 1` 原名）
- **子容器 Auto Layout**：不修复 → Vision 可兜底推断，还原度 70-85%

### Q: 检查通过了但生成还原度还是低？
A: 检查通过只保证基础规范，还原度还受以下因素影响：
- Figma 数据的完整性（颜色、字体、尺寸）
- Vision 解析的准确性
- 管线的实现细节

### Q: 检查通过了但生成还原度还是低？
A: 检查通过只保证基础规范，还原度还受以下因素影响：
- Figma 数据的完整性
- Vision 解析的准确性
- 管线的实现细节

### Q: 如何跳过某些检查项？
A: 当前版本不支持跳过检查。如有特殊需求，可在插件代码中修改检查规则。

## 开发指南

### 本地开发环境

1. 安装 Node.js（v16+）
2. 安装 TypeScript
3. 安装 Figma Plugin CLI

```bash

```

```bash
# 开发模式
figma plugin build --watch

# 生产模式
figma plugin build
```

1. 打开 Figma → 开发 → 插件 → 当前插件
2. 点击「调试」按钮
