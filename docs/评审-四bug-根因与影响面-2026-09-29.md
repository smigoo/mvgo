## 2. Bug2 · `mountUnusedResourceIcons`（今日新增，未提交）

**位置**：`src/ai-engine/utils/resource-import-guard.js:1296-1340`（`git diff` = **+98 行，未提交**）

### 2.1 根因（**候选域口径不等**，铁证）

| 侧 | 候选域 | 实现 |
|---|---|---|
| **门禁** `findUnmountedResourceVars` | **本文件 `<script>` 里 import 了的资源变量** | `code-structure-validator.js:551-571`：先用 `importRe` 枚举本文件 import，再逐个判 `!isResourceVarMounted` |
| **自愈器** `mountUnusedResourceIcons` | **整个 mapping 的全部 icon** | `resource-import-guard.js:1306-1311`：`for (const [varName] of varToMapping)` + `isResourceVarMounted` |

两者**共用** `isResourceVarMounted` 只保证「**单个变量是否被引用**」同口径，**没有保证「候选集」同口径**。
差值 = 「mapping 里有、但本文件没 import 的 icon」。自愈器对差值执行「挂载」⇒ 注入 `<img :src="iconN">` 而 `iconN` **在本文件未声明** ⇒ **SFC 语义门禁必然命中**。

`isResourceVarMounted(c, v) === false` 其实含两种语义：
- **(a)** 本文件 import 了但没引用 ← 这才是 CODE-022 目标
- **(b)** 本文件既没 import 也没引用 ← **与本文件无关**

判据无法区分 (a)/(b)，而「挂载」方向只对 (a) 合法 ⇒ **对 (b) 挂载 = 制造悬空引用**。
（这正是 memory 已记的「同一事实两处姿态相反」的又一实例：**只共用了判据的一半**。）

## 4. Bug4 · `deriveChildLayout` 的 `xSpread > ySpread` 判据

**位置**：`src/ai-engine/utils/section-tree.js:2027-2044`；调用点仅 **2 处**（`1903`、`1982`）⇒ `sections[].layout` 的**唯一来源**

### 4.1 根因

```js
const ySpread = Math.max(...ys) - Math.min(...ys)
const xSpread = Math.max(...xs) - Math.min(...xs)
if (xSpread > ySpread) return 'horizontal'   // ← 用「坐标散布范围」代替「side-by-side 比例」
```
