## 2. 设计原则（硬约束，全部包通用）

1. **Fail-open**：所有新校验首版只留痕（写 meta 独立字段），不阻断落盘；证据不足即跳过，绝不误伤。
2. **宁缺勿造**：契约解析不可辨时返回 null（口径同 `splitTitleValueByStyle`），不猜不兜。
3. **单源铁律**：同一属性只有一个权威来源 —— **结构归 node（文本/绑定/顺序/外层几何/techstack），像素归 vision（图表内层配色/渐变/图例/markLine/立体感）**。同一属性禁止双源。
4. **零硬编码**：无组件名/颜色字面量/尺寸字面量/图表类型特判分支；阈值全部走 config 常量文件，带注释可调。
5. **全适用**：契约按「帧名/样式可辨」通用规则触发，不针对特定组件。
6. **不影响现有流程**：新逻辑全部独立新模块（纯函数导出），现有门禁文件只加一行调用；可独立 jest、可离线 A/B。

## 4. WP1：视觉阶段 chartSpec（治 RC6）

**目标**：图表内层像素事实在视觉分析阶段一次性产出结构化 `chartSpec`，生成节点只消费不分析。

**做法**：
- 视觉分析 provider 的输出 schema 增加 `charts[]`（由 planner 已识别的 chart 节点驱动，触发边界=planner chart 识别，无图表组件零开销）。
- prompt-builder.js / vue3-engineer.js 把 chartSpec 注入图表生成 prompt 的确定性事实区，并声明「配色/图例/markLine 以 chartSpec 为准，禁止臆造」。
- **schema 红线**（禁文本/数值字段，防双源）：刻度值、系列名、markLine 文案、准确率等一律不进 chartSpec（node TEXT 单源）；tooltip 数值标注为 mock；伪 3D 只输出风格描述；地图不进 chartSpec（归 MvMap）。
- **跨图一致性校验**：同一组件多图时校验色板风格一致（留痕级）。
- **主题文字色**：chartSpec 不产出文字色，默认走 css-vars；治 feb1f87a `#EDF4FB` 与 7106503f 自贴色。

**chartSpec 字段**（全部「预估尽量还原」，无精确值硬约束）：

| 字段 | 覆盖图表类型 | 说明 |
|---|---|---|
| palette[] | 全类型 | series 顺序色 |
| gradient | 柱/面积/环 | 方向+起止透明度 |
| barWidth/gap/roundCorner | 柱状 | 相对预估 |
| lineWidth/smooth/symbol/areaOpacity | 折线/面积 | |
| innerRadiusRatio（环厚度） | 饼/环 | 治四案环形图厚度 |
| legend | 全类型 | 位置/形态/显隐；文字归 node |
| axis | 直角坐标系 | xy 显隐、轴线/分割线颜色粗细 |
| markLine/markPoint | 折线/柱 | 颜色/粗细/形态；文案归 node |
| radar/dashBoard/scatter 专有 | 雷达/仪表/散点 | 层数、轴线显隐、点大小 |
| styleHints | 全类型 | 伪 3D、立体感、背景有无 |

**注入点**：视觉分析 schema/ prompt（vision 侧产出）→ `roles/microcode/prompt-builder.js` + `roles/vue3-engineer.js` 双线消费。

## 5. WP2：卡片项资源绑定契约（治 RC1/RC3/RC5）

**目标**：图标/背景 ↔ 业务项的绑定、顺序、var 编号由确定性契约产出，替代 LLM 猜。

**做法**（样板：`techstack-section-contract.js:225 extractTableContract` 的「契约成功才吸收、fail-open」模式）：
- 新模块 `resource-item-contract.js`（纯函数）：输入 Figma 子树（复用 `collectSubtreeTexts` 三类真值），识别「重复卡片项」结构（同构子帧序列），输出 `[ { itemText, bgNodeId, iconNodeId, visualOrder } ]`。
- 识别规则通用化：同层同构子帧 + 每帧内恰好 1 bg + 1 icon + 文本；**不可辨返回 null**，绝不猜。
- 视觉序：按 Figma 节点几何（x/y）排序输出 visualOrder，DOM 生成按 visualOrder（治 RC3）。
- var 编号：icon/bg 资源变量按 visualOrder 分配（治 RC5），不再按文档遍历序。
- 契约成功 → 吸收为确定性绑定注入 prompt；失败 → 走现状（fail-open）。
- 图例文字类交叉校验（vision↔node）冲突时以 node 为准，留痕。

**注入点**：双线同 WP1。

## 6. WP3：渲染探针（治 RC4 门禁盲区）

**目标**：产物落盘后、交付前，用真实渲染结果补盲区（四案坏产物 meta 全 0 的直接对策）。

**做法**：
- 挂点：`screenshot-renderer.js` 现有 page.evaluate 阶段追加只读探测（复用既有截图流程，不新增渲染开销量级）。
- 探测项（全部只读，输出 DOM 事实）：
  1. `img[src=""]` / 无 :src 的 img（治 feb1f87a）
  2. 文字对文字背景对比度 < 阈值（治 7106503f，阈值走 config）
  3. 子元素溢出被裁（scrollWidth/Height > client 且祖先 overflow hidden，治 11afe1c9 tab 裁切）
  4. 零可见尺寸的文本容器（塌缩槽，治 header-right 8px）
  5. 图表容器有占位但无 echarts 实例（治 N2 兜底面）
- 结果写 meta **独立字段 `renderProbes[]`**，只留痕。

## 7. WP4：头部槽收缩守卫（治 RC2 直因）

**目标**：百分比尺寸落在「自身不约束尺寸的收缩容器」时留痕。

**做法**：

## 13. 评审记录（2026-10-08 · d9a0ab7d 三问反向考古：之前的改动是否造成现在的问题）

### 13.1 Q1 bg 错配 + `::before` 空壳 —— **成立：三条治本规则叠加死锁**

| 规则 | 来源 | 单独看 | 叠加后 |
|---|---|---|---|
| bg 禁止独立 DOM，必须绑「已有业务容器」:style | `310578d`（E1 样式保真治本） | 治空壳 DOM 正确 | 「业务容器」无定义 → value span(36×26) 被当容器 |
| 半透明 bg 例外→独立成层（relative+inset:0 层） | `af7c652`（透明度归属治本） | 治透明度传染正确 | 允许写 ::before 层 |
| 禁止 scoped CSS 写 `url(varName)` | `15ea74f` 前后 | 防 LESS 变量编译崩溃正确 | ::before 里写不了 url → **只写出空壳** |
| 无「已下载资源未引用」门禁 | 一直缺位 | — | bg-124/125 孤儿零感知 |

组合效果：唯一合法出路只剩 inline :style，但逐卡绑定契约（WP2）缺位 → LLM 挂了一张（bg-126 到 value span），两张丢弃，::before 死壳。**各治各的实锤、无规则组合回归**。

**修正（并入 WP2）**：① 契约给出多卡多 bg **正解模板**（逐卡 inline 绑卡片根容器）；② 「独立成层例外」的合法写法改为 inline :style 专用层（或给资源 import 的编译期 url() 例外通道），消除与规则3的冲突；③ 新增「已下载未引用资源」探针（WP3）。

### 13.2 Q3 小标题阴影 —— **成立：主题覆盖层对非令牌化字面量失效**

- 机制：`mc-skeleton.js:46 THEME_WRAPPER_TEMPLATES`（mc-check M4-5）把整个 common.less 复制进 `&.dark`/`&.light`，仅切换 CSS 变量。
- `color: var(--colorTextPrimary)` 令牌化 ✓ 两主题正常；`text-shadow: 0 5.05px #333` 硬字面量 ✗ → 两主题同值。
- 根因：**序6颜色接管只收编了颜色，未收编 effects/shadow**（Figma 真值 `5.0479px` 直接落字面量）。
- 修正（并入 WP2/WP3）：① effects→令牌化（如 `--textShadowPrimary`）或 light 变体确定性剥离装饰阴影；② 新增「主题变体值一致性」留痕（`.dark/.light` 同规则同值且非 var → 留痕）。

### 13.3 Q2 tabs —— 无「改坏」证据

代码/生成快照/本地渲染三处均有 tabs；等用户确认截图来源（生产未同步 or 窄容器溢出）后再定。

- 上一轮称「index.css/common.less/index.less 三处漂移」**不准确**：index.less 是生成器固定模板（根主题+@import common.less），common.less 才是样式单源，index.css 是其编译产物——机制如此设计。真正缺陷是 13.2 的主题字面量问题。

**判据演进**（8db2b3b7 真实重放驱动，0 命中必查）：
- 判据 A（方案原文口径）：百分比尺寸（{axis} 含 % 或 flex-basis %）落在无保护 flex 子项（四条保护：flex-shrink:0 / {axis} 显式尺寸 / min-{axis}>0 / overflow hidden）。
- 判据 B（重放 0 命中后补，stat-row 9px 实锤形态）：flex column + space-between/around 容器高度依赖外部（height 为 %/flex/未声明），直接子项（含 v-for 单节点展开）**解除 min-content floor**（显式 min-{axis}:0 或 overflow 非 visible）且无硬保护 → 塌缩高风险。未解除 floor 的子项有 min-content 兜底只会溢出不会塌 → 不判（降误报）。

**实现**（`flex-shrink-guard.js`，纯函数可离线重放）：

- **flex 简写陷阱**：`flex: n n 0` 第三值是 **basis 不是 shrink**——shrink 判定看第二值（两值/三值形态），`flex: none` ≡ 0 0 auto 算保护。
