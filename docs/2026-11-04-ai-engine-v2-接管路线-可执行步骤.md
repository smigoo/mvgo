| roles | **11** | `figma-connector`(figma-adapter:67) · `visual-parser`(node-registry:120) · `layout-reviewer`(:165) · `style-mapper`(:179) · `layout-refiner`(:261) · `style-refiner`(:285) · `adversarial-checker`(:311) · `screenshot-renderer`(:366) · `visual-comparator`(:418) · `microcode-engineer`(:49) · `vue3-engineer`(:50) |

### 1.3 🔴 关键事实修正：v2 并未绕开旧管线守卫链

这是我上一轮口头评估里最容易搞错的一点，代码证据如下。

`configurable-pipeline.js:341-347` 的节点调用是三分支：

```js
const raw = meta.invoke
  ? await meta.invoke(role || fn, params, ctx)
  : fn
    ? await fn(params)
    : await role.execute(params)          // ← code-engineer 走这里
```

`code-engineer` 节点没定义 `invoke`，`kind: 'class'`，所以走 `role.execute(params)`——
即**直接调用 `MicrocodeEngineer.execute()` / `Vue3Engineer.execute()` 原方法**。而这两个 execute 内部：

- 写盘前 pass 链：`runPreWriteSelfHealing`（`microcode-engineer.js:8636` / `vue3-engineer.js:2079`）
- 唯一写盘出口：`file-writer.js#writeFiles`（`:785`）

**结论**：v2 在**生成写盘路径**上整链条继承了旧管线的全部 30+ 守卫。

| 此前的误判 | 代码事实 |
|---|---|
| 「v2 完全不引 quality-score / font-size-guard / style-tokens / resource-import-guard / pre-write-self-healing / mc-check」 | 引用数确实为 0，**但它们全部在 `role.execute()` 内部下游被调用**，v2 无需直接引用 |

⇒ **「接管」的真实成本远低于预想**：不是重写管线，而是**「换壳 + 逐步替换壳内 role 实现」**。
这直接决定了本文的路线选择：**不做平行架构，v2 只做入口与编排，内容改造全部落进 role。**

### 1.4 🔴 已定位的真实缺口：精修节点绕过守卫链

`layout-refiner` / `style-refiner` 各自 `writeFileSync` 直写磁盘，**不经 `writeFiles`、不经 `runPreWriteSelfHealing`**：

| 文件 | 直写点 |
|---|---|
| `ai-engine/roles/layout-refiner.js` | `:609` · `:702` · `:718` |
| `ai-engine/roles/style-refiner.js` | `:753` · `:847` |

旧管线同样存在（refiner 在 engineer 之后跑），**但 v2 把它固化成独立节点 `touchesDisk: true`**，
配合 `_syncIfDirty`（`configurable-pipeline.js:277`）磁盘回读——意味着**精修结果会覆盖 `state.code`，而它没经过任何写盘前 pass**。
`max` 档 `refineLoops: 2` 会把这条无守卫路径跑 2 轮。**这是接管前必须补的第一优先级缺口。**

### 1.5 质量分与视觉审查层的既有链路（公用层已成立）

```
adversarial-checker.resultPatch      → qualityScore（node-registry.js:353，v2 内唯一来源）
screenshot-renderer                  → publishQualityPreview + hardGate + 缺图自愈
visual-comparator.compare            → report + formatForRefiner 指引（降级置 null，不置 0）
revision-decision                    → 合并分 = 文本×0.5 + 视觉×0.5，threshold 75
                                     visualUntrusted 时退回单边分（configurable-pipeline.js:464+）
```

用户要的「**视觉模型审查布局结构，这部分公用的**」在 v2 里**已经结构性成立**：
`visual-parser / layout-reviewer / visual-comparator` 属 `SPEC_AGNOSTIC_NODES`，`promptProp` 为空或指向通用 `guidelines`，
与 `spec` 无关。**这一层不需要新建，只需要断言化与观测化。**
