## 0. 现状：4 条独立变换链（取证清单）

| # | 链 | 产出/改写内容 | 位置 |
|---|---|---|---|
| A | 实例前缀推导 | `c-{semantic}-{sessionTail}`（决定 DOM 长类前缀） | `utils/component-naming.js:160 buildComponentId` / `:175 classPrefixOf` |
| B | 模板类名补前缀（CODE-020） | 模板中「无前缀短类」→ 加实例前缀 | `utils/class-prefix-fixer.js:33 fixMissingClassPrefixes`，调用点 `roles/microcode-engineer.js:6474` |
| C | scoped 短类 ↔ DOM 长类重写 | 收敛进 common.less 时把选择器改写成 DOM 实际形态 | `utils/style-class-consolidator.js:391 buildClassRewriteMap` / `:429 registerClassToken` / `:477 rewriteShort` |
| D | 结构类确定性生成 | 内容根类 `c-{semantic}-slot-con`、section 根类 | `roles/microcode/code-generator.js:146-169 buildDeterministicIndexTemplate` |
| E | 修复器自造类（**方言源**） | 生成 `:class="{ 'is-active': ... }"` 等另一套修饰符方言 | `roles/microcode/code-healer.js:1339-1344` |

**缺陷本质**：
- B/C/A 对同一批 class 独立推导，**无共享事实源** → B 的模板改写结果 C 不知道，C 的 DOM 采集 A 不知道；
- C 的映射表用「剥修饰符的基名」做键 + `!map[base]` 先到先得 → `X` 与 `X--active` 互相抢占，
  **攻击面随模板属性书写顺序漂移**（先见静态 `class` → 激活选择器丢后缀；先见 `:class` → 基类选择器被改写为激活类）；
- E 引入第二套修饰符方言（`is-active` / `--active` 并存），使任何基于命名的判定都可能漏。

**量化影响面**（workspace 254 组件）：含修饰符选择器 **97** 个，呈「重复选择器 + 修饰符」疑似缺陷形态 **28** 个。

## 1. 目标（可验收的不变量）

| 编号 | 不变量 | 验收口径 |
|---|---|---|
| S1 | **事实源唯一** | DOM class 集合每个文件只采集一次（生成期），下沉为只读 `classFacts`；下游禁止再自扫模板解析 class |
| S2 | **变换一次** | 类名「补前缀」只由一处写入（B 收口为 classFacts 的唯一消费者 + 唯一写入者） |
| S3 | **修饰符不丢失** | `--mod` / `-active` 后缀在映射与重写中**逐字保留**；禁止跨修饰符合并到同一映射键 |
| S4 | **双向一致（新增 I7）** | 模板出现的修饰符类必须有对应样式规则；样式中的修饰符规则必须有模板使用（详见 §4） |
| S5 | **方言统一** | `--mod` 为唯一标准修饰符形态；`is-active` 等别名经归一化表登记（别名可扩展，但必须显式登记） |

## 2. 数据流设计（事实对象）

复用 R1-2 已验证的「事实数据流」模式（`_indexTemplateFacts` → `rootLayoutFacts` → pipeline.context），
不新建通道。

```js
// utils/class-facts.js（新增，唯一采集实现）
/**
 * @typedef {Object} ClassFacts
 * @property {string} semantic            // c-env-monitor
 * @property {string} instancePrefix      // c-env-monitor-tmyakrli（classPrefixOf 唯一产者）
 * @property {string|null} rootContainerClass
 * @property {Record<string, FileClassFact>} byFile
 * @property {'deterministic'|'llm'|'healed'} source
 */
/**
 * @typedef {Object} FileClassFact
 * @property {string[]} exact                        // DOM 精确类 token（原样，含修饰符）
 * @property {Record<string,string[]>} byBase        // 语义基名 → 精确 token 数组（不合并修饰符）
 * @property {Record<string,string[]>} modifiers     // 基名 → 修饰符后缀数组（['--active','--on']）
 */
export function collectClassFacts(files, { instancePrefix = '' } = {}) {}
```

**传递链（与 R1-2 同构）**

```
buildDeterministicIndexTemplate()  ──(template, rootContainerClass, sectionRoots, domClasses)
        ↓ input._indexTemplateFacts / _classFacts
generateCode() ──→ execute() ──→ pipeline.context.classFacts
        ↓ 只读消费
  ├─ style-class-consolidator（重写映射改由 facts 提供，不再自扫模板）
  ├─ class-prefix-fixer（补前缀决策改由 facts 驱动）
  ├─ code-healer（生成模板前查 facts，禁止自造方言）
  └─ artifact-invariants（I5 / I7 校验基准）
```

**fail-open 契约**：`classFacts` 缺失（老路径 / 非微码）→ 各消费方回退现有行为，**不引入新错误**。

## 4. I7 不变量定义：修饰符类双向一致

**归一化**：`MODIFIER_ALIASES = { 'is-active': '--active', 'active': '--active', '--on': '--active', '--selected': '--selected', ... }`
（别名表显式登记，未登记别名按字面处理并在 warning 中提示补表）。

| 方向 | 判定 | 级别 |
|---|---|---|
| ① 模板 → 样式 | 文件模板出现修饰符类 `X--mod`（含 `:class` 字面量，归一化后），但全部样式源中**无匹配该精确类**的规则 → 激活态必然失效 | **error** |
| ② 样式 → 模板 | 样式源存在 `X--mod` 规则，但该文件模板未出现该修饰符类 → 死规则 / 疑似被 base 化（本次事故形态） | **warn** |

- 与 I5 分工：**I5** 查「模板基类是否有样式声明」；**I7** 查「修饰符类双向一致」；两者共用 `classFacts`。
- 输出样例：
  - `I7 error (package/components/ContentSection.vue) 模板激活类 c-env-monitor-tab-item--active 无对应样式规则（激活态失效）`
  - `I7 warn  (resources/styles/common.less) 规则 .c-env-monitor-tab-item 疑似激活态被 base 化（源 selector 含 --active）`

## 6. 风险与约束（必须遵守）

| 风险 | 后果 | 约束 |
|---|---|---|
| 多形态候选择一 | 重新引入顺序依赖（换写法即错） | 一律**逗号双写**，不择一 |

| 存量产物 | —— | consolidator 仅在生成期 `writeFiles` 出口运行 → **存量零影响**，仅重生成体现变化 |
