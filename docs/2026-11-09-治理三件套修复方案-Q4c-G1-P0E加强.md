## 0. 背景：触发链与「成对落地」原则

今日真机四批暴露的完整病理：

```
Max 管线（deepseek-v4.1-flash）对高密度画板（2:8417/2:9778）：
  planner 随机分叉：xl 完整方案 vs l 极简方案
```

**原则**：T1（消除误杀）与 Q4-c（内容硬闸）必须成对——只 T1 放行残缺，只 Q4-c 回到 fail-closed。三件套齐了才是「**完整、合规、结构正确才放行**」的边界。

## 1. Q4-c：内容完整性硬闸

### 查重
- TEXT-COVERAGE（09-28 既有）：真值文本覆盖率 <40% BLOCK / <60% WARN——**只看文本覆盖率单指标**，56% 卡 WARN 区放行了 12 卡缺失的残缺版
- subcomponent-coverage（R2）：plan 组件数 vs 磁盘组件数——**以 plan 为基准**，plan 本身残缺（l 方案只规划 3 个）时守卫按 plan 通过 ⇒ 盲区
- 无「文本覆盖率 × 段锚覆盖」联动的硬闸 ⇒ 不重复，为本刀

### 根因
「内容完整性」的多信号（文本覆盖 56%、TECHSTACK-NOT-RENDERED×2、vision 段无承载）各自孤立落在 WARN 层，无联动升级——删内容即可过闸。

### 修法（落点：`code-structure-validator.js` TEXT-COVERAGE 判据块）
在 TEXT-COVERAGE 评估处增加**段锚覆盖联动**：

```
信号 A：文本覆盖率 < 60%（既有 WARN 阈值，<40% 已 BLOCK）
信号 B：段锚覆盖缺口 —— vision layout sections 的直接段 id 集合中，
        产物（全部 files 的 data-section-id）未覆盖的比例 ≥ 50%
联动判定：A && B ⇒ severity 升级 BLOCK（id: TEXT-COVERAGE-GATE）
        A && !B ⇒ 维持 WARN（文本缺但段都在 = 局部欠佳，不拦发布）
```

- 数据源：validator 已有 `analysis.layoutStructure`（vision 段树）+ `files`（产物）——`figmaNodeData` 已透传（P0-C 时加的），零新增入参
- 阈值 50%：段过半缺失才算「整层缺失」（单段缺失交由 unmaterialized/anchors 域）——阈值是判据参数非业务硬编码，写常量并注释依据
- 防误杀：d4c2726b 类「锚形态不同但内容在」（tab 数据驱动渲染）——段锚覆盖按「产物任一形式承载」（data-section-id 或段内文本已渲染）计覆盖；实现按「vision 段的 truthTexts 任一条出现在产物」记为该段已承载

### 影响面
- `code-structure-validator.js` 一处；gate-severity 策略表不动（BLOCK 由 validator 直接产）
- 波及：L0-B 重试循环（新增 BLOCK 会触发重试——l 极简方案重试仍极简 ⇒ 重试耗尽 fail-closed，**符合「宁拦不放」的用户裁决方向**）
- 已知代价：内容确实残缺的单会从「completed+灾难产物」变成「failed+明确死因」——失败可见性好于灾难上线

### 对照
- 阳性：a9052d6a 产物重放（文本覆盖 56% + 段缺失）⇒ TEXT-COVERAGE-GATE BLOCK
- 阴性：4ae7a7b4 产物（覆盖率高、段全）⇒ 不触发；2e747c5d（单段缺但 <50%）⇒ 不触发

## 2. G1：容器布局真值注入（文件已写：`container-layout-truth.js`）

### 查重
- W1（段几何透传）、R9-c（横排定宽 heal）、percentHeightStretch（撑满检测 WARN）——均不含「容器零样式块」判据与「方向+比例注入」⇒ 不重复
- 家族定位：布局真值注入第三刀

### 根因（669d8bf8 实锤）
`1263-38-con / 2-3446-con / 2-3496-con` 三容器在 common.less 零样式块、行内无 display——真值两卡横向并排（x=32/x=227 同 y）被块级堆叠成纵向，右卡掉位、底图塌陷、文本散排。

### 修法
- **判据**：index.vue 带 `data-section-id` 的容器（class 在全部样式源零规则块且行内无 display）⇒ 零样式容器
- **注入**（全部来自 Figma bbox，零硬编码）：
  - 方向：段树子节点 bbox 同 y 异 x ⇒ `display:flex;flex-direction:row`；同 x 异 y ⇒ column；混合/单子 ⇒ 跳过不猜
  - 比例：row 按宽比 / column 按高比，子元素行内追加 `flex: <w/sum>`
- **挂载**：`pre-write-self-healing.js` ⑥-d（R9-c 之后），`childrenBoxesOf` 回调从 effectiveSections 树取子节点 figmaBox（与 W1/R9-c 同一事实源）
- **计数**：`g1Scanned/g1ZeroStyle/g1Injected/g1Skipped*` 恒打

### 实施注意（半成品清理项）
- 现文件的 `out/html/finalContent` 变量逻辑混乱，接线前重写干净（模板段替换策略简化为「全文串替换、逐 tag 精确 replace」）
- 子项 flex 注入需跳过已有 `flex:` 声明的子项（与 R9-c hasFlexSemantics 同口径）

### 对照

## 3. P0-E 加强：重锚祖先链兼容校验

### 根因（a9052d6a 新识别风险面）
重锚 6 条 tab 文案 `2:8439→2:8827（监控）` 等**跨 id 段跳变**——P0-E 判据只验「文案全树唯一命中」，未验命中节点与原锚的**容器/层级兼容性**。若 vision 原锚是「tab 项容器节点」（文案只是其 label），重锚到纯 TEXT 叶子会把容器锚降级成叶子锚 ⇒ 装配结构可能错乱。（8ebb795b 4/4 效果好 = 锚本来就指错；a9052d6a 6 条为潜在降级形态。）

### 修法（落点：`vision-content-anchor-consistency.js` reanchorMisalignedDeclaredTexts）
重锚前增加**同容器校验**：命中节点与原锚节点在 Figma 树中的**父节点 id 相同**（同容器内平移）⇒ 允许重锚；跨容器 ⇒ 记录 `relinkSkipped`（不猜）。8ebb795b 案例的 4 条为同容器平移 ✓ 不受影响；a9052d6a 的 6 条若跨容器则被拦（保守）。

- 实现：indexWalk 时同时记录每个 TEXT 节点的 parentId；校验 `parentId(hit) === parentId(oldAnchor)` 或两者父链 LCA 为 section 级
- 注意：原锚可能是 VECTOR 容器（无文本），命中是同容器的 TEXT——parentId 相同判定成立 ✓

### 对照
- 阳性：8ebb795b 4 条（同容器）⇒ 仍重锚
- 阴性：跨容器唯一命中 ⇒ relinkSkipped 计数

## 5. 评审修正（2026-11-09 17:48 评审轮 · 实现必须吸收）

### A1（Q4-c）段树形态口径——443/443 死代码坑
`state.layoutStructure` 真实形态是 `{ layout: { sections: [...] } }`，**直接读 `.sections` 是全语料 443/443 实测恒不可达的死代码路径**（证据：code-structure-validator.js:1740-1742 注释、layout-direction-guard.js:6-12 + :398 归一化先例）。信号 B 取段必须写死：
```js
const sections = layoutStructure?.layout?.sections || layoutStructure?.sections || []
```

### A2（Q4-c）信号 B 必须读 productFiles——增量轮门禁空转坑
L0-B 增量校验时 `files` 被裁成「变更文件 ∪ {common.less, declare.json}」子集（phase2:5096-5107），未变更子组件缺席 ⇒ 段锚扫描空转（CODE-024/025/026 同一个坑，validator:1755 已有先例警告）。**段锚覆盖与 truthTexts 承载判定一律基于 `productFiles`（全量）**。既有 TEXT-COVERAGE 用 `files` 扫 CJK（:2756）在增量轮同样失真——本刀顺手把 covFileList 切到 productFiles（首轮行为不变：首轮 files=productFiles）。

### A3（Q4-c）truthTexts 字段核对 + fail-open
vision 段树的真值文本字段名需实现前对真机段树核对（可能叫 texts/truthTexts/contentRuns）；**字段缺失 ⇒ 信号 B 整体 fail-open 不判**（不猜），只留 STATS 计数行。同时把「A && B ⇒ BLOCK」的 issue id 定为 `TEXT-COVERAGE-GATE`，message 带缺失段清单。

### B1（G1）半成品清理清单（container-layout-truth.js 逐项）
- **死代码**：L248 `finalContent` 混乱拼接（实际 return out）、L189-196 `htmlStart` 计算段——全删，统一「在 out 全文上按扫描偏移替换」。
