## 一、问题定性

### 1.1 元问题

10-31 方案解决了「vision 输出形态漂移 → 下游漏认」；但**形态认出之后**，多数段仍走 LLM chunk 自由生成。LLM 是概率性的——**即使真值全量在手也会漂移**。刀53 确定性接管家族本是对冲，但其判据前置统一是「Figma 锚点 + 几何证据」，当 **vision 显式契约完整而 Figma 几何证据缺席/不满足**时，接管 fail ⇒ 段落入 LLM ⇒ 越界事故。

这与 10-31 方案 B「只填沉默、不翻案」的哲学并不相反：vision 已经大声发言（`role:'footer'`、`body.items` 2 组 label+value），接管器却嫌「几何证据不足」把发言权扔给了 LLM。

### 1.2 当天实证：两单、两种越界形态

### 1.3 为什么「布局本来由 vision 给出」还会重复——五层实况因果链

用户的疑问点是准确的：vision 确实给了两个**互相独立**的段。重复不是 vision 给错，而是段结构在**下游两处被重新解释**，且中途**丢失了「段身份」这张契约**。


**一句话结论**：vision 给的是「两个段」，planner 保持了「两个段」（连真值都留着），但**刀53 把其中一个段接管走了、另一个段交给 LLM 时，既没告诉它「你只负责哪一段」、也没把 prompt 收窄到那一段**。LLM 于是按肉眼可见的内容重新切了一次段，产出了一个「标签是 footer、内容是列表」的组件；组合层再把两块并排 ⇒ 重复。而**本该兜底的 COMP-002 又因真值入口为空而失明**。

## Phase G-5：表格第五形态扩口径（e7da39ca，风险最低，先做）
