## 0. 部署前必读：架构速览

mvgo 源码包含 Java 与 Node 两个运行时。下图表示职责/目标代理关系；**不代表本次已核实生产 Nginx 当前路由**：

```
浏览器 / 门户 iframe
      │
      ▼  :80 (nginx)  /  :2610 (vite dev)
┌──────────────────────────────────────────────┐
│  Java  :8080  —— 统一 API 网关 + 业务 CRUD 层  │
│   • 鉴权 SessionGuardInterceptor（校验 Token） │
│   • 统一响应信封 Result<T>                      │
│   • 原生 Controller：auth/admin/group/projects/ │
│     sessions/skills/documents/models/component- │
│     split/operation-log/health                 │
│   • NodeProxyController：反向代理到 Node        │
│            │  /api/tasks /config /phase2 /vue3 │
│            │  /demo /preview /lite /microcode … │
│            ▼                                    │
│  Node  :13030 —— AI 生成引擎 + 持久任务记录/内存队列 │
└──────────────────────────────────────────────┘
```

**架构目标（部署前需与目标环境实测对照）**：

| 维度 | 历史直连 Node 形态 | Java 网关目标形态（仅在现场配置证实时适用） |
|------|--------|--------------------------|
| `/api` 入口 | 直连 Node 13030 | **统一进 Java 8080** |
| AI 管线（phase2/vue3/demo/preview） | Node 直连 | **经 Java 代理**到 Node |
| 鉴权 | Node 侧 | **Java 侧 SessionGuard** |
| 唯一例外 | — | `/api/progress`（SSE）前端直连 Node 13030 |

## 1. 通用前置

### 1.1 端口与角色（进程职责；实际映射以目标环境核验为准）

| 服务 | 默认/历史端口 | 角色 | 持久化 |
|------|------|------|--------|
| 前端（Nginx 静态 + 反代） | 80 | 静态资源 + `/api` 反代 | 无状态 |
| Java（Spring Boot） | 8080 | 统一入口 / 鉴权 / CRUD / 代理 | MongoDB |
| Node（NestJS） | 13030 | AI 引擎 / 任务执行 / SSE | 任务记录：`backend-node/data/tasks.json`；组件与指标另存 MongoDB；并发队列/执行回调为内存态 |
| Nginx 监控 | 8282 | `stub_status` 状态面板（运维用，非业务） | — |
| 历史遗留 | 8888 | 与 80 同 server 多开端口（见 §2.2，部署时摘掉） | — |

### 1.2 MongoDB（两端共用，最重要）

Java 与 Node **必须连同一个 MongoDB 实例与库**，否则用户/组/项目/会话/文档各写各的库、数据互不可见。

- **生产**：阿里云 RDS `langgraph-server`（URI 见 `backend-node/.env.production` 的 `MONGODB_URI`）
- **两端通过同一个 `MONGODB_URI` 取值**：Node 从 `.env.production` 读；Java 从启动环境变量 `MONGODB_URI` 读（必须一致）

### 1.3 密钥文件清单（均 gitignored，严禁入库）

| 文件 | 用途 | 部署位置 |
|------|------|----------|
| `backend-node/.env` | Node 基础（Figma 限流等） | 生产（内网裸服务） |
| `backend-node/.env.production` | Node 生产密钥（SESSION_SECRET / FIELD_ENCRYPTION_KEY / MONGODB_URI / MC_PREVIEW_BASE_URL / DEFAULT_ADMIN_UIDS） | 生产 |
| `backend-node/.env.development` | Node 开发环境（含 `DEV_AUTO_LOGIN=true`） | 仅本地 dev，生产禁用 |
| `backend-java/` | Java jar + 启动（prod 环境变量在启动命令行注入） | 生产 `/home/mvbt/mvgo/backend-java/` |

### 1.4 本地开发启动

> 本机完整启动三件套（前端 / Node / Java），访问 `http://localhost:2610`。前置依赖：**MongoDB**（`brew services start mongodb-community` 或 `mongod`），监听 `127.0.0.1:27017`。

#### 1.4.1 启动顺序与端口

| 顺序 | 服务 | 端口 | 启动方式 |
|------|------|------|----------|
| 0 | MongoDB | 27017 | 自启 / `brew services start mongodb-community` |
| 1 | Node 后端 | 13030 | 根目录 `node start-node.js`（已含 `DEV_AUTO_LOGIN=true`） |
| 2 | Java 后端 | 8080 | 根目录 `node start-java.js`（dev profile + `DEV_AUTO_LOGIN=true`） |
| 3 | 前端 Vite | 2610 | 根目录 `node start-frontend.js` |

#### 1.4.2 Node 后端

```bash
cd backend-node

# 构建（增量构建；按需清理 tsbuildinfo，不要删除 dist）
rm -f tsconfig.build.tsbuildinfo
npm run build

# 返回项目根目录，以脱离当前会话的方式启动 Node（含 DEV_AUTO_LOGIN=true）
cd ..
node start-node.js
```

环境变量来源：`.env` + `.env.development`（`DEV_AUTO_LOGIN=true`、`MONGODB_URI=mongodb://localhost:27017/langgraph-server`）。
校验：`curl http://localhost:13030/api/user/info -H "Token: dev"` 应返回用户信息而非 401。

**已知坑**：
- 日常构建不要删除 `dist/`；按需执行 `rm -f tsconfig.build.tsbuildinfo` 后再 `npm run build`。确需干净构建时，先停止服务并按项目清理流程处理，避免误删其他产物。
- 端口 13030 残留旧进程会让新进程 `EADDRINUSE` 静默退出；启动前先执行 `lsof -nP -iTCP:13030 -sTCP:LISTEN` 核对 PID，再按确认后的 PID 停止进程。

#### 1.4.3 Java 后端（⚠️ 必须注入 `DEV_AUTO_LOGIN=true`，否则 Token: dev 被拒 401）

以下命令从项目根目录执行：

```bash
# 启动（dev profile，连本地 MongoDB，开启开发免登录）
node start-java.js
```

| 变量 | 开发值 | 生产值 | 说明 |
|------|--------|--------|------|
| `DEV_AUTO_LOGIN` | **`true`** | 不设置 | 未设置时 Java `SessionGuardInterceptor` 要求真实门户 Token，`Token: dev` 会 401 |
| `MONGODB_URI` | 默认 `mongodb://localhost:27017/langgraph-server` | 必填（RDS URI） | 两端必须指向同一库 |
| `SPRING_PROFILES_ACTIVE` | `dev` | `prod` | prod profile 下 `DEV_AUTO_LOGIN` 强制失效 |
| `NODE_BACKEND_URL` | 默认 `http://localhost:13030/api` | 目标环境中的 Node 内网地址 | Java 反向代理 Node 地址；以现场网络配置核验 |

**沙箱环境陷阱**：某些 CI/沙箱会注入 `SERVER__PORT=0`，Spring 宽松绑定会把 `server.port` 设为 0（随机端口），启动后 `curl :8080` 连不上。临时修复：`unset SERVER__PORT` 或显式 `SERVER__PORT=8080`。

校验：`curl http://localhost:8080/api/auth/current -H "Token: dev"` 返回 `dev-local` 用户即正常。

#### 1.4.4 前端

```bash

cd frontend
npm install
cd ..

# 从项目根目录启动 Vite
node start-frontend.js
```

访问：`http://localhost:2610/mvgo/`，dev 模式前端请求自动带 `Token: dev`。

> **定位 Nginx 配置源**：以 `docker inspect nginx` 的 mounts 与 `docker exec nginx nginx -T` 为准；历史常见路径 `/home/mvbt/nginx/vhost/gzxj.conf`，禁止仅靠 `grep listen 8888` 推断生效文件。

### 2.2 端口说明（8888 / 8282 真相）

实测 `nginx -T` 结论：

- **8888**：`server { listen 80; listen 8888; }` —— 与 80 **同一 server、同一套 location 规则**（前端静态 + `/api` 代理），非独立业务。历史遗留多开端口（外部调用方可能曾走 8888，后统一到 80 未摘）。**切 Java 时一并摘掉 `listen 8888;`**。
- **8282**：主配置 `server { listen 8282; location /basic_status { stub_status on; } }` —— nginx 状态监控面板，运维用，非业务，保留。
- **80**：业务主入口。

### 2.3 ⚠️ Java 入口切换与现状核验（历史迁移方案；执行前必查线上）

以下 `gzxj.conf` 片段是 2026-08-12 迁移前的历史形态示例，**不是当前生产配置的断言**。在任何修改前，先对目标 ECS 执行 `docker exec nginx nginx -T` 并保存输出，确认 Java 8080、Node 13030 与实际 location 顺序；若未实测，不得假定 `/api` 当前指向哪一端。

历史迁移前的 `gzxj.conf` 示例：
```nginx
location /api { proxy_pass http://192.168.112.1:13030/api; }   # ← 直连 Node，绕过 Java 8080（过期）
```
必须改为 `/api → Java 8080`，仅 `/api/progress → Node 13030`。

**完整 gzxj.conf 修正版（基于实测，仅改路由相关段，其余内部服务保留）**：

```nginx
server {
    listen 80;
    # listen 8888;   ← 历史遗留，已摘（与 80 同站多端口，无独立用途）

    server_name _;
    access_log logs/proxy-access.log main;
    error_log logs/proxy.error.log;

    proxy_set_header X-Forwarded-Port 443;
    if ($request_method !~ ^(GET|POST)$) {
        return 405 '{"rid":"","code":405,"message":"Method Not Allowed","detail":"Only GET and POST are allowed","data":null}';
    }
    proxy_set_header Host $host:$server_port;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    ignore_invalid_headers off;
    client_max_body_size 0;
    proxy_buffering off;

    root /www;

    location / {
        index index.html index.htm;
        try_files $uri $uri/ /index.html;
    }
    location /preview/ { try_files $uri $uri/ /mvgo/index.html; }
    location /mvgo/    { try_files $uri $uri/ /mvgo/index.html; }

    # ===== 迁移后新增：AI 引擎 SSE 直连 Node（按 sessionId 鉴权，无 Token 依赖） =====
    location /api/progress {
        proxy_pass http://192.168.112.1:13030/api/progress;
        proxy_http_version 1.1;
        proxy_set_header Host $host:$server_port;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header SourceHost $remote_addr;
        proxy_buffering off;
        proxy_cache off;
        chunked_transfer_encoding off;
        tcp_nodelay on;
    }

    # ===== 迁移后修改：统一业务入口改走 Java 8080（原直连 Node 13030） =====
    location /api {
        proxy_pass http://192.168.112.1:8080/api;
        proxy_set_header Host $host:$server_port;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header SourceHost $remote_addr;
    }

    # ===== 以下内部服务原样保留（非 mvgo 业务，勿动） =====
    location /nacos {
        proxy_pass http://192.168.112.1:8848/nacos;
        proxy_set_header Host $host;
        proxy_set_header SourceHost $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_pass_header Set-Cookie;
        proxy_cookie_path /nacos /nacos;
        proxy_redirect http://192.168.112.1:8848/nacos/ /nacos/;
    }
    location /portlet {
        proxy_pass http://192.168.112.1:39680/portlet;
        proxy_set_header SourceHost $remote_addr;
    }
    location /mvbtapi {
        proxy_pass http://192.168.112.1:15503/mvbtapi;
        proxy_set_header SourceHost $remote_addr;
    }
    location /microcode-framework {
        proxy_pass http://192.168.112.2:18080/microcode-framework;
        proxy_set_header SourceHost $remote_addr;
    }
}
```

> 注：`/api/progress` 必须放在 `/api` **之前**（精确前缀优先）。`/nacos` `/portlet` `/mvbtapi` `/microcode-framework` 是内部服务，原样保留。

改完重载（容器网络内，无需重启容器）：

### 2.4 前端发布（2026-11-06 实测 SOP 模板；执行前核对目标环境）

> 本节中的 `/home/mvbt/nginx/www/mvgo` 是 2026-11-06 实测路径，不是当前主机的自动发现值。执行前须通过目标机挂载和 Nginx 配置核实真实目录；有差异时按现场值替换并记录。

#### 2.4.1 本地构建


#### 2.4.2 打包 + 上传 + staging 校验

```bash
STAMP=$(date +%Y%m%d-%H%M%S)
find dist -type f -exec md5 -r {} \; | sort > /tmp/fe-manifest-$STAMP.txt
tar czf /tmp/fe-dist-$STAMP.tgz --no-xattrs dist
scp /tmp/fe-dist-$STAMP.tgz /tmp/fe-manifest-$STAMP.txt "${MVGO_SSH_TARGET:?set authorized SSH target}:/tmp/"
```

远程 staging 校验（**不直接解压覆盖线上**）：

```bash
rm -rf /tmp/fe-staging && mkdir -p /tmp/fe-staging
tar xzf /tmp/fe-dist-$STAMP.tgz -C /tmp/fe-staging
sed 's/ /  /' /tmp/fe-manifest-$STAMP.txt > /tmp/fe-check.txt
cd /tmp/fe-staging
md5sum -c /tmp/fe-check.txt | grep -v ': OK$'   # 无输出 = 全部通过
grep -oE 'src="/mvgo/static/js/index-[^"]*"' dist/index.html | head -1   # 入口比对
```

#### 2.4.3 上位 + 冒烟（目标目录从现场挂载核验）

> `MVGO_REMOTE_FRONTEND_DIR` 必须由目标机 Nginx volume 与 `nginx -T` 确认后设置；仅当临时 staging 校验通过且该目录确认为当前静态根时执行。

```bash

mv "${MVGO_REMOTE_FRONTEND_DIR:?set verified remote frontend directory}" "$MVGO_REMOTE_FRONTEND_DIR.bak.$NOW"    # 目录级备份=回滚点
mv /tmp/fe-staging/dist "${MVGO_REMOTE_FRONTEND_DIR:?set verified remote frontend directory}"
# 冒烟三判据（在目标主机执行；MVGO_PUBLIC_BASE 按现场配置）：
curl -s -o /dev/null -w "%{http_code}\n" "${MVGO_PUBLIC_BASE:?set verified public base URL}/index.html"            # ① 200
```

> 🔴 **历史环境警告（2026-08-12 实测）**：当次 ECS 的 Nginx 不读取 `/home/mvbt/mvgo/frontend/dist`；其他环境须先核对实际 Nginx 静态根，不可把该历史路径当成通用结论。

## 5. 已知坑（发布必看）

1. **前端 `index.html` 缓存**：静态资源带 hash 可长缓存，但 `index.html` 不带。`gzxj.conf` 建议给 `location = /mvgo/index.html` 加 `Cache-Control: no-cache`；发布后硬刷新（Cmd/Ctrl+Shift+R）验证。
2. **`proxy_pass` 必须用内网 IP**：nginx 是独立容器，`127.0.0.1` 是容器自身非宿主。所有后端 `proxy_pass` 用 `192.168.112.1`（已确认本机主内网 IP）。
3. **Node 沙箱回收（仅本地开发）**：本地后台进程约 6 分钟被回收；ECS/Docker 常驻不受影响。
4. **tsc 增量缓存（Node 构建头号坑）**：`tsconfig.build.tsbuildinfo` 存在时，即使 `dist/` 已被清/换，`nest build` 仍 exit 0 静默跳过 TS 编译 → dist 只剩 assets（无 `main.js`）。**build 前 `rm -f tsconfig.build.tsbuildinfo`，build 后 `ls dist/main.js` 自检**（详见 §2.5.1）。日常增量构建也建议按需清理后重建。
5. **curl 受代理干扰（仅当环境存在代理变量时）**：若 shell 里带 `HTTP_PROXY`/`HTTPS_PROXY`，curl 会返回 502/000，排查用 `curl --noproxy '*'`。本项目生产与本地均未配置出口代理，正常情况下不会触发。
6. **⚠️ 生产网关仅允许 GET/POST（2026-09-03 实测）**：公司 nginx 容器 `gzxj.conf` 有方法过滤器：
   ```nginx
   if ($request_method !~ ^(GET|POST)$) {
       return 405 '{"rid":"","code":405,"message":"Method Not Allowed","detail":"Only GET and POST are allowed","data":null}';
   }
   ```
   **影响**：前端 `http.delete()` / `http.put()` / `http.patch()` 调用会直接返回 405，请求不到后端。
   **修复**：后端 `@DeleteMapping`/`@Delete`/`@Put` 改为 `@PostMapping`，前端 `http.delete()`/`http.put()` 改为 `http.post()`。已修复全量 DELETE/PUT 路由：
   - **Java `AdminController.java`**：`@DeleteMapping("operation-log")` → `@PostMapping("operation-log/delete")`；`@DeleteMapping("users/{id}")` → `@PostMapping("users/{id}/delete")`；`@DeleteMapping("components/{id}")` → `@PostMapping("components/{id}/delete")`
   - **Node `page-skeleton.controller.ts`**：`@Put(':groupId/:id')` → `@Post(':groupId/:id/update')`；`@Delete(':groupId/:id')` → `@Post(':groupId/:id/delete')`；`@Delete(':groupId/:id/file')` → `@Post(':groupId/:id/file/delete')`
   - **Node `component.controller.ts`**：`@Delete(':componentId/file')` → `@Post(':componentId/file/delete')`
   - **Node `recipes.controller.ts`**：`@Delete(':name')` → `@Post(':name/delete')`
   - **Node `agent-builder.controller.ts`**：`@Delete(':name')` → `@Post(':name/delete')`
   - **Node `admin.controller.ts`**：`@Delete('users/:id')` → `@Post('users/:id/delete')`（合并重复方法）
   - **前端 `ManagementView.vue`**：`http.delete('/api/admin/operation-log')` → `http.post('/api/admin/operation-log/delete')`
   - **前端 `page-skeleton.ts`**：`http.delete(...)` → `http.post(.../delete)`
   - **前端 `demo/index.vue`**：`http.delete(.../file?path=...)` → `http.post(.../file/delete?path=...)`
   - **前端 `workflow.ts`**：`axios.delete('/api/recipes/${name}')` → `axios.post('/api/recipes/${name}/delete')`
   **验证**：前端 `http.delete(` / `http.put(` / `http.patch(` 全局搜索已 0 匹配，`npm run build` 通过。
7. **⚠️ SSE / 预览 iframe 401（2026-09-03 实测）**：
   - **根因**：预览 iframe 内 `getAuthToken()` 无法从父窗口取到门户 Token（跨域/非 portlet 环境），且 `SessionGuard` 只认 Header 不认 query token。
   - **修复链**：
     1. **Node `SessionGuard`** 兼容 query token：`request.query?.token`（`session.guard.ts`）
     2. **前端 `api-token.js`** 兜底取 URL token：`window.location.search` + `window.location.hash` 双路径
     3. **`preview-resolver.ts`** 构建预览 URL 时拼 `token` 到 query
     4. **`buildSnapshotFileUrl()`** 拼接 token 参数，保证运行时 loader 读快照文件不 401
   - **部署注意**：Node `session.guard.ts` 改动需 `npm run build` 生成 `dist/auth/session.guard.js` 才生效；前端改动需 `npm run build` 后发布 dist。

| Nginx | `gzxj.conf` | `/home/mvbt/nginx/vhost/gzxj.conf` |
| 本地旧构建 | dist.local-* / dist.old-* | **保留勿 rm**（safe-delete hook 拦批量删除；留作回滚） |

### 6.2 回滚方式

- **前端回滚**：还原旧 dist 目录 / 解压旧 `dist.zip`，`nginx -s reload`。
- **Node 回滚**：还原旧 `dist/`、`npm ci`（如依赖变更）、还原旧 `.env.production`，重新 `nohup node dist/main.js`。
- **Java 回滚**：还原旧 jar 包，按 §2.6 重启。
- **Nginx 路由回滚**：恢复修改前备份的实际生效配置（先由 `nginx -T` 和挂载关系确认配置源），运行 `nginx -t` 后再 `docker exec nginx nginx -s reload`；不要复制本文的历史 IP 示例作为回滚值。
