# mvgo 系统架构文档

> 版本：v1.0 ｜ 日期：2026-08-12

---

## 1. 系统概述

mvgo 是一套 **AI 驱动的组件生成平台**，支持从设计稿（Figma）、需求文档、HTML 原型等多种输入源，自动生成 Vue3 组件和 API 绑定代码。平台提供任务中心、轻量批量生成等能力。

**核心价值**：通过 AI 管线（LLM + 多角色协作 + 断点续跑）实现"输入 → 可运行代码"的全自动交付。

### 4.3 设计原则

| 归属 Java 的场景 | 归属 Node 的场景 |
|-----------------|-----------------|
| 统一入口 / 路由分发 | AI 生成管线（调 LLM、文件系统落地、运行时编译） |
| 请求鉴权（Token 校验） | 内存态任务执行（状态 Map 与执行生命周期绑定） |
| 统一响应格式 | SSE 长连接流式输出 |
| 纯 Mongo CRUD（用户/组/项目/会话/技能/文档） | 依赖 Node 生态的模块（加密、文件 IO、聚合查询） |

## 6. Nginx 路由规则

```
前端静态资源     →  /www/mvgo/  (try_files → index.html)
/preview/*      →  /www/mvgo/index.html
/api/progress   →  Node :13030 (SSE 长连接，proxy_buffering off)
/api/*          →  Java :8080  (统一入口，Java 内部决定原生处理或代理 Node)
/nacos          →  :8848  (配置中心)
/portlet        →  :39680 (内部服务)
/mvbtapi        →  :15503 (内部服务)
/microcode-framework →  192.168.112.2:18080 (微码框架)
```

> **关键**：`/api/progress` 必须放在 `/api` 之前（精确前缀优先）。`proxy_pass` 使用内网 IP `192.168.112.1`（Nginx 容器内 127.0.0.1 是容器自身）。

## 7. 数据流

### 7.1 AI 组件生成流程

```
用户输入（Figma URL / 需求文档 / HTML 原型）
      │
      ▼
  前端发起 /api/phase2/start
      │
      ▼
  Nginx → Java :8080 → NodeProxyController → Node :13030
      │
      ▼
  Node AI 管线启动：
  ├─ 1. 输入适配（Figma API / 文档解析 / HTML 解析）
  ├─ 2. LLM 多角色协作（需求分析 → 架构设计 → 代码生成 → 代码审查）
  ├─ 3. 组件文件落地（workspace/）
  ├─ 4. SSE 实时推送进度 → /api/progress
  └─ 5. 完成回调 → 前端刷新
```

### 7.2 鉴权流程

```
浏览器 → Nginx → Java :8080
                   │
                   ▼
           SessionGuardInterceptor
           ├─ 校验请求头 Token
           ├─ 写入 userId 到请求上下文
           └─ 失败 → 401 返回
                   │
                   ▼
           Controller 处理业务逻辑
```

### 7.3 任务执行流

```
用户发起任务 → /api/tasks/start
                    │
                    ▼
             Node 内存 Map 创建任务
             状态：queued → running → completed/failed
                    │
                    ▼
             SSE 推送进度到前端
             前端轮询 /api/tasks/:id 获取状态
```

**前端关键设计决策**：
- **动态路由生成**：`eventComponentAddRoute()` 扫描 `components/**/component.js`，自动为每个业务组件注册独立路由
- **功能开关分层**：`routes` (页面级) → `subRoutes` (子页面) → `features` (按钮级)，通过 `v-feature` 指令控制显隐
- **SSE 实时通信**：任务进度通过 `/api/progress` EventSource 长连接推送，绕过 Java 直连 Node

**Node 后端关键设计决策**：
- **多角色协作**：`ai-engine/roles/` 封装不同 AI 角色（微码工程师、Vue3 工程师、代码审查员等），通过 `orchestrator` 调度
- **LangGraph 工作流**：`ai-engine/graphs/` 使用 LangGraph 定义有向图工作流，支持条件分支/循环/并行
- **v2 可配置管线**：`ai-engine-v2/` 新架构，通过 `tier-profile` 分层配置 + `node-registry` 动态加载，实现管线的灵活组合
- **断点续跑**：`snapshot-manager` + `microcode-engineer.js` 实现 chunk 级 checkpoint，任务中断后可恢复
- **内存态任务**：`tasks.service.ts` 使用内存 Map 管理任务状态（不持久化），适合短时任务
