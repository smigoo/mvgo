## 3. 确定性回放通道（分支 A：reuseCache=true）

- 调用：`POST /api/phase2/generate`，body 含 `fileKey / nodeId / componentName / target:'microcode' / reuseCache:true / groupId`，headers 带 `token`。
- 命中链：`phase2.service.ts:342` → `loadSharedCache(outputPath, fileKey, nodeId)` → 主仓 `temp-components/_shared-cache/{fileKey}/{nodeId}/`。
- **实测就绪**：三组件缓存 age 1.5–1.8h（< TTL 24h），`figma.json + visual.json` 齐全。命中后跳过 Figma API + Vision ⇒ 输出差异 **100% 归因代码改动**。
- **回放有效性断言**（判分器第一步）：本轮日志必须含 `🗃️ 续跑命中全局缓存`；出现 `续跑未命中缓存，按全新生成` ⇒ 样本作废重跑；缓存为降级结果（`buildVisualAnalysisBlockError` 路径）⇒ 标「回放无效」，不判代码回归。
- **TTL 24h 风险**：缓存 12:55 起算，loop 须当日跑完重投轮；过期 ⇒ 重种（跑 1 次全新生成刷新 `cachedAt`）再回放。
- **续跑跳过集边界**（`phase2.js:1112-1118` 已知坑）：uiCache 存的是**加工后**结构，vision 阶段判据升级对缓存任务不生效。R1/R2/R3 均落在**代码生成 / 写盘 / 校验阶段**，不受影响；未来新增修复项若涉 vision 阶段，须改走「先回放后全新」双模式。
- **🔴 实测发现 1（基线锚定期实证，2026-11-08 晚）——LLM 随机层**：`reuseCache:true` 锁定 figma+vision 输入，但**不锁 LLM 代码生成采样**。同代码（95054ed）+ 同缓存 vision 重放，随机层指标每发漂移：`2:9778` 上午 failed → 回放 completed；`2:8417` 上午 0 降级 → 回放降级 `StatsTunnel+CardGrid` 2 文件；`2:7879` 上午健康 → 回放降级 `ContentSection`；`2:7952` 回放 LESS 笔误（`@color-bg-container` 未定义）failed。而**确定性层完全稳定**：`chartOwned=0` 四发一致（analysisCharts 断链稳定复现）、takeover hits 结构一致。⇒ 判分必须分层（见 §6）。
- **实测发现 2**：S3 命中日志（`phase2.service` 的 `续跑命中全局缓存`）走 `sendSseLog`，**不进 progress 数组也不进 server.log**；graph 侧铁证是 `🗃️ visual-parser: 视觉分析缓存命中，跳过 Vision AI 调用`（`phase2.js:1055`，落 server.log）。采集器断言已改用后者（`replay.mjs#graphCacheHitSince`，串行窗口归因）。
- **实测发现 3（DTO 坑）**：`reuseCache` 不传默认 falsy = **全新生成**。采集器必须显式传 `true`。
- **实测发现 4（对照池现实）**：tasks 列表 API 仅 19 项（16 completed 去 nodeId 后仅 4 个独立组件），广义对照池实际只有 `e33cb213`（环境监测 `2:7879`）1 个独立健康组件，「抽 5 单」降级为「1 广义对照 + 1559f801 主对照」。

```
第 0 步 基线锚定（一次性，修复前）：

  广义对照抽 5 单（结构条件抽样）→ 基线重投 ×1
  jest 真基线（同仓 stash 法）；probe 脚本固化进 scripts/
──────────── 每轮循环（R1 → R2 → [R3]） ────────────
① 实施修复   治理六阶段（查重→根因→方案→影响面→实施）+ 单测（阳性对照+阴性零回归）
② 静态回归   jest 全量 vs 基线（FAIL diff 空）→ env -i 构建 → 验 dist/main.js + 资产 .js
③ 部署放行   （D 分支已授权）lsof 释放 :13030 → 同 Bash 内 rename 探针（保留完整 env）
             → node start-node.js → pgrep 清双进程 → 40s 冒烟（token 头）
```

## 5. 第 0 步 基线锚定（详细）

1. `ROLLBACK_ANCHOR`：backend-node 当前 HEAD `95054ed`（记入 baseline.json；禁 `git show HEAD:` 取态，daily auto-sync 会拆改工作区）。
2. 三组件基线重投：各自 `reuseCache:true` 一次，采集 §6 全部指标 ⇒ `baseline.json`（A 态）。
3. 广义对照抽样（结构条件，零硬编码）：tasks 历史中 `status=completed ∧ 无 artifactIncomplete/降级 ∧ 微码端 ∧ cachedAt 近 7 天` 随机抽 5 单；各重投一次确认全部维持健康，任一不健康 ⇒ 换样本（记录抽样种子）。
4. jest 真基线：同仓 stash 法现建（`mvgo-jest-regression-baseline` skill 流程），两态 FAIL diff 空为前提。
5. probe 脚本固化：`/tmp/probe-latest.cjs`、`/tmp/probe-card.cjs` 的形态版本化进 `backend-node/scripts/loop-verify/`（判分器依赖，不能留在 /tmp）。
6. 广义对照 5 单的 `fileKey/nodeId` 记入 baseline.json（作为重放输入参数，非判据）。

## 6. 判分器规格（零硬编码细则）

**🔴 判据分层（基线锚定期实证后修正）**：
- **确定性层（主判据，单次回放即有效）**：`chartOwned/chartOwnedIds`（vision charts 声明 × section 树，均缓存锁定，与 LLM 采样无关）、takeover hits 分布、R2 新增「终裁快照校验」计数行——三者为收益/回归的**裁决口径**。
- **随机层（参考项，噪声敏感）**：status / degradedFiles / artifactIncomplete / LESS 编译——LLM 采样每发漂移（基线实证），**不得单独作为收益或回归的裁决依据**；仅当确定性层变化时作佐证。status 类异常需同组件补 1 次回放（共 2 采样）确认方向一致才升级为信号。

**改验分离**：判分器读**落盘事实**（meta JSON / 日志计数行 / probe 输出），与修复代码的判据不同源；解析失败 fail-loud（判分器异常即停 loop，不默认通过）。

| 维度 | 数据源 | 收益判定（问题组件） | 回归判定（对照/抽样） |
|---|---|---|---|
| 任务终态 | `/api/tasks` status | failed→completed | 对照非 completed ⇒ 回归 |
| 产物完整性 | meta `artifactIncomplete/degradedFiles/gateSkippedFiles` | 降级文件减少 | 任一新增降级 ⇒ 回归 |
| 子组件覆盖度 | 日志行 `🧩 子组件覆盖度` | missing 4→0 | 对照不变 |
| R1 阳性对照 | 日志 `chartOwned / chartOwnedIds` | >0 且含 vision charts section | — |
| 图表门禁项 | do-not-invent 日志 | CHART-SECTION-MISSING 消失 | 对照无新增 BLOCK |
| R2 阳性对照 | 新增计数行「终裁快照校验」 | `rejected>0`（非法快照被拦）或 `verified>0` | — |
| 视觉守护（仅 1559f801） | probe DOM/样式 | — | 卡数=12、统计条 65±TOL_STAT_H、内容区 320±TOL_CONTENT_H、数值右界 ≤117、名称 #333333 / 数值 #FFFFFF，任一越界 ⇒ 回归 |
| jest | 两态 FAIL diff（去重后） | — | diff 非空 ⇒ 回归（须逐条归因） |

容差常量（命名 + 来源注释，集中在判分器常量区）：`TOL_STAT_H = 5`、`TOL_CONTENT_H = 20`（既往多轮复验的测量波动经验值）；`POLL_TIMEOUT_MS = 900000`、`REPLAY_VALID_LOG = '续跑命中全局缓存'`。**禁止**任何 `if (taskId === '…')` / 组件名特判 / 散落魔法数。

三态决策表：

| 判分结果 | 动作 |
|---|---|
| 收益 ≥1 ∧ 回归 0 | `git commit`（`#code#` 标注 loop 轮次）→ 进下一修复项 |
| 收益 0 ∧ 回归 0（无收益） | `git checkout ROLLBACK_ANCHOR` 回滚 → 重投问题组件 1 次确认恢复基线 → 归因（判据为何未生效）入 memory |
| 回归 ≥1（无论收益） | 同上回滚 → 恢复验证 → 归因到具体判据与代码行 |

同一修复项两次证伪 ⇒ 停 loop、输出归因报告、回滚收尾；**禁止无归因地第三次尝试**。

## 7. 回滚规则（分支 C 落地）

- 粒度：每轮独立 A/B，回滚 = `git checkout <ROLLBACK_ANCHOR>`（源码级），**禁止产物直改**、禁止只改不回滚。
- 回滚后强制**恢复验证**：重投该轮问题组件 1 次，指标须回基线 ±容差；未恢复 ⇒ 判环境异常，停 loop 排查（不许当成「代码已好」）。
- 每轮产出 `baseline.json vs after.json` diff 留档（loop-verify 目录内），作为 commit message 与 memory 的证据引用。

## 9. 验收标准（loop 退出条件）

> 🔴 **2026-11-09 判分口径裁决（第二轮评审 P1-5.4）**：原文「1559f801 对照零退化」与 §6「`degradedFiles` 属随机层、不作裁决」**互相矛盾**——`after-r6.jsonl:3` 该对照降级 `StatsMonitor.vue`+`artifactIncomplete=true` 却仍判通过，暴露同一指标两处口径相反（判据单一来源失效）。
> **裁决：随机层豁免优先（选项 A）**，并据此改写退出条件。理由：`degradedFiles` 由 LLM 采样决定，同一代码同缓存重放即可漂移（§3 实测发现 1 已实证），若把它当硬条件，任何一轮都可能被非本次改动引起的漂移判死。
> 但**不得由此把对照样本降级为「不看」**——对照的确定性层指标仍必须同口径比对。

- **全绿（修订后）**：三问题组件目标指标全达标 ∧ 1559f801 对照**确定性层指标零恶化**（takeover hits / chartOwned / probe 几何在容差内）且**终态非 failed** ∧ 抽样对照同条件 ∧ jest FAIL diff 为空 ∧ 每轮有 commit。
- **降级处理（必须在报告中显式标注，不得沉默）**：对照出现 `degradedFiles` / `artifactIncomplete` 时，按随机层记录并**补 1 次回放**确认方向是否一致；两次都降级 ⇒ 升级为回归信号（不再是纯随机漂移），须归因。
- **诚实退出**：任一轮两次证伪 ⇒ 停 loop，输出归因报告，回滚至 ROLLBACK_ANCHOR。
- 交付话术：查重结论（续接既有方案）→ 根因（文件:行号）→ 修法摘要 → 影响面清单 → 回归结果（基线 diff 空/归因）→「已改完，**未 push、未同步生产**」。

## 10. 实施顺序

`0 基线锚定`（含 probe/判分脚本固化）→ `R3 只读归因`（不进 loop）→ `R1 轮`（analysisCharts 透传）→ `R2 轮`（终裁快照校验 + 登记总纲）→ `验收汇总`（R3 归因若产出修复项，追加 R3 轮后同规验收）。

## 11. 明确不做

- ❌ 判分器按任务 id / 组件名 / 文件名特判
- ❌ 无收益不回滚、或回滚不归因
- ❌ 用产物直改代替源码 checkout 回滚
- ❌ loop 期间 `git push` / 生产同步 / frontend 部署（D 授权明确不含）
- ❌ 判据与验收用同一正则 / 无阳性对照 / 无真机日志计数行
