## 二、整改设计（5 个批次，可独立验证，互不冲突）

### 批次 1 · 折叠器修正（P3 + P8）— 文件 `src/ai-engine/utils/repeated-section-collapser.js`

**1a. items 按视觉顺序排序（P3）**
`collapseSectionsDeep` / `groupSections` 组装 collapsed section 的 items 前，按父容器 layout 方向排序：
- horizontal：`items.sort((a,b)=> boxA.x - boxB.x)`
- vertical / grid 行优先：先 y（容差 ±4px 视为同行）再 x
- 无 box 的项保持原序（与现有 `_sizeGate` 放行逻辑一致，不破坏 device 回归）
落点：生成 `collapsed.items` / `_vforData` 数组处统一走一个 `sortItemsByVisualOrder(items, layoutDir)` 工具；prompt 的 `[0][1][2]` 序号自然跟随。
验收：单测——children 数组 x 倒序时，`_vforData.texts` 输出 x 升序；3329bec8 E2E 重跑 vehicleList=[危化品,重型,超高]。

**1b. chart 容器内部豁免递归（P8，防御项）**
`collapseSectionsDeep` 下钻前判断：节点 `type==='chart'` 或 title/name 命中 `/@eachrts|@echarts|chart/i` → **不对其 children 递归折叠**（整容器作为叶子交给 chart-builder）。
> 评审 R2：P8 现为潜伏项（折叠产物未落 DOM，无可见 bug），本项为防御性收紧，非"必修才正确"。验收：单测补 chart 父级用例即可，**不作 E2E 硬指标**。

### 批次 2 · 语义回填补链（P1 + P7）— 文件 `src/ai-engine/roles/subcomponent-planner.js`、`src/ai-engine/roles/visual-parser.js`

**2a. F1 支持 vision children 级对位（P1）**
F1 二段匹配在扫 vision sections 之外，增加一层：对每个 vision section 的 `children[]`（含 inline-row 的 m1/m2…），若有 `figmaNode` 字段，直接在 E1 树中按 **节点 id 精确对位**（`sec.id === child.figmaNode` 或 sourceNodeIds 包含），命中即把 child 的 name/styles/语义并入该 E1 叶子的 `body._visionSemantics`。
- 优先级：section 级匹配 > children 级对位 > 文本真值模糊匹配（保留现状兜底）。
- c3c3244f 场景：`89:42-m1.figmaNode=2:7889` 一步命中，tab 文本进 prompt。
验收：单测——inline-row vision section + E1 三叶容器，中间叶获得 m1 语义；E2E 环境监测重跑出现 tabs DOM。

**2b. chrome 剥离时语义转挂（P7）**
`stripChromeSectionsFromLayout`（visual-parser「剥离 base-panel chrome 区块」处）删除 vision section 前，若其 `headerRelation==='content-below-title'` 且包含文本/icon 语义：
- 不整段丢弃，而是将其语义（含 children 数组、icon 引用）挂到保留字段 `layout._strippedSemantics[] = { figmaNodeId?, texts, icon, reason }`；
- planner 端 F1 增加第三段：`_strippedSemantics` 按文本真值/figmaNode 回填 E1 叶子（136:122「今日累计」+icon-8070 由此归位）。
验收：日志出现「F1 剥离语义回填 hostId=136:122」；E2E HeaderSub 产物含 `<img :src="iconN">`。

### 批次 3 · 资源挂载反查优先（P2）— 文件 `src/ai-engine/roles/microcode/resource-mount-plan.js`

**3a. S7 兜底改「反查优先 + 跨子树门禁」，禁跨 section 错挂**（评审 R1）
现逻辑：mountTarget 类名不在模板 → 直接 `pickBestMountTarget` 名字相似评分回退（2026-09-16 为修 `c-env-monitor-5ed7a5f8` 静默丢背景而加，不可删除，否则复发旧回归）。改为三级：
1. **反查优先（确定性首选）**：按 mapping 的 `figmaNodeId` 反查哪个 section 的 `sourceNodeIds` 含它 → 挂到该 section 对应 DOM（bg 语义=直接父元素背景，由 Figma 树唯一确定）。bg-7890→tabs-list 由此正解；
2. **跨子树门禁兜底**：反查失败才走 `pickBestMountTarget`，但候选**只能是被挂 section 自身的兄弟/后代**，禁止跨 section 挂到其他业务区（评分 <阈值或跨子树 → 视为无候选）；`c-env-monitor-5ed7a5f8` 场景仍被兜住；
3. **丢弃 + RESOURCE-WARN 告警**：仍无候选 → 丢弃并记录 `dropped:{var,figmaNodeId,reason:"host-dom-missing"}`。
> 删除的是"无门禁的纯名字相似回退"，不是删除兜底本身——保留兜底能力，补上确定性反查与跨子树门禁。
验收：c3c3244f 重跑——tabs DOM 存在后 bg-7890 挂 tabs-list（正确）；若 tabs 仍缺失则 bg 被丢弃而非错挂 icons 区；门禁告警面板可见 dropped 清单。

### 批次 4 · 布局高度链 + v-for 内部骨架（P4 + P5）— 文件 `src/ai-engine/utils/inline-row-assembler.js`（及确定性模板装配处）、`repeated-section-collapser.js`、`microcode-engineer.js`

**4a. 折叠 list 容器补高度链（P4）**
折叠产物（`collapsed:true`，renderHint v-for）装配进模板时，容器 class 样式确定性注入：
`height:100%; display:flex; flex-direction:{row|column}; align-items:stretch;`，条目样式注入 `flex:1 1 0; min-width:0; min-height:0`（替代现在只有 `width:100%` 的骨架）。卡片对父高度可解析，插槽不再塌。
实现为**装配器接管**（删减法原则：不靠 prompt 叮嘱 LLM），并入现有 VERT-004 检查。
验收：3329bec8 重跑，ListSection 根含 height:100%，预览三卡等高撑满槽位。

**4b. _vforData 升级为内部骨架（P5，过渡态）**
折叠器 enrichItemData 时，除平铺事实外，附带**代表 item 的子树骨架摘要**：
`_skeleton: { direction:'row', slots:[{role:'icon',box},{role:'text',text},{role:'value',parts:[num,unit]}] }`（由代表 item 的 Figma children 递归 2 层导出，同构项骨架一致所以只需一份 + 数据数组）。
prompt 的 listLike 分支注入「每项内部结构必须按此骨架还原」模板。同时 D1 的 R-icon/R-img 对 v-for 项内的 icon 同样生效（现只处理普通卡片 DOM）。
> 评审 R3：本项是**过渡态**——骨架经 prompt 注入仍依赖 LLM 遵循，不承诺确定性（与 4a 的"装配器接管"路线不同，不构成矛盾，但需明示）。真正治本要等 H(item-level DOM contract) 落成确定性装配后再删本 prompt 段。
验收：3329bec8 卡内变成 icon左+label/value右列布局；单测断言 _skeleton 字段形状。

### 批次 5 · D1 颜色扩面 + 图例外置契约（P6 + P9）— 文件 `src/ai-engine/utils/card-visual-truth-rewriter.js`、chart 契约生成处（visual-parser / chart-builder 输入）

**5a. R-label（P6）**
D1 新增规则：section 真值含 TEXT 颜色（fills→hex）时，对产物中 `label/title/name/unit` 类选择器的 `color:` 同样执行「var() 取 fallback 比对，不等则改写为真值」。复用 R-num 的归一化函数。
> 评审 R4：开做前先探针一次 `_vforData.textStyles` 是否含 label 色（value 色 #fa8c16 等已证可达，label 色 #333333 可达性待验）；含则直做，不含则先补 textStyles 采集。
验收：card-label 产物色 = #333333（或对应真值）。

**5b. 图例外置检测（P9）**
vision charts[] 契约生成处新增判定：`legend[]` 中每项文本若被**图表相邻 sibling sections**（同父容器下非 chart 的 section 及其子树）文本覆盖 ≥80%，则契约改写为：
`legendExternal: true, legend: []`，并给 chart 组件的 prompt/装配加硬约束「禁止生成 legend DOM 与 legend 数据数组；ECharts `legend.show:false`」。
外置图例的数据由已折叠的 StatsLeft/Right（v-for）唯一承担——一套都不多。
配套：chart 容器豁免折叠（1b）后，`legendExternal` 的 chart section 内部不再出现任何图例结构。
验收：0856b233 重跑，ChartSection 无 leftLegend/rightLegend；全组件图例仅 Stats 两处 v-for；8 色与 Figma 一致。

## 四、风险与守则

- **P2 反查优先可能暴露更多"资源未使用"告警**（宿主 DOM 缺失的组件）——这是从"静默错挂"变"显性告警"，符合删减法；RESOURCE-001 门禁级别暂维持 WARN。**注意：3a 保留名字相似兜底（加跨子树门禁），不得删除，否则复发 `c-env-monitor-5ed7a5f8` 静默丢背景。**
- **4a 装配器注入样式**需避让已有 inline flex（只补 height/align，不覆盖 flexGrow 数值）。
- **2a children 对位**要求 `figmaNode` 字段存在（vision 已稳定输出）；缺失时自然落到文本真值兜底，无破坏性。**2b 剥离语义转挂**只针对"被剥但含 icon/text 语义"的 section，不得触碰 `isChromeOnlySection` 现有 `hasBusinessBody`/`hasBusinessHeaderControls` 早退路径（P1-1 保护）。
- **5b 阈值 80%**：覆盖不足时宁可保留内置 legend（图表类组件内嵌图例仍是常态），避免误杀。
- 全部改动遵循项目原则：确定性事实由 planner/装配器接管，LLM 只填值；每批门禁总数只降不升。
