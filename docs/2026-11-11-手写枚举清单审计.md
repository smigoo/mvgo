| 项 | 数量 |
|---|---|

判定「风险方向」的标准（关键）：
- **fail-closed**：集合被当作全集用，漏列 ⇒ 合法输入被判非法 ⇒ 整任务失败（**危险**）
- **fail-open**：集合用于「命中才动作」，漏列 ⇒ 只是不识别，不会误杀（**可接受**）
- **项目约定**：集合本身不是规范全集，而是业务选择（合理，无需治理）

## 三、A 类：真风险（已治）

### `SCRIPT_GLOBALS`（`sfc-semantics.js:60`）
- 原 208 项手写，含浏览器全局子集；
- 用途：`<script>` 自由变量检测的豁免名单，**不在名单且未声明 ⇒ 判「未声明的自由变量」⇒ 整任务 failed**（fail-closed）；
- 实锤：`6a16224a` — `getComputedStyle`（echarts 容器测量标准写法）不在名单 ⇒ 任务失败；
- **已治**：数据源换 `globals@17`（browser 1196 + builtin 65 + node 81 = 1342 项），手写降级为兜底。

## 六、D 类：职责不同（澄清，勿误改）

### `TEMPLATE_WHITELIST`（`sfc-semantics.js:112`，60 项，**不含 HTML 标签**）
初看像「HTML 标签白名单漏了」，实际职责是**过滤模板里的裸标识符**（`${var}` / `:attr="var"` / `ref="var"`），与组件标签识别由另一个函数 `extractComponentTagNames` 负责。**不要往这里加 HTML 标签**——加了会让「模板引用了未声明的变量名恰好是 `div`」这种错误漏过。

## 七、下一步建议（按性价比排序）

| # | 建议 | 理由 | 成本 |
|---|---|---|---|
| **1** | **给 fail-closed 判据引入「未知值逃生舱」**：遇到不在白名单的值，先 `WARN + 计数行`，只有**连续 N 次**或**显式高危**才 FAIL | 这是根治「枚举必漏」的通用模式——不追求清单完整，而是让未知值不直接判死。今天 3 类失败中 2 类都是「枚举/口径」导致 | 中（需逐判据改造，建议先挑 E3-v4/A1-v2 试点） |
| 2 | `SCRIPT_GLOBALS` 手写兜底组再瘦身：Vue 宏/API 可从 `vue` 包导出（`Object.keys(require('vue'))`）自动生成 | 与 globals 同理，减少人工维护 | 低 |
| 3 | `BLOCK_LEVEL_TAGS` / `PSEUDO_ELEMENTS` 若长期影响质量，可引入 `html-tags` / `known-css-properties` | 规范稳定、基数小，当前风险低，**不急** | 低 |
| 4 | 建立「新增判据必查清单」：判据里若要枚举规范值 ⇒ 必须说明为何不能数据驱动 | 防止再出现「手写 208 项」 | 低 |

**不建议**：为了「清单完整」把 C 类全部外包——它们漏列是 fail-open，改造收益低、回归成本高。
