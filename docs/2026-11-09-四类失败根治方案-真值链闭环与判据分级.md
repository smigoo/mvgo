## 2. 根因（文件:行号 + 真机证据）

### R1 颜色真值链三处断点（25711e88 实锤）

| 断点 | 证据 |
|---|---|
| ① **SOLID 优先于渐变** | `prompt-builder.js:2237` `fills.find(f => f.type==='SOLID' && visible!==false)` 先返回；同时存在 SOLID+GRADIENT 时渐变永不下发 |
| ② **渐变输出非法 CSS** | `prompt-builder.js:2251` 输出 `linear-gradient(#e1f0ff → #00ccff)`（箭头非合法 CSS），且 `:2271` 对 TEXT 直接拼 `color:${bg}` → 模型只能自行改成纯色 |
| ③ **visible:false 即丢弃真值** | `:2240` 要求 `visible !== false`；`设备监测 2:8426` 的渐变 fill 正是 `visible:false` ⇒ 无真值下发 ⇒ 模型默认蓝色 |
| ④ vision 通道只给标记 | `visual-parser.js:673` 仅追加 `[has-gradient]`，stop 值不下发 |

真机真值：`28/68562/98%/56302/5/1280/3` 全部 `GRADIENT_LINEAR #e1f0ff→#00ccff`；产物分别为纯白、`#e03434`、`#1990ff`。

### R3 段锚存在性无判据（25711e88 头部整段缺失）

`2:8419`（388×30，9 子，含 4 条中文真值 + `68562`/`98%`）在产物中**无任何 `data-section-id`**，`index.vue:4-8` 只有 StatsSection + 89:37。但 TEXT-COVERAGE 仍报 96%（只缺「完好率」），`VISUAL-002=0.5996` 险过阈值 ⇒ 整段结构缺失不可见。

## 3. 修法（全部真值驱动，零硬编码）

### S1 统一 pain 编译器（新建 `utils/figma-paint-to-css.js`）

输入节点 `fills/strokes/effects/style`，输出可直接使用的 CSS 片段：

```js
// 全部取值来自节点，函数内无任何字面量色值/尺寸
paintToCss(node) → {
  color?: string,               // SOLID
  backgroundImage?: string,     // GRADIENT → linear-gradient(<deg>, stops)
  backgroundClip?: 'text',      // TEXT + 渐变
  webkitTextFillColor?: 'transparent',
  webkitTextStroke?: string,    // TEXT + DROP_SHADOW(offset 0,0 && radius 0)
  boxShadow?: string            // 非 TEXT
}
```

规则（判据式，非表驱动）：
- `visible === false` 跳过该 paint；全部不可见 ⇒ 返回 `null`（不猜，计数 `paintNoTruth`）
- `GRADIENT_LINEAR` 角度由 `gradientHandlePositions[0→1]` 计算；无句柄则按 Figma 默认 `180deg`
- stop 数量、位置、alpha 全量保留
- `DROP_SHADOW` 且 `offset.x===0 && offset.y===0 && radius===0` ⇒ 文字场景按 `strokeWeight` 生成 `-webkit-text-stroke`

### S2 真值下发接通（改 `prompt-builder.js` / `visual-parser.js`）

- 删除 `fmtFills` 的「SOLID 优先」：改为**按 Figma 图层顺序**逐条输出，TEXT 走 S1 的 `color/backgroundImage`
- 删除 `[has-gradient]` 标记，直接输出 `css:linear-gradient(...)`
- 同一份 S1 结果写入 `componentPlan.styleFacts[nodeId]`，供 S3 出口回填消费（单一事实源）

### S3 出口确定性回填（新 pass，写盘前，接 `pre-write-self-healing` ⑥-e）

- 用 `data-section-id` + 文本内容双重匹配，把产物节点 ↔ Figma 节点对齐
- 产物的 `color` / `background-image` / `text-stroke` 与 `styleFacts` 不符 ⇒ 按真值注入内联样式（元素级恒胜，不改共享 class）
- 匹配不到 ⇒ `colorHealSkipped++`，**不猜**
- 幂等：已等于真值即 `changed=false`

### S4 段锚存在性硬闸（扩 `code-structure-validator` 的 Q4-c）

- 真值段集：`layoutStructure.layout.sections`（含 `data-section-id` 的叶子），**动态取，不写死段名**
- 产物段集：`productFiles` 全量 `data-section-id`（沿用 A2 修正在增量轮的坑）
- 判据：缺失段按「段内文本量」加权缺口；缺口 >0 且缺失段文本量占比 ≥ 阈值 ⇒ `SECTION-ANCHOR-MISSING` **BLOCK**
- 与 TEXT-COVERAGE 互补：前者管「字有没有」，本闸管「整段在不在」
- 覆盖闭包复用 `figma-coverage-dedupe.js:232 sectionCoverageSet`（避免折叠段 id 误判）

### S5 运行时门禁分级（改 `mc-component-graph-phase2.js:3384-3422`）

- 允许降级的只有「运行环境不可达」类：`RUNTIME-001/002`（预览页 404/超时）
- 产物自身缺陷类：`RUNTIME-006 blank-render`、以及 `VISUAL-002 < 阈值且 analysisEvidenceCount===0` ⇒ **fail-closed，不发布、不标 completed**
- 分级来源：`runtime-static-rules.js` 既有 severity 表，不新增硬编码清单

### S6 终写溯源 + SFC 出口校验

- 写盘循环前对每个 `.vue` 跑 `@vue/compiler-sfc parse`；`errors>0` ⇒ 该文件**不落盘**、标记最后修改者（`relocator | semantic-revert | 66-C | theme-var`）并上报
- `stray-template-root-relocator` 的 `strayNodes` 排除 SFC 顶层块标签（`template/script/style`）——结构语义判定，非段名白名单
- `microcode-engineer.js:9586` 语义回退改为：回退前 parse、回退后仍失败 ⇒ 不回退，保留 healing 版并报错

### S7 网关错误分类重试（改 `ai-request-gateway.js`）

- `timeout / 5xx / 502` ⇒ `pick({ excludeIds: [previousProviderId] })` 换 provider
- `finishReason === 'length'` ⇒ 同 provider 强制关推理（保留现有语义）
- 分类依据 error 对象字段（`code/status/finishReason`），不写死 provider 名

### S8 输出预算（32545d82，可独立）

`promptChars≈155k` 已接近单请求上限：按 chunk 维度做 **prompt 瘦身**（复用现有 `maxNodes`/budget 机制）或把「关推理」前置到首请求；不改模型名、不写死 token 数。

## 4. 实施顺序与依赖

```
S6（SFC 出口校验 + 溯源）─┬─→ S4（段锚硬闸）─→ S5（门禁分级）   ← 先止血：坏产物/整段缺失/假绿
```
