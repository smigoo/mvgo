## 3 修复方案

### F1a 段树完整性对账（planner 出口，主修观测点）

**落点**：`microcode-engineer.js:816` 附近——`dedupeDuplicateSections` 返回后、挂 `_effectiveSectionsForLayout` 前。**不在 planner 内部改**（planner 是多任务共用出口，观测先于约束）。

**输入（单一来源，零新增口径）**：
- 上游承诺：`visual.layoutStructure.layout.sections`（vision 输出，顺序即设计序）
- 下游实际：`effectiveSections`（dedupe 后）

**校验项（判据 = 假设，真机验证为准）**：

| 判据 | 口径 | 阈值（假设） |
|---|---|---|
| a. 段缺失/重挂 | **全树递归**收集 vision 段 id 集合与出口段 id 集合（含各级 children，非仅顶层），分成两类计数：`missingIds`（全树找不到）与 `reparentedIds`（id 仍存在但父链改变，**容器吞并归此类，不算丢段**） | missing>0 即记（含 id+title 清单，≤6 条）；reparented 只计数不判错（吞并可能是合法变换，先观测分布） |
| b. 父子关系差异 | 以 vision 父子关系为基准，对出口树逐一核对：`missingParent`（子段在、vision 父段不在出口）+ `unexpectedParent`（父段与 vision 不同）。⚠️ 弃用「depthFlattened/拉平」概念——流量样本层级可能变深不是变平，该词不覆盖 | 任一 >0 即记计数+样例（≤3 条），reportOnly |
| c. 顶层顺序偏离 | **以 vision 段树顺序为唯一基准（Q2 裁决：用视觉分析数据），不引 Figma y**：vision 输出的 sections 数组本身即设计序，取 vision 与出口**都存在**的顶层同父兄弟段，按两树先后序两两比对，相对次序不同计 1 个 `orderInversions`；仅单侧存在的段不参与（已由判据 a/b 覆盖）。`comparablePairs` = 参与比对的对数 | 本轮只报 `orderInversions/comparablePairs`，**阈值待真机分布后再定**（装配存在合法重排形态，先观测） |
| d. 合成段 | 出口存在 vision 没有的新 id（如 `chart-` 前缀合成锚） | 只计数不判错（合成锚是合法机制） |

**级别**：首轮 **reportOnly WARN**（观测误报率），与 G14b/刀56 同纪律；二轮依真机数据收紧。

**计数行（恒打，0 也打）**：
```
🛡️ F1a 段树对账 missing=N reparented=M missingParent=P unexpectedParent=Q inversions=K/comparable=C synthetic=D [missingIds…]
```

**阳性对照**：三单离线重放必须命中——流量监测 `reparented≥4`（2:3439/1263:38/2:3565/chart-2:3604 重挂入 88:33）且 `missingIds` 按 a 判据全树扫描的实际结果定性（顶层消失的三容器 2:3438/83:30/2:3550 若其 id 已不在全树 ⇒ missing=3；若仍在 88:33 子树 ⇒ reparented）；重点车辆 `missingIds≥1`（136:122）；环境监测 planner 对账**全 0（阴性对照）**——注意环境监测的错乱在装配层，F1a 对它必须是阴性，这本身就是判据不越界的验证。

### F1b headerSlots 落地审计（产物出口，独立观测点）

**与 F1a 拆开的理由（第二轮评审）**：headerSlots 是否落进 `<base-panel>` 插槽是**产物 DOM 结构问题**，发生在装配之后；F1a 落点在 planner 出口，彼时产物尚不存在，把判据 e 塞进 F1a 是层级错位。

**落点**：产物 `index.vue` 写盘出口的只读扫描（挂写盘后只读审计，或复用既有出口审计的挂载时序，实施时按守卫总纲时序登记），**不修改产物**。

**身份链（两级锚，实证依据）**：
- **结构锚（硬）**：产物 index.vue 是否存在 `<base-panel>` 具名插槽开标签 `<template #header-right>`（形态实证：`percent-height-resolver.js:94` 注释 `<base-panel><template #header-right><HeaderSection /></template>…`）。缺失 ⇒ `slotAbsent`。
- **内容弱锚（软）**：插槽内是否承载对应 slot 的内容证据——`headerSlots[].figmaNodeId` 出现在插槽内部（`data-section-id` 或属性），或 slot content 文本命中，或对应 HeaderSection 组件被挂入。命中 ⇒ `landed`；结构锚在但无内容证据 ⇒ `unverified`（**不计为未落地**，防误报）。

**关联既有机制（查重结论）**：headerSlots 落地已有确定性兜底 `ensure-header-slots` code-fix-rule（`code-fix-rules.js:1481` → `_ensureHeaderSlots`，microcode-engineer.js:7460），planner 端有 `_headerSlotHost` 标记与 `preservedHeaderSlotContent` 计数（subcomponent-planner.js:2555-2562）。F1b **不重复实现落地**，只审计「兜底跑完后产物里到底落没落」，并与 `headerSlotsEmitted` 既有计数对账——重点车辆病灶与 planner 注释（subcomponent-planner.js:2552「index 无 #header-right 插槽 ⇒ 插槽内容退回 body 再渲一遍」）描述的链路一致，F1b 即为该链路补上出口度量。

**计数行（恒打，0 也打）**：
```
🛡️ F1b headerSlots落地 total=N slotAbsent=A landed=L unverified=U [absentSlotKeys…]
```

**阳性对照**：重点车辆离线重放 `slotAbsent=1`（胶囊，header-right）；环境监测 `slotAbsent=0`。

### F2 R11-B 失效归因（只读端到端追踪，本轮不盲修）

**升级口径（第二轮评审）**：只打印 `Object.keys(finalTruthFiles)` 不足以证明「归位成功但写盘时选了别的内容」。改为对**同一 relativePath 做只读链路追踪**：

1. R11-B 段前打印 `Object.keys(finalTruthFiles)`（key 形态：`package/index.vue` vs `index.vue` vs 其它前缀）；
2. relocator 调用点打印：目标 `relativePath` → key 查找命中形态 → `moved/changed`；
3. relocator 归位后对该文件内容取摘要（长度+hash 即可），在**最终写盘选中该文件内容的分支**再取一次摘要比对——两次摘要一致 ⇒ 归位成果存活到写盘；不一致 ⇒ 后续 pass 又覆写（R11-A 被 allFiles/finalTruthFiles 覆写冲掉的同族时序问题，此时失效点在覆写者，不在 R11-B 本身）。

对 45b0eceb/cbc44755 两单各跑一遍。归因清楚后**视结论另立修复项**（key 不匹配的一行修正可连修；覆写时序问题需另走一轮方案）。
