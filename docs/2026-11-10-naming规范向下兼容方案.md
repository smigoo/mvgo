# naming 规范向下兼容方案 v2（对齐 `_identifyNodeType` 既有口径）

> 2026-11-10 · 状态：**方案待对齐** · v1 作废（两处口径错误，见 §0，已提交 eab7a7a）
> 既有定义源：**docs/product/Figma-管线整理规范.md**（2026-09-01）+ `figma-connector.js#_identifyNodeType`
> 治理依据：六阶段

## 0 v1 作废原因（口径纠正）

1. **`@` 后是技术栈**：`@echarts/*`/`@antd/*`/`@element/*` 是**技术栈标记体系**（管线行为：`@echarts` 跳过整棵子树资源导出、`@antd` 下钻业务内容），不是「图表命名判据」——v1 误把它当 Tier1 命名信号。
2. **`bg-*`/`icon-*` 既有定义早已存在且已被消费**：`figma-connector.js#_identifyNodeType(name, node)` 第一优先级命名惯例（`bg`/`bg-*`/`bg `/背景→'bg'；`icon`/`icon-*`/图标/arrow→'icon'；`title-bg-*`/`header-deco-*`→'chrome' 面板装饰；img-*→'image'），第二优先级视觉属性回落（IMAGE fill >200px→bg 否则 icon），资源识别层完整消费——**断桥不在资源层，在新加的验收判据层**（component-acceptance util 自造了装饰后缀黑名单，未对齐既有口径）。

## 1 真正的缺口

新验收判据（G1-v2 tab 段识别等）**另写了一套识别口径**（name 含 tab + 装饰后缀黑名单），与 `_identifyNodeType` 存在口径漂移风险：

- `bg-tab-active` → 既有口径判 `'bg'`（背景角色，非交互 tab）✓ 与 R10 收紧方向一致，但依据应是**同一判定函数**而非两套黑名单（黑名单漏一个变体就复发）
- `tabs-icon` → 既有口径 `'icon'`（且是「多 icon 容器拆分例外」）✓ 同上
- `tab-*` → 既有口径**无**（业务容器，保留命名生成可读代码）→ G1-v2 应命中
- 未来 `_identifyNodeType` 口径演进（新增前缀/关键词），验收判据若不跟随即再次漂移

## 2 方案：验收判据对齐 `_identifyNodeType` 单一事实源

| 判据点 | 现状（自造口径） | 对齐后（单一来源） |
|---|---|---|
| G1-v2 tab 段识别 | name 含 tab + 装饰后缀黑名单 | **`_identifyNodeType(name,node)` 判定 ∈ 业务容器（非 bg/icon/image/chrome）且 name 含 tab 语义** ⇒ tab 段 |
| E2-v2 图标角色 | img 变量计数（icon3×3 WARN） | 判定='icon' 的节点按段归属分组，同段多卡 icon name 重复 ⇒ FAIL |
| E3-v2/⑥-ii bg 归属 | 双 bg 声明/变量复现 | 判定='bg' 的节点：挂载容器必须为其**父容器**（挂到祖先=错挂）⇒ FAIL |
| 未来新增 | — | 一律先过 `_identifyNodeType` 再加语义 |

**实施（D1 单一来源）**：`_identifyNodeType` 抽为共享（figma-connector 导出/独立 util），component-acceptance util import 同款判定——与 `collectMissingVueImports` 同款纪律。

## 3 向下兼容保证

1. `_identifyNodeType` 本身就是「命名优先 → 视觉回落」两层——**命名缺失自动走视觉属性推断**（IMAGE fill 尺寸分流 bg/icon），验收判据随之回落，旧稿零变化；
2. 段缺失/交互等非角色类判据（A1-v2 段锚/G1-v2 交互绑定）不依赖角色识别，维持现状；
3. spec 加「两口径一致性」夹具 4 例：`bg-tab-active`→'bg'、`tabs-icon`→'icon'、`tab-*`→业务容器、`title-bg-*`→'chrome'。

## 4 实施分期

- **P1**：抽 `_identifyNodeType` 共享 + component-acceptance G1-v2/E2-v2 改走共享判定（替换自造黑名单）；spec 一致性夹具
- **P2**：E3-v2/⑥-ii bg 归属校验升级（'bg' 节点挂载容器=父容器，否则 FAIL——比「变量复现」更本质）
- **P3**：structure-source 计数行加 naming 命中率列（观测规范命名覆盖率，为规范文档 §4.3 vision 增强/几何推断立项留数据）

## 5 回归

1. component-acceptance spec：一致性夹具 4 例（bg-tab-active→'bg'/tabs-icon→'icon'/tab-*→业务/title-bg-*→'chrome'）
2. 全量 jest 基线 diff 空
3. R13 批次：G1-v2 误报率（R10 的 bg-tab-active 形态应零触发）+ effective 率对比

## 6 边界

- 不改 `_identifyNodeType` 既有判定逻辑（只抽取共享，行为零变化）
- 不做设计稿命名硬门禁（Error 拦截由插件 Stage 3 承担）
- 规范文档 §4.3/§4.4 的 vision 增强/几何推断/端到端（中长期）另行立项
