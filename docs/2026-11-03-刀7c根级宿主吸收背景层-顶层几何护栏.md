## 2. 判据与几何护栏（可辩驳）

### 2.1 候选集扩充（唯一新增「输入」规则）

> `candidates(sec) = sec.sourceNodeIds ∪ directChildren(sec.id).map(id)`

**只对「非容器段」启用**。容器段沿用旧候选集（即 `sourceNodeIds`），理由是**构造保证**而非实测巧合（见 §3.2）。

### 2.2 注入护栏（决定层挂在哪）

> **根级宿主** = 唯一满足下列全部条件的段：
> 1. `isLayoutContainerSection(sec) === false`（非容器叶子）；
> 2. `resolveSectionBox(sec, figmaIndex)` 可解析；
> 3. `boxEq(sectionBox, figmaRootBox, 2)` —— `|Δx|,|Δy|,|Δw|,|Δh| ≤ 2px`；
> 4. 全树**恰有 1 个**这样的段（0 个或 ≥2 个 ⇒ 全部 fail-open，不注入）。

满足 ⇒ 该段的吸收层注入**根 `c-{semantic}-slot-con` div**（因为该段盒 ≡ 组件根盒，根 div 就是它在 DOM 里的对应物）。
不满足（但枚举确实算出层）⇒ **不注入**，只累加 `__absorbedBgRootHostDeferred` 并在日志里带 `deferredSections` 列出段 id ⇒ 可诊断、不放水。

### 2.3 为什么不是「给叶子加 wrapper」

叶子分支（`code-generator.js:920-927`）只输出 `<XxxSection style="…" />`，无 div、无锚。要给它加宿主有两种写法：

| 写法 | 代价 |
|---|---|
| A. 叶子外加 wrapper div 承载层 | 需把 `parentFlexStyle` 从组件标签搬到 wrapper ⇒ 破坏 P6「一层承载全部职责」契约；`spec:316/317` 等断言全变；flex 链多一层 |
| **B. 注入根 slot-con div（本刀）** | 根 div 本就 ≡ 组件根盒 ⇒ 几何正确；改动 3 行；不动 flex 链 |

选 **B**（与 A1「改动最小、零错位」口径一致）。

### 2.4 宿主锚点：新属性 `data-absorbed-host`

**不能复用 `data-section-id`**：

- 产物 `ContentFooter.vue` 根元素**已带** `data-section-id="807:2"`（叶子段自身锚）；
- 全仓 `[data-section-id="…"]` 的**唯一运行时下游** = `figma-connector.js:2580` 产出的 `targetDomSelector`（`nodeType==='bg' && parentId` 时写成 `[data-section-id="${parentId}"]`），进入产物 CSS / `resource-mounter` / `quality-score-v1.js:830` 解析链；
- 若根 div 也带同名属性 ⇒ 同页**双命中**，该 CSS 规则会同时命中根 div ⇒ 背景错挂/重复绘制，并污染 `mount-target-scoring` 派分。

因此新增专用属性 `data-absorbed-host="<secId>"`：全仓 grep **0 命中**，无既有消费者；且与容器分支的「宿主可识别」对称（容器靠 `data-section-id`，根宿主靠 `data-absorbed-host`）。

### 2.5 样式必须条件注入（否则既有用例必红）

`code-generator.deterministic-template.spec.ts:80` **逐字**断言：

```
class="c-device-monitor-slot-con" style="display:flex;flex-direction:column;"
```

该 fixture（`makeInput(deviceSections)`）**不含 `figmaNodeData`** ⇒ `indexFigmaNodes(null)` 空 Map ⇒ 恒 0 层 ⇒ 根 div 样式逐字不变。⇒ 定位样式 `position:relative;isolation:isolate;` **只在 `rootHostLayers.length > 0` 时追加**。

## 4. 改动清单（4 处源码 + 2 处 spec + 1 处文档）

### 4.1 `ai-engine/utils/container-absorbed-bg.js` —— 新增 1 个纯函数（判据本体零改动）

```js
/**
 * 刀 7c：把 sec 的 Figma 直系子 id 并入候选集（纯枚举，不做任何裁决）。
 * fail-open：sec/figmaIndex/rawNode/children 缺失 ⇒ 原样返回 sourceNodeIds。
 */
export function expandCandidateIdsWithDirectChildren(sec, figmaIndex) {
  const src = Array.isArray(sec?.sourceNodeIds) ? sec.sourceNodeIds.map(String) : []
  if (!sec || !figmaIndex || typeof figmaIndex.get !== 'function') return src
  const node = figmaIndex.get(String(sec.id))?.rawNode || figmaIndex.get(String(sec.id))?.node || null
  const children = Array.isArray(node?.children) ? node.children : []
  const out = [...src]
  const seen = new Set(src)
  for (const c of children) {
    const id = String(c?.id ?? '')
    if (!id || seen.has(id)) continue
    seen.add(id)
    out.push(id)
  }
  return out
}
```
