## 0. 一句话结论

本单**不是**配色/主题问题，而是**接管器选错了类**：本应走 `detectStatRowLeaf` 的三统计卡，被「每卡恰 2 TEXT」「成员宽高 ±2」两条硬约束证伪，回退到 `detectListLeaf`（通用 v-for 列表）。而 list 接管器的**几何源取自 Figma 帧盒（含透明留白的选择框）**、**卡内布局写死 row**、**填充真值只认 SOLID**，于是同时产生「卡重叠 / 值被右推 / `次` 换行 / 段标题丢失 / 卡底无渐变无圆角」五个可见差异。四处缺陷同源于「**真值取错层**」，不是一个地方的值填错。

## 2. 根因链（四方对齐）

### 2.1 声明层：plan 其实是对的，被渲染器丢弃

`.checkpoint/analysis.json#subComponentPlan.effectiveSections[0]`（仅 1 段）：

```text
id=136:121  type=list  layout=vertical  collapsed=true  renderHint=v-for  itemCount=3  title="今日累计"
body.layout = horizontal-3-columns
items[i].content.layout = vertical
items[i].content.elements = [ {label, position:"top"}, {value, position:"bottom", parts:[number, unit]} ]
items[i].repeatedFill = "#a6ceff" / "#d9e8ff" / "#d9e8ff"
```

plan **已经声明**了「标签在上、数值在下、数值由 number+unit 组成」。渲染器把它压平成 `it.texts`（只剩标签）+ `it.stats`（单条 `{v,l}`），再套死 `row` + `column` 模板，声明信息整体丢失。**这与刀55 的病灶同构**：声明存在但消费端不读，最终被硬编码模板覆盖。

### 2.2 接管层：`detectStatRowLeaf` 被真值证伪（不是判据写错了，是样本形态超出了它的假设）

三卡真值（每卡 TEXT 数 = 3）：

| 卡 | 帧盒 x / w / h | 卡内 TEXT | 判定 |
|---|---|---|---|
| 136:129 | 37 / 140.5 / 74.2 | `危化品车` fs12.3 + `51` fs20 + `次` fs12.3 | 3 TEXT |
| 136:128 | 166 / 120 / 74.2 | `重型货车` + `2` + `次` | 3 TEXT |
| 136:127 | 274 / 141 / 74.2 | `超高车辆` + `19` + `次` | 3 TEXT |

- `:884` `if (texts.length !== 2) continue;` ⇒ 三卡**全部**被跳过 ⇒ `parsed.length = 0` ⇒ `detectStatRowLeaf` 必然 fail；
- 即便放宽 TEXT 数，`:916` `member-size-mismatch` 也会因 `140.5 / 120 / 141` 触发拒绝。

即：**「统计卡 = 恰 2 个 TEXT」是单卡只有「名称+数值」的老样本假设**；本单是「名称 + 数值 + 单位」三段式，属合法形态而非畸变。这是判据的**适用域缺口**，不是阈值问题。

### 2.3 几何层：帧盒不是布局单元（可证伪论证）

- 帧盒 x = `[37, 166, 274]`，宽 = `[140.5, 120, 141]` ⇒ **Σ宽 = 401.5**；
- slot `136:121` 内容宽 = **377.5**；
- ⇒ 按帧盒排布**必然溢出 24px**，间距被算成 `[-11.5, -12]`。**溢出即证伪**：帧盒含透明留白（第三卡帧盒左边比可见底左移 21px），不是卡片。
- 可见卡底 `2:8034 / 2:8047 / 2:8058` x = `[37, 166, 295]`，宽均 120 ⇒ Σ宽 360 + Σ间距 18 = **378 ≈ 377.5（+0.5）**。**自校验通过 ⇒ 可见底才是布局单元**。

这条等式（`Σ卡宽 + Σ间距 ≈ 段内容宽`）就是 P0-1 的可辩驳判据：取错层必然不满足，取对层必然满足。

### 2.4 填充层：只认 SOLID ⇒ 渐变卡底结构性 miss

六个渐变节点（三卡顶部条 + 三卡卡底）**stops 完全一致**：

```text
2:8035 / 2:8048 / 2:8059  RECTANGLE 120×60  cr=1.76   GRADIENT_LINEAR  opacity=0.3
2:8024 / 2:8026 / 2:8025  VECTOR    140.5/120/140.5 ×14.5  同上
gradientStops = [ {p:0, #284565, a:0}, {p:1, #284565, a:1} ]
```

`resolveCardBox` 的匹配目标是 `findFillAnchorNode(node, normalizeCssColor(fill))`，而 `findFillAnchorNode` 内部只用 `firstSolidFillRgba(n)`（`:163`）。**渐变底不是 SOLID ⇒ 恒不命中** ⇒ 整条卡盒解析每次都在第一轮就 miss、回落帧盒。连带丢失：

- `radius`：`cards[0].fillNode` 为 null ⇒ `radius = null` ⇒ 产物无 `border-radius`（真值 1.76）；
- `padL`：`geoReady=false`（宽不等）⇒ 不写（真值 `icon.x − card.x = 41 − 37 = 4`）；
- `itemBgs`：三卡都走子树轨但 `backgroundImageOf` 无对应登记 ⇒ `skipped = 3`。

⚠️ `itemBgs.skipped=3` 本身是 **fail-closed 正确行为**（mapping 里确实没有三张卡底图，卡底真值是**矢量渐变**不是位图）。缺的是「渐变 → CSS」这条能力，不是「图片归属判据失效」。

### 2.5 附属缺陷（同轮发现，非本单可见差异来源）

plan `items` 的 id 与真值**错配**：`items[0] = {id:"136:127", name:"危化品车"}`，但真值 `136:127` 是 `超高车辆`（x=274），`136:129`（x=37）才是 `危化品车`。LLM 按内容排对了顺序，却把 id 贴反。这正是 §1 #2「141 贴给第一张卡」的成因。

## 3. 治本方案

### P0-1｜卡盒与填充真值同源（几何取「可见自绘底」，不再取帧盒）

**改动点**：`folded-grid-section-takeover.js#resolveCardBox`（`:2309`）与 `findFillAnchorNode`（`:2290`）。

**判据（单一来源，可辩驳）**：

1. 在成员子树内枚举**自绘底节点**：`fills` 中任一项 `visible !== false` 且 `type ∈ {SOLID, GRADIENT_LINEAR, GRADIENT_RADIAL, IMAGE}` ⇒ 视为「可见底候选」；**不再要求颜色等于 plan 归一值**（渐变/位图的 SOLID 近似天生不可等）。
2. 候选资格：`候选盒 ⊇ 本行成员盒` 且 **不含任何其他行成员盒**（"恰好容纳本行"，沿用既有 `boxContains` 口径）。
3. 多候选 ⇒ 取**面积最大**者；面积并列 ⇒ fail-open（回落旧口径，不猜）。
4. **自校验**：`Σ cardWidths + Σ gaps ≈ 段内容宽（±2）`。不满足 ⇒ **整体 fail-open 回落帧盒**（保证只可能变好，不可能变得更离谱）。
5. 主序统一：items 先按几何主轴重排（row→x，column→y），`cardWidths` / `gaps` / 渲染顺序**全部同序**。几何不可证 ⇒ 保持 plan 序（fail-open）。

**派生（全部由同一个 `fillNode` 输出，不另立第二套）**：`cardH`（=可见底高 60）、`radius`（=1.76）、`padL`、`itemBgs`、P0-3 的渐变 CSS。

**预期**：`cardWidths → [120,120,120]`、`gaps → [9,9]`、`cardH → 60`、`radius → 1.76`、`padL → 4`，`selfCheck: 378 ≈ 377.5 ✅`。

**为什么这条判据不容易假绿**：它不比对任何 LLM 归一值，只做纯几何闭包；写错（仍取帧盒）时 `Σ=401.5 ≠ 377.5` 会**自己报 fail-open**，日志里 `cardBox` 字段会直接暴露用的是 `frame` 还是 `visible-fill`。

> 副作用说明：`cardH` 由 74 → 60，段高会矮 14px。丢掉的 14px 是卡顶那条 `14.5` 高的装饰渐变条（`2:8024/8026/8025`），属 P0-3 的还原范围；先修布局再补装饰，不在同一步混改。

### P0-2｜卡内布局改为几何分支（值与单位强制同行）

**改动点**：`detectListLeaf` 新增 `resolveListItemInnerLayout(items, figmaIndex)`；渲染器 `:2710-2720` 按产出重建结构。与刀55 的 `resolveListMemberDirection` **同构范式**：几何可证优先，plan 声明次之，皆不可证回落现状。

**判据**：

| 字段 | 几何判定 | 取值 |
|---|---|---|
| `innerDir` | 名称盒与数值盒的 **x 重叠率 > 50%** 且 **y 不重叠** | `stacked`（纵排，本单） |
| | y 重叠率 > 50% 且 x 不重叠 | `inline`（横排） |
| | 皆不成立 | `null` ⇒ 回落现状（`row` + `margin-left:auto`） |
| `valuePartsDir` | number 盒与 unit 盒 **y 重叠率 > 50%** | `inline`（本单：`51` y1029 / `次` y1030） |
| | x 重叠率 > 50% | `stacked` |

次源：plan `items[i].content.layout === 'vertical'` 仅当几何 `null` 时作为 tie-break，**不覆盖几何**（与刀55「几何胜过 declared」一致，避免出现第二套优先级）。

**渲染契约**：

- `stacked`：`item = row`（`icon` + 文本列），文本列 `flex-direction:column;justify-content:center;`，**去掉 `margin-left:auto`**（正是它把数值推到最右）；
- `valuePartsDir === inline`：数值行外层 `flex-direction:row;align-items:baseline;`（`51` 与 `次` 同行，底对齐校正 fs20/fs12.3 的基线差）；
- `valuePartsDir === stacked`：保持现状 column。

**预期（OCR 可验）**：`51次` / `2次` / `19次` 各自成一行、数值在名称正下方、不再贴右边。

> ✅ **已落地**（步⑤，2026-11-03）。实现与本节有三处偏差（未单立函数名、未实现 plan 次源、`valuePartsDir` 的 x 轴补了「不重叠」约束），逐条见 **§14.5**。

### P0-3｜卡底渐变真值 → CSS（新增能力，判据明确）

**改动点**：新增 `gradientToCss(fill)`（与 `inferBackgroundStyle` 并列，单一来源），由 P0-1 的 `fillNode` 驱动。

**判据**：

1. `fill.type === 'GRADIENT_LINEAR'` 且 `gradientStops.length >= 2` ⇒ 生成
   `linear-gradient(<deg>, rgba(r,g,b,a) p%, ...)`，角度由 `gradientHandlePositions` 两端点向量还原（缺省 `180deg`）；
2. 叠加 `opacity`（本单 0.3）作为元素级 `opacity`，**不乘进每个 stop 的 alpha**（保持「整体半透明」语义，双层叠加时不会算错）；
3. stops 归一化：`position` 按 min/max 线性映射到 `0%..100%`（Figma 的 handle 位置不保证 0/1）；
4. 走 **`:style` 绑定**，禁拼静态 style / JSON（守 CODE-022 / CODE-028，与本文件 `bgImageVar` 通道同规）。

**预期**：三卡与三条顶条共享同一条 CSS（真值 6 节点 stops 全同 ⇒ 只应产出 1 个常量，避免 6 份重复字面量）。

### P1｜段小标题回填（`今日累计`）

**改动点**：`detectListLeaf` 返回契约增加 `title` 字段；渲染器输出标题行。

**判据（几何，不依赖 plan）**：在**段锚点容器**（`slot`）内找满足全部条件的节点：

1. 唯一 TEXT（`collectTexts(n).length === 1`）；
2. 盒的上界**早于**首行成员上界（`n.y + n.h <= firstRowTop`），且水平与成员区有重叠；
3. 距首行成员最近的唯一一个。

命中 ⇒ `title = { text, fs, color, icon:{file,w,h} }`；不命中 ⇒ 不写（**绝不回填 plan `title` 作为几何替代**，plan 值只作日志对照）。

**为什么不能只读 plan `sec.title`**：plan 的 `sourceNodeIds` 不含 `136:122`，说明该节点**不在段覆盖范围内**；直接读 plan 文本会让「标题存在性」失去真值校验（Vision 幻觉文本会照单全收），违反「只认 Figma 真值」的既有约定。

### P2｜header tabs（`江阴靖江长江隧道` / `江阴大桥`）

属 **LLM 侧段内渲染缺失**，非接管器职责（`hits.header = 0`，`136:120` 未被任何接管类认领，也未被 plan 覆盖）。建议**单独立项**，不要塞进本刀：混进来会让「接管器命中率」这条核心指标失真。

### P3｜vision 侧收敛项（记录，不在本刀）

- `repeatedFill` 臆造：真值三卡底 stops 全同（`#284565` α0→1 @ 0.3），plan 却给出 `#a6ceff` / `#d9e8ff` 两种浅蓝纯色，**色相与透明度均无真值支撑**。建议在 vision prompt 层加「卡底若为渐变，`repeatedFill` 必须置 null 或给出 stops」，否则该字段长期污染下游。
- item id 错配（§2.5）：建议在 plan 落盘前做一次「item 内容文本 ↔ 成员子树唯一 TEXT」的存在性校验，不通过则置 `id: null` 交几何配对。

## 4. 判据登记与防假绿

本刀**不新增 kind**（仍是 `list`），故不涉及 `FG_TAKEOVER_CLASS_RX` / reject-summary `HIT_KEYS` / `mc-check.cjs` 内嵌正则的 kind 登记。但须完成：

1. **真机计数行**（必挂，禁止只塞入参）——`detectListLeaf` 命中处输出单行 JSON：
   ```json
   {"cardBox":"visible-fill","widths":[120,120,120],"gaps":[9,9],"radius":1.76,"padL":4,
    "selfCheck":{"sum":378,"slots":377.5,"ok":true},"innerDir":"stacked","valuePartsDir":"inline",
    "gradient":1,"title":"今日累计"}
   ```
   `cardBox` ∈ `visible-fill | frame | null`，一眼可辨走的是新判据还是 fail-open 旧口径。
2. **reject-summary 扩展**：`takeover.listGeo = {selfCheckOk, failOpen}`，计数 0 也必须打（沿用 `panelBg` 约定）。
3. **判据单一来源**：卡盒解析只允许 `resolveCardBox` 一个入口；渐变 CSS 只允许 `gradientToCss` 一个实现；卡内布局只允许 `resolveListItemInnerLayout`。禁止在渲染器里写第二份 fallback 分支。
4. **同构锁**：`resolveListItemInnerLayout` 的 `innerDir/valuePartsDir` 枚举与渲染器消费分支需加一条 spec，防止后续新增枚举值未接线（对齐 `section-tree` 的合并列表悬崖教训）。
5. **验的人 ≠ 改的人**：改动者写的新正则/新断言不得作为唯一验收，必须用**真机复测产物的 OCR 行坐标**独立核。

## 5. 影响面与回归风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 卡盒解析放宽后误取大容器 | 面积最大候选可能是列表容器本身 | 「恰好容纳本行」`boxContains` 反证 + `Σ宽+Σ间距 ≈ 段宽` 自校验双重闸门 |

| `cardH` 74→60 段高变矮 | 顶部 14.5 装饰条暂缺 | 明确接受，P0-3 补齐装饰后复核段高 |
| list 接管影响其他样本 | 本判据对**所有** list 段生效 | 建议先在 `0907-l6` / `0908` 两个并行样本上跑离线重放比对 `cardBox` 字段变化 |

### 9.4 判定：两种「根治」不是同一件事

先拆词。「根治」在本仓有两种含义，两方案各占一头：

| | 含义 | 本方案 P0/P1 | G0~G4 |
|---|---|---|---|
| **A. 修到根因** | 改掉产生错值的那个判据 | ✅ **是**（`resolveCardBox` 取层 + `firstSolidFillRgba` 单口径） | ❌ **否**。G 全篇无一处改 `detectListLeaf` 几何判据 |
| **B. 防这一类复发** | 让同类缺陷不可能静默通过 | 🟡 部分（P0-1 自校验 + fail-open，仅覆盖 list） | ✅ **是**（G0 观测 / G2 出处 / G3 槽位 / G4 合一） |
| **C. 所见即所错** | 改完能证明改对了 | 🟡 需 G0.2 计数配合 | ✅ G0.2 `patchHitReport` |

**关键否证（为什么 G0~G4 单独跑完，这个 bug 依然在）：**
- G0.2 能把 `listGaps:-11` 记进日志，**但落盘产物仍是 `-11`**。观测 ≠ 阻断。
- G0.1 `PATCH-CHAIN-ERROR` 是**异常哨兵**；本缺陷是「算出了一个合法但错误的数」，全程不抛错 ⇒ 哨兵恒不触发。
- G4 把 3.4 万行收到 6~8 千行，`resolveCardBox` 该行**原样搬过去**仍是同一处错（文件变小不改变判据）。
⇒ **G 系列不含对本缺陷的修复项，它只提供「修复之后不被推翻」的基础设施。**

**反向否证（为什么本方案单独也到不了「根治」）：**
- `resolveCardBox` / `findFillAnchorNode` / `firstSolidFillRgba` 经全文件核对，**仅被 `detectListLeaf` 区段使用**（`:2101-2468`；其余 `:264/:761/:1318` 是文本色/图例点/其他 bg，非同一条链）。⇒ P0-1 的影响面**只有 list 一类段**，能在 172 个产物里覆盖 5 个（2.9%）。
- 本缺陷成立需要**两个独立根因同时成立**：①「这个段该由 list 接管」—— 由 plan 声明单方决定，`detectStatRowLeaf` 的 `:884 texts.length!==2` 与 `:916 member-size-mismatch` 在此单是**被真值证伪的过窄前提**，属**接管归属**问题（G1 域），本方案明确不修；②「卡盒真值取错层」—— 本方案 P0-1 修。
- ⇒ 只做 ①：段归对了类，卡盒还是负间距。只做 ②：卡盒对了，下次同样几何的段被判成 statrow 时依旧错。

### 9.5 结论

**没有一个方案单独能根治。真正的根治 = 本方案 P0-1（唯一触及根因的改动）× G0.2（让它可证）× G1（接管归属同批修正），三者缺一，且顺序不可换。**

- 若「只能先做一个」：**选本方案的 P0-1**。它是全表唯一直接改根因判据的改动，其余全部是基础设施或覆盖面扩展。G 系列没有它，跑完 3.4 万行→6 千行后此 bug 原样存在。
- 若目标是「这类问题别再回来」：**G0.2 的 `listGeo` 计数必须与本刀同批落**，否则「修好了」只能靠人肉截图确认（一改就假绿的经典形状，见本仓 E1/刀17 教训）。
- P0-1 治本性的硬证据只有一条，就是 §3 那条自校验：**`Σ cardWidths + Σ gaps` 必须 ≈ 段内容宽（±2）**。负间距在任何样本、任何方向上都会让该等式失败 ⇒ 整体 fail-open 回落帧盒。这是**「让错值不可能被写出去」**，而不是「把 -11 改成 9」。前者才叫根治。

据此 §8.5 排期表**不需要改**：`A → A′ → B → C`，其中 A′ 内含 P0-1 与 `listGeo` 计数同批、B 内含 `detectStatRowLeaf` 适用域修正。

## 10. 先做什么 —— 一处新定位的确定性缺陷与实施顺序修订

> 结论先行：**第一步不是改取层逻辑，是先挂计数行 + 加一道「间距不得为负」的总闸。** 原因见 10.1：负间距不是「真值取错」的结果，而是一个**分支守卫不对称**的纯代码缺陷 —— 它比原诊断更小、更确定、更不可能误伤。

### 10.1 新发现：`row` 分支缺 `geoReady` 守卫（代码级不对称）

同一段几何求解，两个方向用了**两套守卫**：

```js
// :2350  geoReady 已算出（要求所有卡盒同宽且同高）
const geoReady = boxesReady && cardBoxes.every(b =>
  Math.round(b.w) === Math.round(cardBoxes[0].w) &&
  Math.round(b.h) === Math.round(cardBoxes[0].h));

// :2364  row 分支 —— 只要 boxesReady，不看 geoReady
if (boxesReady && direction === 'row') {
  cardWidths = cardBoxes.map(b => Math.round(b.w));      // ← 异宽也照写
  gaps = byX.slice(1).map((p, k) => Math.round(p.b.x - (prev.x + prev.w)));  // ← 重叠即负
} else if (geoReady) {                                    // :2372 column 分支 —— 有守卫
  ...
}
```

**用本单真值代入，负间距精确复现**（真值可见卡底 120×60 等距 x=[37,166,295]，但 `resolveCardBox` 拿的是帧盒 140.5/120/141 @ x=[37,166,274]）：

| 相邻 | 计算 | 结果 |
|---|---|---|
| 卡1→卡2 | `166 − (37 + 140.5)` = `−11.5` | `Math.round` → **−11** |
| 卡2→卡3 | `274 − (166 + 120)` = `−12` | **−12** |

与产物 `FG_LIST_GAPS = [-11, -12]` **逐位吻合**。⇒ 这不是「取错层导致算不出」，而是 **`geoReady` 算出来了却没在 row 分支使用**（`sameHeight` 也只用于卡高、未 gate 宽度）。属**判据缺失**，与 `geoReady` 本身无关。

补充：`c-vehicle-monitor-41c0038c` 的 column `[-86,-86]` 走的是**有守卫**的分支，说明其 `cardBoxes` 全部同 y ⇒ `resolveCardBox` 对该样本**全量回退到同一个 `rowBox`**（去重/回退路径缺失），是与 10.1 不同的第二个成因，归 P0-1 的取层修复。

### 10.2 实施顺序修订（四步，每步可独立回归）

原 §3 把 P0-1 当一个整体做，实际应切成四刀，**按「误伤概率」从低到高排**：

| 步 | 改动 | 行为变更 | 误伤风险 | 判据 |
|---|---|---|---|---|
| **①** | `listGeo` 计数行（`reject-summary.js` 归一 + 日志 + spec） | **无** | 0 | 把 5 个存量样本的当前值变成可观测数字 |

## §12 步③ 已落地：row 分支补宽度守卫（含一处刀55 契约反转）

### 12.1 语义：从「拦负值」升级为「拦不可证」

步③ 修的是 §10.1 指出的**代码级不对称**：row 分支原本 `if (boxesReady && direction === 'row')`
**不看 `geoReady`**，而 column 分支有守卫。后果是「回退帧盒 + 异宽」时按 `x(后) − (x(前) + w(前))`
相减，得到负值并原样写进产物。

步③ 的判据不是「算完再拦负值」，而是**先判定横向几何可否证明**：

| 条件 | 含义 | 处置 |
|---|---|---|
| `sameWidth`（与 `sameHeight` **互相独立**） | 与 v-for「重复成员同构」契约一致 | ✅ 下发宽度 + 间距 |
| `horizProven` = `cards.every((c) => !!c.node)` | 每卡盒由 `resolveCardBox` **独立证明** | ✅ 下发（异宽也是真值） |
| 两者皆不满足（回退盒 + 异宽） | 横向几何**不可证** | ⛔ **同门拦下**（宽度与间距一起不下发） |

**为何 `gaps` 与 `cardWidths` 必须同门**：row 的横向间距 = `x(后) − (x(前) + w(前))`，
**同一个不可信盒**同时决定宽度与间距 —— 宽度不可证则间距同样不可证。只拦宽度会留下
「宽度不下发、间距照发」的自相矛盾态。

**为何必须保留 `horizProven` 这一支**：只用 `sameWidth` 会把「逐项已独立证明的真异宽」也拦掉 ——
那种样本的宽度是**事实**，照发才对。真机病灶样本恰好**两者皆不满足**。

### 12.2 🔴 与步①② 的关键交互（读计数前必看）

步③ 的守卫**先于**步①② 的负间距总闸生效 ⇒ 在「回退盒 + 异宽」样本上 `gaps` **从未被计算**
⇒ `negGapValues=[]`、`negGapClamped=false`，**信号由 `widthNotUniform` 承载**。

两个计数因此**互补而不重叠**，合起来恰好枚举「横向几何未下发」的全部成因：

- `widthNotUniform` = 「**不可证 ⇒ 不算**」（步③）
- `negGapClamped` = 「**算了但为负 ⇒ 拦下**」（步①②）

> ⚠️ 由此可推：步③ 之后，真机病灶样本的 `listGeo:negGap` **会掉到 0**。
> 看到 `negGap=0` 时**不能**直接判「判据失效」，必须同时看 `widthNotUniform`
> —— 这正是把两个计数**并列打在同一行**的原因。

### 13.4 跨度自校验：为什么不是「Σwidths + Σgaps ≈ 段内容宽」

原设计要求「`Σwidths+Σgaps ≈ 段内容宽 ±2`」。落地时改为 `|span(卡盒) − span(帧轨)| <= 2`，理由：

1. **代数恒等**：`Σw + Σg` 恒等于 `max(x+w) − min(x)` ⇒ 它**不是**独立事实，只是跨度的另一种写法。
2. **第二事实源**：「段内容宽」还要再取 `sec` 的 padding 口径 —— 违反「判据单一来源」。
3. **帧轨本身已是真值**：`rowBoxes` 就是「重复成员占位」的几何真值，卡底理应与它对齐同一行区间。
   真机两侧 `37..415` **逐位相等**（跨度 378 = 378）。

守卫效果：若几何锚选到卡内小色块 ⇒ 跨度必然远小于帧轨 ⇒ 整段 fail-open，退回步③ 的「不可证 ⇒ 不下发」。
计数上 `geomPicked` 记**尝试数**（不因回退清零）、`spanRejected` 记**拒绝**，
生效口径是 `geomPicked > 0 && !spanRejected` —— 否则「尝试」会被算成「生效」（假绿形状）。

## §14 步⑤ 已落地：卡内布局按几何重建（`margin-left:auto` 退场）

> 对应 §3 **P0-2** / §10.2 **⑤**。与步④ 同一份真机夹具（`REAL_CARDS`），**零合成数字**。

### 14.1 语义：换「谁来决定横向关系」，而不是调间距

病灶不是数值大小，是**关系被渲染层猜了**。真机三卡是「名称在上、`51`+`次` 同一行在名称**正下方**且左对齐」，
而渲染器硬编码「名称列 + stats 列 + `margin-left:auto`」⇒ 数值被推到**最右**、数值与单位上下两行
⇒ OCR 读成「名称 …… 右对齐的 51、次」。

🔴 `margin-left:auto` 与 `cardWidths`/`gaps` 是**同一种病**：声明层没有这条事实，是渲染器替真值做了决定。

### 14.2 四条几何判据（每条都可辩驳）

| 字段 | 几何判定 | 取值 |
|---|---|---|
| `innerDir` | 名称盒 × 数值盒：**x 重叠率 > 50% 且 y 重叠率 ≤ 50%** | `stacked`（纵排，本单） |
| | **y 重叠率 > 50% 且 x 重叠率 ≤ 50%** | `inline`（横排） |
| | 皆不成立（含**两轴都重叠**） | `null` ⇒ 回落现状 |
| `valuePartsDir` | 数值盒 × 单位盒：**y > 50% 且 x ≤ 50%** | `inline`（本单 `51`+`次`） |
| | **x > 50% 且 y ≤ 50%** | `stacked` |
| `valuePartsGap` | 单位盒左 − 数值盒右（真值 2） | **逐卡同整数**才下发；且**仅当 `valuePartsDir==='inline'`** |

**分母口径（易错点）**：重叠率分母取**较窄者** `Math.min(la, lb)` ⇒ 小盒被大盒包含即 **1.0**。
若改用「并集」或「较宽者」，真机的「名称宽 60 / 数值宽 20」会被算成 0.33 而判不出 `stacked` ⇒ 判据静默失效。

**为何反向轴是「不重叠（≤50%）」而不是「不显著重叠」**：放宽到「<80%」这类写法会吃掉真机样本
（名称 y1029、数值 y1029 的横排样本两轴都重叠 ⇒ 落入 `null`，安全）；而「不重叠」这个强约束
是**可辩驳**的：真值形态要么纵排要么横排，同位叠放本就不是「排列」⇒ `null` 是对的。

### 14.3 🔴 三道 fail-open 闸（缺一即「一条误判重排整段」）

| 闸 | 规则 | 若去掉会怎样 |
|---|---|---|
| ① **配对唯一** | 卡子树内 `characters` 与 vision 文本**全等**的 TEXT 恰 **1** 个才可用（0 个 = 取不到真值；≥2 个 = 有歧义）⇒ 该卡**不投票**，绝不按顺序猜 | 图条/装饰文本与名称同字时**取错盒** ⇒ 方向反着判 |
| ② **多卡一致** | 各卡结论取**集合**，只有一种才采纳；出现第二种 ⇒ `innerConflict` ⇒ 整段不下发 | 重复成员段被**多数票强排**，少数卡结构错 |
| ③ **只改「改变现状」的方向** | 只有 `stacked` 会重排（现状是 inline）；`inline` 仅**确认**现状 | 把 `inline` 段误压成纵排（双向伤害） |

**③ 的量化意义**：判错的**最坏后果是保持原样**，而不是产生新错形态。这是本步「误伤风险 ≈0」的全部依据。

### 14.4 渲染契约与产物证据

- `innerStacked` ⇒ stats 块**移入 `it` 的文本列内**（紧接名称下方 ⇒ 天然左对齐）：
  外层 `display:flex;flex-direction:column;align-items:flex-start;flex:none;`；**`margin-left:auto` 一字不写**。
- `vPartsInline` ⇒ stats 组 `display:flex;flex-direction:row;align-items:baseline;justify-content:center;`
  （`baseline` 校正 fs20 与 fs12.32 的基线差，否则小字贴大字底线）；`valuePartsGap` ⇒ 追加 `gap:2px;`。
- 非 `stacked` ⇒ **逐字保留**旧结构（`margin-left:auto;display:flex;flex-direction:row;flex:none;`）。
