# 骨架层确定性装配 —— P0 独立计划

**日期**：2026-09-16
**定位**：影响效果最大的根因 —— 「确定性事实没有被确定性装配，而是丢给 LLM 自由发挥」，尤其是骨架层（模板结构 / header 归属 / 图表位置）。
**核心思想**：把「模板结构」从 LLM 手里收回，由管线根据 layoutStructure 确定性生成骨架，LLM 只填叶子内容。

---

## 一、问题现状（这一轮的实证）

| 现象 | 事实（视觉分析已给出） | 产物（LLM 自由发挥） | 根因 |
|------|----------------------|---------------------|------|
| 环形图到最右边（12bc3750） | charts = doughnut | chartRef 在 `</base-panel>` 外 | 骨架位置错 |
| 布局全纵向（54c256c7） | layout = horizontal | 产物 column | facts 对齐失败（已治本） |
| header 图标进内容区 | review 建议「归并 header」 | headerRelation=None，独立 section | header 归属没装配 |
| 图例/环形图三栏布局 | 「两列图例 + 中间环形图」 | ListSection + 外面的 chartRef | 结构自由发挥 |

**共同规律**：视觉分析其实**给对了事实**，但下游没有把它**确定性装配成骨架**，而是让 LLM「看着事实自由发挥结构」，LLM 就发挥错了。

---

## 二、三个子项

### E3-1：模板骨架装配（chartRef 位置 + 子组件顺序）

**现状**：LLM 自由写 index.vue 模板，`chartRef` 常跑到 `</base-panel>` 外面。

**确定性做法**：管线用 `layoutStructure.sections` 的视觉顺序，确定性生成骨架：

```html
<template>
  <base-panel panelKey="default-panel">
    <template #header-right>          <!-- 确定性：header 插槽 -->
      <HeaderSection />
    </template>
    <div class="c-xxx-slot-con">      <!-- 确定性：内容容器 -->
      <ContentSection />              <!-- 按 sections 顺序 -->
      <ChartSection />                <!-- 图表 section，chartRef 在其内部 -->
    </div>
  </base-panel>
</template>
```

- 子组件标签顺序 = `sections` 视觉顺序（确定性）
- `chartRef` 永远在**图表 section 的子组件内部**，绝不在 base-panel 外

**要删的纠偏器**：chartRef 位置自愈、结构自愈（`stripInterBlockProse` 之外的结构修补）。

### E3-2：header 归属装配（小标题/tabs → header 插槽）

**现状**：`headerRelation`/`slotCandidate` 全 None，review 的「归并建议」只记录不消费。

**确定性做法**：
1. 消费 review 归并建议 + section 语义（「小标题」「tabs」「sub-header」），确定性标记哪些 section 属于 header。
2. 属于 header 的 section → 放进 `#header-right` 插槽，不生成独立内容区组件。

**要删的纠偏器**：`ensureHeaderSlots` 的猜测逻辑（R3 之前延后的那块）。

### E3-3：图表位置装配（chart section 的容器）

**现状**：图表容器（chartRef）与图例/标题的布局关系靠 LLM 自由写，导致「两列图例夹环形图」变成「图例列表 + 外面一个图」。

**确定性做法**：chart section 的布局（图例在左/右、图表居中）由 `layoutStructure.charts[].layout` 确定性推导，管线生成图表 section 的骨架（图例容器 + 图表容器 + 背景容器）。

**要删的纠偏器**：图表布局自愈。

---

## 三、实施步骤（顺序）

1. **先做 E3-1（骨架装配）**：建立「layoutStructure.sections → index.vue 模板骨架」的确定性生成器，子组件顺序 + chartRef 位置由管线定。
   - 这是最基础的一步，E3-2/E3-3 都依赖它。
2. **再做 E3-2（header 归属）**：在骨架生成器里，把 header 类 section 放进 `#header-right`。
3. **最后 E3-3（图表位置）**：chart section 的容器骨架。

## 五、风险与边界

1. **骨架生成器必须是 fail-open**：layoutStructure 缺失/异常时，回退到 LLM 自由生成（不阻断）。
2. **不能破坏已有治本**：facts 对齐（布局 display）、S6/S7（资源）、A2（命名）都是骨架之上的「填值」层，骨架装配后它们照常工作。
3. **与 A1（类名骨架化）的关系**：E3 管「结构骨架」（模板标签顺序），A1 管「样式骨架」（common.less 规则），两者互补，可并行。
4. **每做一项，必须删对应纠偏器**（删减法铁律）。

---

## 六、预期效果

- **「事实对但产物错」的骨架级错误归零**：chartRef 位置、header 归属、图表位置、子组件顺序都不再依赖 LLM 运气。
- **删 3-5 个结构自愈纠偏器**。
- **为 A1（样式骨架）、D（图表）铺路**：骨架确定后，样式和图表配置的确定性装配才有稳定锚点。
