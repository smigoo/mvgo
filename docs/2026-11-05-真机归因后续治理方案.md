### 13.2.1 D1 撤销与 `imgSrcNoMountTarget` 判据更正（2026-11-05）

**结论：D1（"资源挂载计划覆盖 `imgSrc` 类资源"）撤销——治本方向建立在误判之上，不做。**

### 13.7 D2 治本：`sizeFromScaleMode` 的 STRETCH 语义错配（2026-11-05 19:5x）

> 🔴 **本节更正 D2 的既有定义**。`docs/2026-11-05-真机归因-六任务证据链与既有方案冲突.md:114` 与 G3 写的是「per-item 背景缺**激活态语义**」——**不准确**。真因是 `scaleMode` 真值的语义错配，与激活态无关。

#### 13.7.1 根因（`background-size-inference.js:63-78` + `:149-176`）

`c72bbe2`（2026-11-05 同日「背景 scaleMode 进真值」）新增：

```js
case 'STRETCH': return { size: '100% 100%', repeat: 'no-repeat', inferredBy: 'scaleMode' }
```

且 `inferBackgroundSize` 拿到 `authoritative` 就**提前 return**，完全绕过 `figmaBox/parentBox` 几何。

**错配**：Figma 的 `STRETCH` 描述「图在**自己的框内**如何缩放」，不改变「框相对父容器的几何」；CSS 的 `100% 100%` 描述「拉伸填满**当前挂载元素**」。当图节点只是容器的一块局部区域时，两者直接冲突。

**真值链条（`c-aiot-dpjh-bsjd-09636315` 实锤）：**

| 层 | 值 |
|---|---|
| Figma 卡 | `470×72`；卡底色 `Rectangle 346242317` = `470×72`（整卡） |
| Figma image 节点 | `image 313`（`48:5800`）= **`459×29` @ 相对 y=0** → 卡顶部装饰带，占卡高 40% |
| mapping 真值 | `figmaBox {459×29 @ (20837,51606)}` / `parentBox {470×72 @ (20831,51606)}`，**字段齐备** |
| coverage | `(459×29)/(470×72)` = **0.3934** < `COVER_RATIO(0.9)` |
| 几何推断应给 | `459px 29px` + `position: 6px 0px` ✅ |
| 修复前产物 | `100% 100%` + `0px 0px` ❌ → 29px 带子被拉伸 **2.48 倍**铺满整卡 |

**用户症状的完整解释**：装饰带被拉满后，激活卡底色 `#a6ceff` 与非激活卡 `rgba(255,255,255,0.43)` 的差异被**完全盖住**，6 卡视觉一致 ⇒ 「`image_313-5800.png` 出现在每一个 list，应该激活才有」。**激活态从未缺失**（`repeatedFill` 已正确区分 1×`#a6ceff` + 5×`rgba(255,255,255,0.43)`），缺的是背景图的**几何还原**。
