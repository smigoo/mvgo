# 布局真值整治方案（Layout Truth Remediation）

> 版本：v1（2026-11-14） 适用：microcode-max / vue3-max / lite 三条生成管线
> 触发事故：`mc-max-1794651114530-9ed088e3`（流量监测）、`mc-max-1794651128303-1d3ccbb5`（设备详情）
> 关联提交：`2e761b69`（几何并集段高 + header 条并入）、`bde60c07`（S1 段头渲染）

## 一、问题现象（真机取证）

| # | 现象 | 直接观感 | 真因（已定位） |
|---|---|---|---|
| 1 | 「当日总流量」整块统计消失 | 只剩一行标题 | 段锚点落在 24px 的标题 GROUP 上，内容块 `2:3660` 无段认领；三条高度上溯全 miss ⇒ 段高 24 |
| 2 | 「车型分布 / 流量预测」副标题消失 | 只有卡片和图表 | 副标题条是段锚点的**兄弟**，既不在段高里也不在段内 |
| 3 | tab 块跑到组件顶部压住面板标题 | 「流量预测」横在面板头上 | 副标题条没进段 ⇒ tab 只能靠 S4-b 兜底，落点退化为 index 根 |
| 4 | 产物总高溢出 101px | 末段被压 / 内容出框 | `flex:0.044…0.260` 之和 = 0.999（= h/Σh），再叠 `margin-top:10+42+49` |
| 5 | tab 间距翻倍 | 视觉松散 | 真值 `itemSpacing = 8.04`，产物硬编码 `gap:16` |
| 6 | 容器被判成 flex 后错位 | 两张卡 + 中间装饰图被摊平 | `2:3660/2:3604` 几何上是**重叠摆放**，却被当 auto layout |

## 二、根因分类

### R1 布局真值多源（7 个写者）

| # | 写者 | 写什么 | 事实来源 |
|---|---|---|---|
| 1 | `prompt-builder:2358` | 段 `layout`（vertical / horizontal-2-columns） | 模型猜测 |
| 2 | LLM 生成 | 非接管文件内联 `gap`/`flex-direction` | 模型自由 |
| 3 | `code-healer` | 自愈改写内联样式 | 规则 + 模型 |
| 4 | `resource-mounter` / `mount-plan` | S4-b tab 块等注入（`gap:16`） | 硬编码 |
| 5 | `folded-grid-section-takeover` + S1 header | 接管 SFC 内联布局 | 各自推断 |
| 6 | `code-generator` 装配层 | `index.vue` 的 `flex:<比例>` + `margin-top` | 各自推断 |
| 7 | **`file-writer:1783` 终裁覆写** | takeover 快照整包替换 | 快照内容（最终赢家） |

⇒ 接管段由 #5/#7 决定，非接管段由 #2 决定，段间由 #6 决定。**任一条没吃同一份事实，就会出现"部分生效"**。

### R2 判据依赖图层命名

`slotAncestorHeightFor()` 要求父节点名**严格等于** `slot-<段名>`。设计稿整理后（插件改名为 `0sub-header` / `1统计` / `5cards`）该判据 100% 失效；同一份设计的旧版（`f4ffe0c6`，名为 `slot-当日总流量`）却能取到 556。

### R3 Figma `layoutMode` 不可信

| 节点 | `layoutMode` | 几何事实 | 结论 |
|---|---|---|---|
| `2:3660` 1统计 | HORIZONTAL | 子项 **重叠**（gap −72） | mode 说谎 |
| `88:32` 0sub-header | null | 子项同一行、间距齐次 | mode 缺失 |

⇒ **判据必须只看几何**，`layoutMode` 只作交叉验证留痕。

### R4 门禁盲区（"已接入但没生效"）

`G10v2 段高比例画布收敛` 真机日志长期是 `{"groups":0}` —— 判据挂在 `bands` 分支，而实际产物走 `topBodyRoots` 分支。没有计数行就无法区分「没命中」与「没生效」。

## 三、目标与原则

1. **唯一真值**：布局结构（方向 / 间距 / 是否叠放）只在**视觉分析阶段**算一次，冻结下发，下游只读不推。
2. **几何优先**：判据只吃 `bbox` + 父子关系 + 节点类型；不读 `layoutMode`、不读图层命名。
3. **失败安全**：任一层缺事实 ⇒ 不写布局（回落自然流），禁止猜。
4. **可观测**：每条判据都有计数行（0 也打），能区分"没命中"与"没生效"。
5. **零回归**：无事实的产物必须**逐字不变**（字符串级断言）。

## 四、判据规格：`inferLayoutFacts`

### 4.1 输出形态

```js
// key = Figma 容器节点 id
{
  "1744:125": { mode:"column-stack", gaps:[7,0,10,14,4,15,10], align:"stretch", overflow:true },
  "88:32":    { mode:"row-between",  align:"space-between" },
  "2:3566":   { mode:"row",          gap:8, align:"center" },
  "2:3660":   { mode:"free-overlay", reason:"children-overlap" },
  "2:3604":   { mode:"free-overlay", reason:"children-overlap" },
  "2:3436":   { mode:"unknown",      reason:"single-child" }
}
```

字段：`mode / gap / gaps / align / reason / overflow / modeConflict / confidence`

### 4.2 五态定义

| mode | 含义 | 渲染建议 |
|---|---|---|
| `row` | 一行，间距齐次 | `display:flex;flex-direction:row;gap:<真值>` |
| `row-between` | 一行，首尾贴边、中间弹性 | `display:flex;row;justify-content:space-between` |
| `column` / `column-stack` | 纵向，间距齐次 / 不齐 | `flex;column;gap:<真值>` / `flex;column` + 逐项 `margin-top` = 真值差 |
| `free-overlay` | 子项重叠或交叉摆放 | `position:absolute` / `display:grid` 叠放，**禁止 flex 比例** |
| `unknown` | 单子节点 / 缺 bbox | 不写布局 |

### 4.3 判定流程（容差固化）

```
1  取容器内 ≥2 个有 bbox 的直接子节点；不足 ⇒ unknown
2  主轴判定（区间法，不用"对齐"）：
     按 y 排序后 y 区间两两不交叠（容差 2px）且另一轴重叠率 ≥0.5 ⇒ column
     按 x 排序后 x 区间两两不交叠（容差 2px）且另一轴重叠率 ≥0.5 ⇒ row
     都不满足 ⇒ free-overlay
3  算相邻间隙 gaps[]；任一 < -2 ⇒ free-overlay（子项重叠）
4  间距齐次：max(gaps) - min(gaps) ≤ 2 ⇒ uniform
5  守卫 G1 越界：任一子项越出容器 bbox >2px ⇒ 不判 between（降为 stack/free）
6  守卫 G2 单间隙：仅 1 个 gap 且 gap > 主轴尺寸×0.3 ⇒ row-between（不写 gap）
7  守卫 G3：uniform=false 且（G1 不成立）且首尾贴边(≤16px) ⇒ row-between/column-between
             否则 ⇒ column-stack（逐项 margin = 真值差）
8  modeConflict = (layoutMode 推得方向 ≠ 几何方向) 或 (有 mode 但判 free-overlay)
```

## 五、数据契约（唯一真值怎么落地）

```js
// 1) 分析阶段（visual-parser 后处理链，模型调用之后）
parsed.layoutFacts = inferLayoutFacts(figmaData)        // 全局 map，key = 容器 id
parsed.layoutStructure.layoutFacts = parsed.layoutFacts // 与既有 inlineCompositeRows 同址

// 2) planner 出口：绑定到段对象（随对象走，避免 id 被改后查不到）
section.layoutFacts = parsed.layoutFacts[section.figmaNodeId || section.id] || null

// 3) 下游只读
takeover / code-generator / resource-mounter / prompt-builder  → 一律读 section.layoutFacts
```

**三条硬约束**

| 约束 | 理由 |
|---|---|
| 只在分析阶段算一次，之后不重算 | 全树只有那一刻完整；planner 之后是裁剪视图 |
| 绑定到段对象，不靠 id 查表 | `uniqueSectionIds` / `mergeAdjacentHeaderStrips` 会改 id |
| 拿不到 facts ⇒ 不写布局 | 与既有 fail-open 纪律一致，禁止猜 |

## 六、接入顺序（每步独立可验）

| 步 | 改动 | 影响产物 | 验收 |
|---|---|---|---|
| **S0** | `utils/layout-geom-facts.js` 纯函数 + golden spec | 否（只加字段） | 10 容器期望值全绿 |
| **S1** | `visual-parser` 后处理链写 `layoutFacts`，planner 出口绑定；计数 `layoutFactsBound` | 否 | 日志出现 bound=N；产物逐字不变 |
| **S2** | takeover 读 facts：`row` 用 gap、`between` 用 space-between、`free-overlay` 禁用 flex 比例；S1 header 的 `margin-bottom` 取 facts | 是（接管段） | 1263:38 产物 `gap:3`；2:3566 `gap:8` |
| **S3** | `prompt-builder` 下发 facts（"body 为 row-between，间距 8px（真值），禁止改结构"） | 是（LLM 段） | 生成文本含结构约束 |
| **S4** | 装配层 `flex` 分母含 Σgap（`topBodyRoots` / `isRowBand` 两条路径） | 是（全局） | 9ed088e3 不再溢出 101px |
| **S5** | 一致性门禁 + 计数 + 真机对照 | 否（只观测） | 4 个冲突计数为 0 |

## 七、门禁与可观测（新增计数，0 也打）

| 计数 | 含义 | 触发条件 |
|---|---|---|
| `layoutFactsBound` | 绑定成功的段数 | S1 |
| `layoutGapConflict` | 产物 gap 与 facts 不符 | facts.gap 存在且产物 gap 差 >1px |
| `layoutFlexOnOverlay` | facts=free-overlay 却写 flex + 比例 | S2 后应恒 0 |

| `flexFallback1` | 真值缺失回落 `flex:1` | 兜底可观测 |

## 八、验收标准

**必须同时满足**

1. golden spec 全绿（10 容器 + 三条守卫 + modeConflict 用例）
2. 9ed088e3 真机重跑：tab `gap` 16→8、总高不再溢出、`2:3660/2:3604` 不再被摊平、两个副标题出现
3. 无 facts 的产物**逐字不变**（字符串断言，防回归）
4. 门禁 4 个计数：冲突类为 0，绑定类 >0

## 九、风险与回滚

| 风险 | 处置 |
|---|---|
| 判据把"自由摆放"误判成 row/column | G1/G2/G3 守卫 + golden 用例；单容器可临时用 `MVGO_LAYOUT_FACTS=0` 关闭 |
| 分母改动导致所有产物布局变化 | S4 单独提交，便于整提交回滚；先观察一轮真机 |
| facts 查不到导致布局全丢 | fail-open：拿不到 ⇒ 不写布局（回落自然流），并计 `layoutFactsMiss` |
| 与 takeover 快照冲突 | 快照生成时即消费 facts，终裁覆写内容天然一致 |
