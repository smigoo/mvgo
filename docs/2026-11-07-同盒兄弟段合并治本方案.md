## 3. Phase 3 治本设计（硬约束逐条对照）

### 3.1 修法：R1a 三段式（留痕 → 透传 → 归一）+ R1b 纯观测

**R1a 三段缺一不可**——v2.2 的核心修订是补上第②段，否则第③段在真机永远拿不到输入。

#### ① 产出处留痕（`section-tree.js#uniqueSectionIds`，`:389-405`）

改名时同步写内部留痕 `_derivedFromId` = 改名前原始 id（`_derivedFromId: sec._derivedFromId || id`，幂等保留最早来源）。

- 只增不改：`id` 仍按 E1 原样加后缀（prompt 唯一性、组件命名、DOM 锚唯一性全部不变）。
- `_derivedFromId` **不进** `sectionAnchorCandidates`、**不进** `collectSourceNodeIds` 并集、**不进** prompt / `data-section-id`。
- 这是「派生后缀确由本管线产生」的**唯一铁证**，替代形态猜测。

#### ② 白名单透传（`generation-context-assembler.js`，v2.2 新增，**必需**）

`uniqueSectionIds` 在 planner 产出，engineer 主路径读的是 assembler 重建后的 `generationInput.componentPlan`（`generation-context-shadow.js:47` 是 `assembleGenerationContext` 唯一调用点）。当前 `normalizeSectionNode` 手写白名单（`:244-322`）不含该字段 ⇒ 留痕被剥；且 `droppedKeys`（`:230-235`）**只统计对象/数组值**，字符串被剥连痕都没有。

三处改动（全部沿用 R8-7 既有范式）：

1. `BODY_PASSTHROUGH_KEYS`（`:162-171`）加入 `_derivedFromId`；
2. `normalizeSectionNode` return 显式透传：`...(section._derivedFromId ? { _derivedFromId: String(section._derivedFromId) } : {})`（缺字段不产键，零副作用）；
3. `ctx` 新增 `derivedIdPassthrough` 计数（0 也打），随 `normalization`（`:366`）进既有 `🛡️ plan 归一化·已评估` 日志（`:417-421`）；同时断言 `droppedKeys._derivedFromId` 恒不存在（防被当内容字段重复计数）。

#### ③ 判据处归一（`section-tree.js#dedupeDuplicateSections` G14a 分支，`:207-214`）

**最终复核发现：v2.2 原写法不成立，必须先修订才可实施。** G14a 的现行条件不是比较 `prevAnchor === curAnchor`，而是分别检查 `intersection.includes(prevAnchor)` 与 `intersection.includes(curAnchor)`，再以两布尔值不相等豁免（`:208-214`）。对 9f43a112 的真实两段：

- `prev.id = 2:8437`，`prev.sourceNodeIds` 含 `2:8437`；
- `cur.id = 2:8437-2`，`cur.sourceNodeIds` 也含**原始** `2:8437`，但不含 `2:8437-2`；
- 归一后双方锚点都是 `2:8437`，于是 `prevIsIdentity=true`、`curIsIdentity=true`，G14a 不豁免；
- **但是**若只把 `curAnchor` 归一为 `2:8437` 而不改 `intersection`，仍得到 `true/true`；而若实现只在比较身份时把两锚点都归一，理论上成立，但必须明确该归一结果**只替换身份比较值**、绝不能修改 `sourceNodeIds`。方案原文没有精确定义到这一步，§3.4 的阳性结果不能只靠同一函数 fixture 推定。

修订后的实现契约：新增零依赖纯函数 `canonicalAnchorIdentity(sec)`，只用于 G14a 的身份读取；保留原始 `sectionAnchorKey` 给所有其他消费者。G14a 必须显式改为：

```
prevAnchor = canonicalAnchorIdentity(prev)
curAnchor  = canonicalAnchorIdentity(sec)
intersection = 原始 sourceNodeIds 交集（不归一、不增删）
prevIsIdentity = intersection.includes(prevAnchor)
curIsIdentity  = intersection.includes(curAnchor)
```

命中前置条件仍为：`_derivedFromId` 非空、`sectionAnchorKey(sec) === String(sec.id)`，且留痕值为非空字符串；否则返回原始 `sectionAnchorKey(sec)`。此实现必须用**真实有效段对象经过 `uniqueSectionIds → assembler → dedupeDuplicateSections` 的端到端真机路径**证明：阳性任务 `identityNormalized>0`、`nestedExempt=0`、既有 R1-1 实际记录 `shared-anchor-superseded`。如果这组事实与 §2.2 的单变量回放不一致，停止实施并重开根因分析，不能通过改断言让它绿。

- 🔴 条件「`key === String(sec.id)`」是防「锚点修复结果被留痕字段覆盖」的必需闸门；留痕不是更高优先级身份来源。
- 🔴 **不改 `sectionAnchorKey` 返回值**、不改候选表、不改 `sourceNodeIds` ⇒ `visionSemantic` / `heightById` / DOM 锚零波及。
- 效果（仍是假设，待真机）：9f43a112 两段身份恢复为原始 `2:8437`；相交集合保持原始值；两方均命中交集 ⇒ G14a 条件不豁免 ⇒ 由既有 R1-1 决定是否按 `elementCount` 收敛。必须实测确认保留的是 stats 段而不是丢错内容。

#### R1b `sectionsShareSameBox`：纯观测，不拦截

- 判据与既有同盒口径**同构**：逐字段**严格相等**、**不用容差**（对齐 `figma-node-layout-facts.js:129` 刀6、`folded-grid-section-takeover.js:166-169 sameBox`）。取 `figmaBox ?? absoluteBoundingBox`，任一盒缺失/非法 ⇒ false（fail-open）。
- 只在 G14a 冲突分支计数 `sameBoxSeen`，**不改变豁免与否**；升级拦截另案，且需第二个真机同盒样本 + 同盒壳+内容阴性 fixture。

**不新增第三套判据**：收敛仍由既有 R1-1 完成；留痕/透传/归一只恢复判据输入的真值；不合并段树、不改父子形态、不碰 prompt/装配/产物。
