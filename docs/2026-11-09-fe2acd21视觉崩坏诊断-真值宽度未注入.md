## 3. 根因（三条，互相放大）

### A. 子段定值宽度真值未注入 → tab 列被内容撑爆（主因）

- 真值：`89:39` 列 46px、每个 tab 项 34–46px（Figma 里是**竖排窄条**，高 40–72）。
- 产物：`.c-device-monitor-89-39-con { flex: 0 0 auto }`（`common.less:160-168`），6 个 tab 写成横排文字按钮，自身 min-content ≈193px ⇒ 列宽由内容决定，**46px 真值彻底丢失**。
- 后果：`89:37` 是 row flex，`gap 8` 之后网格只剩 `405−193−8 = 204px`。

### B. grid 列宽/间距用 `1fr` 代替真值 → 三列被压成 37.5px

- 真值：3 列定值 117 + 列 gap 8（总 367）。
- 产物：`grid-template-columns: repeat(3, 1fr)`（`common.less:169-176`），容器只有 204px，而每个卡 min-content ≥117 ⇒ `1fr` 被压到 **37.5px**，第三列被内容顶到 117（`37.5 37.5 117` 的异常组合）。
- 后果：卡内文字横向全部重叠（探针命中 **15 组**文本重叠：摄像机/超高检测器/激光雷达/CO/CO-VI/水质监测设备…），并在 `x=0` 处向外溢出（探针 25 个元素逃出 stage）。

### C. flex 子项缺 `min-width:0` → header 溢出 148px

- `.c-device-monitor-header-stat-group { width: 100% }`（`common.less:28`）在 flex row 父级里没有 `min-width:0`，三项 stat 的 min-content 之和 568px 直接把父级撑出 stage 右边界。
