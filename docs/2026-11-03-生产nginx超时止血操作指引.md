# 生产 nginx 超时止血配置（2026-11-03，任务 mv-lite-1793686730643-ae7d4a85 504）

## 背景
生产 `/api/` 反代 `proxy_read_timeout` 未显式配置（默认 60s），AI 修复等长请求被网关掐断返回 504。
主治理已把 AI 修复异步化（fixId+轮询），本配置为其余长接口（如同步 ai-chat、生成类 SSE 前置请求）的兜底止血，与异步化不矛盾。

## 操作（在 ECS 上执行，属部署动作——由用户执行）

```bash
ssh -p 65522 root@47.98.216.206

# 1. 先看现状（确认当前值，留改动前快照）
grep -rn "proxy_read_timeout\|proxy_send_timeout" /etc/nginx/nginx.conf /etc/nginx/conf.d/ 2>/dev/null
cp /etc/nginx/nginx.conf /etc/nginx/nginx.conf.bak-$(date +%Y%m%d-%H%M%S)

# 2. 找到反代 backend-node(:13030) 的 server/location 块（大概率在 nginx.conf 或 conf.d/*.conf 的 /api/ location），
#    在其中补两行（300s 覆盖后端 180s 硬超时 + 余量）：
#     proxy_read_timeout 300s;
#     proxy_send_timeout 300s;

# 3. 语法校验 + 平滑重载（不断连接）
nginx -t && nginx -s reload

# 4. 验证：对任一 /api/ 接口观测不再 60s 掐断
```

- 本仓 `docker/nginx/nginx.conf` 已是 3600s（容器方案），生产是宿主机 /etc/nginx 直装配置，两者独立，勿混淆。
