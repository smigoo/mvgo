## 3. 治理方案（四刀口 + 观测）

### 3.1 主刀：内容契约通用透传（事实层）

**位置**：`generation-context-assembler.js#normalizeSectionNode`。

**做法**：新增 **`declaredContent`** 透传，但**不是整体回流**（体积与幻觉双控）：

> ⚠️ **实施修正（评审第二轮）**：初版直接透传到 `body`，被 `assembler-rowpeers.spec.ts`
> 既有断言拦下——`body` 是 `normalizeTableHeaderContract` 的**最小表头契约**专用键
> （bc38e1e6/40b65d9f/e7da39ca 深等于断言，刻意「不回流 cells/items/bg」），共用键必然
> 互相覆盖。故改为**独立键 `declaredContent`**，`body` 行为逐字不变（旧断言零改动）。
> 判据读取口径同步扩：`collectDeclaredItems` / `collectSectionFigmaRefs` 的 OR 链最前加
> `declaredContent.children|items|elements`（与 body 同族，优先级最高）。

```
declaredContent: {
  layout, gridColumns,                       // 布局契约（标量，仅附随内容数组产出）
  items | children | elements: [             // 三键取首个非空（与 collectDeclaredItems 同族）
    递归白名单，深度 ≤ 4：
      标量: id, role, type, name, text, value, label, title, figmaNode, layout, gridColumns
      容器: children, items, elements, content(对象), parts
      资源: icon.resourceFile / icon.width / icon.height（仅引用，不回 base64）
  ]
}
```

**产键门槛**：无内容数组（items/children/elements 均空）⇒ **不产键**（layout/gridColumns 不单独成键，
与表头契约「宁缺不猜」同语义）。

**体积上限**：单段节点数 ≤ 200、单字符串 ≤ 40 字符；componentPlan 级 declaredContent 总字节 ≤ 6144
（`componentPlanBytes` 预算 8KB，余量留给既有字段），超限**只剥该段 declaredContent、保留段本身**
并计 `bodyDroppedByBudget`（不静默丢）。

**不做什么**：不透传 `bgPlaceholder` 等样式大对象、不回 base64、不改既有字段语义（纯新增键）。

### 3.2 配套：R6-2 内容量口径补齐

**位置**：`folded-grid-section-takeover.js#MASS_CHILD_KEYS`（当前 `['children','items','elements']`）。

**增补**：`'content'`、`'parts'`。本单厂商文本位于 `content.parts[].text`，当前仅靠 item 级 `name` 兜住
（mass=6 已足够拒 header），但 stat-card 的 `content.elements[].text`（33/66）同理应计入。

**注意**：只加容器键，不放宽 `MASS_NON_TEXT_VALUE_RE` 过滤（颜色/路径仍排除）。

### 3.3 纵深：header 判据口径对齐（第二道防线）

**位置**：`detectHeaderRowLeaf`（:280-283）。

**做法**：`texts` 计数与 icon/text 判据对齐，但**按锚点来源分两态**（评审第三轮修正）：

> ⚠️ **实施修正**：初版「一律递归」被 `renderFoldedGridLeafVue` 既有用例的连锁红拦下——
> 合成 `…-tail-text` 叶（无 sourceNodeIds）走 `collectAnchorNodes` 的**剥后缀兜底**锚到父容器，
> 它本就只是父容器的一个**切片**（深层文本归折叠列表/网格叶），对这类叶递归必然误判。
> 故：**精确锚点才递归，兜底锚点保持 1 层**。

- **精确锚点**（`sec.id` / `sourceNodeIds` / `figmaNodeId` 直接命中真值树）⇒ 本叶**拥有整棵子树**
  ⇒ 递归 walk 计数（seen 防父子重复入队）。38:3137（604×161 容器）递归 TEXT=13 ⇒ header 拒。
- **剥后缀兜底锚点**（合成 `…-tail-text` / `…-list` 叶 → 父容器）⇒ 本叶只是切片 ⇒ 保持 1 层 filter。
- 递归仅从本叶锚点集合起步，不触碰锚点外节点 ⇒ `8bbcf027` 反向断言不受影响。

### 3.4 观测：`droppedKeys` 计数行（还债）

**位置**：`normalizeSectionNode` / `normalizeComponentPlan`。

**做法**：返回段级 `droppedKeys`（本次被白名单剔除的字段名，如 `["body"]`），`normalizeComponentPlan` 聚合为
一行日志：`plan 归一化·已评估 {sections, droppedKeys: {body: 4, …}}`。

**目的**：今后任何事实被白名单剥掉**即刻可见**，终结「第 N 次同类补丁」。
日志按字段名聚合（不逐段打印），避免噪声。

### 3.5 不在本刀范围

- 段粒度（一段多形态：标题 + 网格 + 图标）——见 §6 后续项。
- 覆盖门禁（`uncovered≥1`）由计数升级为阻断——见 §6 后续项。
- 资源导出策略（段级整块图）——已否决。
