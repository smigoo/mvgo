# A4 配对时序：容器重建必须在 A4 之后（尺寸串位根治）

- 日期：2026-11-05
- 触发：`mc-max-1793884413982-7b49f607`（c-device-monitor）——「`c-device-monitor-fg-grid-8938` 的高度和设计差异非常大」

### 1.3 时序

`_postProcessAnalysis`：
```
:1524   chrome 剥离 / bg sizing / tab 幻觉纠正
```

A4 的配对语义是「vision 段 ↔ Figma 视觉区域」，**id 直配要求全段命中**，一旦失配整体退回「顺序配对」。容器重建改写了段集 ⇒ id 直配只剩 1 段命中 ⇒ 顺序配对按位置对齐 ⇒ 串位。

## 2. 修法（三处）

### 2.1 A4 前置（`visual-parser.js`）

A4 调用移到 `_overrideVisionDimensionsWithFigma` **之前**（仍在 chrome 剥离等前置处理之后）。A4 看到 vision 原始段集，`idDirect` 全命中；随后 merger + 容器重建再改写结构，此时高度事实已落在各段上，rebuild 不会改动它们。

### 2.2 容器高度事实（`subcomponent-planner.js`）

A4 前置后，新建容器 `89:37` 没有 `styles.figmaHeightPx`，而 `figmaSectionBox` 只读 `sourceNodeIds`（重建容器没有）⇒ 高度取不到 ⇒ 该段不参与归一 ⇒ 同层其他段瓜分全部高度（比例全错）。

修：容器段（`isLayoutContainerSection`）的几何兜底改用新增的 `unionSectionBox`（并集盒，`section-tree.js`）。非容器段保持 `figmaSectionBox`（C1 立独立项，不铺开 279 段）。

### 2.3 缓存补跑加前置判据（`mc-component-graph-phase2.js`）

`uiCache` 存的是**加工后**结构（已含重建容器）。原逻辑「A4 是幂等纯函数，补跑不漂移」在本刀后不再成立。新增 `hasRebuiltContainerSection()`：命中 ⇒ 跳过补跑并打计数行 `reason:'container-build'`。

## 3. 附带修掉的一处假绿

`plan()` 里 `indexFigmaNodes(opts.figmaNodeData)` **没有解包 `.document`**。`opts.figmaNodeData` 存在 `{document, fileKey, cachedAt}` 包裹形态，而 `indexFigmaNodes` 只沿 `children` 走 ⇒ 空索引 ⇒ `applyFigmaHeightGrow` 的 `size === 0` 守卫静默 return 0。改为 `opts.figmaNodeData?.document || opts.figmaNodeData`（与同文件 `buildItemLevelFacts` / `enrichSectionsWithTechStack` 口径一致）。
