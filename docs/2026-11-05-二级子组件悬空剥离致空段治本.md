## §3 根因

### 3.1 单点缺陷

```js
// microcode-engineer.js:2508-2510  批5: 子组件（据 index.vue import 引用动态补生成，并行）
const subComps = this._detectSubComponents(allFiles['package/index.vue'] || '');
```

**子组件发现/生成只有一层**：`index.vue → package/components/*.vue`。生成出来的 section 文件**不会再被扫描**，因此 section 内部再引用的组件**永远没有生成槽位**。

而 planner 明确要求二级拆分：

```js
// subcomponent-planner.js:1012
if (reasons.charts < 2 && reasons.elementCount > 10) {   // R2 元素密度拆分
  const groupCount = Math.min(Math.ceil(reasons.elementCount / 8), 3);
```

prompt 也明确要求「每个内部子组件也必须是独立的 `package/components/{YourName}.vue` 文件」（`microcode-engineer.js:1304`），且**命名交给模型自由发挥**（`:1013`「文件名和组件名由你根据语义自行命名」）。

⇒ **要求了文件、给了命名自由、但没有生成槽位。**

### 3.2 触发条件（三处阈值同时被跨过）

vision 把整个 slot 切成「今日累计 + 统计卡片组」后，同一批卡片的度量方式变了：

| 阈值 | 旧 | 新 | 后果 |
|---|---|---|---|
| `effectiveSections >= 3` | 2 | **3** | `isForced: false → true`，`minFiles: 0 → 5` |
| `elementCount > 10`（R2） | `136:121` = **3** | `2:8023` = **12** | `internalSubcomponents: 0 → 2` |
| 二级子组件生成槽位 | 不需要 | **需要但没有** | 悬空 → 剥离 → 空容器 |

### 3.3 失败发生点（日志铁证）

```
[2026-11-05T07:56:17.926Z] [WARN] [microcode-engineer] 🔧 已剥离全 .vue 层悬空子组件引用
{"stripped":[{"file":"package/components/StatsSection.vue",
  "refs":["StatsCardDangerous","StatsCardHeavyTruck","StatsCardOverheight"]}]}
```

`stripDanglingComponentRefs`（`microcode-engineer.js:3979` → `section-coverage-guard.js:435`）连 import 带模板标签一并删除，留下 3 个空行。设计上 **fail-open**：删完"内容自洽"，无任何硬闸。

### 3.4 五个失明点

| # | 失明点 | 证据 |
|---|---|---|
| 1 | `detectUnmaterializedSections` 只查「文件在不在」，不查「文件里有没有内容」 | `section-coverage-guard.js:261` `.filter((m) => !m.hasFile)` |
| 2 | `stripDanglingComponentRefs` 剥完不校验残留 | `section-coverage-guard.js:435` |
| 3 | `RES-UNREF` 只 WARN | `pre-write-self-healing.js:948`；真机 `component-meta.json#failOpenEvents` 已记录 5 张图零引用 |
| 4 | `coverageReport` 两版**完全相同**（27/9/15/100%/missing 0） | 它是 **vision 侧**指标（`visual-parser.js:811`），物理上看不见产物 |
| 5 | `artifactIncomplete` 是**死出口**：只进返回值，不落 `component-meta.json`，全仓无消费方 | 真机产物里该字段根本不存在 |

### 3.5 为什么 `RES-UNREF` 不能一刀切升级

全语料 382 份 `component-meta.json` 中 **220 份（57.6%）命中 RES-UNREF**（orphan 1~5 张为常态）。**升级为阻断会拒收 3/5 的产物** ⇒ 保持 WARN，改由更精确的空段判据（§4.2）承担。

## §4 修法

### 4.1 主修：递归补齐二级子组件（A1）

**落点**：`genSubComponents`（`microcode-engineer.js:2011`）末尾 —— 它是 complex / medium / simple **三个分支共用的单一出口**（调用点 `:2548` / `:2628` / `:2672`）。

**逻辑**：
```
1. 现有逻辑生成 subComps（wave=1）
2. 扫描 allFiles 中全部 .vue 的 .vue 引用（复用 detectDanglingComponentRefs，单一事实源）
3. dangling = 引用目标不在 allFiles 的项
4. 若 wave < SUBCMP_WAVE_MAX(1) 且 dangling.length <= SUBCMP_SECOND_WAVE_CAP(8)
     → 递归调用 genSubComponents(danglingPaths, nextIndex)，wave+1
   否则 → 不生成，留给 §4.2 止损
5. 计数行恒打
```

**硬约束**：
- 深度上限 1 层（常量 `SUBCMP_WAVE_MAX`），防 LLM 无限嵌套；
- 数量上限 8（常量 `SUBCMP_SECOND_WAVE_CAP`，来源见 §4.4 实测：真实悬空数 1~6）；
- **必须复用** `detectDanglingComponentRefs`，禁止新写第二套引用识别正则。

### 4.2 止损：空段诚实降级（B1）

**新纯函数** `detectEmptySectionComponents(files)`（`section-coverage-guard.js`）：
> 判据：`package/components/*.vue` 的 `<template>` 内，除最外层容器外**无任何元素节点、无任何非空文本** ⇒ 空段。
> 纯结构判据，**不读图层名、不读 plan**，零副作用。

**接入点（顺序即正确性）**：紧接 `stripDanglingComponentRefs` 之后、在**同一出口**完成：
1. `detectEmptySectionComponents(allFiles)`；
2. 对空段根元素**剥离背景**（`backgroundImage` / `backgroundSize` / `backgroundPosition` / `backgroundRepeat`）—— 宁留白，不出错色；
3. 结果并入 `evaluateArtifactCompleteness` → `artifactIncomplete = degraded>0 || unmaterialized>0 || emptySections>0`；
4. `artifactIncomplete` + `emptySections` **落盘到 `component-meta.json`**（补上失明点 5）。

**为什么不做 BLOCK**：`section-coverage-guard.js:250-256` 已论证「LLM 无法组装一个不存在的组件，重试只会重放同一份源码 → 重试预算耗尽 → 软失败发布」。BLOCK 是重演已知死路。

> **边界补充（2026-11-08 二次评审）**：上述论证成立的前提是「重试无 guidance、只会重放同一份源码」，适用于引用悬空 / 隔离降级 / 收尾断言（A 类）。planner 强制清单缺件（`internalSubcomponents` 未落独立 `.vue`）属 B 类：`microcode-engineer.js:1767-1785` 的 `isL0BRetry` 在 guidance 非空时会重新生成代码分块，前提已变，故允许带 guidance 走 L0-B 重试（耗尽仍软失败 + `artifactIncomplete=true`，不 fail-closed）。详见 `2026-11-08-子组件覆盖度P1P2治本方案-评审修订版.md` §6。

**为什么不改 `analyzeSectionCoverage#hasFile` 语义**：该内核被 COMP-001（`code-structure-validator.js:2323`，**fail-closed BLOCK**）共用，改语义会波及其阻断行为。因此空段判据**独立成函数**，与 COMP-001 解耦。

### 4.3 收尾断言（D1）

两条只读断言，两端同源写入 `component-meta.json`，**不触发重试**：

| 断言 | 判据 |
|---|---|
| 悬空引用归零 | `detectDanglingComponentRefs(allFiles).length === 0` |
| 空段归零 | `detectEmptySectionComponents(allFiles).length === 0` |

失败仅计入 `artifactIncomplete` + 计数行（A1 已由构造保证，断言价值在**防回归**）。

### 4.4 不改项（明确不做）

| 项 | 理由 |
|---|---|
| `RES-UNREF` 升级阻断 | 57.6% 命中率，会拒收 3/5 产物 |
| `coverageReport` 口径修改 | vision 侧指标，物理上看不见产物；改它解决不了本问题，属另一议题 |
| Vue3 端同步修改 | `stripDanglingComponentRefs` / `pruneDanglingSubComponentImports` **仅 mc 端接入**，Vue3 端零波及（符号级核验：`vue3-engineer.js` 无 `_detectSubComponents`） |
| 修产物文件 | 违反「禁止产物直改」 |
