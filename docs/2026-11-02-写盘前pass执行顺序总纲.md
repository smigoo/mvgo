# 写盘前 pass 执行顺序总纲（守卫群单一事实源）

> 2026-11-02 立项。背景：max 链路写盘前有 **30+ 个守卫 pass**，互相之间的执行顺序与属性管辖是**隐式的**，已实锤三起「守卫互相拆台」事故（见 §3）。本文档是顺序与管辖的**单一事实源**；新增守卫必须在此登记，改顺序必须更新本文档。
>
> 证据口径：① a92e10df/d140fb11/f96752c8 三单真机日志实测顺序（server.log）；② 源码锚点（函数/注释编号）；两者冲突时以日志为准并标注。

## 1. 四层总图

```
[视觉/规划层]  visual-parser → layout-reviewer → style-mapper → subcomponent-planner(R1/R2 锚点)
        │
[接管评估层]  folded-grid-section-takeover 刀53（R3 scope 拒止 / R6 declaredUnconsumed 出口对账）
        │       ├ 命中 → 确定性模板（不进 chunk LLM）
        │       └ 拒/skip → chunk LLM 生成
[chunk 修复层] chunk 级守卫 → resource-mounter(语义分流) → code-validator 2.x 主修复链
        │
[落盘出口层]  pre-write-self-healing(④~⑫) → writeFiles 出口(53h/R24/刀49/FONT-MIN-GUARD)
```

每层只看到上一层的输出；**没有跨层的回滚**——层 N 写坏的属性，层 M>N 只能再改写，不能恢复。

## 3. 已实锤的相互作用事故（为什么必须有本文档）

### 事故一：先剥后补（d140fb11，R6-B1 治）
`V6 dedup`（前提=shared 有同名属性）剥掉宿主类显式 `flex-direction: row` → `V8 注入器`看到「缺失」→ 按几何 fact 补 column。**V6 拆掉仲裁载体、V8 按错误事实补全**——两 pass 各自判据都「正确」，组合出错误。R6-B1 豁免宿主类后闭环。

### 事故二：正反向剥离夹写回 pass，shared 表被掏空（d140fb11，🟡 未治）
`V6 dedup` 剥 SFC 的 X（X 只剩 shared）→ `C5/C6/V8` 某 pass 又把 X 写回 SFC → `W4 刀23` 看「SFC 有 X」→ 剥 shared 的 X ⇒ **X 双丢失，SFC 那份还是守卫写入值而非 LLM 真值**。多轮 fix loop 中 LLM 重写 SFC 再带 X 时，交替剥离最终把属性从两边都剥光（`.c-device-img` width:98px 断供实锤）。刀23 反向（pre-write ⑫）与 dedup 正向（code-validator V6）**相距 10+ pass、契约相反、无对账**。

### 事故三：fallback 生成污染宿主类（d140fb11，🟡 挂观测）
`CLASS-MUST-EXIST` 检测 common.less 缺类 → `generateFallbackCssRule` 从 elementStyleMap 抄样式写入 common.less（`align-items:center; justify-content:space-between` 进了 section 宿主类）→ 与 dedup 剥离后的 SFC 残块组合成「column + center = 居中」。fallback 无「宿主类真值门槛」。

## 4. 仲裁总纲（R4b-A/R6-B1 确立，全局推广口径）

1. **显式声明保留**：任何 pass 不得翻转/剥离产物已显式声明的布局方向（`flex-direction`）与容器模式（`display`）——宿主类（`data-section-id` 标签 class）绝对豁免，内部类按各自判据。
2. **事实只补缺**：几何/视觉事实（nodeLayoutFacts/itemFacts）只允许注入缺失声明，冲突时**留痕不覆盖**（`LAYOUT-FACTS-CONFLICT` / `strippedUnbacked` 等计数行）。
3. **纠错归门禁**：显式声明与真值冲突属 LAYOUT-001（WARN）+ review 循环管辖；注入器/剥离器不做无仲裁的翻转。
4. **收敛必对账**：剥离（dedup/刀23/53h）、接管（刀53）、fallback 生成，凡收敛动作必须留计数行且不得造成「双丢失」（剥完 A 侧再剥 B 侧 = 违规）。
5. **新增守卫登记制**：新 pass 必须在本文档 §2 登记（顺序/管辖/模式），并声明与 V6/V8/W4 三个高危点的相互作用。
