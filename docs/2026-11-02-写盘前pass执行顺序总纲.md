## 1. 四层总图

```
[视觉/规划层]  visual-parser → layout-reviewer → style-mapper → subcomponent-planner(R1/R2 锚点)
        │
[接管评估层]  folded-grid-section-takeover 刀53（R3 scope 拒止 / R6 declaredUnconsumed 出口对账）
        │       ├ 命中 → 确定性模板（不进 chunk LLM）
        │       └ 拒/skip → chunk LLM 生成
[chunk 修复层] chunk 级守卫 → resource-mounter(语义分流) → code-validator 2.x 主修复链
        │
[落盘出口层]  pre-write-self-healing(④~⑫) → writeFiles 出口(53h/R24/刀49/FONT-MIN-GUARD)
```

每层只看到上一层的输出；**没有跨层的回滚**——层 N 写坏的属性，层 M>N 只能再改写，不能恢复。

## 3. 已实锤的相互作用事故（为什么必须有本文档）

### 事故一：先剥后补（d140fb11，R6-B1 治）

## 4. 仲裁总纲（R4b-A/R6-B1 确立，全局推广口径）

1. **显式声明保留**：任何 pass 不得翻转/剥离产物已显式声明的布局方向（`flex-direction`）与容器模式（`display`）——宿主类（`data-section-id` 标签 class）绝对豁免，内部类按各自判据。
2. **事实只补缺**：几何/视觉事实（nodeLayoutFacts/itemFacts）只允许注入缺失声明，冲突时**留痕不覆盖**（`LAYOUT-FACTS-CONFLICT` / `strippedUnbacked` 等计数行）。
3. **纠错归门禁**：显式声明与真值冲突属 LAYOUT-001（WARN）+ review 循环管辖；注入器/剥离器不做无仲裁的翻转。
4. **收敛必对账**：剥离（dedup/刀23/53h）、接管（刀53）、fallback 生成，凡收敛动作必须留计数行且不得造成「双丢失」（剥完 A 侧再剥 B 侧 = 违规）。
5. **新增守卫登记制**：新 pass 必须在本文档 §2 登记（顺序/管辖/模式），并声明与 V6/V8/W4 三个高危点的相互作用。
6. **新守卫入库门禁（2026-11-03，管线根治方案 v2 S0.1）**：新增**修补型守卫默认拒绝**。合入前必须在本文档论证「为何不能是接管 kind 或编译期断言」，并提交**退役判据**（hit 计数口径 + 连续 N≥20 单 hit=0 降级为只报断言 / M≥10 单零命中删除）；无法给出退役判据的修补型守卫不予合入。观测型计数行、断言型校验（只报不改）不受此限，但仍须按第 5 条登记。
