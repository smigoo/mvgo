## 7. 用户决策 + 终版治本方案

### 7.1 决策（原则）
**以设计为准；设计没覆盖的那套主题由系统"补"（确定性派生）。**
例：浅色组件若无深色稿 → 深色由系统补；反之亦然。

### 7.2 管线**已实现**该契约
`src/ai-engine/utils/style-tokens.js` 头注释铁律 1-3：
1. dark 核心三变量永远来自规范枚举（M4-10），**禁 LLM 生成、禁 Figma 提取**；
2. 原 UI 深色 → 呈现以设计稿为准（Figma 深色真值进 dark 槽位）；
3. **light 色值分源：原 UI 浅色 → Figma 确定性提取；原 UI 深色 → 确定性派生算法**。

- `resolveBackgroundBrightness()`：用**最大面积填充色的 WCAG 亮度**确定明暗（不靠 LLM 猜）。
- `buildStyleTokens(input)` 返回 `{fontSize, defaultTheme, themes, light, dark, designVars, darkWithDesign, palette}`；已接线 `microcode-engineer.js:6899`。
- 🔴 **症结**：该派生结果**只喂了 `css-vars.js`（模式 A）**；而 **`theme-vars.less`（模式 B）仍是 LLM 独立 chunk** → 两个事实源。

### 7.3 终版治本（接线 + 删残留 + 门禁；不新建逻辑）

**P0（低风险高收益）**
| # | 动作 | 落点 | 验收 |
|---|---|---|---|
| 0.1 | **`theme-vars.less` 改由 `buildStyleTokens` 确定性产出**，删掉 LLM 生成该 chunk 的通路 | `style-tokens.js` / `microcode-engineer.js` / `prompt-builder` | 产物与 tokens 逐字段一致 |
| 0.2 | `healSlotHexToVarRefs`/`healPresetLiteralDecls` 的 `hex→var()` 改为 **`hex→@color-xxx`** | `file-writer.js:535` | 产物内 `var(--color` = 0 |
| 0.3 | `THEME-VAR-NAME-MISMATCH`、`THEME-MIXINS-IDENTICAL` **WARN→BLOCK** | `theme-color-guard.js` | 重放不触发 |
| 0.4 | 清 `style-mapper.js:90-103` 的 var() few-shot | `style-mapper.js` | LLM 不再被教 var() |
| 0.5 | 修 `style-theme-rules.md` 失效前提 | `prompts/engineer/shared/` | 文档↔实现一致 |

## 10. `c-env-monitor-6e065bd7` 定位（tabs 被排到最后 + 失去 tab 布局）

**现象**：生成物里 `EnvMonitorTabs` 被放到**最后**、且 tab 项**竖排成列表**（无 tab 条）；设计稿里 tabs 在标题下方**最上**、是横向 pill 条。

### 10.1 根因 A：章节顺序用了 Figma **文档序**，而非**视觉 y 序**
- 生成物 `index.vue` 的 DOM 顺序：`EnvMonitorChart` → `EnvMonitorTabs`（chart 在前、tabs 在后）。
- 设计稿 `.checkpoint/figma.json` 的 `slot-con` 子节点（**children 数组文档序**）：
  | 序 | 节点 | 类型 | y | h |
  |---|---|---|---|---|
  | 1 | `@echarts/line` | GROUP | **930** | 113 |
  | 2 | `sub-t` | FRAME | **898** | 32 |
- ⇒ **数组里 chart 在前，但视觉上 `sub-t`(y=898) 在 chart(y=930) 之上**。生成物**完全照抄文档序** → tabs 被排到最后。
- **事实源错误**：对**非 auto-layout 的 FRAME**，应**按视觉 y 排序**，不能直接取 `children` 数组序。

### 10.2 根因 B：tab 列表**缺 `display:flex`** → 竖排
- `EnvMonitorTabs.vue`（scoped）与 `common.less:87` **两处**的 `.c-env-monitor-tab { align-items:center; gap:4px }` **都没有 `display:flex`**（对比外层 `.c-env-monitor-sub-t` 有 `display:flex;flex-direction:row`）。

#### ⛔ 附：为什么不能靠泛化 `text-order-guard` 解决（读了契约后，2026-09-26）：**缺"身份键"**
- 该守卫的匹配键是**文案字符串**：`collectFigmaTextSiblingGroups` 只收 `type==='TEXT'` 且有 `characters` 的 ≥2 个直接子节点，再按 (x|y) 排序；`detect/fixTextOrderDrift` 拿这串文案去代码里的数组/v-for 对位。**文案是强键 → 安全**。
