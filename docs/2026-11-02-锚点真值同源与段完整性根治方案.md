## 0. 一句话根因

section 的锚点候选键存在**两套互不一致的优先级**：几何轨已接入修复产物 `figmaAnchorId`，归属/子树轨没有接入。
锚点守卫每修一次锚点，就制造一次「几何来自 A 节点、内容来自 B 节点」的撕裂段。
**修复越多，撕裂越多**——这解释了「越优化越坏」。

## 3. 根治措施（R1–R5）

### R2 先行：锚点修复门槛补「不得覆盖兄弟段」（前置，否则 R1 会把病害放大）

在 `section-anchor-truth.js:255-260` 的 `reason` 判定中追加一条：

> 候选 `candidateLca` 的子树若包含**其他 section 的声明锚点**，则拒修，
> 记 `unrepaired(reason='lca-covers-sibling-sections')`。

判据形式（集合包含，类型无关、命名无关）：

```
covered = otherSections.filter(s => s !== section && isAncestorOrSelf(index, candidateLca, anchorOf(s)))
if (covered.length > 0) reason = 'lca-covers-sibling-sections'
```

为什么不能用「高度放大倍数」当判据：刀33 的聚合段修复（首卡 → 整组）本来就需要更大的 LCA，
放大是正当的；**「是否覆盖兄弟段」才是区分正当聚合与有害扩张的充分必要条件**。
本次 `796:3` 含 `38:3137 / 38:3162 / 38:3206` 三个兄弟段锚点，必然被拦。

配套：`unrepaired` 新增计数行进真机日志（当前只进 JSON，无人消费）。

### R1 核心：锚点候选键全链单一来源

把 `collectSourceNodeIds`（G3）的候选来源改为**复用 `sectionAnchorCandidates`**，
不再自带一份优先级；同时消除 `nodeId` / `figmaNodeId` 字段名漂移（归一到 G1 的候选表，
`nodeId` 作为别名保留在候选表内，由 G1 单点维护）。

落地后必须成立的不变量（写成断言，进 spec）：

```
anchorGeometryId(section) === anchorMembershipId(section)
```

**顺序约束：R2 必须先于或同刀于 R1。** 若只做 R1，`796:3` 这类覆盖兄弟段的锚点
会让统计区的归属子树扩成整个内容容器，从「内容缺失」变成「一段吞掉全部内容」，病害更大。

### R3 段完整性：超界段禁止「单元素接管」

现状：刀53 的 `icon/header/text` 接管只看锚点子树内的事实，
子树被锚点削窄时就输出一个图标或一行标题，**把整段内容确定性地裁没**，且无任何告警。

判据（可辩驳，不依赖措辞）：

> 当 `collectSectionFigmaRefs(section)` 中存在落在**当前锚点子树之外**的树内引用时，
> 该 section 标记为 `scope-incomplete`，**禁止** `icon/header/text` 三类单元素接管，
> 回退 LLM 生成，并计 `scopeIncomplete++`。

理由：refs 超出锚点子树 = 声明的内容范围大于可取真值的范围，
此时任何「只输出一个元素」的接管都必然丢内容。宁可回退 LLM，不可确定性裁没。

### R4 无真值段：禁止静默 `flex:1` + 资源零引用门禁

- G4 回退分支加计数行：`flexFallback++`，并输出 sectionId 列表。
  当前「全部段无高度 ⇒ 三段等分」在日志里完全不可见，与「真值齐全」不可区分（假绿温床）。
- 无锚点段（`noAnchorNode`）**不参与** `flexItemStyleFromHeights` 的比例分配，
  改为 `flex:0 0 auto`（内容自适应），把可分配空间留给有真值的段；
  全无真值时显式记 `layoutTruthMissing=all`，作为可拦截的质量信号而非静默产物。
- 新增资源零引用校验：`resources/images/**` 已下载且未被任何 `.vue`/`.less` 引用
  ⇒ `orphanResources++` 并列名。本次 `img-1725.png` 即此型。

### R5 治「反复」：同节点基线回归 + 真机代码一致性门禁

这是「为什么简单布局反复出错」的根治，不是可选项。

1. **基线固化**：把 `38:3134`（合作厂商弹窗）与设备详情节点的历史好产物固化为基线，
   存不变量而非逐字 diff：
   `子组件数 / 总行数 / 刀53 hits 分布 / flex 向量 / 资源引用率 / scope-incomplete 数`。
   每刀改动后跑**离线 checkpoint 重放**（不烧真机额度），不变量退化即红。
2. **真机代码一致性**：投真机前必须通过
   `npm run check:r3b -- --real` + 进程启动时间 ≥ dist mtime。
   本次事故环境为「`9234c86` + 未提交 WIP」，且 dist 在 13:40 被二次 build 而进程
   （PID 34579，12:45 起）未重启——**磁盘 / 内存 / 提交三处代码互不相同，无法归因**。
3. **未提交 WIP 不进真机**：真机投单要求 `git status --short` 对 `src/ai-engine/**` 干净，
   否则投单结果既不能复现也不能 A/B。

### 7.3 评审补充（4 条，落地时并入）

1. **R1 隐藏耦合**：`collectSourceNodeIds` 尾部挂 **P2-1 语义 id 重映射自愈**（触发条件 =
   「`ids` 为空」）。归一到候选表时**不得改变 `ids` 空判定语义**（候选表含 `figmaAnchorId`
   可能让原本为空的 ids 非空 ⇒ 自愈静默失活）。spec 必须加反向用例：语义 id 段自愈仍触发。
2. **R2/R3 基础设施已齐**：`lowestCommonAncestor`（`section-anchor-truth.js:110`）、

3. **R4 落地注意**：`flexItemStyleFromHeights` 是导出纯函数、有既有 spec；3a 只上计数行
   `flexFallback++` 同意，3b 切 `flex:0 0 auto` 前必须先过两态全量 `B∖A=∅`（含既有 spec 逐字不变）。
4. **与 Phase H 真机验收合并为一波投单**：打通 401 后，R1+R2 同刀落地 → build → 重启 →
