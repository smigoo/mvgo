# section 结构契约与骨架接管（第一阶段）

> 日期：2026-11-03。续接 R8-11 P0 止血，不另建第二套布局判据。
> 目标：让 `contentType / placement / parent / children` 成为 index 装配的唯一结构事实源。

## 根因

`code-generator.js#buildDeterministicIndexTemplate` 当前由三套并行集合决定归属：header 候选、`bodyLeavesFinal`、`topBodyRoots + renderBodyNode`。它们口径不同，会产生：

- 多 header 唯一化后，落选者既不进插槽也不进 body；
- 嵌套 header 入槽后又被递归 body 渲染一次；
- `type=header` 的内容语义与空间 placement 混用。

## 方案

在 `resolvePlanSections()` 之后，从最终生效树派生纯函数契约：

- `contentType`：容器为 `container`，叶子投影现有 `type || content`；
- `parent`：直接装配父 section id，顶层为 null；
- `children`：只含直接装配子 section id，不读 `body.children/internalTree.children`，折叠叶的特殊 children 不混入；
- `placement`：每个叶子唯一为 `header-right` 或 `body`。

placement 保持既有事实优先级：有效 headerSlots 节点匹配 > 安全 type=header 回退；业务型 header 留 body；多候选只保留一个插槽，其余显式归 body。

`code-generator` 的插槽、bodyLeaves、bodyRoots、递归 body 跳过全部消费同一契约。第一阶段不持久化到 planner，避免 planner 白名单、Assembler 二次裁剪和后注入/去重造成事实过期；也不扩大到所有 leaf SFC 的 DOM 接管。

## 影响面与回滚

- 仅 microcode 的确定性 index 装配；不改 Vue3 路径、LLM 内容生成、资源与几何守卫。
- 直接调用方：`buildDeterministicIndexTemplate` 的 simple/medium/complex 三条汇聚路径。
- 回滚：还原本阶段 commit；无运行时双判据开关。

## 验收

- 纯函数：parent/children、输入不变、幂等、业务 header、slot 匹配/虚假回退、多候选落选归 body、嵌套入槽。
- 模板：落选 header 在 body 恰好一次；嵌套入槽在 body 零次；R8-11 业务 header 不回退入槽。
- 真实 checkpoint：`dd87be8e` 保持 header-right=0、业务段在 body。
- 家族测试、全量同仓两态 FAIL diff、nest build。

## 第二阶段：`001c5615` 插槽事实供应链（任务 #20 第一刀）

### 查重与真实根因

续接 C0 单一结构契约，不新增第二套 placement 判据。真实 `visual.json + figma.json` 证明断链有三点：

1. `subcomponent-planner#isPanelHeader` 把 `2:7959` 当纯 panel chrome 删除，最终 plan 只剩 `136:122`；但该段 `header.headerSlots` 明确含两个 Tab，`header.controls=[]` 并未表达这些内容。
2. Figma 推导的全局 slot 只有子节点 `figmaNodeId=2:7954`，没有宿主 `sectionId`。同时 `findHeaderContainer()` 返回外层 `136:120`，而 `2:7954` 与标题段 `2:7959` 是该容器内的**兄弟**，不能直接把容器 id 当宿主，也不能要求二者是父子。
3. C0 只读 `figmaNodeId || id`，即使上游补了 `sectionId` 也不会消费；且带 chrome body 的 `type=header` 不属于 safeHeaders，未匹配时只能留 body。

### 治本方案与影响面

- planner 仅在 `header.headerSlots` 至少有一项非空 `content/text/label` 时豁免 panel-header 过滤；空数组、空白内容、仅 `slotCandidate` 均不豁免，既有纯 chrome 行为不变。新增 `preservedHeaderSlotContent` 真机计数。
- Figma 推导器接收原始 slot 候选；只在**同一 header 容器内、同 slotType 的候选归一到唯一 sectionId**时补宿主。多个不同宿主、缺候选均不加字段；rejected 候选只提供归属证据，不会被重新纳入 headerSlots。
- C0 将 `figmaNodeId / sectionId / id` 全部作为互补匹配证据，不再用 `||` 丢掉宿主 id。显式 slot 证据命中后，带 chrome body 的宿主只入槽一次；无匹配时业务 header 留 body 的回退不变。
- 不改 Vue3 模板装配、列表方向、逐项背景、资源挂载或提示词；这些仍按任务 #20 后续小刀独立验收。
