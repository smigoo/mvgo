# leaf 内容归属与 TEXT-001 止血方案

> 2026-11-03。续接《section 结构契约与骨架接管（第一阶段）》与写盘前 pass 总纲，不新建第二套文本角色判据。

## 查重结论

- 已有 `section-leaf-assembler`，但默认灰度关闭，且只覆盖根直接子节点全为 TEXT 的纯文本叶；设备 Header 与统计卡不在其适用范围。
- 已有 `splitTitleValueByStyle`，只负责单卡 title/value 角色，不负责跨卡归属。
- `declaredContent` 已透传到生成侧，但两个 graph 的内容守卫仍消费 legacy plan；本方案续接该贯通链路。
- TEXT-001 曾升级二维网格行主序，但未校验产物侧 DOM 同父关系；本次不是再调排序规则，而是补齐既有“兄弟组”契约缺失的另一半。

## 真机根因

### A. TEXT-001 跨父节点改写

`text-order-guard.js#findStaticTextElements` 只按全文件文本唯一性定位元素，未记录实际 DOM 父节点。`detectTextOrderDrift` 与 `fixTextOrderDrift` 因而会把 Figma 同父文本组映射到产物中跨 wrapper、跨卡片的文本集合。

真实回放：

- `b01c2b10` 原始 chunk 本为 `33/合作厂商`、`66/在线设备`，经 TEXT-001 后变成 `合作厂商/在线设备`、`33/66`。
- `9343c314` 原始 Header 的设备字段本正确，经 TEXT-001 后被“产品描述”和长描述跨槽位替换。

### B. duplicate owner 忽略显式声明

`section-content-guard.js#checkSectionContent` 只按 `sourceNodeIds` 子树构建 owner。`section-description` 显式声明描述文本但 `sourceNodeIds=[]`，因此描述被误判为 `801:3/ContentHeader` 所有，随后从真正的 `ContentDescription.vue` 删除，留下空壳。

真实 checkpoint 首轮回放又暴露了同根缺口：R8-7 的 `BODY_MAX_TEXT_LEN=40` 会把 `declaredContent` 长文本截成前缀；若只做逐字显式声明，完整正文仍会落到 Figma 子树回退，真实 `ContentDescription.vue` 仍被删空。因此 owner 归一必须识别这种已知截断形态，而不是假设 declaredContent 永远保留全文。

## 治本方案

### 1. TEXT-001 产物侧同父约束（检测与修复同一判据）

template 分支仅在所有目标文本元素属于同一个实际 DOM 父节点、且构成可证明的直接兄弟文本组时才允许报告和修复。跨卡片、跨 section、跨 wrapper、不同父节点均 no-op；script 数组分支保持原行为。

实现采用模板标签配平/深度扫描，不用新的非贪婪正则推定父级。检测和修复复检复用同一元素定位函数。保留真实同父横向、纵向、二维网格能力。

### 2. 显式声明优先的 owner 事实源

- 非容器 section 的显式 `declaredContent`/vision body 文本优先作为 owner 证据；Figma 子树只作补充或声明缺失时回退。R8-1 回归约束：带 Figma 节点 id、但自身子树不含该文本的段不得凭重复声明推翻另一段的唯一子树 owner；这条只保护既有幻觉段收敛，不限制真正的语义合成段。
- 显式声明与另一段的祖先子树重叠时，不把祖先段当成唯一 owner；冲突不可判定则保留文本并报告，禁止删除唯一正确宿主。
- microcode 与 Vue3 两个 graph 均向内容守卫传入归一化后的 componentPlan，避免 declaredContent 已生成却不可消费。
- 不做两源无条件 union，避免 owners 数量膨胀导致规则失明。
- 对非 Figma 逐字文本的显式声明做**唯一前缀归一**：若它恰是一个更长 Figma 文本的前缀，且全树只有这一候选，则把 owner 声明归一到该全文；多个候选则全部禁止 Figma 回退删除，按冲突弃权。不得反向用 `includes` 猜归属，也不得把截断片段额外当成一条独立渲染文本。

以上判据先作为待真机验证假设，不把方案文档当验收证据。
