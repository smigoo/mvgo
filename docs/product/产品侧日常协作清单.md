# 产品侧日常协作清单

> 目标：产品同事在日常工作中注意/提供以下事项，可显著提升平台组件生成效率与质量
> 适用对象：产品经理、产品助理、设计对接人
> 更新日期：2026-09-01

---

## 一、Figma 设计阶段（生成前）

### 1.1 图层命名规范（影响最大，优先级 P0）

**产品需要推动设计团队做到：**

| 元素类型 | 命名规则 | 示例 | 不规范的后果 |
|---------|---------|-----|------------|
| 背景图层 | `bg` 或 `bg-*` | `bg`、`bg-header`、`bg-card` | 资源丢失，背景不渲染 |
| 图标图层 | `icon` 或 `icon-*` | `icon-close`、`icon-tab-active` | 图标不显示，组件残缺 |
| 图表容器 | 语义化英文 | `chart-bar`、`chart-pie` | 图表类型识别错误 |
| 文本标签 | 语义化英文 | `title`、`subtitle`、`legend` | 文字错位或缺失 |
| 按钮/交互 | 语义化英文 | `btn-submit`、`tab-active` | 交互元素丢失 |

**产品侧检查方法：**
- 打开 Figma 文件 → 左侧图层面板 → 检查是否有 `Frame 123`、`Rectangle 45` 这种无意义命名
- 如有 → 提醒设计同学改为语义化命名 → 重新提交生成

### 1.2 Auto Layout 属性完整（影响布局还原度）

**产品需要确认：**
- 设计稿使用了 Auto Layout（不是手动拖拽定位）
- 检查方法：选中图层 → 右侧面板看是否有 `Add auto layout` 按钮（已添加则显示 `Shift+A` 快捷键）
- 如未添加 → 提醒设计同学添加 Auto Layout → 重新提交生成

**Auto Layout 关键属性（设计同学需保留）：**
- `layoutMode`：`HORIZONTAL` 或 `VERTICAL`
- `primaryAxisSizing`：`FIXED` 或 `AUTO`
- `counterAxisSizing`：`FIXED` 或 `AUTO`
- `padding`：上下左右内边距
- `itemSpacing`：子元素间距

### 1.3 组件级设计稿标注

**产品需要推动设计同学在 Figma 中补充：**
- 组件尺寸（宽×高，单位 px）
- 主题色/辅助色（色值，如 `#1E3A8A`）
- 字体规范（字号/字重/行高）
- 间距规范（网格系统，如 4px/8px 基准）

**为什么重要：**
- Vision 解析 fallback 不可靠，会覆盖 Figma API 确定性事实
- 有标注 → 生成还原度提升 30%+
- 无标注 → 颜色/尺寸/间距全靠猜，BLOCK 率高

### 1.4 提交生成前的自检清单（产品可独立操作）

```
□ 图层命名是否语义化？（无 Frame 123 / Rectangle 45）
□ Auto Layout 是否完整？（关键容器已添加）
□ 尺寸/颜色/字体是否有标注？（或设计稿本身清晰可见）
□ 是否有隐藏图层/锁定图层？（如有，确认是否 intentional）
□ Figma 文件权限是否开放？（平台需要读取权限）
```

## 二、需求文档阶段（Lite 生成 / 文档驱动生成）

### 2.1 需求文档结构化要求

**产品写需求时注意：**

| 部分 | 必须包含 | 可选但建议 |
|-----|---------|-----------|
| 模块划分 | 页面包含哪些模块（如"图表区""统计卡""表格区"） | 模块优先级（P0/P1/P2） |
| 字段说明 | 每个模块展示哪些数据字段 | 字段类型（文本/数字/图表/表格） |
| 交互说明 | 用户能做什么操作（点击/筛选/排序/分页） | 交互优先级 |
| 数据示例 | 每个字段的示例数据（用于 mock） | 数据量级（如"表格 100 条"） |
| 布局要求 | 响应式要求（桌面/平板/手机） | 特殊布局（如"图表占 2 列"） |

**反例（无法有效生成）：**
> "做一个流量监测页面，展示流量数据，要好看。"

**正例（可生成）：**
> "流量监测页面，包含 5 个模块：
> 1. 统计卡（4 个）：今日流量/昨日对比/峰值/平均值
> 2. 折线图（24 小时趋势）：X 轴时间，Y 轴流量值，折线+面积
> 3. 饼图（流量来源分布）：直接/搜索/社交媒体/其他
> 4. 表格（最近 20 条记录）：时间/来源/流量/状态，支持排序
> 5. 筛选栏：日期范围/来源类型/状态
> 
> 布局：桌面端 1200px 宽，图表区 flex:1，响应式适配平板。"

### 2.2 提供截图或低保真原型

**如果需求文档写不清楚，产品可以提供：**
- 页面截图（哪怕是竞品截图）
- 低保真原型（手绘/墨刀/Axure 均可）
- Figma 草稿（不要求规范，有大致布局即可）

**平台 Lite 模式支持：**
- 截图 → 秒级出简单布局 + 基础交互 + 图表
- 适合快速验证需求可行性，再决定是否投入完整版

## 三、接口定义阶段（APIFOX对接）

### 3.1 维护 APIFOX 目录完整性

**产品需要确保：**
- 接口已定义（URL/方法/入参/出参）
- 字段类型正确（string/number/boolean/array/object）
- 枚举值完整（如 status: `0-待处理, 1-处理中, 2-已完成`）
- Mock 数据已配置（或至少提供示例数据）

**检查方法：**
- 打开 APIFOX → 找到对应接口 → 检查"请求参数"和"响应参数"是否填写完整
- 如有缺失 → 补充或提醒后端同学补充

### 3.2 需求文档中明确标注接口需求

**产品写需求时，在文档末尾补充：**

```
## 接口需求
- 模块 1（统计卡）：需要接口 `GET /api/traffic/stats`
- 模块 2（折线图）：需要接口 `GET /api/traffic/trend?range=24h`
- 模块 3（饼图）：需要接口 `GET /api/traffic/source`
- 模块 4（表格）：需要接口 `GET /api/traffic/records?page=1&size=20`
- 模块 5（筛选栏）：筛选条件作为查询参数传递

## 字段映射（如有特殊要求）
- 流量值单位：万（接口返回 1.5 表示 1.5 万）
- 时间格式：YYYY-MM-DD HH:mm:ss
- 状态枚举：0-待处理, 1-处理中, 2-已完成, 3-已失败
```

**为什么重要：**
- 平台自动生成 service 函数 + 类型定义 + mock 数据
- 接口定义完整 → 生成后直接可用，联调零返工
- 接口定义缺失 → 生成后字段不匹配，开发需手动修改

## 四、验收反馈阶段（生成完成后）

### 4.1 产品验收 checklist（5 项还原度 + 3 项功能）

**还原度检查（看视觉）：**

| # | 检查项 | 怎么看 | 不合格处理 |
|---|-------|-------|-----------|
| 1 | 布局结构是否与 Figma 一致 | 打开 Playground 预览，对比 Figma 设计稿 | 重新生成（附 Figma 修正） |
| 2 | 颜色/字体是否与设计稿一致 | 检查主色/辅助色/字号/字重 | 重新生成（附设计稿色值） |
| 3 | 图标/背景图是否完整加载 | 检查是否有空白/占位符 | 检查 Figma 图层命名 → 重新生成 |
| 4 | 图表数据是否占位正确 | 检查图表结构（不关心真实数据） | 补充接口定义 → 重新生成 |
| 5 | 交互元素是否可见 | 检查按钮/tab/输入框是否显示 | 检查 Figma 图层是否隐藏 → 重新生成 |

**功能检查（看行为）：**

| # | 检查项 | 怎么看 | 不合格处理 |
|---|-------|-------|-----------|
| 1 | 接口字段是否绑定 | Playground 网络请求看是否调通 | 核对 APIFOX 目录 → 重新绑定 |
| 2 | 数据展示是否正确 | mock 数据 vs 真实数据 | 补充接口 mock 数据 → 重新生成 |
| 3 | 响应式是否生效 | 拖拽窗口看布局变化 | 补充响应式要求 → 重新生成 |

### 4.2 不合格反馈模板（产品直接复制填写）

```
## 组件生成验收反馈

**组件名称**：[填写]
**生成时间**：[填写]
**验收结果**：□ 通过  □ 需修改

### 不合格项
1. [还原度/功能] [具体问题描述，如"背景图未显示"]
   - 期望：[期望效果]
   - 实际：[实际效果]
   - 截图：[附截图]

2. ...

### 补充材料（如有）
- Figma 修正链接：[如有]
- 接口补充定义：[如有]
- 其他说明：[如有]
```

## 五、日常协作习惯（长期提效）

### 5.1 需求提交规范

**产品提需求时，尽量包含：**
- 业务线（哪个项目/产品）
- 组件类型（图表/表单/布局/弹窗/其他）
- 输入源（Figma URL / 截图 / 需求文档 / 无）
- 功能描述（业务语言即可）
- 接口需求（需要对接哪些接口，可选）
- 优先级（P0 紧急 / P1 重要 / P2 一般）
- 期望交付时间（可选）

**提交渠道（待平台需求提交表单上线后统一）：**
- 短期：群内反馈 / 飞书文档
- 中期：平台需求提交表单（规划中）

### 5.2 定期同步机制

| 频率 | 内容 | 参与方 |
|-----|------|-------|
| 每周 | 生成任务状态同步（待生成/生成中/已完成/需修改） | 产品 + 开发 |
| 每两周 | 质量看板 review（成功率/BLOCK 原因分布） | 产品 + 开发 |
| 每月 | 组件库新增组件同步 + 高频需求盘点 | 产品 + 开发 + 设计 |

### 5.3 问题升级路径

```
产品发现生成问题
  → 填写验收反馈模板
  → 群内反馈 / 平台提交
  → 开发确认（3 天内）
  → 重新生成 / 手动修复
  → 产品验收
  → 通过 / 继续修改
```

## 六、产品侧能提供的最高价值物料（优先级排序）

| 优先级 | 物料 | 什么时候提供 | 对生成的影响 |
|-------|-----|------------|------------|
| **P0** | 规范的 Figma 设计稿 | 提交生成前 | 还原度提升 30%+，BLOCK 率降低 50%+ |

## 七、快速参考卡片（产品同事可保存）

### 提交生成前 3 分钟自检
```
1. Figma 图层命名是否语义化？（无 Frame 123）
2. Auto Layout 是否完整？（关键容器已添加）
3. 需求文档是否结构化？（模块/字段/交互/数据）
```

### 验收不合格 3 步处理
```
1. 对照 checklist 定位问题（还原度 5 项 + 功能 3 项）
2. 填写反馈模板（附截图/补充材料）
3. 群内反馈 / 平台提交 → 等待 3 天内确认
```

### 最高价值 3 件事
```
1. 推动设计团队 Figma规范（命名 + Auto Layout）
2. 写结构化需求文档（模块/字段/交互/数据）
3. 维护 APIFOX 接口定义完整性
```
