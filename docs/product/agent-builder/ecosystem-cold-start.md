# 从零到多智能体：Agent 生态冷启动规划

> 版本：v0.1 ｜ 日期：2026-08-20 ｜ 作者：产品通 + smigoo
> 核心问题：**在"什么都没有"的环境下，如何长出脚本、模板、提示词、单智能体、多智能体这套完整体系**

---

## 1. 愿景

让平台具备**自举（bootstrap）能力**：即使资产库为空，也能通过一条清晰的生长路径，从第一段手写脚本开始，逐层长出可复用的模板、可调用的提示词、可编排的单智能体，最终组装成多智能体生产管线。**资产不是前提，是生长出来的。**

## 2. 五层生长架构

| 层 | 名称 | 定义 | 产出物 | 载体（界面入口） |
|---|---|---|---|---|
| L0 | 空环境 | 起点：无代码、无模板、无数据 | — | — |
| L1 | **脚本 Scripts** | 平台预置的确定性执行单元（url 解析、字段映射、校验…） | `roles/*-agent.js`（skipLLM） | 脚本库 |
| L2 | **模板 Templates** | 脚本的参数化骨架（占位符 + 参数 Schema），选模板+填参即生成新脚本 | 模板库条目 | 模板库 / Agent Builder |
| L3 | **提示词 Prompts** | LLM 角色的灵魂（职责、输入输出、规范、参考文档引用） | prompt 模板 | 提示词库 / Agent Builder |
| L4 | **单智能体 Single Agent** | 脚本或提示词封装为统一 execute 契约的可编排节点 | 注册表条目 + 可用列表节点 | Agent Builder / 注册表 |
| L5 | **多智能体 Multi-Agent** | 单智能体按 DAG 编排（串行/分支/并行），state 在节点间流动 | 工作流 JSON | WorkflowEditor |

**核心认知**：每层都是下一层（或组合）的原料。**单智能体 = 脚本（L1）或 提示词（L3）包装成统一契约；多智能体 = 单智能体的 DAG 组合。**

## 3. 层间转化（生成矩阵）

| 从 \ 到 | 脚本 | 模板 | 提示词 | 单智能体 | 多智能体 |
|---|---|---|---|---|---|
| 脚本 | — | ✅ 参数化（占位符替换） | — | ✅ 直接包装（skipLLM） | — |
| 模板 | ✅ 选模板+填参 | — | — | ✅ 渲染后包装 | — |
| 提示词 | — | — | — | ✅ 封装 BaseAgent（LLM） | — |
| 单智能体 | — | ✅ 另存为模板（泛化） | — | ✅ 复制编辑 | ✅ DAG 编排 |

**两条回流路径（飞轮）**：
1. **脚本 → 模板 → 新脚本**：验证过的脚本参数化进库，用户选模板更快产出
2. **单智能体 → 模板**：跑通的智能体一键「另存为模板」→ 模板库增长

## 4. 冷启动路径（L0 → L1 播种）

**第一个模板怎么来（先有鸡还是先有蛋）**：模板 = 已验证脚本的参数化版本。**先人工写第一段脚本，再参数化成模板。**

| 步骤 | 做什么 | 产物 |
|---|---|---|
| 1 | 开发者手写第一个确定性脚本（如 URL 解析） | `url-parser-agent.js` |
| 2 | 冒烟测试验证 | 测试报告 |
| 3 | 参数化（提取占位符 + 参数 Schema） | `url-parser` 模板 |
| 4 | 沉淀为 create-ai-agent 技能资产 | 模板库种子 |

**MVP 种子清单**（从现有 19 个 roles 参数化，先做 5-6 个够演示）：
- URL 解析（url-parser ✅ 已存在）
- 透传/包装（hello ✅ 已存在）
- 字段映射 / JSON 转换 / 校验器 / 聚合器 / 路由器（待参数化）

## 5. 功能承载（每层的界面入口）

| 入口 | 位置 | 能力 |
|---|---|---|
| 脚本库 | 新增页面或并入 WorkflowEditor | 浏览/查看预置脚本 |
| 模板库 | Agent Builder 内 | 选模板 → 填参数 → 生成脚本 |
| 提示词库 | Agent Builder 内 | 创建/编辑 prompt，绑定模型与参考文档 |
| **Agent Builder** | WorkflowEditor 工具栏「＋新建智能体」 | 表单创建：元数据 + 数据契约 +（选模板｜写 prompt） |
| WorkflowEditor | `/generator/workflow` | 单智能体 → 多智能体 DAG 编排、保存、运行 |

**统一接口契约（所有层都对齐）**：
```js
execute(state) → 结果对象合并回 state
parseOutput(raw) → 结构化输出
onProgress → SSE 进度上报
```

## 6. 分期路线图

| 阶段 | 范围 | 交付 | 验收 |
|---|---|---|---|
| **P0（冷启动 MVP）** | ① 动态注册表改造（热加载）② Agent Builder 表单（工具节点：选模板+填参）③ 模板库种子 5-6 个 ④ 冒烟测试 | 界面可创建工具节点并进管线 | 创建→进管线转化率演示通过；4 条受保护管线回归 |
| **P1（AI 节点）** | ① 提示词库 ② Agent Builder 支持 LLM 节点（prompt+模型）③ 节点内试跑 ④ 权限/隔离 | 界面可创建 AI 节点 | LLM 节点创建→运行链路通过 |
| **P2（生态飞轮）** | ① 模板库 UGC（自定义脚本+审核）② 单智能体「另存为模板」③ 复制编辑 ④ 模板/提示词市场 | 生态自增长 | 周新增模板数 ≥ 3；UGC 审核通过率 ≥ 80% |

## 7. 指标

| 类型 | 指标 | 目标（上线后 8 周） |
|---|---|---|
| 北极星 | 用户自建资产（脚本/模板/智能体）被管线引用次数 | 累计 ≥ 50 |
| 驱动 | 周新增模板数 | P0 后 ≥ 2，P2 后 ≥ 5 |
| 驱动 | 创建→进管线转化率 | ≥ 60% |
| 健康 | 资产创建成功率（语法+冒烟） | ≥ 95% |
| 健康 | 模板复用率（模板生成占比） | ≥ 40% |

## 8. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 动态注册表改造影响现有管线 | 🔴 高 | 内置角色迁移为同构条目；强制回归 4 条受保护管线 |
| 冷启动种子不足，功能空转 | 🟡 中 | P0 先沉淀 5-6 个模板（从现有 19 个 roles 参数化），保证可演示 |
| 模板生成代码注入 | 🔴 高 | 白名单模板（用户文本不进代码）；vm 语法门禁 |
| 自定义脚本安全（P2） | 🔴 高 | 沙箱 + 审核 + 白名单函数 |
| LLM 配置缺失（P1） | 🟡 中 | 创建时校验模型凭证；缺省给出配置引导 |
| 用户命名冲突/资产隔离 | 🟡 中 | author 字段 + 唯一性校验 + 内置名保留 |

## 9. 关键路径（依赖顺序）

```
P0-① 动态注册表改造 ──→ P0-② Agent Builder（工具节点）
   （地基，风险最高）      └──→ P0-③ 模板库种子
                                └──→ P0-④ 冒烟测试
P1：提示词库 → Agent Builder（AI 节点）→ 权限隔离
P2：UGC 模板 → 另存为模板 → 市场
```

**一句话关键路径**：先打通"选模板→生成脚本→注册→进管线"的最小链路（P0），再扩展 AI 节点（P1），最后靠 UGC 形成飞轮（P2）。

## 10. 依赖的既有资产（不是从零，但当作从零的参照）

- `create-ai-agent` 技能：已沉淀"从零建智能体"的完整流程（roles 模板 + 3 处注册 + 验证）
- `hello-agent` / `url-parser-agent`：已验证的 2 个最小智能体（可直接参数化为模板）
- WorkflowEditor + dynamic-workflow-graph：已支持 DAG 编排与热加载目标点
- 19 个现有 roles：模板库参数化的原料库
