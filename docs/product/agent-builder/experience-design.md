# Agent Builder 体验升级规划：从 0 到 1 构建复杂智能体

> 版本：v1.0 · 2026-08-20
> 背景：Agent Builder 已具备"新建节点（工具 16 类 + AI 2 类）+ 编排（串行/条件/并行/校验门）+ 资源手填/上传"。
> 本文目标：把"建一个**复杂功能**智能体"的体验从"会拖画布的人才能做"升级为"说一句话 / 选个场景就能做"，并让产物**可衍生到各种功能**。

---

## 一、现状盘点与体验断层

### 已具备（今天完成的能力）

| 能力 | 状态 |
|---|---|
| 单节点创建（选模板/写 Prompt + 资源清单 + 手填/上传） | ✅ |
| 编排（串行 / 条件分支 / 并行组 / 校验门 / phase2 变体） | ✅ |
| 动态注册热加载（新建即用） | ✅ |
| 单节点冒烟测试 | ✅ |
| 运行质量报告（管线级） | ✅ |

### 从 0 到 1 建"复杂智能体"的 4 个体验断层

| # | 断层 | 用户感受 | 根因 |
|---|---|---|---|
| 1 | **空白画布恐惧** | "复杂智能体要 10+ 节点，我该从哪个开始？" | 没有"场景化起点"，入口只有裸画布 |
| 2 | **连线靠猜** | "A 节点输出什么、B 节点要什么，我怎么知道？" | 节点间**字段级数据流不可见** |
| 3 | **模板粒度错位** | "模板都是单节点级，没有现成的完整方案" | 只有"零件模板"，没有"整机蓝图" |
| 4 | **调试靠猜** | "跑完不对，是哪个节点的问题？" | 运行快照有但**节点级数据查看/断点**弱 |

**结论**：现有能力是"能工巧匠的工具箱"，缺的是"让普通人也能造出复杂机器"的**脚手架与路径**。

---

## 二、设计原则（4 条）

1. **脚手架优先**：默认给可运行的骨架，用户改参数而非从零造。复杂 ≠ 必须手动。
2. **语言即入口**：一句话能说清的目标 → 就能生成蓝图。让"想清楚"直接变成"建出来"。
3. **数据流可观测**：字段级依赖在画布上可见，运行中可查每个节点输入/输出。复杂系统必须可检查。
4. **一切可衍生**：跑通的智能体一键参数化进库，配方库随使用增长——这是"衍生到各种功能"的机制保证。

---

## 三、三层创建入口（核心体验）

同一目标，三种深度；**默认给脚手架，高级才见裸画布**。

```
┌─ L1 对话式（默认）──── 说一句话 ──────────────────────┐
│  "我要一个输入竞品URL、输出功能对比表的智能体"           │
│  → AI 生成完整节点拓扑 + 连线 + 字段契约 → 确认即落地    │
├─ L2 蓝图式（推荐）──── 选一个场景 ────────────────────┤
│  竞品分析 / 数据报表 / 组件生成 / 接口对接 / 文档总结…   │
│  → 预置配方（多节点+数据流+参数）→ 改参数即用            │
├─ L3 编排式（进阶）──── 拖拽画布（现状）────────────────┤
│  自由搭建，完全自定义 → 已具备，作为高级模式保留          │
└──────────────────────────────────────────────────┘
```

| 特性 | L1 对话式 | L2 蓝图式 | L3 编排式 |
|---|---|---|---|
| 上手时间 | ~1 分钟 | ~3 分钟 | ~20 分钟 |
| 控制力 | ★ | ★★★ | ★★★★★ |
| 适用人群 | 业务人员 | 进阶用户 | 专家/开发 |
| 产物 | 可运行蓝图 | 可运行配方 | 完全自定义 |

**层级间可转换**：L1 生成的蓝图可升入 L2 保存为配方；L2 配方可升入 L3 画布继续精修；L3 产物可另存为模板降级供 L2 使用。

## 四、复杂智能体配方（数据模型）

**复杂智能体 = 一份配方，不是节点堆叠。** 六要素齐全，才能"被理解、被复现、被衍生"：

```jsonc
{
  // ① 目标描述
  "name": "competitor-analysis",
  "label": "竞品分析智能体",
  "description": "输入竞品官网 URL，输出功能对比表与差异化建议",
  "scenario": "竞品分析",

  // ② 节点蓝图（拓扑 + 结构）
  "nodes": [
    { "id": "fetch", "handler": "url-fetch-agent", "type": "agent" },
    { "id": "parse", "handler": "llm-analyzer", "type": "agent",
      "config": { "model": "qwen3.7-plus", "prompt": "提取页面功能特性..." } },
    { "id": "compare", "handler": "llm-analyzer", "type": "agent",
      "config": { "model": "qwen3.7-plus", "prompt": "与内置竞品基线对比..." } },
    { "id": "format", "handler": "formatter", "type": "agent" }
  ],
  "edges": [ { "source": "fetch", "target": "parse" }, ... ],
  "structure": { "parallel": [], "conditions": [] },   // 并行组/条件分支

  // ③ 数据契约（字段级）
  "contracts": [
    { "from": "fetch", "outputs": ["pageContent"] },
    { "to": "parse", "inputs": ["pageContent"] }
  ],

  // ④ 参数与资源
  "params": { "model": "qwen3.7-plus", "temperature": 0.2 },
  "resources": [ { "name": "竞品基线.md", "url": "...", "type": "md" } ],

  // ⑤ 测试集
  "testCases": [
    { "input": { "url": "https://example.com/a" }, "expect": { "hasTable": true } }
  ],

  // ⑥ 使用说明
  "usage": "粘贴竞品 URL 到入口节点，运行后到结果节点取对比表",
  "version": 1, "author": "u-xxx", "createdAt": 1787200000000
}
```

配方 = 六要素 JSON + 可执行的蓝图。**前端一次加载即得可运行管线**（与现有 workflow JSON 兼容扩展）。

## 五、关键体验细节

### 1. L1 对话式生成器（NL → 蓝图）

```
用户输入一句话
  → LLM 生成结构化蓝图草案（节点清单/连线/契约/参数）
  → 蓝图校验器（规则：必须含入口/出口、字段契约两端匹配、handler 必须已注册）
  → 前端画布预览（节点已摆好，用户可勾选调整）
  → 确认 → 保存为可运行配方 → 立即试跑
```

- **约束**：handler 只能从"已注册节点"中选择（白名单），LLM 只负责**选型和连线**，不生成任意代码（安全边界延续现有原则）
- **防错**：校验器失败 → 返回具体修改建议（"compare 节点缺少输入字段 pageContent"）→ 让 LLM 修正后重试（沿用 revision 循环模式）
- **降级**：LLM 不可用时退回 L2 蓝图选择

### 2. 数据流可观测性（画布升级）

| 能力 | 交互 |
|---|---|
| 字段级依赖 | 连线上 hover 显示"传递字段：pageContent → parse"；节点间契约不匹配时**红点警告** |
| 节点运行快照 | 运行后点击任一节点 → 看该节点输入/输出 JSON（现有质量报告升级为"节点级"） |
| 断点调试 | 节点可设"暂停点"，运行到该节点停下，看数据再决定继续/改参重跑 |
| 全链路追踪 | 一次运行的时间线：每节点耗时/状态/字段变更 diff |

### 3. 测试集与一键回归

- 创建时：按输入字段**自动生成 mock 用例**（手填 + 上传的资源可作参考）
- 保存用例集 → 改配方后"一键回归"：全用例重跑，输出结构/覆盖率变化即拦截
- AI 节点用**回归基线**（上次验收通过的输出快照）比对，覆盖率下降提示

### 4. 衍生机制（"衍生到各种功能"的飞轮）

```
单智能体/配方跑通 → 一键「另存为模板」（参数化，敏感字段打码）
  → 进场景配方库 → 别人选配方 → 改参数/加节点 → 新智能体
  → 新智能体又可另存为模板 → 库越用越大
```

- **复制改造**：任何配方可"复制一份"后自由改（拷贝式，不影响原配方）
- **模板授权**：作者/管理员/内置三级（延续既有权限模型）
- **模板描述**：配方六要素天然就是模板的"说明书"

## 六、落地分期

| 阶段 | 内容 | 达成效果 |
|---|---|---|
| **P0 衍生闭环**（地基） | 配方数据模型 + 蓝图保存/加载 + 「另存为模板」+ 场景配方库（先内置 3-5 个手写配方） | "跑通 → 存库 → 别人复用"闭环打通 |
| **P1 对话式 + 可观测** | NL→蓝图生成器 + 蓝图校验器 + 字段级依赖显示 + 节点快照/断点 | L1 入口上线，调试效率提升 |
| **P2 测试与市场** | 测试集/一键回归 + 配方市场/分享 + 团队协作（权限/评论） | 质量可信，UGC 飞轮转起来 |

**建议顺序**：P0 先行——它只做数据层和"另存为模板"，不动生成引擎，风险最低，且是 L2/L1 的地基。

## 七、指标

| 类型 | 指标 | 目标 |
|---|---|---|
| 北极星 | 从 0 到 1 建出可运行复杂智能体的成功率 | ≥ 70%（首次试跑成功） |
| 转化 | L1/L2 创建占比（相对纯画布） | 首月 ≥ 40% |
| 衍生 | 配方被复用次数 / 模板衍生率 | 月环比 +30% |
| 效率 | 平均"从想法到首次试跑"时长 | ≤ 10 分钟 |
| 健康 | 蓝图校验器拦截率 / 运行失败率 | 拦截后修正成功率 ≥ 80% |

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| LLM 生成蓝图不稳定（选错节点/契约断裂） | 蓝图校验器 fail-closed + 修订循环；handler 白名单防代码注入 |
| 配方库质量参差 | 模板分"官方/社区"；社区模板标注复用次数与成功率 |
| 参数化模板改坏影响面 | 拷贝式引用（图纸改了，已造好的零件不变）；版本化 |
| 复杂度失控 | 配方版本锁定 + 依赖节点清单（缺节点时明确提示"需先安装 XX"） |
