# 子组件覆盖度校验治本方案（microcode 链）

> 日期：2026-11-08 · 实锤：`mc-max-1794076626809-402679ed`
> 状态：**已实施并本地提交，未构建、未重启、未部署**。
> 查重结论：**不另立第二套口径** —— 判据复用 `vue3-engineer.js:2148` 的 `expectedMinFiles` 语义，只把 microcode 端缺失的同一件事补齐。

## 1. 现象

用户报「经过治理反而效果更差」的产物：

| 真值 | 产物 |
|---|---|
| 2 个顶层 section：`2:8419` header（388×30.09）、`89:40` 内容区（407.4×380，含 `89:38` tab / `89:37` 左导航 / `2:8437` 12 卡 3×4 网格） | 2 个组件文件：`StatsSection.vue` + `MainSection.vue`；`MainSection` 是一张 4 行 × 2 列 `<a-table>` |
| 27 条中文文案真值 | 覆盖 10 条（37%），12 张卡片传感器名全丢 |
| 资源映射 31 条（30 success），owner 含 12 个卡片 | 18 张图零引用，资源使用率 7% |

## 2. 根因（文件:行号）

不是「治理把结构做塌」，也不是 prompt 措辞问题。链路上**已经要求 5 个文件，但没有任何地方验收**：

1. `subcomponent-planner.js:2064-2083`：`enableInternalSplit && shouldSplit` → `splitSectionInternally()` 正常拆出 3 个 `element-group`（group3 明确带 `2:8437` 与 6 条卡片文本真值）。
2. `generation-context-assembler.js:331-375`：`normalizeComponentPlan` 把内容契约迁到 `declaredContent`（带 6KB 体积闸），section 的 `body` 不再承载内容层次 ⇒ `collectLeafSections` 只看到 2 个叶子，`89:40` 被当叶子。
3. `microcode-engineer.js:1064-1069`：prompt **已明确**「本组件必须拆分为 **5** 个独立子组件文件」「数量和对应关系不得缩减」。
4. **断点**：模型只落 3 个组件文件，而 microcode 链**没有任何 `minFiles` / `expectedMinFiles` 消费** —— `vue3-engineer.js:2148-2150` 有，microcode 端 grep 为空。
5. C8（守卫总纲 §C8）只在「被引用但缺文件」时递归补；模型没引用 group1/2/3 ⇒ `dangling=0` ⇒ 不触发。
6. 兜底只剩 `TEXT-COVERAGE`（error 级），却被 `_l0SoftFail=true` 降级放行；产物最终 `completed` + `runtimeVerified=true` + `artifactIncomplete=false`。

⇒ 一句话：**planner 拆了、prompt 写了、模型缩水了、链路没验收。**

## 3. 修法

新增纯函数判据 `src/ai-engine/roles/microcode/subcomponent-coverage.js`：

```
expected  = isForced ? minFiles : 0
generated = `<outputPath>/package/components/*.vue` 一级文件数
missing   = max(0, expected - generated)
```

接入点（写盘唯一出口）：`microcode-engineer.js#writeFiles` 调 `microcodeWriter.writeFiles` 之前——

- `microcode-engineer.js:807` 记账 `this._coverageMeta = { isForced, minFiles, internalSubcomponents }`
- `microcode-engineer.js:6059` 调判据 + 打计数行 `🧩 子组件覆盖度: expected=… generated=… missing=… internalExpected=… forced=…`（**0 也打**）

**本步只留痕，不阻断**：升级为 BLOCK 会改变存量任务终态（现在 `completed` 的会变 `failed`），属门禁强度变更，须单独授权。

## 4. 判据可辩驳性

- 单一来源：不复制 `vue3-engineer` 逻辑，只共用同一 `minFiles` 语义；口径常量 `SUBCOMPONENT_DIR_PREFIX = 'package/components/'`。
- 阳性对照：`expected=5 / generated=3 → missing=2, ok=false`（复现 402679ed 真实数字）。
- 阴性对照：数量达标 / 非强制（`isForced=false` 时 `minFiles` 残留不得误报）/ 只有 index+less。
- 边界：二级目录 `components/xx/yy.vue` 不计一级槽位；`files` 传数组；入参缺失不抛错。
- 计数行 0 也打，避免「没执行」与「执行了零缺失」同形。
