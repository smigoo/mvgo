## 1. 病灶与根因链

### 1.1 病灶①：LLM 裸写 backgroundImage → repeat 平铺（ea959204 / 7d3fc546）
`ListSection.vue:8` 卡片级 `:style="{ backgroundImage: url(bg1) }"` 只有 url，无 repeat/size/position
→ CSS 默认 `repeat` + 图片原始尺寸（459×29）→ 72px 高卡片内垂直平铺 N 遍。
而这张图是**整条列表级**背景，`:2` 父级已由系统注入器正确挂四件套——双源并存。

**根因（契约层）**：提示词**没有红线**告诉 LLM「背景挂载是系统注入器独占职责，禁止自写 background* 绑定」。
LLM 看到 vision 里卡片有底色装饰就自由发挥写了半截绑定。
（**兜底处置续接既有守卫**：裸绑定补全=S6 `ensureBackgroundStyleComplete`（2026-11-06 勘误，原误记刀39）；多锚收敛=刀68 `collapseBgMultiAnchor`，本刀不另立 bg 口径。）

### 1.2 病灶②：段级契约复读到子元素 → 卡片内切 4 格文字截断（c-a03fe）
common.less 出现 7 处错位块：
```less
.c-7a03fe-content-section3 .c-7a03fe-vendor-item {
  display: grid;
  background: #f6fff7;
  grid-template-columns: repeat(4, 1fr);   /* 段级契约 */
  flex: 1.188 1 0;                          /* 段级 flex 比例 */
  min-height: 0;
}
```
卡片内部被切 4 列轨道，name 占第 1 格（25%）→ ellipsis 截断。**内部没有 4 份内容也切 4 格**
——grid 轨道定义的是空间划分，与内容份数无关。

**根因（契约层）**：两把强契约夹击——
- `prompt-builder:3417`：「**网格列数**：必须使用 `grid-template-columns: repeat(N, 1fr)`，N 为标注列数」——
  **无适用域限定**，LLM 理解为「凡网格场景都要写」；
- FLEX 门禁体系（flex-sibling-guard FLEX-003/005）：「每个区块 `flex: <高度系数> 1 0`」——
  LLM 曾因「缺声明」被闸，学会**多处复读以求过闸**（块内空行拼接缝 = 分片段输出拼入）。

下游全盲区：刀41 契约自愈只管**段容器/wrapper**层；css-sanitizer 的 display 补全 pass 只补不删；
flex-sibling-guard 只查兄弟区块根级。「**深层子元素选择器上的段级契约块**」无人管辖 → 原样落盘。

### 1.3 病灶③：四件套口径死值 → 容器弹性时错位（用户裁决：比例口径）
`background-size-inference.js` 现行口径：
- size：铺满（coverage≥0.9）→ `100% 100%`；局部 → **死像素** `${fw}px ${fh}px`（如 `459px 29px`）；
- position：**死像素**偏移 `${dx}px ${dy}px`。
容器弹性宽（width:100% / 大屏自适应）时死像素错位/留白；而「盲目 100%」已被 D2 治本
（09636315：局部装饰带 coverage=0.393 被 STRETCH→100% 拉满 2.48 倍）证明同样危险。
**用户裁决：位置/大小用比例，大小不能盲目 100%。**

## 2. 治本方案（四刀，实施顺序 T1→T2→T4→T3）

### T1 提示词红线：背景挂载系统独占（病灶①根因）【裁决：WARN+守卫兜底，不 BLOCK】

> 你（LLM）禁止在任何模板 `:style` / CSS 里自写 background 图绑定——只负责 DOM 结构与内容。
> 若某容器在 Figma 里有背景图，什么都不做（系统会挂对地方）。**

配正反例各 1（正例：卡片只写结构；反例：`:style="{ backgroundImage: url(bg) }"`）。

### T4 四件套比例口径（病灶③，`background-size-inference.js` 单一事实源）【裁决：双端同改】
- `inferBackgroundSize`：局部场景（coverage < COVER_RATIO 且有 parentBox）由
  `${fw}px ${fh}px` → `${(fw/pw*100).toFixed(2)}% ${(fh/ph*100).toFixed(2)}%`
  （CSS background-size 百分比天然相对挂载容器，容器弹性时等比跟随；
  天然规避盲目 100%——coverage<0.9 时恒不等于 100%，D2 守卫语义保留）。
  无 parentBox → 维持 px 兜底（无比例依据不臆造）。
- `inferBackgroundPosition`：**CSS 语义陷阱**——position 百分比是「图的 x% 点对齐容器 x% 点」，
  **不是偏移比例**。换算公式：
  `posX% = offsetX / (容器宽 − 图渲染宽) × 100`（图渲染宽 = 容器宽 × sizeX%）；
  容器宽 == 图渲染宽（分母 0）或偏移 0 → `0px 0px`。
  验证：ea959204 例 `6 / (470−459) × 100 = 54.5%`，容器缩放时视觉偏移等比保持。
- scaleMode 真值优先（cover/contain）**不动**——本身就是保形比例语义。
- `areaBackgroundSizing` / `sizingFromScaleMode` 两个同族出口**同步同口径**（禁止第二套口径）。
- **实施影响面核对项**：grep vue3 端消费点有无假定 px 格式的解析器
  （如 `/(\d+)px (\d+)px/` 正则 parse backgroundSize）——有则同步适配，无则记录确认。

#### T4 实施记录（2026-11-06 落地）
`background-size-inference.js` 四出口同口径已落地，spec 28/28 绿。实施中新增一条边界勘误：

- **cov = 0（无交集退化数据）回落 px**：`percentSizeFrom` 对 `coverageRatio ≤ 0` 返回 null
  （一处防御覆盖 `inferBackgroundSize` 两分支 + `sizingFromScaleMode` 三出口），
  `areaBackgroundSizing` 内联计算同步加 `cov !== 0` 条件。理由：无交集时偏移动辄数百 px
  （实锤用例 500px），换算成超界百分比（625%）在预览沙箱与浏览器间行为不可控，
  px 实际像素 + 真实偏移才是最保真表达（D2 守卫原文语义）。
- **expectPctPos spec helper 镜像边界语义**：偏移 0 → `'0px'`（与 `percentOffsetFrom` 一致），
  size 解析取 `split('%')[1]`（索引 [2] 是空串）。
- **vue3 消费点 px 解析器核对 ✅（T4 影响面收尾）**：grep `backgroundSize` 全部消费点
  （style-refiner/style-mapper/visual-parser/microcode-engineer），无 `/（\d+)px (\d+)px/`
  假定格式的解析器；`style-refiner#hasFullSize` 检测 `100% 100%` 字面量——T4 后局部背景
  不再产出该值 ⇒ 铺满清理不触发 ⇒ 行为正确（局部背景本就不该删 position）。零适配需求。
