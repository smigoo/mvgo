## 二、使用过程中暴露的问题

### 2.1 🔴 工作台意图识别薄弱 —— 用户说「人话」，系统给「菜单」

**现象（生产会话原文，10 条会话中 6 条命中）**：

| 用户原话 | 系统回应 |
|---|---|
| 「重生成一次」（zhjie，24 条会话） | 「我理解你的需求："重生成一次"。目前我支持以下操作：……请告诉我你想做什么？」 |
| 「帮我使用」（zhjie） | 同上，回落到 12 项能力清单 |
| 「帮我使用mock」（zhjie） | 同上 |
| 「今日日期」（lius） | 同上 |
| 「test」（wangxushenga） | 同上 |
| 「嘿嘿」（wangxushenga） | 同上 |

**问题本质**：这不是「AI 能力不足」，而是**意图路由表缺失**。用户的高频自然表达（重生成 / 再来一次 / 用 mock / 改样式）不在路由词典里，系统无法识别，直接降级为「打印菜单」。

**代价**：用户拿到的不是答案而是**一份说明书**。在对话式界面里，弹菜单等于把用户推回 API 文档。

**改进方向**：① 建立**口语意图 → 动作**映射词典（重生成 / 再来一次 / 换主题 / 用假数据 / 撤回 / 复制…）；② 识别失败时**先追问澄清**（「你是想重新生成上一个组件吗？」），而不是甩菜单；③ 菜单兜底应作为**最后一次**手段。

---

### 2.2 🔴 核心操作链路存在失败，且无引导

**实例（最活跃用户之一）**：

```
liuqh（软件研发中心，累计生成 22 次）
  ── [user] 绑定 API
  ── [assistant] 好的，我来帮你绑定 API。
      ⚠️ 1 个操作执行失败，请检查参数后请重试。
```

这是 10 条会话中**唯一一次功能调用失败**，且发生在「绑定 API 数据源」这一核心场景上。用户的下一步反应是**结束会话** —— 失败后没有重试、没有替代路径、没有说明原因。

**改进方向**：失败必须返回**可执行的下一步**（缺什么参数、怎么改、能否跳过），而非一句「请检查参数」。

## 三、大家对晓界工坊的评价

> **样本说明**：生产 `conversations` 共 10 条会话，覆盖 9 人、5 个部门。以下为**用户原话摘录与行为分析**，非问卷结果。样本量小，结论仅作方向性参考。

### 3.1 ✅ 正面信号：**「重复使用」本身就是最强好评**

| 用户 | 部门 | 累计生成 | 行为特征 |
|---|---|---|---|
| **zhjie 周洁** | 桥隧事业部 | **66 次** | 单日（09-29）反复生成 4 个组件、连续追问「重生成一次」 |
| liuqh 刘清华 | 软件研发中心 | 22 次 | 生成 + 绑定 API + 查询状态，多轮组合使用 |
| lixye 李星晔外协 | 软件研发中心 | 10 次 | — |
| leishihao 雷世豪外协 | 软件研发中心 | 9 次 | — |
| lijunjie 李俊杰外协 | 软件研发中心 | 9 次 | — |
| wangtongt 王桐桐 | 视频事业部 | 8 次 | — |

**24 人在近两周有生成行为，累计产出台账 334 次任务、242 个组件** —— 这批人是真在用，不是被安排来试试。

### 3.2 ⚠️ 负面信号：**「用不下去」比「不好用」更常见**

三类卡点，**全部有原话或行为证据**：

| 卡点 | 证据 | 性质 |
|---|---|---|
| **说了人话没被接住** | 「重生成一次」「帮我使用」「帮我使用mock」「今日日期」→ 弹菜单 | 意图路由缺失 |
| **操作失败没下文** | 「绑定 API」→ 「1 个操作执行失败，请检查参数后请重试」→ 用户结束会话 | 失败路径缺失 |
| **打开就走** | 3 条会话 0 消息 | 首次引导缺失 |

**共同特征：用户不是在抱怨功能不好，是在「不知道下一步该做什么」的地方流失。**

### 3.3 🔴 最值得注意的一条：**「帮我使用mock」**

用户说「帮我使用mock」——想用**假数据**跑通组件。系统回了菜单。

这条需求的业务含义是：**用户想脱离真实接口，先看组件跑起来什么样**。这是一个**高频、明确、低成本的诉求**，却完全没被支持。

**衍生问题：是否存在 mock 数据能力？** 若不存在，这是**成本最低、价值最高的一个小需求**（支撑「组件体检」「版本回滚」「批量生成」等后续能力的可信度验证）。

### 3.4 🟡 中性观察：用户实际只用「最笨」的方式

10 条会话里，用户的操作序列高度一致：**粘贴截图 → 点确认 → 等生成**。所有高级能力（改样式、绑 API、推 GitLab）都需要**先有组件**，但用户在「生成完」之后就没了下一步。

**这说明平台的「生成」做完了，「生成之后」是空白。**

## 四、改进建议

### P0 · 本周内（低成本、直接影响口碑）

| # | 事项 | 动作 | 验收 |
|---|---|---|---|
| P0-1 | **意图路由词典** | 补口语映射：重生成 / 再来一次 / 换主题 / 用 mock / 撤回 / 复制 / 缩小 / 放大；识别失败改为**追问澄清**而非弹菜单 | 「重生成一次」不再落菜单 |
| P0-2 | **失败路径可执行化** | 所有操作失败必须返回「缺什么 / 怎么改 / 能否跳过」三要素 | 「绑定 API」失败可自助修复 |
| P0-3 | **首次进入引导** | 新会话首屏给出 2-3 个具体可点示例（如「用这张截图生成一个面板」） | 0 消息会话占比 < 10% |
| P0-4 | **mock 数据能力** | 提供假数据源开关，支撑无接口场景的组件验证 | 用户可说「用 mock 跑一下」 |

### P1 · 下月内（提升价值转化）

| # | 事项 | 动作 | 验收 |
|---|---|---|---|
| P1-1 | **生成后续动作引导** | 生成完成后主动提示可继续的动作（绑定 API / 发布 / 体检），把 9 项零使用能力推到用户面前 | 高级能力使用率 > 20% |

| P1-4 | **成功率 SLA** | 当前部署后 68%，目标 ≥ 85%；失败原因 TOP5 自动归类 | 失败分类看板上线 |
