# 判分驱动定向重试闭环（分支② A 最小版）· 立项方案

> 2026-11-10 · 状态：**方案待对齐**（管线编排级改动，对齐后实施）· 治理依据：六阶段

## 1 背景与实证

R5-R9 九轮批次：结构性病灶零复发（第 0 层守卫有效），但**随机生成缺陷导致批次无法收敛**——

| 轮次 | 结果 | 失败形态 |
|---|---|---|
| R6 | 2.5/4 | 设备 12 卡→3 卡坍缩、流量排版崩 |
| R7 | 3/4 | 设备 L0-B 硬闸（SFC 编译失败） |
| R8 | 2/4 | 环境表达式错误（该族当日 29 次）、流量悬空引用 |
| R9 | 3/4 | 设备模板内嵌 script/style 标签（新形态） |

**关键事实**：每一次失败/不可用都被判据**精确量化**（skill 28 维 + RUNTIME-016 + F1a/F1b），但判分在闭环外——量化了却不驱动修复。设备三连败证明随机重跑不可控收敛。

## 2 修法（最小闭环）

```
generate-runtime-verify 通过
  → 【新增】管线内快速验收（复用 skill 判据 util）
  → FAIL 清单结构化（段 id / 维度 / 差距值）
  → 非空 ⇒ 组装定向修复指导 → 回灌 L0-B 修复轮（复用 _l0CodeRetryGuidance 通道）
  → 重试后复检 ⇒ 仍 FAIL 如实降级（上限 1 轮，防失控）
```

### 关键设计决策（请对齐）

| # | 决策点 | 推荐 | 理由 |
|---|---|---|---|
| D1 | 判据单一来源 | **从 skill 脚本抽取判据 util 到 `src/ai-engine/utils/component-acceptance/`**，管线与 skill 脚本共同 import | 禁两侧口径漂移（collectMissingVueImports 同款纪律）；skill 独立运行能力保留 |
| D2 | 重试通道 | **复用 L0-B 修复轮**（FAIL 清单塞 retryGuidance），不新增重生成通道 | 机制现成、预算可控、失败归因路径单一 |
| D3 | 触发范围 | 仅 `v3Mode=generate` 首轮 + 修订轮后各跑一次 | 修订轮自己会改产物，需复检 |
| D4 | 重试上限 | **1 轮** | 防失控空转烧 Token（L0-B 已有耗尽语义可复用） |
| D5 | 验收维度（管线内 v1） | 先接 5 个已实证判据：D2 重叠 / A1 段缺失 / E3 双 bg / G1 交互 / 悬空引用（兜底后仍缺=生成层问题） | 全部阴阳验证过；D1 承载/C 组观测维度后补 |

## 3 判据与计数行

- 每次验收打计数行：`🛡️ acceptance：FAIL=N WARN=M dims=[D2:2,A1:1,...] retry=0/1`
- 重试后复检行：`🛡️ acceptance-retry：FAIL=N'（Δ=N-N'） effective=true/false`
- 哨兵：新 catch 全部接 reportPatchChainError（coverage 基线同步）

## 4 影响面

- `component-acceptance/` 新 util（判据搬家，skill 脚本改为薄封装 import）——**skill 既有行为零变化**（同一函数）
- `mc-component-graph-phase2.js`：complete 前插验收+条件重试编排（约 1 个节点/段落）
- L0-B 修复轮：接受新来源的 retryGuidance（通道已存在，格式兼容）
- 预算：每 FAIL 单 +1 轮修复的 Token 成本（换取交付质量）

## 5 回归

1. 判据 util spec（从 skill 冒烟样本转单测：0dce5e24 五 FAIL / b15aa33a 零 FAIL 作阴阳夹具）
2. 全量 jest 基线 diff 空
3. 真机：R10 批次对比——FAIL 单的 retry 命中率与复检收敛率（`acceptance-retry` 计数行）
4. 验收门不变：连续 2 轮批次 4/4（R10/R11 起计）

## 6 明确不做（本立项边界）

- 不做跨任务缓存复用（B 路线）
- 不做观测维度（C4 行高等）的门禁化——只接已实证 FAIL 判据
- 不改 vision/planner 结构决策（结构来源收紧另列观察项）
