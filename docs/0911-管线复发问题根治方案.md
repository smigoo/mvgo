# 管线复发问题根治方案

> 2026-09-11 · 基于当日 6 个实锤案例（2aa25837 塌陷、cfb53488 双 tabs、1fduq67s 悬空标签、
> 064a5fc9 覆盖率虚低、46859f40 标签无文件、generation-context 死代码）的系统性分析。
> 定位：**止血已完成（出口补丁层），本方案定义治愈路径**——错误在产生层被拒绝、
> 门禁可见性等于真实故障面、修复机制有可达性保证。

## 0. 治愈的验收标准（总口径）

1. 同一 Figma 连续生成 3 次 + 3 个不同 Figma，产物不变量检查全绿；
2. 全程**零人工就地修复**（不再用 python/sed 改 workspace 产物）；
3. 人为构造的坏产物（悬空标签/缺 import/双解释）**被门禁 BLOCK**，而不是靠人眼发现；
4. 每个注册的确定性机制能从生成入口静态可达。

## P0 · 门禁盲区闭合（小改动，最高性价比）

### R3-1 悬空标签变 BLOCK（新增 CODE-023）

**现状**：语义门禁对 subCompTags 白名单放行（假设"后面有人接线"），
`有标签无文件`/`有标签无 import` 在门禁中不可见（1fduq67s、cfb53488 均靠人眼发现）。

**方案**（`sfc-semantics.js` + `code-structure-validator.js`）：
- 白名单放行前提收紧为三要素齐备：模板有 `<Tag />` ↔ script 有 import（含 defineAsyncComponent）↔ `package/components/{Tag}.vue` 文件存在；
- 任一缺失 → `CODE-023: dangling-component-tag`（BLOCK，消息指明缺哪一要素）；
- 层①/终验兜底（`_unionTemplateTagSubComponents` + `ensureSubComponentImport`）保证正常路径三要素天然齐备，新门禁只拦异常路径。

**验收**：手工删掉产物中一个 import 或一个 .vue 文件 → 门禁 BLOCK；正常生成不受影响。

### R3-2 CODE-022 修复器（资源 import 未挂载）

**现状**：只检测无修复，BLOCK → 重试 → LLM 常犯同一错。

**方案**：`props-wiring-guard.js` 或独立 util 新增 `pruneUnmountedResourceImports`：
import 了资源变量但模板/脚本零引用 → 确定性删除该 import（与 `pruneDeadSubComponentImports` 对称）。
挂载在 microcode-engineer 落盘终验链（fixMissingClassPrefixes 旁）。

**验收**：构造未挂载 import 产物 → 调用后 import 被删、CODE-022 不再触发。

### R3-3 CODE-011/012 分两步

- 第一步（本方案内）：检测保留，重试指导精确化——把 echarts-init-guard 的诊断文本带上
  「应移入 onMounted/nextTick 的具体语句行号」，提高重试一次通过率；
- 第二步（独立任务）：确定性搬移风险高（上下文依赖），单独立项评估。

## P1 · 结构治本（产生层拒绝错误）

### R1-1 Figma 子树单一归属（planner 层）

**现状**：planner 对同一区域双重解释（`89:37` @antd/tab 壳 + 臆造 `section-main-content`），
出口 `dedupeDuplicateSections` 只是过滤——planner 换个措辞即可绕过 `type|responsibility` key。

**方案**：
- planner 产出每个 section 时携带 `sourceNodeIds: string[]`（归属的 Figma 节点 id 集合）；
- planner 产出后**就地校验**：任一 Figma 节点 id 只能归属一个叶子 section（layout 容器除外）；
  冲突时保留 elementCount 更大者，另一个删除（与出口去重同规则，但发生在产生层）；
- 出口去重器降级为兜底（防 planner 校验被绕过/旧 checkpoint 数据）；
- `tabStructure.panels` 引用的节点 id 也纳入归属图。

**验收**：cfb53488 同款输入重跑，effectiveSections 仅一个 tabs 叶子，且 sourceNodeIds 无交集。

### R1-2 布局事实数据流化（替代命名枚举）

**现状**：规则②豁免靠 `ROOT_SELECTOR_RE`（`-root`→补 `-slot-con`）猜命名。上游每引入新命名，下游枚举必漏——塌陷两次复发的直接机制。

**方案**：
- `buildDeterministicIndexTemplate` 返回值扩展：`{ template, rootContainerClass, sectionRoots }`
  （rootContainerClass = `c-{semantic}-slot-con`；sectionRoots 可从 nameOf map 推导）；
- engineer 将其写入 ctx（`rootLayoutFacts`），向下传递给：
  - `fixSectionHeightsForResource`：豁免清单从 `ctx.rootLayoutFacts.rootContainerClass` 读取，
    `ROOT_SELECTOR_RE` 退役为兜底；
  - `normalizeRootContainerLayout`：同样改读 facts，`detectContentRootClass` 词尾猜测降为 fallback；
- LLM 模板回退路径（无计划 sections 时）：index.vue 落盘后由 detectContentRootClass 提取一次写入 facts。

**验收**：把根容器类改成任意名字（如 `-content-wrap`），规则②与归一器仍正确豁免（不再依赖词尾）。

### R1-3 类名单一事实源 + 修饰符类双向一致不变量（2026-09-11 新增）

**触发**：`260ff122` 非激活 tab 文字被激活态规则污染（`#bacff3` vs 真值 `#2c9bea`）——
`style-class-consolidator` 重写选择器时剥掉 `--active` 修饰符。同日另两例（lazy `</template>` 截断、
资源映射占位 selector 断裂）同主题：同一事实被 4 条变换链各自推导。

**方案**：见 **[P1-类名结构单一事实源-方案-2026-09-11.md](./P1-类名结构单一事实源-方案-2026-09-11.md)**
（含现状链清单 A–E、classFacts 数据流、P1.1–P1.4 分阶段实施、I7 不变量定义、风险约束表）。

**验收**：属性顺序反转结果恒定；全 workspace 干跑变化集合可解释；I7 对存量报违规、新生成 0 error；
重生成 `260ff122` 后非激活 tab 文字 = `#2c9bea`。

## P2 · 防复发基建

### R2-1 机制可达性审计 + 修复时序治理

**现状（2026-09-11 07:40 修正）**：微码 engineer 在 generateCode 内直接消费 CodeFixPipeline
（6012 清洗 / 6061 完整修复，且传 figmaNodeData → anchor-root-container **有注册**），
死代码仅为 `generation-context.js` 包装层（零消费者，可删）。
但 2aa25837 实测 anchor 未生效（common.less 无 height/aspect-ratio，bbox 420×186 正常），
主嫌疑：**修复时序**——anchor 在 fix pipeline 阶段打补丁，之后 `validateAndFixGeneratedFiles`
里的 style-class-consolidator **重建 common.less** → 补丁被覆盖。与「chunk 快照中途正常、
落盘终版坏了」的历史现象同构（规则②注释已记载同类时序放大）。

**方案**：
- **时序治理（核心）**：凡"产物重建类"步骤（consolidator、样式生成）之后的终验链，
  必须重跑布局类关键修复（root-container-normalizer 已在终验链 ✓；aspect-ratio 注入
  需扩展 normalizer 支持 figma bbox，或把 anchor 挪到终验链并适配注入条件）；
- 新增 `scripts/mechanism-reachability-audit.mjs`：从入口（microcode-engineer/vue3-engineer/graphs）
  反查 import 链，不可达的机制文件报告（CI 非零退出）；
- **存量处置**：删除 `src/ai-engine/generation-context.js` 死包装层
  （`anchorRootContainerInFiles` 纯函数保留在 code-fix-rules.js，vue3 侧在用）；
- 待验证任务：在 fix pipeline 打 anchor 补丁后打断点/加日志，确认 consolidator 覆盖路径。

**验收**：重跑 2aa25837 同款输入，终版 common.less 带根容器 height:100%（已由
root-container-normalizer 保证）+ aspect-ratio；audit 脚本输出 0 个不可达机制。

### R2-2 产物不变量回归集

**现状**：每个实锤修完即丢，下次管线改动（如层①改名）可静默破坏旧不变量。

**方案**：新增 `scripts/artifact-invariants.mjs`，对交付组件跑不变量清单：

| # | 不变量 | 来源实锤 |
|---|---|---|
| I1 | 内容根容器 `height:100%`，flex 填充 = 0 | 2aa25837 / cfb53488 塌陷 |
| I2 | 模板标签 ↔ import ↔ 文件 三者双射 | 1fduq67s / 46859f40 |
| I3 | 同 responsibility 的 tabs 叶子 ≤ 1 | cfb53488 双 tabs |
| I4 | 有 Figma 真值时根容器有 aspect-ratio 或显式尺寸 | anchor 从未生效 |
| I5 | 模板 c- 类 ↔ CSS 定义 双射（CODE-020 口径） | P0-6 |
| I6 | 资源变量 import ↔ 挂载 双射 | CODE-022 |

- 接入点：生成完成后自动跑，结果写入任务 meta（TaskDetail 可展示 invariant 结果）；
- 手动模式：`node scripts/artifact-invariants.mjs <componentDir>` 可批量扫描存量。

**验收**：cfb53488 / 2aa25837 修复后全绿；人为破坏任一不变量 → 对应条目红。

## P3 · 流程与运维护栏

### R3-A 契约变更 ADR + 影响面清单

- `docs/adr/` 建目录，资源归属/props 接线/命名规范各立一份 ADR（记录当前结论与理由）；
- 反转类变更（如 P0/D → 本地 import）**动手前**必须产出：
  1. 受影响确定性函数清单（grep 契约关键词生成，本次实为 4 处）；
  2. 需同步更新的 spec 清单；
  3. 回滚点（revert 单 commit 即可回到旧契约）。

### R3-B 版本一致性护栏

- `start-node.js` 启动时打印 `dist` 构建时间 vs `src` 最新 mtime，不一致打 WARN；
- 生成任务 meta 记录代码版本（git HEAD 短 hash + dist 构建时间），TaskDetail 展示
  → 杜绝"旧 dist 生成的产物被当成新代码效果"的误判（cfb53488 即此类）；
- 修复链路纪律（已入 memory）：build 输出必须落盘验证、build 与 commit 分两步跑。

## 明确不做的事

- 不再增加任何"命名约定豁免"（新规则一律走 facts 数据流）；
- 不在出口补丁层为"未见过的错误形态"写防御（防御只针对不变量，不针对模式）；
- 不做 echarts 时序的确定性搬移（风险大于收益，重试指导足够）。
