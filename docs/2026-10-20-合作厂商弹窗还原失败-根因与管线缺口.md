### 2.3 根因：两个判据不同构（memory「同判据 ≥2 份 = 事故温床」再犯）

`src/ai-engine/utils/style-class-consolidator.js:477`

```js
/** 括号平衡校验（防止把残缺块写进 common.less） */
function isBalanced(less = '') {
  let depth = 0;
  for (const ch of String(less)) {
    if (ch === '{') depth += 1;
    else if (ch === '}') depth -= 1;
    if (depth < 0) return false;
  }
  return depth === 0;
}
```

**只数 `{}`，完全不数圆括号。** 而 `less-compile-gate.js:572-580` 数的是圆括号：


`[style-class-consolidator] 合并后 LESS 括号不平衡，已回退（不改动 common.less）`

### 4.1 flex 比例算错（可精确定量）

真值（`796:3 slot-icon` = 604×787，y 相对根）：

| 段       | 节点                       | 真值高 | 真值占比                | **产物 flex** | 偏差           |
| ------- | ------------------------ | --- | ------------------- | ----------- | ------------ |
| 顶部两统计卡行 | `38:3260` + `38:3282` 并排 | 76  | 76/787 = **0.0966** | **0.192**   | **×1.99** 🔴 |
| 战略合作厂商卡 | `38:3137`                | 161 | 0.2046              | 0.204       | ✓            |
| 优质厂商卡   | `38:3162`                | 212 | 0.2694              | 0.268       | ✓            |
| 普通厂商卡   | `38:3206`                | 265 | 0.3367              | 0.335       | ✓            |

**反推模型**：令 `h₁ = 152`（**两张并排卡 76+76 相加**），`Σh = 152+161+212+265 = 790`：

```
152/790 = 0.19240  →  0.192  ✓
161/790 = 0.20380  →  0.204  ✓
212/790 = 0.26835  →  0.268  ✓
265/790 = 0.33544  →  0.335  ✓
```

**四个值全部命中** ⇒ 结论确定：LLM 用 `flex_i = 段高 / Σ段高`，但对**行内并排（row）的子项取了高度之和**，而不是取 `max`。

**危害**：顶部统计卡实际高度 = `0.192 × 787 ≈ 151px`，真值 76px ⇒ 截图里顶部区被撑掉近 2 倍高度，下方三卡被压缩。

**正确算法**：`行内高 = max(子项高)` = 76；`flex_i = h_i / (Σh + Σgap)`。
