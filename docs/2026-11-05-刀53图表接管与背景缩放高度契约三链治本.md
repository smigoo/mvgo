## 3. 根因（四条，均为文件:行号）

### RC1 —— 刀53 判据对 `charts[]` 零感知

`src/ai-engine/utils/folded-grid-section-takeover.js` 全文件检索 `charts / 图表 / 环形 / pie / doughnut`：**零命中**。

判据只看「同构标题行 + 折叠网格」的结构形态。环形图段（标题行 + 两个圆环容器并排）在结构上恰好长得像折叠网格 ⇒ 被判 `kind=table`。

触发点在 `src/ai-engine/roles/microcode-engineer.js:2110`：

```js
const _fgTakeover = collectFoldedGridTakeover({
  treeSections: microcodePrompt.resolvePlanSections(input),
  figmaNodeData: input?.figmaNodeData || null,
  resourceMapping: effectiveMapping || input.resourceDomMapping || [],
  componentName: input?.componentName || '',
  logger: this.logger,
});          // ← 无 charts 入参
```

> 这不是概率问题：同一张设计稿重跑必然再犯。

### RC2 —— 子组件根高度契约无差别加 `height:100%`

`src/ai-engine/utils/style-class-consolidator.js:1097` `ensureSubComponentRootDimensions(files)`：

```js
// 🛡️ 根因 C 修复（2026-09-18）：确保子组件根元素有 width:100%; height:100%。
//    缺失 width/height 时补 width: 100%; height: 100%。
newBody = `height: 100%;\n${newBody}`;      // :1135
```

该规则为「让 echarts canvas 可见」而设（合理），但**无差别作用于所有子组件根**。非图表子组件（如统计卡组）在 column flex 父内 `height:100%` ⇒ 取父全高 ⇒ 吃掉整段。

**同文件已有图表豁免判据可直接复用**：`:1512` `const isChartComponent = /echarts/.test(sfc)`，`:473` `if (b.isChartComponent) return b`。

### RC3 —— 背景缩放被下游无条件覆盖（方案互相推翻）

已实施方案 A（c72bbe2 `background-size-inference#sizeFromScaleMode`）：FILL/CROP→`cover`、FIT→`contain`、STRETCH→`100% 100%`、TILE→`repeat`。

但 `src/ai-engine/roles/layout-style-refiner.js:727-733` `_applyRedLineFixes(modifiedFiles, outputPath, params)` 无条件改写：

```js
background-size: cover    → background-size: 100% 100%
background-size: contain  → background-size: 100% 100%
backgroundSize: 'cover'   → "backgroundSize: '100% 100%'"
删除 background-position: center
删除 background-repeat: no-repeat
```

且 `src/ai-engine/roles/style-refiner.js:310-316` 的 prompt **明文禁止** LLM 写 `cover/contain/center/no-repeat` 并声明「会被自动替换」。

⇒ 方案 A 在上游算出 `cover/contain`，下游又被改成 `100% 100%` 并丢掉 `no-repeat`。这就是 191×82 变 250×370 的机理。

### RC4 —— body 背景补全选错图（且无去重）

`src/ai-engine/roles/visual-parser.js:3326` 策略1：

```js
const pathMatch = availableBgMappings.find(m => {
  const path = m.figmaPath || ''
  return /slot-con|content|body/.test(path) && !/header/.test(path)
})
if (pathMatch) return pathMatch
```

- 入参 `contentNode` **收了却未使用**：与目标节点无关的全局正则，返回**列表第一张**。
- 命中即 return，**绕过策略3 的全部尺寸/比例过滤**（策略3 本可挡住 191×82 的 `h<120 && ratio>2.5`）。
- 上层防线 `_bodyChildrenHaveResources`（`:3383`）只查**直接子节点**、不递归；本单 section 的直接子节点是 `GROUP` 容器，资源挂在孙节点 ⇒ 防线放行。
- 无去重：同一张图在一个 section 内被补 3 次。

## 9. 待裁决项（实施前必须拍板）

**F3 的实现路径受架构约束**：`layout-style-refiner._applyRedLineFixes(modifiedFiles, outputPath, params)` 是**写盘后精修**，只拿到文件内容，**拿不到 per-element 的 `scaleMode` / mapping**。因此「仅在无 scaleMode 时生效」无法按元素自然实现，需二选一：

| 选项 | 做法 | 代价 |
|---|---|---|
| **A1（推荐）** | 在 refiner 实例上构建「本轮有 scaleMode 真值的文件/类白名单」（来源 `buildRefinePrompt(input)` 已入参的 `styleMappings` / resourceMapping），`_applyRedLineFixes` 命中白名单则跳过改写 | 引入实例状态（隐式依赖），需保证在同一 refine 周期内赋值 |
| **A2** | 删掉「cover/contain → 100% 100%」三条改写（保留 center/no-repeat 两条不动） | 等于放弃兜底，LLM 写错就真错；与「精确还原」初衷相悖 |

> 用户已裁决「scaleMode 优先，改写降级」；A1 符合该裁决，A2 是退让。**默认按 A1 实施**，若实施中发现白名单无法可靠传递，回退征询。

### 11.2 F3′：S6 自愈用中性默认推翻了真值（本次新增，实锤）

**证据**：`c-traffic-monitor-e23b0b40` 产物 `DailyFlowStatCards.vue:6,21` 与 `ContentDailyTotalFlow.vue:38` 的
`:style` 为 `backgroundSize: '100% 100%', backgroundPosition: '0px 0px'`。用该单真机 mapping 直跑
`inferBackgroundStyle` 得：

| 资源 | 真值 | 产物 | 判定 |
|---|---|---|---|
| `bg-_m-36.png`（191×80.27 / parent 192×114） | `191px 80px` @ `1px 31px` | `100% 100%` @ `0px 0px` | **被推翻** |
| `bg-_m-35.png`（191×81.27 / parent 192×114） | `191px 81px` @ `1px 30px` | `100% 100%` @ `0px 0px` | **被推翻** |
| `bg-_m-34.png`（425.8×91.4 / parent 同尺寸） | `100% 100%` @ `0px 0px` | `100% 100%` @ `0px 0px` | 一致 |

`0px 0px` 正是 `inferBackgroundStyle({})` 的**中性默认指纹** ⇒ 说明值不是被红线改写，而是
`post-process#ensureBackgroundStyleComplete`（S6，落盘前自愈）**拿到了空 mapping**。
根因：该函数签名 `ensureBackgroundStyleComplete(content)` **只收 content**，
`pre-write-self-healing.js:737` 传的第二个实参 `mapping` 被静默丢弃，补值一律用 `inferBackgroundStyle({})`
⇒ 191×81 的卡片底图被铺满整卡（环形图被拉成巨环，即用户截图现象）。

**修法**：

1. `background-size-inference.js` 新增三个**声明级真值归属**解析器（唯一事实源）：
   `buildBackgroundResourceIndex` / `buildBgVarToResource` / `resolveBackgroundResourceRef`。
   归属锚 = `url(${bg4})` → 同文件 `import bg4 from '.../bg-_m-36.png'` → `resourceFile` 精确命中，
   **不依赖 class 名、不依赖 vision 猜测**。
2. `ensureBackgroundStyleComplete(content, mapping, stats)` 真正使用 mapping；解析不到资源才回落中性默认
   （旧行为，零回归）。
3. 计数位：`summary.bgStyleTruthUsed` / `summary.bgStyleNeutralFallback`（`pre-write-self-healing`
   summary 显式初始化为 0，0 也打）。

**验证**（真机 mapping 直跑）：
`bg-_m-36` → `191px 80px` @ `1px 31px` ✅；`bg-_m-35` → `191px 81px` @ `1px 30px` ✅；
`bg-_m-34` → `100% 100%` @ `0px 0px` ✅（与真值一致）；未知变量 → 中性默认 ✅；
`stats={truthUsed:3, neutralFallback:1}`；不传 mapping 时**逐字等同旧行为** ✅

### 11.3 F3（A1）落地形态

**被护栏的「6 红线」原始行为**（`_applyRedLineFixes`，7 条正则、全部无条件改写）：

| # | 匹配 | 改写 |
|---|---|---|
| 1 | `background-size: cover` | → `background-size: 100% 100%` |
| 2 | `background-size: contain` | → `background-size: 100% 100%` |
| 3 | `backgroundSize: 'cover'` | → `backgroundSize: '100% 100%'` |
| 4 | `background-position: center` | 删除 |
| 5 | `, backgroundPosition: 'center'` | 删除 |
| 6 | `backgroundPosition: 'center',?` | 删除 |
| 7 | `background-repeat: no-repeat` | 删除 |

这 7 条与 `sizeFromScaleMode`（FILL→`cover`、FIT→`contain`、TILE→`repeat`）**互逆**：
只要某资源带 scaleMode 真值，链尾的红线就把真值推翻成拉伸。

**落地要点**：

- 红线改写逻辑**下沉为纯函数** `utils/bg-redline-scale-mode-guard.js#applyBackgroundRedLine`

### 11.6 统计口径补注（与 §5 对照表的差异）
