## 模块 1 · 先认得平台（简要铺垫，不展开）

### P4 平台理念：统一生成 → 在线迭代 → 一键交付

- 统一生成：Figma / 截图 / 需求文档 / HTML 多输入源，一套引擎统一产出
- 在线迭代：生成不是终点，在线编辑 + 大模型交互持续打磨
- 一键交付：下载 / 推 Git（门禁后）/ 对接真实接口，成果落地可用

### P5 核心概念：微码 / Vue3 / 一体化（用之前先认得产物）

- **微码组件（mc-*）**：平台自有轻量组件规范，生成快、约束强、最稳，适合标准化业务组件
- **Vue3 组件**：标准 Vue3 SFC，灵活度高，适合复杂交互 / 接入现有 Vue3 工程
- **一体化组件**：兼容公司一体化平台的组件形态，生成时标注兼容，便于后期纳入一体化体系
- **怎么选**：纯展示 / 标准业务组件 → 微码（最省事）；要复杂交互 / 融入现有 Vue3 项目 → Vue3；目标是一体化复用 → 生成时选"一体化兼容"
- 三者共用同一套"统一生成 → 在线迭代 → 一键交付"管线，区别在产物规范与落地方式

### P6 平台基础架构（简单说明）

> 一句话：输入进得来、引擎生成得了、沙盒看得改、库里存得下、Git 交付得出。

- **① 接入与输入层**：Figma 连接器、页面 / 组件截图、需求文档 / HTML、APIFOX（真实接口）——多类输入统一进管线
- **② 生成引擎层**：Node 后端用多智能体协同完成生成、校验与迭代（平台的"大脑"）
- **③ 工作台与预览层**：Playground（在线改代码的 IDE）+ 隔离沙盒预览 + 快照版本
- **④ 底座与交付层**：共享组件库、GitLab 一键交付、MongoDB（运行态 / 快照）、Java 业务后端对接真实系统
- 关联：生成引擎怎么协同见 P10；Playground 与沙盒见 P13；质量门禁见 P14

### P7 怎么开始：模型池 / 工具配置 + 三种使用方式

- **模型池与三方工具**：Figma 连接器、APIFOX、GitLab、公司 Skills——配置一次，全员复用，不必每人各配各的
- **三种使用方式**：
  - 个人项目：本地 AI（Cursor / Copilot）辅助写码，资产散落个人仓库
  - 团队项目：共享规范 + 平台模板 + 协同评审，资产沉淀团队库
  - 平台（本培训）：统一生成 → 在线迭代 → 一键交付，资产进共享库 + 评分反哺
- **平台上手四步**：登录 → 配 Token / 授权 → 贴输入（Figma / 截图 / 需求）→ 生成

### P8 传统前端开发有哪些事 + AI 如何提效（背景）

> 先看清"前端到底在干什么"，才能说清平台帮你省了哪一步。

| 工作项         | 传统做法（人工为主）               | AI 能怎么提效                     |
| ----------- | ------------------------ | ---------------------------- |
| ① 视觉还原      | 设计稿 → 手写 HTML/CSS，逐像素调   | 按截图 / Figma 直接产出规范组件，省掉逐像素还原 |
| ② 组件 / 页面开发 | 写交互逻辑、状态管理、复用组件          | 生成骨架 + 交互 + 复用库代码，专注业务差异     |
| ③ 数据对接      | 接口联调、请求封装、字段映射           | APIFOX 自动生成接口调用与服务层，字段对齐     |
| ④ 工程化       | 脚手架、构建、CI/CD、lint/format | 生成配置、脚手架、流水线模板，开箱即用          |
| ⑤ 联调与自测     | 前后端联调、单测、调试              | 分析报错、生成单测、定位问题               |
| ⑥ 文档与交付     | 写组件说明、API 文档             | 自动生成组件 / API 文档，与代码同源        |
| ⑦ 性能与体验     | 首屏、兼容性、可访问性              | 给优化建议、自动诊断                   |

- 结论：AI 把 7 类工作里"重复、机械、易错"的部分自动化，人聚焦业务与判断

### P9 优缺点对比：本地 AI vs 团队协同 vs 平台

| 维度    | 本地 AI（个人）  | 团队协同    | 感智晓界工坊平台          |
| ----- | ---------- | ------- | ----------------- |
| 提效幅度  | 个人 +30~50% | 团队一致    | 组织级倍增             |
| 规范一致性 | 低（随人）      | 中（靠约定）  | 高（强制 Vue3/微码）     |
| 资产沉淀  | 无（散落）      | 部分（团队库） | 强（共享库 + 评分反哺）     |
| 交付闭环  | 无          | 部分（手动推） | 完整（门禁 + Git + 接口） |
| 学习成本  | 低          | 中       | 中（一次配置全员复用）       |
| 适用场景  | 个人原型 / 小工具 | 团队常规项目  | 标准化业务组件           |

- 一句话：本地 AI 解决"个人快"，团队协同解决"一致"，平台解决"组织能持续生产"

### P10 平台智能体 vs 公司 MVP154《提示词工程》
> 很多人上过公司 MVP154《提示词工程》——那套思路和本平台不是一个层级，先讲清区别，避免用错预期。

- **MVP154《提示词工程》范式（串型单智能体）**
  - 你写好一个 prompt，单一 LLM 顺序执行 → 产出
  - 质量几乎完全取决于你 prompt 写得好不好：要把"角色 + 任务 + 约束 + 输出格式 + 反面示例"全塞进一段话，靠人反复调
  - 多轮改进靠你手动迭代，模型不会自己挑自己的毛病
  - 局限：一个 prompt 承载所有要求，复杂任务容易顾此失彼，质量上限 = 你的 prompt 水平

- **本平台（多智能体协同）**
  - 不是"一个人写 prompt 让一个模型干"，而是一组专职 agent 分工协同完成生成与校验
  - **同步**：多个 agent 并行做不同事（如视觉解析、布局审查、样式映射同时推进），提速且互相印证
  - **对抗**：有 agent 专门挑刺 / 找漏洞，另有 agent 据反馈自我优化——不是一个人闷头写，而是"互相找茬、互相改"
  - **三角把关**：负责人 / 生成 / 审查分工，生成完有人专门审查，不过关打回重来
  - 质量门禁 L0-B 就是这套"对抗 + 审查"协同的硬落地（不过关直接拦、自动重试修正）

- **对学员意味着什么**
  - 你**不需要像 MVP154 那样精调 prompt**——平台已把"写好 prompt + 多轮评审 + 对抗校验 + 自我进化"固化进管线
  - 你只负责给业务输入（Figma / 截图 / 需求）+ 验收产物

- **一句话收口**：MVP154 教你"怎么让一个模型听你的话"；本平台把"多模型互相挑错、互相优化"工程化成开箱即用的生产能力

## 模块 2 · 怎么用（本次培训重点）

### P11 如何使用①：完整生成（Figma URL → 业务组件）

- **入口**：平台「生成」页，粘贴 Figma 组件 / 页面链接
- **选择产物类型**：微码 / Vue3（按 P5 怎么选）
- **开始生成**：平台按规范产出组件（含 index.vue / styles / declare 等文件）
- **查看结果**：还原度、规范遵循即时可见
- **要点**：首次建议用一个真实、图层规范的 Figma 组件练手；强调"还原度 + 规范"而非"花哨"

### P12 如何使用②：Lite 快速生成

- **入口**：同「生成」页，选 Lite 模式，贴页面 / 组件截图（或 Figma URL）
- **产出**：简单布局 + 基础交互 + 图表，秒级出
- **适用**：后台管理页、数据看板、表单页、图表卡、活动 / 落地页
- **对比完整版**：Lite 快但不重细节；要还原度用完整版
- **要点**：先用 Lite 快速看到效果，再决定要不要升级到完整版

### P13 如何使用③：在线迭代 + Playground / 沙盒

- **Playground 是什么**：平台内置「组件工作台」，VS Code 风格 IDE（Monaco 编辑器，带格式化 + 行号），你 / AI 在这里直接改生成的组件代码
- **AI 对话式修改**：用自然语言说"把背景改成蓝色、加个 tab"，AI 在 Playground 里改代码并实时预览
- **沙盒（为什么敢改）**：组件在隔离沙盒里渲染 / 预览，与宿主、生产环境物理隔离——改坏只影响沙盒预览，不污染平台、不碰生产数据
- **快照 / 回滚**：每次生成与每次手改都留快照，改坏了可回到上一可用版本
- **建议**：小步快改，每次保存即一个新版本，便于对比与回退

### P14 如何使用④：质量门禁（怎么看错 / 怎么修 / 强制预览）

- **是什么**：生成后平台自动跑质量门禁，按「规范 / 样式 / 结构」校验
- **查什么**：组件规范（Vue3/微码/一体化）、LESS 编译、SFC 结构、资源引用合法性（含禁止宿主 Tailwind / 原子类泄漏）
- **结果**：通过 → 可交付；**BLOCK → 拦截并自动重试修正**（重试耗尽则禁止发布，避免劣质产物外流）
- **怎么看错**：报错带 文件 / 行 / 列 + 具体错误 + 代码上下文 + 修复建议，逐条定位
- **怎么修**：在线编辑问题文件 → 保存（新快照）→ 重新校验 → 刷新预览，形成闭环
- **不合格也能预览**：即便门禁未过，也可「强制预览」看效果，先评估再决定改不改
- **提醒**：门禁拦的是「规范 / 可编译」，业务逻辑仍由你确认

### P15 如何使用⑤：一键交付 + 产物集成进项目

- **获取产物**：平台下载 zip，或一键推 Git（门禁通过后）
- **微码怎么用**：按平台组件引用方式，在业务页登记 / 引入组件，传参即可
- **Vue3 怎么用**：把生成目录拷入工程 `components/`，按普通 Vue3 组件 `import` 使用
- **对接接口**：组件内已按 APIFOX 绑定真实接口字段，联调时核对字段即可
- **后续维护**：改样式 / 逻辑回到平台在线迭代，或本地改后重新推送，保持单一来源
- **提醒**：先小范围试点（1 个组件），跑通再推广

### P16 微码学习成本与 AI 配置化（使用时的认知）

- **微码有学习成本（实话）**：declare 声明、样式变量（css-vars）、事件 / 状态、业务配置写法，初次上手不低
- **微码的本质目的**：高复用——一次开发，多页面 / 多业务线引用，靠"配置"适配差异
- **AI 生成的价值：交付的同时把配置能力做进去**（降低门槛 + 提升复用）：
  - 兼容一体化的 em：生成时带上一体化扩展点，便于后期纳入一体化体系
  - 微码深浅主题色：自动注入 css-vars 主题变量，组件天然支持浅色 / 深色切换
  - 动态背景图：背景图做成可配置项，调用方传参即可换
  - tab 入参：把 tab 等可变项抽成组件入参，组件即参数化
- 收口：AI 不只是"生成更快"，更帮你在交付时把"复用该有的配置基线"补齐

## 模块 3 · 答疑与计划（简要）

### P24 数据安全与资产归属（简要）

- **输入**：你提交的 Figma 链接 / 截图 / 需求文档，仅用于本次生成
- **产物归属**：生成的组件归团队 / 公司所有，沉淀进共享组件库，统一治理
- **存储与授权**：走公司平台与已授权服务（Figma / APIFOX / GitLab 均用你授权的 token），不外传第三方
- **涉密提示**：涉密 / 离线页面建议走本地 AI，或脱敏后再生成，不在平台留敏感数据

### P25 常见问题

- Figma 还原度不足：检查设计稿图层 / 规范映射
- Lite 适用边界：简单页用，正式复杂页用完整版（见 P12）
- 组件规范冲突：Vue3 / 微码 / 一体化兼容策略（见 P5）
- 微码学习成本：规范初学不低，但 AI 生成已帮你跨过样板与配置（见 P16）
- Playground / 沙盒：在线改代码的隔离环境，试错都在沙盒里（见 P13）
- 门禁 BLOCK 怎么处理：看行列级报错 → 在线改 → 重校验 → 强制预览（见 P14）
- 接口对接失败：核对 APIFOX 目录与字段
- Git 推送门禁：质量门禁未过先修再推
- 产物怎么用到自己项目：见 P15

### P26 平台计划讨论（含进阶学习路径）

- 回顾平台演进方向（管线可自定义 / 模型路由降成本 / 后端代码生成 / 多规范扩展 / 生态互通 / 自我进化）
- 讨论：各业务线下一阶段诉求与试点意向
- 明确：平台共建方向、资源诉求（X 人周 MVP + 1 个试点业务线）
