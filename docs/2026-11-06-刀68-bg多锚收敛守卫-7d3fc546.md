## 3. 修法（写盘前守卫，用户裁决）

### 3.1 新守卫 `utils/bg-multi-anchor-guard.js`
```js
export function collapseBgMultiAnchor({ files, plan, resourceDomMapping }) → {
  changed: Array<{path, removed: number}>,
  evaluated, multiAnchorHit, collapsed, skipped, reasons

```
**判据（四支，全部确定性；F6/F7 评审补充）**：
0. **前置硬前提（实施前强制验证）**：`resourceDomMapping` 中该 base 的 `figmaNodeId` 集合**必须 =1**。刀44 实锤「去重复用会让同一图片文件同时挂在多个 Figma 节点上」（`icon-3561.png` 双节点）⇒ 若 `image_313` 是多节点复用，**每卡挂载可能是合法的**，本守卫必须跳过（`skipped:multiNodeReuse`）。⚠️ 该 base 的 mapping 节点数未在 7d3fc546 checkpoint 落盘——**实施第一步就是离线探针确认**，确认前禁止动判据。
1. **变量级**：单 `.vue` 内同一资源变量（`bgN`/`imgN`→ `import` 的 `resources/images/<base>`）在 `backgroundImage` 中出现 **>1 处**；
2. **权威锚**（依次降级，命中即用）：
   - a. `resourceDomMapping` 中该 base 的 `ownerSectionId` === 该组件的 section id ⇒ 该组件是合法宿主，但**只允许根元素**持有（mounted class/根 div 的 `:style`）；
   - b. 无 owner 声明 ⇒ 以「带真值四件套（`backgroundSize` 像素或 `100% 100%` + `backgroundPosition`）」的那处为权威（系统注入特征，`microcode-engineer.js:6786` 产物）；
   - **c.（F7 评审补充）2b 路径下若多份都带四件套 ⇒ 无法定权威 ⇒ fail-open 不动**（`skipped:ambiguousAuthority`）。注意 2a 不受刀39 影响（owner 声明与尺寸无关）；2b 仅在无 owner 声明时触达，刀39 补尺寸可能制造多份四件套 ⇒ 由 c 兜底弃权；
   - d. 两支都不成立 ⇒ **fail-open 不动**（宁漏不误伤）；
3. **收敛动作**：权威处保留；其余处**仅剥 `backgroundImage` 键**（保留元素与其它样式），并删同处 `backgroundSize/Position/Repeat`（避免空壳残留）。
   若权威处是「v-for 子项」而根无 —— 视为真值语义为「每项一张」（合法重复），**不处理**（判据 2a 要求 owner 层的根元素，非根时不删）。
