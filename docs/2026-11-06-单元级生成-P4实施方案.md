# 单元级生成 P4 实施方案

日期：2026-11-06 ｜ 状态：方案已查重、范围已由用户确认，尚未实施

## 背景与查重结论

单元拆分快照和 HTML 页级锚点已由 `unit.v2` 契约定义。`unit-contract.ts:11-14` 明确要求 `spec/components.json` 是可重建快照、`spec/unit-state.json` 是独立运行状态；service `project-pipeline.service.ts:218-219` 也注明状态文件留待 P4。查重未发现 `POST /generate-unit` 或 `unit-state.json` 读写实现；memory `2026-11-06.md:898` 记录 P4 未开工。docs 中已有的 fidelity P4 是重构事务单点回滚（`2026-11-06-架构评估-事实树基线四阶段.md:68-97`），主题不同，无直接方案冲突。

用户裁决首版范围：
- 仅支持 `sourceType: 'html'` 的页级单元；其他来源明确拒绝，不回落到全量生成。
- 单元产物写入 `generated/units/<componentId>/...`，和现有全量 `generated/` 隔离。
- 若同一单元已有 `running`，重复请求返回冲突；完成/失败后可再次请求。

## 根因与代码证据

现有 S4 不具备单元隔离：
- `stages/s4-vuegen.ts:1230-1238` 扫描全部 HTML 页。
- `:1249-1304` 将所有页的自定义标签聚合后建立共享组件 registry。
- `:1315-1403` 依遍历顺序编号 `GenViewNN` 并写共享 `s4-meta.json`。
- `project-pipeline.service.ts:3432-3485` 的 `generateVue()` 调用全量 builder，将所有文件写入共享 `generated/`，随后运行 `verifyVueGen()`。

因此不能通过调用 `generateVue()` 后挑选一个文件实现单元生成；那会把跨页组件依赖、顺序编号和共享产物写入混入单元结果。

## 实施设计

### 1. S4 明确单页模式

在 `VueGenOptions` 增加可选的单页目标参数（路径必须是相对 `projectRoot` 的规范化路径），页面筛选发生在组件 registry 聚合之前。全量模式不传参数时保持现有行为。单页模式须确认唯一目标页确实被发现且含可提取的 `#app`，否则失败而非返回空成功。

单页模式接收稳定视图名（由服务使用已验证的 `componentId` 确定性派生），而不是依赖 `GenViewNN` 顺序。组件相对路径、view、meta 中的文件路径与导入必须一致地重映射到该单元命名空间；不能把组件写进共享全量目录。单页模式只处理该 HTML 页，页面标签 registry 只取该页观察值及其组件依赖闭包。保留原 S4 的模板处理、样式/组件生成与 `verifyVueGen()`。

### 2. 生成 service 流程

新增 `generateUnit(runId, componentId, userId)`：
1. 用既有 `resolveRunDir(runId, userId)` 校验运行目录与 owner。
2. 读取并校验 `spec/components.json` 的契约版本、runId、形状；componentId 必须唯一命中。
3. 首版只接受 `sourceType === 'html'` 且唯一 `anchor.pagePath` 非空的单元。路径按 projectRoot 解析后必须仍位于根目录内，拒绝绝对路径、越界路径和缺失/不可读源文件。
4. 读取冻结契约中的 `projectRoot`，调用 S4 单页模式；输出到 `generated/units/<componentId>/`。
5. 仅当单页产物存在且 `verifyVueGen()` 通过才转为 `done`。失败不得返回成功或标记 done。
6. 返回该单元状态、summary、gate 和该单元文件清单；不修改 `components.json` 的任何内容。

### 3. 状态文件模型与并发

`spec/unit-state.json` 独立保存单元状态，以 `runId` 绑定运行，按 `componentId` 存条目。每条至少包含 `status`、`updatedAt`；进入 running 时记录 `startedAt` 和递增 `attempt`；成功记录 `completedAt` 及相对产物路径；失败记录稳定错误码和可诊断但不泄露敏感信息的错误摘要。

状态迁移：初始/未运行 `pending` → 请求接受后 `running` → gate 全通过并写入产物后 `done`；构建、gate 或写盘失败进入 `failed`；failed 可重试到 running。已有 running 请求返回 409。进程内同一 run 的状态读改写必须串行，避免不同单元并发时互相覆盖；不同单元的生成可以并行，但状态文件 merge 更新必须排队。模块增加锁/原子文件写策略前，先按 Node 沙箱 rename 风险核实适用性；禁止未经验证使用临时文件 rename 假定安全。服务重启后遗留 running 不可永久阻塞，首次读取时按明确 stale 规则将旧运行标记 failed（错误码例如 `INTERRUPTED`）并允许重试；阈值必须是有注释的命名常量，不能散落魔法数。

### 4. 接口与错误语义

新增 DTO 校验 `runId` 与 `componentId` 均为非空字符串、长度上限 64。controller 增加 `POST generate-unit` 并单独挂 `SessionGuard`，复用现有 `req.session.userId` 和 HttpException 原样透传模式。

建议业务边界：未知 componentId → 404；重复 componentId 或契约不合法 → 409/422（需实现时统一错误码）；非 HTML / 缺少页锚点 → 422；越界/缺失源文件 → 400/404；同一单元运行中 → 409；S4 gate 未通过或生成/写盘失败 → 状态 failed 并返回失败错误，不得 200 done。

### 5. artifact 可见性

`ARTIFACT_WHITELIST` (`project-pipeline.service.ts:206-222`) 同时驱动 `inspectRun()` 列表和 `readArtifact()` 授权。实现时将 `spec/unit-state.json` 纳入白名单，使调用方可观察状态；状态错误字段不得保存凭证、绝对路径或原始异常堆栈。单元生成目录位于现有 `generated/**` 白名单覆盖范围内，但需确认通配匹配对嵌套 `generated/units/...` 生效。

## 影响面

- `stages/s4-vuegen.ts`：新增单页筛选/稳定 view 名/单元路径命名空间；全量调用零行为变化。
- `project-pipeline.service.ts`：单元查找、owner 校验、生成编排、状态读写、并发与 stale 恢复；`ARTIFACT_WHITELIST` 可见性。
- controller / DTO：新增受保护写端点与请求校验。
- units 模块：新增状态 schema、校验及存储 helper（除非能证明 service 内实现更清晰）。
- tests：S4 单页筛选与 TEXT-TRUTH、service 状态迁移/重试/异常/并发/权限/路径边界、DTO/controller 路由。
- 不影响 scanner 输入、`unit.v2` 契约形状、拆分快照缓存、Figma/screenshot 生成（首版显式不支持），也不修改前端入口。

## 验收判据（假设，须实测）

1. 双页面夹具按一个 `pagePath` 生成时只出现目标页文本、extract、view 与其组件依赖；另一页文本不能借给 gate。
2. 单元 view 命名和目录在加入其他页面/改变枚举顺序时保持稳定；两个 componentId 和全量 S4 产物路径互不相交。
3. `verifyVueGen()` 对目标页文本缺失可拦截；成功路径真实产物 gate pass，失败路径不会 done。
4. `spec/components.json` 字节/哈希在状态变化前后不变；`unit-state.json` 可观察状态迁移及失败重试。
5. 同一单元并发调用中只有一个进入 running，另一个得到 409；不同单元并发状态更新均保留。
6. 日志为每次真实执行输出结构化计数：runId、componentId、pagePath、selectedPages、generatedFiles、gatePass、最终 status；阳性对照实跑 selectedPages=1 且 gatePass=true，错误路径也有非零 failed 计数。
7. `componentId` 未知、非 HTML、锚点缺失、路径穿越、目标文件缺失及 owner 不匹配均按各自错误语义失败。
8. 单元测试使用临时 `PROJECT_RUNS_ROOT`，不写仓库 `data/`；不启动或重启服务。
