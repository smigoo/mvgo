# 段划分覆盖率判据与产物 flex 一致性治理（2026-11-11）

## 三、根因（Phase 2，文件 + 实测数值）

`74722f0f` 的 blueprint（`3-package_index.vue.txt:441` 的 layout JSON）只有 3 段：

| 段 id | name | figmaHeightPx | flexGrow |
|---|---|---|---|
| 2:3550 | `header-` | 33 | 0.28 |
| 2:3438 | 车型分布 | 142 | 1.222 |
| 83:30 | 流量预测 | 174 | 1.498 |

段高合计 **349px**。而同一父级 `cp-流量监测` 下真实存在的 `88:33 slot-当日总流量` 为 **556px，未被任何段覆盖**。

⇒ 覆盖率 ≈ 349 / (556+142+174) ≈ **40%**。

**链路推演**：
1. vision 段划分把 `header-`（33px 标题条）当作「当日总流量」段，漏掉 `slot-当日总流量`（556px）整块；
2. `applyFigmaHeightGrow` 按 33:142:174 归一化算 flexGrow（0.28/1.222/1.498）⇒ **比例只覆盖了 40% 的版面**；
3. prompt 把这份 blueprint 原样下发（LLM 确实拿到了 0.28/1.222/1.498，**不是没给数值**）；
4. LLM 面对 556px 无段承载的空白，自行拆成 `ContentDailyTotalFlow` / `ChartChart` / `ChartChart2`，flex 自拟 ⇒ 0.055（相对 0.689 偏差 92%）；
5. 管线无任何环节校验「产物段级 flex 是否与 blueprint 一致」⇒ 错值落地。

**为什么前 4 轮没根治**：刀53/V14/V-4/A4 全都在优化「段内部的比例计算准确性」，而 **没有任何环节校验「段清单是否覆盖了内容区」**——上游漏了 60% 的版面，下游算得再准也只覆盖 40%。

## 四、修法设计（Phase 3）

### P1 段划分覆盖率判据（新增，核心）

- **判据**：对每个父容器，`Σ(子段 figmaHeightPx) / 父容器内容高度 < 阈值(0.7)` ⇒ 判定段划分不完整；
- **无硬编码**：只用 `absoluteBoundingBox` 几何与段清单的 `figmaHeightPx`，**不认 name**（不写 `slot-` 前缀判定，遵守文本命名无关原则）；
- **单一事实源**：判据函数放 `section-plan-coverage.js`（与 A1 段数比同文件，同属"段规划质量"族）；
- **可观测**：计数行 `🛡️ section-coverage：parent=X covered=Y/Z ratio=R verdict=pass|incomplete`，全量也打。

### P2 未覆盖区域补段（P1 命中时）

- 在父容器子节点中，找出**几何上未被任何段 bbox 覆盖**的业务容器（排除纯装饰/纯文本叶子），按真值盒补成段（带 figmaHeightPx / flexGrow）；
- 只补「覆盖面积占比 ≥ 阈值」的缺口，避免碎片补段把 A1 段数比重新推爆（与 A1 联动：补段后重新过 A1 段数比）；
- 计数行 `🛡️ section-coverage-heal：added=N`。

### P3 产物段级 flex 一致性校验（写盘前 pass，出口侧）

- 以 `data-section-id` 精确对位（S1 已注入锚点），比较产物容器 flex 与 blueprint `flexGrow` 归一化值；
- 相对偏差 > 30% ⇒ **确定性改写为真值** + 计数行 `🛡️ flex-consistency：fixed=N deviated=M maxDeviation=X%`；
- 只处理能精确对位的段；LLM 自拆的、对不上 id 的段不强行改写（留给 P1/P2 从源头解决）。
