## 1. THEME-SLOT-LOCAL-OVERRIDE（4 处）

### 1.1 症状

```
package/components/ContentActive.vue:1   @color-text-inverse: #FFFFFF;
package/components/ContentCons.vue:1     @color-text-base: #333333;
package/components/ContentDefault.vue:1  @color-text-base: #333333;
package/components/HeaderSection.vue:1   @color-primary: #3170aa;
```
（`slotOverrides.length = 4` ⇒ error 条数 4，但 issue 只 1 条：`theme-color-guard.js:692` 只在 `length > 0` 时 push 一次）

### 1.2 病态形态 —— 是**我们的注入器**造的，不是 LLM 写的

LLM 原始分块 `.mc-gen/cache/code-chunks/6-...ContentActive.vue`：
```html
<style lang="less" scoped>
@import '../../resources/styles/index.less';
```
⇒ `<style>` **独占一行**。

终产物 `package/components/ContentActive.vue:26`：
```html
<style lang="less" scoped>@color-text-inverse: #FFFFFF;
```

**唯一生产者链**：
```
file-writer.js:599   applyHealToVueStyleBlocks(sanitizedContent, (css) => injectThemeVarDeclsForLess(css, themeVars))
code-healer.js:1508  injectThemeVarDeclsForLess  →  return `${decl}\n${source}`
code-healer.js:2120  applyHealToVueStyleBlocks   →  return open + healed + close   ← 无换行拼接
```
⇒ `open`（`<style lang="less" scoped>`）后面**直接接** `decl` ⇒ 声明被拼到 `<style>` 同一行。

### 1.3 检测器 vs 自愈器：作用域不等（病灶）

| | 实现 | 口径 |
|---|---|---|
| 检测器 | `theme-color-guard.js:348` `collectFileLevelSlotOverrides` | 先调 `extractStyleText`（L149，用 `/<style\b[^>]*>([\s\S]*?)<\/style>/gi` **剥掉标签**）⇒ 同行字面量变成**第 1 行** ⇒ `line = 1`（与日志逐字吻合） |
| 自愈器 | `theme-color-guard.js:398` `healFileLevelSlotOverrides` → `healStyleContent`（L418） | **逐行扫原文**；L427-429 `enter` 分支命中 `<style ...>` 那一行后 `out.push(line); continue;` ⇒ **L433 的删除判定被完全跳过** |

⇒ **自愈器作用域 ⊂ 检测器作用域**（与已删除的阶段 D `healBorrowedEvidence` 同构）。
自愈器有三个调用点（`code-structure-validator.js:2724` 内存版、`less-variable-checker.js:111`/`527` 磁盘版），**三处都删不掉**。

### 1.4 自证式差分（唯一变量 = 格式）

脚本 `.tmp-verify-e320a641.mjs`，直接 import `dist/` 的真实函数：

```
[A0] 真实产物（字面量与 <style> 同行）   检测器 4 处 · 自愈器 changed=false removed=0 · 复检仍 4 处 ❌
[A1] 只把字面量挪到下一行（其余逐字不变） 检测器 4 处 · 自愈器 changed=true  removed=4 · 复检 0 处  ✅
```

⇒ **唯一差异是「格式」**。检测器对格式不敏感、自愈器对格式敏感。

### 1.5 为什么测试没发现

`theme-color-guard.spec.ts:620-629` 的 fixture：
```ts
'<template>\n  <div @click="onX">a</div>\n</template>\n<style lang="less" scoped>\n@color-text-base: #333333;\n...'
```
⇒ fixture 里字面量**在下一行**。**从未覆盖「与开标签同行」的形态**（正是「测试 fixture 的真值集必须覆盖不含目标值的形态」这条已知复发模式的又一实例）。

### 1.6 治本方向（待确认）

1. **削源 + 兜底双管**：
   - 削源：`applyHealToVueStyleBlocks`（`code-healer.js:2120`）改为 `open + '\n' + healed + close`（保留 `css` 原有前导换行），使注入器不再产出病态格式；
   - 兜底：`healStyleContent` 的 `enter` 分支必须**先做删除判定再 `continue`**（即把 L433-437 的判据抽成函数，`enter` 分支内也调一次，对 `<style ...>` 与字面量同行的情形做**行内切除**而非整行删除）。
2. 必配：新增 fixture「字面量与 `<style>` 同行」；并在**真机产物**上复测（单测样例不含同行形态 ⇒ 是盲区）。
3. 按「删减法」精神：削源之后兜底只处理历史/外部来源，不应成为常态路径。

### 2.2 真正的阻断点 = 注入器自检全量回滚

`roles/microcode/resource-mount-plan.js:249-262`：
```js
const lessGlobalVars = extractLessGlobalVars(allFiles);   // ← 单次快照，取一次
```

### 2.3 变量来源与时序矛盾（根因）

| 变量 | LLM 原始分块 `10-...theme-vars.less` 的 `.common()` | 终态 `theme-vars.less` `.common()` | 谁补的 |
|---|---|---|---|
| `@fontSize` | `@fontSize: 14px;`（字面值） | `@fontSize: var(--fontSize);` | `file-writer.js:836-850` M5-6 归一（**写盘期，早**） |
| `@fontWeightStrong` | **完全没有** | `@fontWeightStrong: var(--fontWeightStrong); // 自动添加（框架预设透传映射，规范形态）` | **`less-variable-checker.js:360`**（**11:50:56.746，晚 13 秒**） |

`FRAMEWORK_PRESET_NAMES`（`theme-color-guard.js:31-40`）含 `fontSize` / `fontWeightStrong`，但**系统主题模板只预声明了 `@fontSize`，没有预声明 `@fontWeightStrong`** ⇒ 后者只能等下游 `less-variable-checker` 补。

而 `common.less` 与各 `.vue` 的 `<style>` **大量引用** `@fontWeightStrong`：
- `common.less:253/274/379/389/442/450/615`
- `ContentActive.vue:70/77`、`ContentDefault.vue`、`ContentCons.vue`、`HeaderSection.vue`

⇒ 11:50:43 那一刻 `lessGlobalVars` 里没有 `fontWeightStrong` ⇒ `validateVueSfc` 判死 ⇒ **96 次回滚**。

### 2.4 自证式差分（唯一变量 = `.common()` 里有没有 `@fontWeightStrong`）

```

```

### 2.5 连锁

```
@fontWeightStrong 未声明
  → 注入器自检 validateVueSfc 失败
  → 全部 bg 注入回滚（96 次）
  → bg1/bg2/bg3 只 import 不挂载
  → CODE-022 ×3
  → L0-B 硬闸 BLOCK → 重试
  → 每轮 theme-vars 仍由 LLM 重生成、仍缺 @fontWeightStrong（补全永远在最后一步）
  → 三轮逐字同错 → 重试耗尽 → fail-closed
```

### 2.6 次要成因（并存，非主因）

- `{"reason":"mount-target-not-found","file":"ContentCons.vue","var":"bg3","mountTarget":"cons"}` ×2
- `{"reason":"container-state-root-miss","file":"ContentActive.vue","var":"bg1"}` ×1
- `{"reason":"mount-target-not-found","file":"HeaderSection.vue","var":"icon1"}` ×1
  ⇒ fail-closed（设计如此），bg3/bg1 被明确放弃。
- `runPreWriteSelfHealing`（`microcode-engineer.js:7478`，方案 E 落盘前自愈链）**在日志里没有任何一条它的条件日志**。注意：**该函数所有日志都在 `changed` 分支内，没有无条件入口日志** ⇒ 「无日志」**不能**反推「未执行」，此项**存疑待验**（需离线重放确认）。

### 2.7 治本方向（待确认）

1. **消除时序依赖（首选）**：把 `@fontWeightStrong`（以及 `FRAMEWORK_PRESET_NAMES` 全集）**预声明进系统主题模板**（`buildStyleTokens` / `renderMicrocodeThemeVarsLess` 的 `.common()`），与 `@fontSize` 同源同寿命 ⇒ 自检与世界态一致，不再依赖下游补全。
2. **或**：`writeGuarded` 的判据改为「**只校验本次注入引入的新错误**」（对 `original` 与 `updated` 各跑一次 `validateVueSfc`，仅当 `updated` 新增错误时才回滚）⇒ 对「预先存在的变量缺失」免疫。
3. **或**：`mountPlannedResources` 前先跑一次 LESS 变量补全（把 `file-writer` 的补全步骤前移），使自检上下文与最终态同源。
4. 无论选哪条：**`theme-vars.less` 由系统确定性生成，不应让 LLM 重写**（其文件头已写「系统确定性生成；§3 核心槽位值由 buildStyleTokens 注入，勿手改」）。
