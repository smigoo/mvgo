## 2. 根因（证据链）

1. LLM 把 footer 文案拆成多 span：`<span>共</span><span> </span><span>6</span><span> </span><span>个节点</span>`。产物文件 `temp-components/6a51f7caed28c5d5b13c61a5/mc-max-1793902330765-7d3fc546/package/components/ListSection.vue:43-46`。
2. `text-truth-guard.js:370 extractRenderedText` → `extractTemplateText` 用 `tpl.replace(/<[^>]*>/g, ' ')`（**每个标签边界退化为一个空格**，`text-truth-guard.js:388`），抽取结果为 `共  6  个节点`（多空格）。
3. 真值文本来自 Figma（`analysis.json` effectiveSections：`footer.body.children[].name = "共6个节点"`、`"接入设备10810"`），**无空白**。
4. 比对点 `section-content-guard.js:1480 if (!renderedText.includes(text)) continue;` ⇒ `"共  6  个节点".includes("共6个节点") === false` ⇒ 借据判据静默跳过。
5. duplicateText 判据同源（`:109` 的 `renderedText` 字段供 `:54/:140/:272` 三处 `includes`）⇒ 同样失明。
6. 刀53 接管的合法那一份（`ContentSection.vue`）走 `{{ runs[0].text }}` + script 数据 `"共 6 个节点"`（真值带空格、模板被 `{{}}`→空格替换），与无空白真值同样对不上 ⇒ **双向失配**，不是「谁对谁错」问题。

**结论**：判据逻辑正确，输入比对口径对空白敏感 ⇒ 跨 span 拆词 + 真值无空白场景 100% 失明（真机复现：本单 `borrowedTextIssues=0`、`duplicateTextIssues=0`）。

## 3. 修法（单一出口，不改 extractRenderedText 本体）

### 3.1 新增归一出口（`text-truth-guard.js`）
```js
/** 比对用归一：去所有空白（含全角空格 U+3000）、零宽字符、BOM；不做大小写/繁简变更。 */
export function normalizeForMatch(s) {
  return String(s || '').replace(/[\s\u3000\u200b-\u200d\ufeff]/g, '');
}
```
**为什么不改 `extractRenderedText`**：`section-content-guard.js:354` 用它判「模板渲染文本是否为空壳」，归一会改变空壳语义（空白串归一后为空仍是空，但含零宽字符的假文本会被判空——属行为变更）。按最小影响原则：抽取函数不动，只改**比对点**。

### 3.2 比对点改造（4 处，全部同一出口）
| 位置 | 语义 | 改法 |
|---|---|---|
| `section-content-guard.js:1480` | 借据判据「该文本是否被渲染」 | `if (!normRendered.includes(normalizeForMatch(text))) continue;` |
| `:54` | duplicateText 的 hostCount | 归一后 includes |
| `:140` | duplicate 判据 expected 命中 | 归一后 includes |
| `:272` | duplicate owner 定位 hostFiles | 归一后 includes |

（`:354` 空壳判定**不改**，保持原口径。）

### 3.3 healing 粒度（用户裁决）
`healDuplicateTextIssues` / 借据 healer 命中后：
1. 定位命中文本的**最外层连续文本容器**（父级 inline 容器，如 `.node-footer`；判据=该容器归一后文本包含命中文本且不含兄弟段其它真值文本）；
2. 删除该容器整块（不删单个 span，避免碎词残留）；
3. 删除后跑 `validateSfc`（既有入参），不可编译 ⇒ **回滚该文件**并留痕计数；
4. 无法唯一定位容器 ⇒ 只留痕不删（宁漏不误伤，沿用模块铁律）。

## 4. 判据与观测（假设，以真机为准）

### 4.1 healing 硬护栏（F2 评审补充，三重护栏缺一即只留痕不删）
1. 目标容器**不得是组件根元素**（`<template>` 直接子级）；
2. 目标容器**不得是带 `data-section-id` 的元素**（段身份载体）；
3. 目标容器必须是**纯文本容器**（直接子节点均为文本/span 类 inline 节点，无 img/chart/业务子组件）。
不满足 ⇒ `skipped:noSafeContainer` 计数留痕，不做删除（宁漏不误伤）。

### 4.2 灰度标记（F4 评审补充）
