## 4. 治本方案（评审修订 v2：消灭补丁式修复点）

> ⚠️ 评审结论：v1 的 M1「写盘前剥除守卫」本质是第 31 个补丁——在产物上做字符串手术，
> 违背「修复点在问题产生处/统一判据源」。v2 把两个修复点分别上溯到**真值判据**与**评分单一事实源**。

### M1（v2）背景真值判据推广：无来源背景一律不合法

- **不再新增「图色互斥剥除守卫」**，而是把既有 `container-background-truth` 的管辖从「容器背景」推广为**全元素背景单一判据**：
  产物中任何 `background` / `background-color` / `linear-gradient` 声明，必须能在该节点（或其样式归属节点）的 Figma 真值 fills 中找到来源（色值/渐变/透明）；
  **无来源 = 臆造 → 剥除并计数**；有 IMAGE 填充的节点，其色值/渐变真值视为「已被图片承载」，同样不构成产物写底色的合法来源。
- 真机依据：本单 `.checkpoint/analysis.json` 中卡片区真值仅 `bg: bg-126 backgroundBlock`，无任何 gradient → 渐变属臆造，正中此判据。
- 判据唯一、双端共用（container-background-truth 已被刀32/刀37/panel-chrome 共用，推广时三处调用点全量回归）。
- 计数行：`bgTruthlessStripped=N`（选择器+写入文件留痕）；`transparent` 豁免保留。
- 登记守卫总纲：不新增条目，更新既有 container-background-truth 行的管辖描述。

### M2（v2）挂载点评分排除文本叶子（mount-target-scoring 单一事实源）

- 修复点不在挂载函数（`microcode-engineer.js:6448` 只是执行器），而在**评分函数** `utils/mount-target-scoring.js`：
  候选节点为文本语义（tag 为 span/p/strong/em 等文本叶子，或对应 Figma 真值 type=TEXT）→ **直接移出候选池**（不是降权，是排除）；容器候选耗尽时才允许 fail-open 跳过并计数。
- 评分函数本可单测 → 阳性对照：构造「span 候选 vs div 容器候选」样本，断言 span 永不中标。
- 计数行：`bgMountTextExcluded=N`（被排除的文本候选数）。
- 与 D1 per-card 改写共用真值源，不复制口径。

### M3 prompt 反向禁令（不变，仅减量）

- `prompts/engineer/shared/root-container.md` / `resource.md` 增：「元素已分配背景图资源时，禁止再写 background/background-color/渐变；底色已由图片承载」。
- M3 不是裁决，裁决由 M1 真值判据兜底。
