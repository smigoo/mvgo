## 三、缺陷清单（逐条附证据）

### D1｜列表折叠只保留第一行：12 → 3、15 → 4（**最严重**）

**真值**：`38:3162` 下 3 个行容器、`38:3206` 下 4 个行容器。

**section-tree 实际产出**（`analysis.json` → `subComponentPlan.effectiveSections`）：

```
38:3162 '优质厂商'  children = 2 个
  ├ 38:3162-tail-text  (header, elems=1)
  └ 38:3167-list  (type=list, layout=grid, collapsed=true, elems=3, src=38:3167..38:3179)
       └ 38:3168-list (type=list, 内含 38:3169 / 38:3170 = 名称+数量)
  ← 行容器 38:3180、38:3193 完全消失（仍在 38:3162.src 里，但没有对应段）

38:3206 '普通厂商'  children = 2 个
  └ 38:3211-list (elems=4)  ← 行容器 38:3224 / 38:3237 / 38:3250 全部消失
```

**双重折叠**是根因：
1. 外层：4 个行容器被当作「重复 item」折叠 → 只留第 1 个当模板，**其余 3 行直接丢弃**（不是「list 段代表所有行」）。
2. 内层：模板行容器（如 `38:3167`）内部的 4 张卡又被折叠成 `38:3168-list`。
3. 结果：`38:3167-list` 只承载「第 1 行的卡」，且 `elems` 记成 3（真值 4）。

产物数字完全对得上：`ListList.vue` 3 项 = 第 1 行 3 卡；`ListList2.vue` 4 项 = 第 1 行 4 卡。

**这一条同时解释了用户看到的「三个 section 样式不一致」**：战略段残余 2 个段（行1 + 行2），优质/普通各余 1 段 —— 三段自然长得不一样。

- 缺陷层：`utils/section-tree.js` 重复兄弟折叠（`deriveNestedSections`）+ 列表段识别（模板节点选择）
- 待修判据：**折叠必须保留「所有被折叠兄弟」为同一 list 段的 items 全集**；「行 → 卡」两层重复不得只折一层。判据可证伪：折叠前后 `Σ items` 必须等于真值卡片数根数（12 / 15 / 6）。

### D2｜战略段标题重复 + 尾部 2 项重复

```
index.vue L18  <HeaderText/>        → components/HeaderText.vue  data-section-id="38:3137-tail-text"
index.vue L19  <ContentSection7/>   → data-section-id="38:3137"（与外层 div 同 id）
                                      模板里又自带一个 <span class="c-e3ab04-header-title-text">{{ title }}</span>
index.vue L20  <ContentSection8/>   → data-section-id="38:3153"  渲染 浪潮信息 / 天地伟业
```

- `ContentSection7.vue` 根 `data-section-id="38:3137"` **与外层 `<div data-section-id="38:3137">`（L17）同 id** —— 这是刀 36（自嵌套折叠）的目标形态，但本轮没触发：父 div 的「内容」不是被组件 I 完全覆盖（父里还有 HeaderText / ContentSection8 两个兄弟），所以 `surfaceCovers` 判据不成立。
- `ContentSection7` 已把 6 项全部渲染（4 列 × 2 行 grid，写法正确），而 `ContentSection8` 又渲染 `38:3153` 的 2 张卡（浪潮信息 / 天地伟业，即全局第 5、6 项）⇒ **这 2 项重复出现两次**。
- 根因：`38:3153`（行2，仅 2 卡，宽 272）没有被并入行1 的列表段，而是被当成平级段独立成组件。与 D1 同源（行容器没被聚合）。

### D3｜`38:3140` 被标成 `grid` 又在内部套 `list`

```
38:3137 '战略合作厂商' children = 3
  ├ 38:3137-tail-text (header)
  ├ 38:3140  (elems=3, layout=grid)
  │    └ 38:3141-list (type=list, collapsed, 内含 38:3142 / 38:3143)
  └ 38:3153  (elems=6, layout=horizontal)
```

同一个视觉层级的两个行容器被判定成两种不同东西（一个 `grid` + 内嵌 list，一个 `horizontal` 直接当容器），所以 `ContentSection7` 与 `ContentSection8` 必然长得不像。这是 D1 的同一处判据在「行容器数量不足 4」时走到了不同分支。

### D4｜卡片底色用通用语义槽位，丢掉三段各自主色

```
ListList.vue  .c-e3ab04-frame-2136639905 { background: @color-bg-list-item; }        ← 应为 #f6fff7
ListList2.vue .c-e3ab04-list-list2-row   { background: @color-bg-card-normal; }      ← 应为 #f2fdff
ContentSection7.vue .c-e3ab04-strategic-cell { background: #fffdf1; }  ✓ 唯一对的
```

真值三段卡片底**各不相同**且**不是白色**（`#fffdf1 / #f6fff7 / #f2fdff`），是各自面板主色的极浅同色系。用 `@color-bg-list-item` / `@color-bg-card-normal` 这类「通用语义槽位」表达，等于把三层结构压成一层语义 —— 与 memory 记录的「陷阱：语义推断槽位 ≠ 真值」同一类错。

### D5｜`.c-e3ab04-strategic-cell` 两份副本、圆角值不一致

| 位置 | 声明 |
|---|---|
| `resources/styles/common.less` L112-118 | `min-height:24px; background:@color-surface-1; border-radius:**6px**; cursor:pointer; flex:0 0 auto` |
| `package/components/ContentSection7.vue` scoped | `width:126px; height:30px; padding:0 6px; background:**#fffdf1**; border-radius:**2px**; …` |

这正是 memory「同判据 ≥2 份 = 事故温床」的实例。`style-conflict-detector.js` 只报不改，没拦住。

### D7｜统计卡 1 的背景与边框是臆造（卡 2 已被刀 37 修对，卡 1 漏掉）

**产物**（`common.less`）：

**为什么 N1 也没拦住**：`truth-color-usage-guard` 判据②「纯色才判、渐变跳过」⇒ 卡 1 是渐变 + 渐变描边，全跳过。

> 顺带一个**真值本身的缺口**：`38:3261` / `38:3283` 的 `gradientHandlePositions` 是 `null`，即方向不可知。`fillsToCss` 在缺 handle 时默认给 `180deg` —— 卡 2 那个 `180deg` 就是这样来的，**不可证**。真值缺方向时应显式标记 uncertain 并降级（不给渐变、或给最保守表达），不能静默硬猜。

### 9.4 两种「循环」要分清

| | A. 样式单源（不循环 DOM） | B. 段级 v-for（循环 DOM） |
|---|---|---|
| 做法 | 识别同构段 ⇒ 收敛成 1 份样式模板 + 每组色 1 个 CSS 变量 | 1 个 `XxxSegments.vue` + `segments[]` 数据，`v-for` 渲染 N 段 |
| 组件数 | 仍 3 套 | 6 个组件（3 标题 + 3 列表）→ **1 个** |
| 解决 | 视觉不一致（颜色/间距） | 视觉不一致 + 代码重复 + **生成期再分歧** |
| 风险 | 低（不动结构） | 中（两层 v-for / 槽位丢失 / 末行窄） |

**根因是 B 侧**：三次独立生成，每次都重新决策布局，必然分歧。A 只是把分歧收口到变量，
下一次生成仍可能再分歧。⇒ **推荐 B，但必须带强约束与逃逸口**。

### 9.5 落地方案（B）

**第一阶段 · 布局层识别（planner）**

对「同级兄弟 section」算结构签名（**不含颜色、不含文案、不含行数**）：
`面板 RECT+radius` / `icon 尺寸+x` / `标题 fontSize+weight` / `卡 WxH+radius` / `列距+行距`。
签名全等且 N≥2 ⇒ 产出 `repeatGroup`：

```js
{
  kind: 'segment-repeat',
  signature: { panelRadius:12, iconSize:[16,16], cardSize:[126,30], radius:6, gap:[50,20] },
  slots: ['title', 'icon', 'panelBg', 'glowColor', 'glowAlpha', 'cardBg'],
  segments: [
    { title:'战略合作厂商', icon:icon1, panelBg:'…', glow:['#ffc800',1],   cardBg:'#fffdf1', items:[…6] },
    { title:'优质厂商',     icon:icon2, … items:[…12] },
    { title:'普通厂商',     icon:icon3, … items:[…15] },
  ]
}
```

**第二阶段 · 代码生成**：一个 `VendorSegment.vue`（段内再一层 `v-for` 渲染 items）：

```html
<div v-for="seg in segments" :key="seg.title" class="seg"
     :style="{ '--seg-bg': seg.panelBg, '--seg-glow': seg.glowColor }">
  <div class="seg-head"><img :src="seg.icon"/><span>{{ seg.title }}</span></div>
  <div class="seg-grid">
    <div v-for="it in seg.items" class="seg-card" :style="{ background: seg.cardBg }">…</div>
  </div>
</div>
```

容器必须是（**这是唯一正确的布局契约**，三段共用）：

```less
.seg-grid { display:flex; flex-wrap:wrap; gap:20px 20px; }   /* 列距 20 / 行距 20 */
.seg-card { flex:0 0 126px; height:30px; border-radius:6px; } /* 定宽定高，末行自然变窄 */
```

> 🔴 **勘误（2026-10-21 18:50，刀 41 按真值复算）**：本节初版写 `gap:50px 20px`（行距 50），**错的**。
> 真值 y = `51830 / 51880 / 51930` ⇒ **行 pitch = 50**，卡高 30 ⇒ **行距 = 50 − 30 = 20**。
> 把 pitch 当 gap 会让行间距变 80px。**列距 20 / 行距 20，两轴相等。**
> 另：走 grid 时正确写法是 `grid-template-columns: repeat(4, 126px)`（**固定列宽**），
> `repeat(4, 1fr)` 只在「每行都满」时碰巧等价（12 项=满 ⇒ 等价；15 项末行 3 卡 ⇒ 拉宽）。

> ⚠️ 不能用 `grid-template-columns: repeat(4, 1fr)`：末行 3 卡/2 卡会被拉伸填满，
> 违反真值（418 / 272 宽）。**`flex-wrap` + `flex:0 0 126px`（或 grid 固定列宽）才能自然产生「末行更窄」。**

**逃逸口（必须有）**：出现下列任一 ⇒ 不循环，退回独立组件
- 结构签名任一项不等（如某段卡尺寸不同、多一个角标）
- 槽位差异超出 `slots` 白名单
- 某段 items 为空

### 9.6 风险清单

| # | 风险 | 对策 |
|---|---|---|
| 1 | 两层 `v-for`（段 × item）易混淆，LLM 常把 item 层写成静态 | 沿用 `_vforData` 段内通道经验，段级另开 `_segments` 白名单字段 |
| 2 | 槽位（`panelBg`/`glow`）在多层解构中被静默丢弃 | 记忆铁律「加新入参必查下游每层解构 + 白名单/initialState」 |
| 3 | 4 组色 × 3 段 × light/dark 两套 = 24 个值 | **必须走 CSS 变量 + 主题层两套值**，不得写成字面量（否则 dark 无法切换） |
| 4 | 用 grid 固定 4 列 ⇒ 末行被拉伸 | 明确 `flex-wrap + flex:0 0 126px`（见 9.5） |
| 5 | 识别过度：把「只是长得像」的不同组件硬套循环 | 签名必须逐项相等、且差异只在白名单槽位 |

### 9.7 建议顺序

1. ✅ **已完成**：§8.3-③ 的「同属性重复声明」消歧（刀 40）——直接解决「12 项全在却看着没修」；

### 11.2 真值来源与契约（纯几何、命名无关）
