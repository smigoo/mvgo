# Figma 结构整理规范（自动插件侧）

> 版本：v2（2026-11-14） 定位：**插件只做本地结构化整理，不连生成管线**
> 目标：整理出来的 Figma 结构能被生成管线**几何判定一次到位**，也便于人工阅读与后续维护
> 关联：[`2026-11-14-布局真值整治方案.md`](./2026-11-14-布局真值整治方案.md)（判据侧）

---

## 零、一句话原则

> **一个语义段 = 一个容器；容器内保留"层级"，不要扁平化；重叠关系靠 z 序，不靠挪位置。**

管线的布局判定只吃几何（bbox + 父子 + 类型），不吃图层命名，所以整理的目标不是"名字好看"，而是**层级边界正确**。

## 一、现状 vs 推荐（用「流量监测」真机对照）

### 现状（插件整理后）

```
cp-流量监测
├─ header-                 面板标题行
├─ bg-[m]                  整块背景
└─ slot-con
   ├─ 0sub-header   (30)   ← 「当日总流量」标题 + 24小时下拉
   ├─ 1统计         (91)   ← 两张统计卡 + 中间装饰图
   ├─ 2charts      (131)
   ├─ 3charts      (131)
   ├─ 4sub-header   (24)   ← 「车型分布」副标题
   ├─ 5cards       (114)   ← 车型分布卡
   ├─ 6sub-header   (24)   ← 「流量预测」副标题 + tab
   └─ @echarts/line-7 (141)
```

**问题**：每个语义段被拆成 2 个兄弟节点（标题条 + 内容块）。管线必须靠"几何相邻 + 未认领"把标题条并回段（已实现 `2e761b69`、`bde60c07`），但这条链更脆弱：

| 现象 | 管线代价 |
|---|---|
| 段锚点落在标题条里（`2:3559` h=24） | 段高只有 24px ⇒ 内容块被"饿死"（本次事故） |
| 副标题条是兄弟 | 标题不进段 ⇒ 副标题消失、tab 兜底注入到组件根 |
| 段与段之间靠 slot-con 平铺 | 只能靠 `column-stack` 逐项 margin 表达，溢出风险高 |

### 推荐（段容器优先）

```
cp-流量监测
├─ segment.panel-header     面板标题行（含 *数据实时更新）
├─ bg-[m]                   整块背景
└─ slot-con
   ├─ segment.daily-total-flow
   │   ├─ header    (30)     标题 + 24小时下拉
   │   └─ body      (91)     两张统计卡 + 中间装饰图（保留重叠）
   ├─ segment.tunnel-chart    (131)
   ├─ segment.bridge-chart    (131)
   ├─ segment.vehicle-dist
   │   ├─ header    (24)     车型分布
   │   └─ body      (114)    两张卡
   └─ segment.forecast
       ├─ header    (24)     流量预测 + tabs + 节假日预测
       └─ body      (141)    面积图 + 图例/装饰
```

**收益**：
- 段锚点 = 段容器（高度天然正确，不再需要"并集上溯"兜底）
- 标题条在段内 ⇒ 标题不丢、tab 有正确落点
- 每段结构可独立判定（row / between / overlay），互不干扰

> ⚠️ 兼容性：**不要求**一次到位。管线对"现状（兄弟结构）"已做兜底；"段容器"结构能让判定从"多判据修补"变成"一次命中"。

## 二、整理规则（12 条，每条带理由）

### A 分组粒度

| # | 规则 | 为什么 |
|---|---|---|
| A1 | **一个语义段 = 一个容器**（标题条与内容区同属该容器，至少同属一个父级下的 `header`/`body` 两层） | 段识别以容器为锚点；标题条作子层能被确定性识别为 header |
| A2 | 段与段之间**不要合并**到同一个 Group | 合并后段高、段间距全部失真，只能靠 LLM 猜 |
| A3 | **不要扁平化**：保留中间层（`header` / `body` / 卡片行） | 中间层是几何边界；扁一层，结构判定就退化为 `unknown` |
| A4 | 重复卡片保持**同构**（同层级、同类型、尺寸一致） | 同构是 `grid`/`list` 判据的基础；不同构会被判成"自由摆放" |

### B 几何表达

| # | 规则 | 为什么 |
|---|---|---|
| B1 | **重叠装饰必须保留在原位**（统计区中间图形、图表图例/装饰） | 重叠是 `free-overlay` 的证据；删掉会被判成 `row`，两块内容被并排摊开 |
| B2 | 重叠关系用 **z 序（图层顺序）** 表达，不要"挪位置避开重叠" | 挪走后几何变成并列，结构判定随之改变 |
| B3 | 容器尺寸**固定**（不要 hug contents），子项 constraints 明确 | hug 会让导出尺寸随内容漂移，与服务端拉取的 bbox 不一致 |
| B4 | `clipsContent` 按设计意图设置（面板容器一般 true） | 否则溢出内容参与判定，`overflow` 标记失真 |

### C auto layout

| # | 规则 | 为什么 |
|---|---|---|
| C1 | **要么真用 auto layout，要么完全自由摆放，不要混用** | 真机 2/6 容器 `layoutMode` 与几何不一致（`2:3660` 标 HORIZONTAL 但子项重叠）；管线只能用几何，mode 只作交叉验证 |
| C2 | 用 auto layout 时：间距走 `itemSpacing`（统一值），不要用逐项 padding 模拟间距 | `itemSpacing` 是唯一可读的间距真值；逐项 padding 读不出"结构" |
| C3 | 用 auto layout 时不要手动拖动子项（会破坏 mode 与几何一致性） | 同上，混合状态是最坏情形 |

### D 命名（**仅人类可读，不承载语义契约**）

| # | 规则 | 为什么 |
|---|---|---|
| D1 | 不要用 `slot-<段名>` 这类"名字即契约"的约定 | 管线已改为几何判据；命名一旦被当契约，改名就会整体失效（本次事故的直接诱因） |
| D2 | 推荐命名模板（可读、可排序、不参与判定） | 便于人工排查与设计协作 |

```
segment.<英文短名>          例：segment.daily-total-flow
segment.<英文短名>/header   例：segment.vehicle-dist/header
segment.<英文短名>/body     例：segment.vehicle-dist/body
card.<序号>.<名称>          例：card.01.客车
decor.<名称>                例：decor.center-graphic
bg.<名称>                   例：bg.panel
```
> `segment.` / `header` / `body` 前缀**不参与任何判定**，只用于阅读。

### E 文本与资源

| # | 规则 | 为什么 |
|---|---|---|
| E1 | 文本必须是 **TEXT 节点**（不要轮廓化/转图片） | 转图后文案真值丢失，产物只能编造 |
| E2 | 多行文案用"单个 TEXT + 固定宽度 + auto height"，不要用回车拼多行 | 换行由排版引擎决定，服务端能算出行高 |
| E3 | 装饰图用**容器的 image fill**，不要同时再放一个 `<img>` 节点 | 否则资源被注册两次（一次背景、一次图标），产物可能双图或丢图 |
| E4 | 图标统一走同一图层类型（`VECTOR` / `IMAGE fill` 二选一） | 混用会让资源映射判据分叉 |

## 三、Auto Layout（mode）整理规范

> 前提：生成管线**只吃几何**，`layoutMode` 仅作交叉验证。但 mode 标对有两件实际好处：
> ① 插件整理可重复执行（幂等）；② 设计侧再改动时结构不会漂移。
> 反过来说：**mode 标错不影响生成结果，只要几何是对的**。

### 3.1 先判"该不该有 AL"（不要凭手感）

| 几何事实 | 该用什么 | 说明 |
|---|---|---|
| 子项沿一条轴排列、两两不重叠、间距齐次（极差 ≤2px） | **AL + itemSpacing = 间距众数** | 典型：tab 行、卡片行、label+value 行 |
| 子项沿一条轴排列、不重叠、首尾贴容器内缘、中间弹性 | **AL + SPACE_BETWEEN**（不设 itemSpacing） | 典型：标题左 + 下拉右、副标题 | tabs | 按钮 |
| 子项有**任何重叠**（相交 >2px） | **不要 AL**（用普通 Frame 自由摆放） | AL 无法表达重叠；硬设会把内容摊平（真机 `2:3660` 就是这么错的） |
| 子项二维网格（行列都齐） | AL + `layoutWrap: WRAP`，或自由摆放 | Figma 无 grid AL |
| 只有 1 个子节点 | **不需要 AL** | 无排布语义 |

### 3.2 AL 参数怎么设（易错清单）

| 参数 | 正确做法 | 常见错误 |
|---|---|---|
| `itemSpacing` | 统一值 = 几何间距众数 | 用透明 spacer 节点模拟间距（读不出"结构"） |
| `padding*` | 用 AL 的 padding 属性 | 用一块空白节点当 padding（会被当成子项参与判定） |
| `primaryAxisAlignItems` | MIN / CENTER / **SPACE_BETWEEN** / MAX 按几何选 | 两端对齐却写 MIN + 固定 gap |
| `counterAxisAlignItems` | 起点对齐→MIN；居中→CENTER；拉伸→STRETCH | 全部沿用默认 MIN |
| `primaryAxisSizingMode` / `counterAxisSizingMode` | 面板容器 **FIXED**；内容自适应才 HUG | 面板用 HUG ⇒ 导出尺寸随内容漂移 |
| 子项 absolute | **不要和 AL 混用** | AL 容器里放 absolute 子项 ⇒ 几何上出现重叠，整段被判 `free-overlay`，AL 语义全废 |

### 3.3 铁律：设 AL 不能改变几何

设 AL 会让 Figma 重新排版。**必须先算后设，设完复核**：

```
1  读子项 bbox 快照
2  按 3.1 判定 + 按 3.2 设置 layoutMode / itemSpacing / align / sizing
3  重新读子项 bbox，与快照逐项比较
4  任一子项偏移 > 1px 或尺寸变化 > 1px  ⇒  撤销（说明这组本来就不符合 AL），回退自由摆放
```

这条防的是"为了整洁把结构排歪" —— 比"没有 AL"更糟。

### 3.4 流量监测：6 个容器的 mode 应该怎么设

| 容器 | 几何事实 | 现状 mode | **应设为** |
|---|---|---|---|
| `1744:125` slot-con | 8 段纵向、间距不齐 `7/0/10/14/4/15/10` | null | **不加 AL**（保持自由摆放；若强行 VERTICAL 会把不齐的间距抹平） |
| `88:32` 0sub-header | 一行、首尾贴边 | null | `HORIZONTAL` + **SPACE_BETWEEN** |
| `2:3566` @antd/tab | 一行、间距 8 | HORIZONTAL | `HORIZONTAL` + `itemSpacing 8`（对齐：CENTER） |
| `2:3660` 1统计 | 两卡 + 中间图形**重叠** | HORIZONTAL | **删掉 AL**（改为自由摆放）← 目前是错的 |
| `2:3439` 4sub-header | 一行、间距 4 | null | `HORIZONTAL` + `itemSpacing 4` |
| `1263:38` 5cards | 两张卡、间距 3 | HORIZONTAL | `HORIZONTAL` + `itemSpacing 3` |
| `1263:39/40` 卡内 | 图标 + 文本列、两端对齐 | null | `HORIZONTAL` + **SPACE_BETWEEN** |
| `2:3565` 6sub-header | 标题 | tabs | 按钮 | null | `HORIZONTAL` + **SPACE_BETWEEN** |
| `2:3604` @echarts | 图表 + 装饰**重叠** | null | **不加 AL** |

### 3.5 插件落地（Figma Plugin API）

```js
// 只在"判定为 AL"时调用；调用后必须复核几何（3.3）
node.layoutMode = 'HORIZONTAL' | 'VERTICAL';
node.itemSpacing = gap;                 // SPACE_BETWEEN 场景设 0
node.primaryAxisAlignItems = 'SPACE_BETWEEN' | 'MIN' | 'CENTER';
node.counterAxisAlignItems = 'CENTER' | 'MIN' | 'STRETCH';
node.primaryAxisSizingMode = 'FIXED';   // 面板容器
node.counterAxisSizingMode = 'FIXED';
// 反向：判定为"不该有 AL"时
node.layoutMode = 'NONE';
```

自检报告里同时输出建议值，便于设计确认：

```
⚠ 2:3660 mode=HORIZONTAL 但子项重叠（gap −72） ⇒ 建议 layoutMode=NONE
⚠ 88:32 mode=null 但几何是一行两端对齐 ⇒ 建议 HORIZONTAL + SPACE_BETWEEN
```

## 四、整理后自检清单（插件本地计算，不连管线）

插件已有「结构清单」区域，建议整理完成后追加一份自检报告：

| 检查项 | 判定 | 不通过时的提示 |
|---|---|---|
| 段完整性 | 每个语义段是否有独立容器（标题与内容同容器或同父级） | `⚠ segment.daily-total-flow 的 header 与 body 是兄弟，建议合并到段容器` |
| 子节点数 | 容器内直接子节点 ≥2 | `⚠ 1 个子节点，布局判定将跳过` |
| 中间层保留 | header/body/卡片行是否仍在层级中 | `⚠ 内容被扁平化，结构判定不可用` |
| 重叠装饰保留 | 与内容重叠的装饰节点是否还在 | `⚠ 检测到重叠装饰被移除，容器会被判为并列` |
| mode 与几何一致性 | `layoutMode` 推出方向 vs 几何推出方向 | `⚠ 2:3660 mode=HORIZONTAL 但子项重叠（gap −72）⇒ 建议 layoutMode=NONE` |
| AL 设置可复核 | 设 AL 后子项偏移是否 >1px | `⚠ 设 AL 导致 3 个子项偏移 12px，已回退` |
| 尺寸固定 | 容器是否 hug contents | `⚠ 容器尺寸 hug，导出尺寸会漂移` |
| 文本完整性 | 是否存在被轮廓化的文本 | `⚠ 检测到 3 个疑似轮廓化文本` |

输出形式（与现有 `downloadJson` 同一份 JSON）：

```json
{
  "rootId": "2:9778",
  "segments": [
    { "id": "1263:38", "name": "segment.vehicle-dist", "hasOwnHeader": true,
      "children": 2, "flattened": false, "overlapDecor": 0, "modeConflict": false }
  ],
  "warnings": [
    { "code": "sibling-header", "id": "2:3559",
      "hint": "标题条与内容块是兄弟，建议合并到段容器" }
  ]
}
```

## 六、与生成管线的分工（边界）

| 事项 | 谁负责 | 说明 |
|---|---|---|
| 图层/容器层级是否合理 | **插件（本文档）** | 一段一容器、保留中间层、保留重叠装饰 |
| 段高、标题归属、结构方向、间距 | 管线（几何判定） | 只吃 bbox；插件无需为管线特殊处理 |
| 图层命名 | 插件（仅可读性） | 不承载契约；管线不依赖 |
| auto layout 是否标对 | 设计 + 插件自检提示 | 管线以几何为准，mode 只留痕 |

## 七、验收（整理一版「流量监测」后应满足）

1. 5 个语义段各自有独立容器，`header` / `body` 在段内（不是兄弟）
2. 每段容器直接子节点 ≥2，无扁平化
3. `1统计` 的中间装饰图仍在原位（与两张卡重叠）
4. 自检报告 `warnings` 里没有 `sibling-header` / `flattened` / `modeConflict`
5. 用这份整理结果重新生成时：段高判据**一次命中**（不再依赖"兄弟并集"兜底），4 个已知缺陷（统计块、两个副标题、tab 位置、溢出）不靠补丁即可消失
