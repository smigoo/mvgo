# 大屏页面骨架生成器 · 需求文档（v1）

> 状态：待评审 ｜ 日期：2026-08-26 ｜ 模块代号：`page-skeleton`
> 关联系统：mvgo（感智晓界）｜ 后端 `backend-node`（NestJS）｜ 前端 `frontend`（Vue3）

---

## 1. 背景与目标

当前 mvgo 的组件生成管线以 **Figma 节点树 + 多轮 LLM 精修** 为核心，产出的是"一个组件"。
但实际业务中大量存在**整页大屏 / 监测驾驶舱**类需求：用户拿到一张截图或 Figma 整页链接，希望快速得到
**页面级骨架**（头/边栏/中间地图占位 + 各区域组件清单），用于评审、占位、后续下钻。

**目标**：新增一条与"组件生成"平行的 **页面骨架生成管线**，具备：

- 输入：大屏截图 **或** Figma 整页 URL
- 分析：后端调用**用户已配置的 vision 模型**（前端零 LLM 配置）产出结构 JSON
- 产物：`vue3-pages/{groupId}/{pageId}/` 独立目录（index.vue + components/ 占位子组件 + 组件清单 MD + meta），遵循公司 Vue3 代码规范
- 管理：按用户 + 分组归属，支持列表 / 预览 / 下载(ZIP) / 删除（任务与产物目录同删）

**v1 明确不做**（已与用户确认）：
- ❌ nodeId 几何映射与"点组件下钻生成组件代码"（后续迭代）
- ❌ 迭代修改历史快照（`.snapshots/`）
- ❌ 资源 DOM 映射抽取（`resource-dom-mapping.json`，骨架模式不抽资源）

---

## 2. 输入

| 输入类型 | 来源 | 归一处理 |
|---------|------|---------|
| 截图 | 前端 `multipart/form-data` 上传 | 直接作为分析图；记录原始 `W×H` 作为 vw/vh 基线 |
| Figma URL | 前端文本传 `figmaUrl` | `figma-url-parser` 解析 `{fileKey, nodeId}` → `figma-connector` 渲染该节点 `scale=0.75` 整图；记录渲染图 `W×H` |

> 注：Figma URL 路径依赖 `FIGMA_TOKEN` 与 figma-connector，建议 **v1 优先截图**；figmaURL 作为 fast-follow。

**比例规则（已确认）**：不使用固定 1920×1080，自适应基线 = **图片自身真实 W×H**。
预览/产物以 `W×H` 计算 `--vw = 100vw / W`、`--vh = 100vh / H`，宽高各自填满、不变形。

---

## 3. 处理流程

```
[前端] 选图 / 填 figmaURL + 选分组(groupId)
   │
   ▼  POST /api/page-skeleton  (multipart 或 {figmaUrl, groupId})
[后端 page-skeleton 服务]
   ① 归一为一张图（截图直用 / figmaURL 渲染 0.75）
   ② 校验 vision 模型可用：providerPool.pick('vision') 探空 → 空则直接报错「未配置 vision 模型」
   ③ 调用统一 invoke(role='vision') 喂图 → 结构 JSON
        { layout:{headerH,footerH,leftSidebarW,rightSidebarW,centerPlaceholder,theme},
          components:[{name,region,type,heightRatio,placeholder,note}] }
   ④ JSON → 渲染 page-xxxx/ 目录（见 §5）
   ⑤ 存盘 vue3-pages/{groupId}/{pageId}/ + 登记 TaskService(taskType='page-skeleton')
   ⑥ 返回 { id, path, downloadUrl, meta }
```

**vision 调用约束**：走后端全局 `provider-pool` 的 `vision` 角色槽（`resolveProvider(config, primary, 'vision')`），
复用统一 invoke 的 `pick()` + 重建 LLM + failover 熔断。前端**不持有任何 API key**。

## 4. 结构 JSON Schema（分析产物中间态）

```jsonc
{
  "layout": {
    "title": "运行监测",
    "headerH": 60,            // 设计像素，渲染时 × --vh
    "footerH": 36,
    "leftSidebarW": 22,       // % 视口宽
    "rightSidebarW": 22,
    "centerPlaceholder": true,// 中间为地图/GIS/孪生 → 压底占位、不实现
    "theme": {                // 取色回填（像素聚类 or 设计令牌），不写死深色套路色
      "bg": "#eef4f6", "panel": "#ffffff", "text": "#1d4a5e",
      "accent": "#a7cbdb", "header": "#dcebf0", "footer": "#dcebf0"
    }
  },
  "components": [
    { "name": "当日总流量", "region": "left",  "type": "card",
      "heightRatio": 15, "placeholder": false, "note": "卡片" },
    { "name": "地图区域",   "region": "center","type": "map",
      "heightRatio": 100, "placeholder": true,  "note": "不实现，仅占位" }
  ]
}
```

**映射规则**：
- `region ∈ {header, footer, left, right, center}`
- `type ∈ {card, chart-line, chart-bar, chart-pie, list, map, table, custom}`（仅用于清单/注释，v1 不区分渲染）
- `centerPlaceholder=true` 的区域 → 渲染为**压底背景层占位**，两侧面板浮其上
- 地图/GIS/孪生类（视觉判定）→ 自动 `placeholder:true`

## 5. 产物目录结构（page-xxxx/）

```
vue3-pages/{groupId}/{pageId}/            ← 与 vue3-components/ 平级独立目录
├── index.vue                             # 布局：header / sidebars / center占位
│                                         #   <style lang="less" scoped> + @import '../resources/styles/index.less'
├── components/
│   ├── TrafficPanel.vue                  # 占位缺省内容（区域标题 + 占位块）
│   ├── DevicePanel.vue                   #   @import '../../resources/styles/index.less'
│   └── ...N 个（按 vision 区域生成）
├── resources/styles/index.less           # 公司 Vue3 规范：c-monitor 前缀 class
├── 组件清单.md                            # 序号/名称/区域/类型/高度占比/占位/备注
├── page-meta.json                        # 见 §6
├── screenshot.png                        # 原始输入图（figmaURL 时=0.75 渲染图）
└── .mc-gen/                              # 轻量缓存（可删可重建）
    ├── cache/
    │   ├── figma-node-data.json          # 仅 figmaURL 输入：节点树(pruned)，防二次拉取
    │   └── vision-response.json          # 原始 vision 输出，重渲染 SFC 免重调 LLM
    └── debug-prompt.txt
```

**与组件产物的一致性**：复用组件既有约定 —— `package/index.vue` 同级 `resources/styles/index.less`、
子组件 `../../resources/styles/index.less`、L0-B 门禁至少满足 **CODE-002**（less @import）。

**刻意省略**（相对组件目录）：`.snapshots/`、`.checkpoint/figma.json` raw 大文件、`code-chunks/`、
`resource-dom-mapping.json` —— 页面为一次性骨架生成，无需迭代中间态。

## 7. 用户归属与分组（复用组件范式）

| 维度 | 规则 |
|------|------|
| 归属 | 创建时写 `creatorId = req.session.userId`；列表/读取/删除均校验 `meta.creatorId === req.user.id` |
| 分组 | 复用组件现有 `groupId` 与群组校验（`component.service.ts` 同套逻辑），不新建命名空间 |
| 目录隔离 | `vue3-pages/{groupId}/{pageId}/`，与 `vue3-components/`、`custom-components/` 完全独立 |
| 越权防御 | 路径拼接用 `path.join` + 校验解析后路径仍以 `vue3-pages/{groupId}` 为前缀，防穿越 |

---

## 8. 接口设计（前缀 `/api/page-skeleton`）

| Method | 路径 | 说明 | 隔离校验 |
|--------|------|------|---------|
| POST | `/` | 创建：归一图 → vision → 渲染目录 → 存盘 + 登记 TaskService | creatorId from session |
| GET | `/` | 列出**当前用户**全部页面（id/name/groupId/时间/缩略） | 仅本用户 |
| GET | `/:id` | 取单个（meta + structure + sfc + md） | 校验归属 |
| PUT | `/:id` | 改名 / 改 structure 重渲染 → 覆写文件 | 校验归属 |
| GET | `/:id/download` | 返回 `skeleton.vue + 组件清单.md + components/ + styles` 的 **ZIP**（复用 screen-layout 范式） | 校验归属 |
| DELETE | `/:id` | **删任务 + 删文件夹同清**（见 §9） | 双层归属校验 |

统一响应信封：`{ success, code, message, data, source }`。

---

## 9. 删除语义（任务与页面都删）

```
DELETE /api/page-skeleton/:id
  1. 读 page-meta.json → 校验 meta.creatorId === req.user.id（防御）
  2. await tasksService.removeTask(pageId, userId)   ← 删任务记录 + 持久化
  3. fs.rmSync(pageFolder, { recursive:true, force:true })  ← 删页面产物（含 .mc-gen/ 缓存）
  4. 均成功 → { success:true }
```

满足用户要求：**"任务和页面都删"**。删除幂等：文件夹已不存在时 `force:true` 不报错。

## 10. 前端（playground）

定位：`/generator/page` 下「页面开发 / 普通页面」页签（现有占位 tab 实现化）。

- **我的页面列表**：卡片（名称/分组/时间/缩略），按当前用户过滤
- **新建 / 打开**：进 studio 加载 `structure` + 原始图预览
- **保存**：POST（新建）/ PUT（改名·改结构重渲染）
- **下载**：GET `/:id/download`
- **删除**：DELETE + 二次确认（明确提示"将同时删除任务与所有产物文件"）
- **自适应预览**：stage 用 `aspect-ratio = imageW / imageH` 跟随原图比例，骨架以 `--vw/--vh` 填充、不变形
- 调试面板（v1 可选）：全局布局 / 主题色 / 逐组件增删改（参考 `skeleton-studio.html` 原型）

> 注意：`file://` 打开无 session/CORS，前端必须经由 `frontend` 应用内（`VITE_LANGGRAPH_API` → 后端 :13030）调用，
> 不保留独立 HTML 直连 LLM 的形态。

## 11. 公司 Vue3 代码规范约束

| 门禁 | 要求 | 适用范围 |
|------|------|---------|
| CODE-001 | `<style lang="less" scoped">` | index.vue + 所有子组件 |
| CODE-002 | `@import .../resources/styles/index.less` | 主组件 `../`、子组件 `../../` |
| CODE-003 | common.less class 须 `c-monitor` 前缀 | 样式类命名 |
| FLEX-002 | flex 容器须有子属性 | 布局容器 |

v1 至少满足 CODE-002；地图压底用 `position:absolute; inset:0; z-index:0`，侧栏 `z-index:1` 浮层。

## 12. 注意点 / 风险

1. **vision 模型必须运行时已配置**（qwen-vl-plus/max、gpt-4o、qwen3.7-plus(vision) 已注册，但需 env 配 key/endpoint）。
   接口第一道校验 `pick('vision')` 探空，空则明确报错，不延迟到调用才崩。
2. **figmaURL 依赖 `FIGMA_TOKEN`**；v1 优先截图，避免引入 token 依赖。
3. **整页尺寸超限**：超大页面 scale=1 可能超 Figma 单边上限（≈8192px），0.75 已缓解；仍超限需动态降 scale。
4. **色系不写死**：theme 从像素取色或设计令牌回填，杜绝"科技大屏=深色"套路色（已踩坑）。
5. **子组件命名**：中文区域名 → PascalCase 文件名（如「当日总流量」→ `DangriZongliuliang`），需定映射规则。
6. **缓存清理**：删除时 `.mc-gen/` 一并 `rm -rf`；figma-node-data.json 仅在 figmaURL 输入时存在。
7. **nodeId 暂缓**：本 v1 不产出 nodeId，不下钻；目录与接口预留 `structure` 扩展位。

## 14. 验收标准

- [ ] 截图（0.5–0.75 降采样）输入 → 输出 `vue3-pages/{groupId}/{pageId}/` 完整目录
- [ ] 产物 index.vue 经 `vite build` / L0-B 门禁（至少 CODE-002）通过
- [ ] 预览随原图比例 `aspect-ratio` 自适应，宽高填充、无变形、无黑边
- [ ] 地图/GIS 区域自动压底占位、两侧面板浮层
- [ ] 组件清单 MD 含全部区域组件（名称/区域/类型/高度%/占位）
- [ ] 列表/读取/删除校验用户归属，越权返回 403
- [ ] 删除后 TaskService 任务记录与磁盘目录均不存在（含 `.mc-gen/`）
- [ ] 下载返回可解压 ZIP，含 index.vue + components/ + 清单 MD + styles
- [ ] figmaURL 输入（fast-follow）能渲染 0.75 整图并复用同一分析链路
