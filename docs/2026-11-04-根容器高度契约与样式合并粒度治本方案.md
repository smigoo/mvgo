## §2 根因（三处，各自独立、均有代码/产物级证据）

### RC1 —— 装配器根 `slot-con` 无高度契约（图表消失主因）

`code-generator.js:771`：

```js
lines.push(`    <div class="${rootContainerClass}"${rootHostAttr} style="display:flex;flex-direction:column;${rootHostStyle}">`);
```

- 内联样式**只有 `display/flex-direction`，没有 height**。
- 同函数 `:752-755` 的 P5 注释自认：「高度只能靠 less 里的 `height:100%`（LLM 写了才有）」⇒ 契约实际落在 LLM 身上。
- 本例 `index.vue` 的 `<style>` 只有一行 `@import`（草稿 `3-/5-package_index.vue` 均无样式块），`.c-env-monitor-slot-con` 在 `resources/styles/` 中**零规则**（其他正常组件如 `c-device-104f5a31` 的 `common.less:2` 有 `.c-device-slot-con{width:100%;height:100%;min-height:0}`，故同形态不塌）。
- 结果：`slot-con` 在 block 父层里 `height:auto` → 子项全是 `flex:<r> 1 0` + `min-height:0` → 内容高 **0** → 全链 0。
- 放大因素：`figma-height-ratio.js:906-908`（A4 比例写入）对每个段写 `flexGrow/flexShrink:1/flexBasis:0`，使「容器无定高 ⇒ 全员塌 0」成为必然，而非偶发。

### RC2 —— 共享表合并「百分比块整体丢弃」连带丢掉结构声明（tabs 纵向主因）

`style-class-consolidator.js:376-390`：

```js
if (hasPercentageSize(b.text) && hasPixelSizeInCommon(commonLess, b.selector)) {
  return false;   // ← 整块丢弃
}
```

- `hasPercentageSize`（`:275`）只认 `width|height: N%`；`hasPixelSizeInCommon`（`:285`）只认 px。
- 本例 `TabsSection.vue` 草稿块含 `height:100%`（百分比），而 `common.less` 里同名类已有 Figma 真值像素块（`height:27px; padding:3px 4px; flex:0 0 auto`）⇒ **整块被丢** ⇒ 块内 `display:flex; flex-direction:row; flex:1` 一并消失。
- 离线 A/B 复现（同一合并函数、真实草稿）：预置像素块时输出 `display:flex ? false`，无像素块时 `true` ⇒ 判据与真机产物完全一致。
- 丢弃粒度是**整块**而非**逐声明**，与 `:408-414`「批0 并集防声明净丢失」的既定治理方向自相矛盾（批0 只修了「同名块覆盖」路径，没修「整块丢弃」路径）。

### RC3 —— 图表 `min-height` 保底被同课后置规则反杀（图表消失的二阶放大）

- T2 已注入 `.c-env-monitor-chart { min-height: 160px; /* 🎯 防挤压 */ }`。
- 但 `common.less:107-112` 的 `[自动修复] 模板 class .chart → 匹配元素 chart-section` 又追加了一个**后置同名规则** `.c-env-monitor-chart { min-height: 0; /* VERT-004 */ }` → 同名后者胜 ⇒ 160px 失效。
- 产物 `.vue` 侧同样以 `min-height: 0` 结尾（`ChartSection.vue:262-264`），两处一致归零。
- `stripZeroMinHeightForClass`（T2-D）只剥「同块内」的 0，覆盖不到**后续追加的同名块**。

- 三处均落在**产生处**（装配器内联、合并器判据、图表守卫单一事实源），对全语料生效，不是本组件补丁。
