# AI 修复异步化 + Lite 截断自动重试（2026-11-03）

## 背景与真机实证

生产任务 `mv-lite-1793686730643-ae7d4a85`：Lite 生成报「生成的组件结构不完整，缺少闭合标签 `</script>`」（`lite.service.ts validateLiteSfc` 拒收）；组件快照显示文件在字符串中间硬切断（`Unterminated string constant`）——LLM 输出**截断**。用户点「AI 修复」收到 **nginx 504 Gateway Time-out HTML**。

## 根因（文件:行号）

| # | 故障 | 根因 |
|---|---|---|
| 1 | 修复 504 | `POST /api/demo/ai-fix-render-error`（demo.controller.ts:60）**同步长请求**：后端 `AI_FIX_RENDER_ERROR_TIMEOUT_MS=180s`（demo.service.ts:24），前端 abort 190s（preview/index.vue:448），生产 nginx `proxy_read_timeout` 更短 ⇒ 网关先掐断 |
| 2 | demo 页修复必败 | `demo/index.vue:940` 调 `POST /api/component/:id/ai-fix-render-error`——**后端无此端点**（src 全库 grep 无命中）⇒ 必 404 |
| 3 | 生成截断 | LLM 输出截断（max_tokens 到顶/流中断）后 `validateLiteSfc`（lite.service.ts:2690，调用点 :453/:1536/:3464）直接抛「生成失败」，用户只能人工点修复 |

## 查重结论

docs/、守卫总纲、memory、mvgo-* skills 均无既有异步修复/截断重试方案；lite.service 无 finish_reason 处理。新建，无矛盾。

## 修法

### ① 修复链路异步化（治本，摆脱网关超时）
- `demo.service.ts`：原 `aiFixRenderError` 主体改名 `runAiFixRenderError`（**剥离锁管理**）；新增 `startAiFixRenderError`（同步持锁 + 建内存 job `aiFixJobs: Map<fixId, {status,summary,…}>` + fire-and-forget）与 `getAiFixStatus(fixId)`（完成超 10 分钟清理）。
- `demo.controller.ts`：POST `ai-fix-render-error` 改返回 `{success, fixId}` 立即返回；新增 GET `ai-fix-render-error-status/:fixId`。
- `preview/index.vue requestAiFix`：POST 拿 fixId → 3s 轮询状态（总上限 240s）→ success/failed 分支复用原逻辑。
- `demo/index.vue handlePreviewAiFix`：从 404 端点切到新异步端点 + 同款轮询。

### ② 生产 nginx 止血（配置层，交付指令由用户执行）
`/etc/nginx` 的 `/api/` 反代补 `proxy_read_timeout 300s; proxy_send_timeout 300s;`。与 ① 不矛盾（①后请求变短轮询，②保护其余长接口）。

### ③ Lite 截断自动重试（治本，统一出口）
- 判据单一来源：抽出 `missingSfcBlocks(vueCode)`，`validateLiteSfc` 与截断检测共用，不复制口径。
- 新增 `callCodegenWithTruncationRetry`：包 `callCodegenWithControlGuard`，首趟缺必需块 ⇒ 日志 warn + 进度条提示 + **重试一次**；两趟仍缺则放行到 `validateLiteSfc` 照旧拒收（fail-visible）。主路径（:416）与断点续跑路径（:3444）统一走新 helper。

## 影响面

- POST `/api/demo/ai-fix-render-error` 响应语义变更：唯一消费者 `preview/index.vue` 同步改造；**后端+前端需一起部署**，单独部署后端会使旧前端修复按钮行为变化（改为立即返回 fixId）。
- `aiFixLocks` 语义不变（仍按 componentId 互斥），管理点从 run 移到 start。
- `validateLiteSfc` 对外行为不变（3 个调用点照旧抛错）。
- `/api/component/:id/ai-fix-render-error` 前端切换后不再被引用（本就不存在）。
- 回滚：改动前 commit id 可整体 revert。

## 判据与验证

- 日志计数行：lite 重试 warn 行含 sessionId + `缺 <标签>` 明细（真机可 grep）；demo 修复 job 状态日志。
- 回归：tsc 构建通过 + 相关 jest 套件无新增失败 + 冒烟（本地起服务 POST 修复端点拿 fixId、轮询到终态）。
