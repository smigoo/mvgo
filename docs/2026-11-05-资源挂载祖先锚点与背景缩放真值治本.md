## 1. 根因（Phase 2，文件:行号）

### R1 锚点 id 未与产物存在性对账
- `resource-mount-plan.js:254-268`：`ownerSectionId` 有值即返回，不判断产物中是否存在 `data-section-id="<owner>"`。
- 实测：`bg 88:34` 的 `owner=2:3660`，产物 section id 实际为 `88:33 / 83:30 / 2:3438` ⇒ 锚点悬空 ⇒ 落回 `findTagByClassKeyword(content, 'slot-当日总流量')` ⇒ 与产物类名（`c-traffic-monitor-daily-total-section`）词集交集为 0 ⇒ fail。
- 祖先链可行性实测（figma.json parent 索引）：12 个资源中 **10 个**可通过上溯命中产物已有 section（`88:33`/`2:3438`/`83:30`），2 个为根级资源（`2:3436` 根背景 skipMount、`2:3552` header 图标）。
- 图标 `targetDomSelector` 由 `_inferDomSelector` 按名字猜（`.g-container`/`.icon-container`），产物类名是 `c-traffic-monitor-*` ⇒ 永远不命中，属「猜测型选择器」。

### R2 scaleMode 在真值生产处被丢弃
- `figma-connector.js:1360-1395` 重建 fills 时只保留 `type/visible/color/opacity/imageRef/gradientStops`，**丢掉 `scaleMode`**；全仓 grep：`src` 内 `scaleMode` 仅出现在两处注释（`background-size-inference.js:7`、`microcode-engineer.js:6425`），无任何提取。
- 实测 76/76 条 IMAGE fill 无 scaleMode；图片为 1x 导出且像素 = 真值 rect（`image_313-5800.png` = 459×29）。
- 后果：`inferBackgroundSize` 只能用几何（覆盖比 ≥0.9 → `100% 100%`，否则固定 px），既无法表达「保形填充」（Figma FILL ≈ CSS `cover`），也无法区分 STREETCH 与 FILL。

## 2. 修法（Phase 3，治本）

### 修法 A：scaleMode 进真值 + 推断器权威分支
1. `figma-connector.js` prune fills：保留 `scaleMode`（与 `imageRef` 同处，注释说明用途）。
2. `figma-connector.js` mapping 构建：新增 `imageScaleMode`（取首个可见 IMAGE fill 的 scaleMode）。
3. `background-size-inference.js`：新增**唯一判据** `sizeFromScaleMode(m)`：
   | Figma scaleMode | CSS size | repeat |
   |---|---|---|
   | FILL / CROP | `cover` | no-repeat |
   | FIT | `contain` | no-repeat |
   | STRETCH | `100% 100%` | no-repeat |
   | TILE | `auto` | `repeat` |
   | 缺失/未知 | 回落几何推断（现状），并置 `inferredBy:'geometry'` |
4. 判据单一来源：只在 `inferBackgroundStyle` 内分流，其它调用方（N3、S7、vue3-engineer）自动继承。

### 修法 B：产物存在性锚点 + 祖先上溯
1. `buildResourceMountPlan(..., opts)`：新增 `opts.productAnchorIds:Set<string>`（产物实际存在的 `data-section-id`）。
2. `resolveSectionAnchor`：候选序列 = `[ownerSectionId, ...figma 祖先链]`，**取第一个 ∈ productAnchorIds 的 id**；全不命中返回 `null`。
   - 未传 `productAnchorIds` 时保持旧行为（向后兼容，spec 不受影响）。
3. `_mountPlannedResources`（microcode-engineer.js:6540）：进入前扫 `allFiles` 收集 `data-section-id` 集合传入；返回值新增 `anchorStats:{ownerHit, climbedHit, unresolved}` 并打**计数行**日志。
4. 猜测型 `targetDomSelector`（icon 的 `.g-container`）不再参与锚点判定，仅保留在真值里作提示。
5. **不做**根容器回退（历史禁令：挂根 = 背景消失/错位根源）；根级资源 unresolved 记数，由门禁 WARN 提示人工确认。
