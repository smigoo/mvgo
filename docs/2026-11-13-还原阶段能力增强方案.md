# 还原阶段能力增强方案（对齐 mv-ai-framework3-vue 高还原度）

> 日期：2026-11-13
> 目标：把外部项目 `mv-ai-framework3-vue` 在「还原（渲染保真）」阶段的高还原度能力，以**只加分支、不破坏现有能力**的方式引入 mvgo 管线。
> 核心约束：**不碰 mvgo 现有 flex 默认路径、不碰门禁体系、不碰四象限同步、不自行部署**。

---

## 0. 一句话结论

外部项目还原度高，根因是「**坐标绝对定位 + 确定性穷举样式规则**」；mvgo 还原度波动，根因是「**LLM 推断 flex 自动流 + 事后门禁纠错**」。
本方案把这两条能力做成**默认关闭的增强分支**，对「非标准 Auto Layout / 绝对定位 frame」启用坐标钉死 + 更全的样式真值，而标准 flex、全部门禁、运行时预览门禁一律保持不变并继续兜底。

---

## 1. mvgo 现有「好的地方」（必须保护，不改动）

| 能力 | 位置 | 保护方式 |
|---|---|---|
| flex 自动流响应式（抗极端长宽比） | `figma-style-extractor.extractLayout:126` + `style-mapper.resolveLayoutCss:485` | 默认路径不动；坐标模式仅作**补充分支**，标准 Auto Layout 仍走 flex |
| 自动化保真门禁（FLEX-003/004/005、CODE-007/014/017、TEXT-TRUTH、COMP-001） | `validators/code-structure-validator.js` + `utils/text-truth-guard.js` | 对两条路径**一视同仁**运行，新分支坏产物同样被拦 |
| 运行时视觉校验（截图比对） | 图节点 `runtime-preview-gate` + `screenshot-renderer.js` | 继续作为最终兜底 |
| LLM 宏观 + 真值兜底设计 | `style-mapper._synthesizeThemeVarsFromElementStyles` / `design-facts-compiler` | 真值只增强不强制覆盖 LLM |
| 四象限同步（vue3/mc × max/lite） | `mc-component-graph-vue3.js` + `lite.controller.ts` | 新增分支同样四象限同步落地 |
| 资源接线自愈 | `utils/resource-import-guard.js` | 保留作二级兜底，不删除 |

---

## 2. 全局保护设计（贯穿 4 项改造）

1. **开关隔离**：新增配置 `RESTORE_ENHANCEMENT`（默认 `false`，仅任务级 option / 实验开启）。所有新增逻辑用 `if (ctx.restoreEnhancement)` 包裹，关闭时行为 = 现状。
2. **门禁一视同仁**：FLEX-/CODE-/TEXT-TRUTH/COMP-001/runtime-preview-gate 不感知新模式，纯按产物判定 → 新分支若产生坏产物同样被拦、同样可回退。
3. **四象限同步**：vue3/mc × max/lite 同步改；每个象限都是新增分支，不影响现有 flex 产物。
4. **回归锚（A/B 比对）**：选 3~5 个历史任务，同输入开/关增强跑两轮，用 `code-structure-validator` + `runtime-preview-gate` 比对 BLOCK 数、覆盖率、截图差异，确认不引入新回归。
5. **不部署**（硬约束）：只改源码 + 本地 `npm run build` 验证；不重启 `:13030`、不 push、不同步生产。

---

## 3. 改造 1：坐标绝对定位还原模式（收益最大）

> ⚠️ **事实澄清（2026-11-13 复核）**：本改造"用 layoutMode 区分 flex/坐标"**不是新造的判定标准**，而是沿用 mvgo 现有管线对 `layoutMode` 的权威定位——它本就是布局决策的核心信号：
> - `design-facts-compiler.js:193`：*"标准读 layoutMode；不标准读 absoluteBoundingBox 几何推断，**默认 flex**"* （现有"无 layoutMode"分支的官方定义 = 几何推断 + 猜 flex）。
> - `subcomponent-planner.js:1662`：*"真实 Auto-Layout（layoutMode HORIZONTAL/VERTICAL）**永不覆盖** —— 那是 figma 声明的事实"*。
> - `code-fix-rules.js:2039`：layoutMode 真值表，是"是否注入 flex"的**单一来源**。
>
> **因此本改造真正改动的是「无 layoutMode」这一条分支**：把现状的"几何推断 + 默认 flex（靠猜）"改为"按 absoluteBoundingBox 相对父容器坐标钉死"。有 layoutMode 的节点继续走 flex，与现状零差异。用户从未要求"使用 layoutMode"——那是方案设计决策，且技术上正确、与现有代码一致；待用户拍板的实质是"无 layoutMode 时是否从猜 flex 切换到坐标钉死"。

- **现状缺口**：`layout-generator.renderZoneStyles:278` 已有绝对定位分支（基于 `node.position` + vw/vh），但**默认路径是 flex 自动流**；AI 误判嵌套/间距时还原漂移。
- **外部参照**：`mv-ai-framework3-vue/figma-ops/pipeline/layout-analyzer.cjs:123-148,314-355` —— 读 `absoluteBoundingBox`，坐标减父节点 → `toVW/toVH`（`px/designWidth*100`）钉死。
- **具体改法**：
  1. `figma-style-extractor` / `layout-generator` 新增 `resolveCoordinateCss(node, parentBox, designSize)`：输出 `position:absolute; left:Xvw; top:Yvh; width:Wvw; height:Hvh`。
  2. 模式判定（**仅增强、不替换；按「直接父容器」判定，非按自身、非按祖先链**）：
     - 决策依据 = **直接父容器是否 Auto Layout**，而非节点自身 `layoutMode`，也**不**看祖先链。
     - 父容器有 `layoutMode`（AL）→ 本节点是 flex 流子项，**不绝对定位**（即便本节点自身无 `layoutMode`，也由其 AL 父按 flex 排布，否则混合文件结构会乱）。
     - 父容器无 `layoutMode`（自由布局 / 根）→ 本节点按 `absoluteBoundingBox` 相对父坐标钉死（vw/vh）。
     - **整文件无 layoutMode 时**：每个父都是自由布局 → 全树逐层「相对父绝对定位」递归钉死 = 像素级 1:1，正是坐标模式最强、flex 默认最弱的场景（规则自然收敛，无需特判）。
     - 混合文件：AL 段落内部走 flex，自由布局孤岛走坐标，互不干扰。
     - 附带收益：自由布局下 Figma 的 constraints（pin/scale）逻辑在坐标模式里被直接绕过（按真实包围盒落点），不必再实现约束推导。
  3. 设计稿比例兜底：根容器加 `min-width/min-height` + 设计稿宽高比容器，避免非 16:9 留白/溢出（外部同做法）；flex 保留为门禁检测到重叠/溢出时的回退建议。
- **涉及文件**：`tools/figma/figma-style-extractor.js`、`roles/layout-generator.js`、`context/generation-context-assembler.js`（注入开关）、`roles/style-mapper.js`（模式判断）、`graphs/mc-component-graph-vue3.js`（任务级 option）。
- **回归**：A/B 比对同任务，确认坐标模式不引入新 FLEX-/COMP- 类 BLOCK，且截图还原度提升。

## 4. 改造 2：穷举样式映射规则表（补静默遗漏）

- **现状缺口**：`figma-style-extractor` 覆盖 SOLID / DROP_SHADOW / INNER_SHADOW + 基础 typography；缺**四角 radius、径向渐变、letterSpacing、textTransform、clipsContent、zIndex、opacity** → LLM 静默漏写门禁抓不到。
- **外部参照**：`figma-ops/docs/complete-style-generation-rules.md` 9 大类全属性表（含 `rectangleCornerRadii` 分四角、`GRADIENT_RADIAL`、`letterSpacing`、`textCase→text-transform`、`clipsContent→overflow`、`layerId→z-index`、`opacity`）。
- **具体改法**：
  1. `extractLayout` 增加 `rectangleCornerRadii` → `border-top-left-radius` 等四角分别提取（`:150-158` 规则）。
  2. `extractEffects` 增加 `GRADIENT_RADIAL` 分支。
  3. `extractTypography` 增加 `letterSpacing`、`style.textCase→text-transform`。
  4. 新增 `extractMisc`：`clipsContent→overflow`、`opacity`、`layerId→z-index`。
  5. 以上作为**确定性真值**喂 `design-facts-compiler`，让 `style-mapper` / LLM 有更全约束源（参考 `CODE-007` 真值口径）。
- **涉及文件**：`tools/figma/figma-style-extractor.js`、`context/design-facts-compiler.js`、`roles/style-mapper.js`。
- **隔离**：纯新增提取字段，不改现有映射；先 `dry-run` 比对现有产物，确认更全的真值不会误触发 CODE-007/014 BLOCK（真值更严但更准，需回归确认）。

## 5. 改造 3：背景图确定性映射（移植外部）

- **现状缺口**：`resource-import-guard.js` 资源接线依赖 LLM import 注入 + 自愈；历史上 `pruneRedundantFields` 误删 `imageRef/scaleMode`、`import.meta` 改写、`.value` 误用等坑。
- **外部参照**：`figma-ops/docs/background-mapping-improvements.md` + `config/image-handling.md` —— 命名识别 `背景/bg/合并/merged` → 归属父容器；`asset-mapping.json` 取真文件名；`cover/center/no-repeat`。
- **具体改法**：
  1. `figma-connector` 抽取阶段**前置**确定性背景识别（命名规则 + `imageRef`），输出「背景节点 → 父容器 cssClass 归属」映射。
  2. 写入 `design-facts-compiler.collectBackdropEvidence`（已有兜底层，`:60`），让 `background-image` 直接落在正确父容器，不挂错页面根。
  3. 文件名用 `asset-mapping` 真名（避免 `bg--2656409.png` 错名），路径按组件深度 `./` / `../` 处理。
- **涉及文件**：`ai-engine/.../figma-connector.js`（前置步骤）、`context/design-facts-compiler.js`、`utils/resource-import-guard.js`（保留自愈作二级兜底）。
- **隔离**：新增预处理步骤，不删 `resource-import-guard` 现有逻辑；现有自愈仍保留。

## 6. 改造 4：渐变角度与文字渐变

- **现状缺口**：`compileBackgroundTruthColors:109` 只取各 stop 颜色，不取角度；无文字渐变处理 → 渐变方向错、金色文字渐变丢失。
- **外部参照**：`figma-ops/config/gradient-handling.md` —— `calculateGradientAngle(handles)`（`atan2(dy,dx)*180/π + 90`）算 CSS 角度；文字渐变 `-webkit-background-clip:text; -webkit-text-fill-color:transparent`。
- **具体改法**：
  1. `design-facts-compiler` 新增 `calculateGradientAngle(handles)` → 输出 `linear-gradient(angle, stops)` 真值；`CODE-007` 校验根背景渐变角度（有则必准）。
  2. TEXT 节点 `fills[0].type` 为 `GRADIENT_*` → `style-mapper` 生成文字渐变裁剪兜底（仅对文字节点，默认不强制，仅当真值判定为渐变文字时生效）。
- **涉及文件**：`context/design-facts-compiler.js`、`roles/style-mapper.js`、`validators/code-structure-validator.js`（CODE-007 增强）。
- **隔离**：新增分支，默认不强制；门禁只校验「有则必准」，不新增 BLOCK 噪音。

## 8. 风险与回滚

- **风险 A**：坐标模式在非 16:9 比例下留白/溢出 → 用设计稿比例容器 + flex 回退建议兜底；A/B 比对早发现。
- **风险 B**：更全样式真值误触发现有门禁 → P0 先做 dry-run 比对，确认 `CODE-007/014` 不会误 BLOCK 现有 flex 产物。
- **回滚**：所有改动受 `RESTORE_ENHANCEMENT` 开关控制，关闭即完全回到现状；git 按 memory 规范显式路径提交（禁 `git add .`）。
- **不部署**：改动只到源码 + 本地构建验证，重启/同步生产等用户明确授权。
