# E2N 映射：视觉分析产物 ↔ Figma 节点的结构对应机制（设计）

- 日期：2026-11-05
- 触发：`c-environment-monitoring-6e59a0d4` —— 静态资源 `bg-7890` 挂到了 `.tab`（每个胶囊）
  而不是 `.tabs` 容器；文字颜色同名多实例只能放弃。根因是**没有一张对应表**，各通道各自启发式。
- 状态：设计稿，**未实施**

## 0. 问题本质

LLM 视觉分析生成的是**产物结构**（Vue 模板 + CSS 规则）；Figma 是**设计结构**（节点树 + 几何 + 填充）。
两者没有共同的 id，现有回填靠「点对点特征匹配」：

| 回填项 | 现有定位手段 | 断点 |
|---|---|---|
| 文字颜色/字号/尺寸 | 模板文本 exact/substr（`backfillSfcFiles`） | 同名多实例 → 不唯一 → 放弃；插值文本 → 跳过 |
| icon 资源 | 空 icon 变量位 + 邻居文本语义 zip | 无变量位则失效 |
| bg 资源（命名） | 文件名语义段 ↔ 类名 | 纯 id 命名（`bg-8439`）无解 |
| bg 资源（AI/结构） | 词 → 叶子 → LCA → **找有 background 键的规则** | 落点被"哪条规则碰巧有 bg 键"决定 ⇒ 挂到 `.tab` |
| 容器底色 | childTexts 交集 | 同名/空文本失效 |

共同缺陷：**没有中间表示**。每次都要在"产物侧特征"里重新猜 Figma 侧意图，判据互不一致。

## 1. 目标

建一张 **E2N 映射表**（Element→Node）：

```
产物元素（实例化后）  ←→  Figma 节点（nodeId）
```

一旦建成，所有回填都变成查表 + 写值：
- 文字颜色 = `N(TEXT).fills` → 映射到的产物文本实例 → 写内联 style 或规则
- 静态资源 = `N(VECTOR/IMAGE)` → 其父容器/所在实例 → 映射到的产物元素 → 写 `:src` 或 `background`
- 尺寸/字号 = `N.bbox / style.fontSize` → 映射到的产物元素

映射表落盘 `e2n-map.json`（可观测、可复算、可单测），每条边带**证据**与**唯一性计数**。

## 2. 三层算法

### Step 0 产物实例化（关键前置）

LLM 产物的模板是**压缩过的**：`v-for` 只写一个元素，文本是 `{{ tab.label }}`。
Figma 侧是**展开的**：4 个独立 TEXT 节点。直接比对必然错位，必须先实例化：

| 产物形态 | 实例化规则 |
|---|---|
| 静态文本 | 1 个实例，文本 = ownText |
| `{{ x }}` / `{{ x.y }}` | 文本 = script 里该路径的字面量集合（多值 → 多实例） |
| `v-for="t in tabs"` | 查 script 数组长度 N → 复制 N 份；每份把 `{{ t.label }}` 绑定为第 i 项的字段值 |

本例实测（`c-environment-monitoring`）：

```
script: const tabs = [{key:'co',label:'一氧化碳'},{label:'能见度'},
                      {label:'洞内照明'},{label:'洞外光强'}]
模板:  <div class="…-tab" v-for="tab in tabs">{{ tab.label }}</div>

实例化后：
  .…-tab#0  文本=一氧化碳
  .…-tab#1  文本=能见度
  .…-tab#2  文本=洞内照明
  .…-tab#3  文本=洞外光强
  .…-tabs   子树文本集合={一氧化碳, 能见度, 洞内照明, 洞外光强}  (4)
```

### Step 1 文本 seed（唯一锚点）

对每个 Figma TEXT 节点（`normalizeAnchorText(characters)`），在实例化产物里找**文本相等**的实例：

- 唯一命中 → 建 seed 边
- 多命中 → 用**兄弟序号**消歧（同一父容器内，第 k 个同文本 TEXT ↔ 第 k 个实例）；仍不唯一 → 不建边（记 `ambiguous`）
- 零命中 → 记 `miss`（可能被 LLM 改名/合并/省略）

**按文本值匹配，不按顺序**：本例 Figma 顺序（一氧化碳/洞内照明/洞外光强/能见度）与产物数组顺序
（一氧化碳/能见度/洞内照明/洞外光强）**不同**，按序对应会错 2 个；按文本值则 4/4 全对。

### Step 2 祖先传播（集合相等，唯一性闸门）

seed 只覆盖文本叶子，容器（and 资源挂载点）要靠向上传播：

```
对 seed 对 (F_text, V_inst)：
  S_F(A) = A 子树内**已 seed** 的 Figma TEXT 集合
  S_V(C) = C 子树内**已 seed** 的产物实例集合
  若 S_F(A) == S_V(C) ≠ ∅ 且 C 在候选集中唯一  →  建边 (A ↔ C)
```

本例逐层验证：

| Figma 节点 | S_F | 产物候选 | S_V | 判定 |
|---|---|---|---|---|
| `2:7889 tabs-list` | 4 条（一氧化碳…） | `.c-…-tabs` | 4 个实例 | **相等且唯一 → 建边** |
| `2:7889 tabs-list` | 4 条 | `.c-…-tab#0` | 1 个实例 | 集合不等 → 排除 |
| 页面根 `2:7879` | 全部文本 | `.c-…-content` | 子集 | 集合不等 → 不建（继续上溯到真正相等的层） |

这条判据天然解决"v-for 单元素"难题：**`.tabs` 的实例集合有 4 个、`.tab` 只有 1 个**，
不需要任何尺寸/背景键证据就能区分。

### Step 3 回填消费

**静态资源**

- 资源节点 `N` 的 bbox ≈ **父容器** bbox（±1px）⇒ **容器级背景**：挂载点 = `map(N.parent)`，
  允许在该类规则上**插入** `background`（授权来自结构边，不来自"规则碰巧有 bg 键"）
- 否则（元素级，如 `bg-tab-active` 78×21）⇒ 挂载点 = `map(N)`：若 `N` 自身已 seed/已映射则用它，
  否则用「父容器内同类资源的第 k 个」对应产物状态变体类（`--active`）→ 无法唯一则 skip

本例：`2:7890 bg` bbox **295×27 = 父容器 bbox** ⇒ 容器级 ⇒ 挂 `.c-…-tabs`（正确落点）；
`2:7891 bg-tab-active` 78×21 ≠ 父 ⇒ 元素级（本轮未下载，不处理）。

**文字颜色**

- `N(TEXT).fills`（首个可见 SOLID）→ 映射到的产物文本实例
- 写入方式按产物形态决定：
  - 文本在**独立元素**（`<span>文本</span>`）→ 写内联 `style="color:…"`
  - 文本在**容器规则**里（`.tab { color:#fff }`，实例文本是元素直接内容）→ 写规则（该类逻辑唯一）
  - 两者都不满足（规则多类/无类）→ skip 并记录原因

**改进点**：① 同名多实例（12 张设备卡的「摄像机」）按实例一一对应，不再因"不唯一"整体放弃；
② 插值文本经实例化后有真实值，可参与颜色回填（现在因 `{{ }}` 全被跳过）。

## 3. 判据与可辩驳输出

`e2n-map.json`：

```json
{
  "sessionId": "...",
  "seeds":  [{ "figmaId": "2:7893", "text": "洞内照明", "prodPath": "package/index.vue#tab#2",
               "how": "text-exact", "candidates": 1 }],
  "nodes":  [{ "figmaId": "2:7889", "figmaType": "GROUP", "prodSel": ".c-…-tabs",
               "how": "subtree-set-equal", "texts": 4, "unique": true }],
  "unmapped": [{ "figmaId": "2:7891", "reason": "no-file" },
               { "prodPath": "...", "reason": "no-figma-counterpart" }]
}
```

计数进 `truth-backfill-report.json`：`e2nSeeds / e2nNodes / e2nAmbiguous / e2nMiss`。
**所有回填消费方只准查表**，不再自己匹配 —— 判据单一来源。

## 4. 降级链（逐级弱化，逐级可观测）

```
文本 seed 命中  →  祖先集合传播  →  （无 seed 的子树）几何形状+顺序对齐
                              →  （仍不行）现有单通道启发式（命名锚定 / AI label）
                              →  （仍不行）skip + 原因
```

旧通道**不删除**，降为最后一级 fallback，且每次 fallback 命中都计数（`e2nFallbackHit`），
用于衡量映射层覆盖率。

## 6. 已知边界

- `v-for` 嵌套/条件渲染（`v-if`）实例化需要更强的 script 求值；M1 只支持「顶层数组 + 简单字段」
- Figma 侧没有对应物的产物元素（LLM 臆造结构）无法映射 → 记 `no-figma-counterpart`，不猜
- 图被 `background-size: 100% 100%` 拉伸跟随容器：**形状一致**由映射层保证，
  **容器自身尺寸正确**仍属尺寸回填通道职责，映射层不越界补偿

## 8. 与设计稿的 6 处偏离（全部由真机证据强制）

1. **`instanceTexts` 判据不能只看本节点 `v-for`** —— 单元内的子节点自身不带 `v-for`，
   但它的插值仍会把 12 项全展开；只判 `vforCount>1` 会让单卡的实例文本集从 2 条膨胀成 24 条，
   `vfor-unit` 边永不成立。改为「本节点或任一祖先带 v-for 作用域」。
2. **单元匹配不用「两边 seed 数相等」** —— 83cfb20e 首卡多出的 `(2/484)` 在产物侧组合不出来（无 seed），
   按等式判定首卡永远无边，而它的 `bg-8439` 恰好挂在该容器上。改判据：
   `有交集(sr>0) && 容器文本量 ≤ 单元单实例文本槽位(instTextNodes)`。
3. **并列候选分两类** —— ①同一条祖先链（`.tabs-list > .tab` 都只渲染「总数」）= 只是"深度未定"，
   取最外层建边并计 `depthResolved`（子树区域唯一，深度不影响资源归属）；②分叉在不同子树 → `multi` 不猜。
4. **选择器唯一性必须剥噪声** —— 产物里同一逻辑规则有 4 个投影（SFC 副本 / 预编译副本 / `.dark X` / `.light X`），
   且 selNorm 会带选择器前的注释（`/* Tab 切换栏 */\n.c-…-tabs`）。不剥 ⇒ `skipRuleAmbiguous` ⇒ 容器底图永远挂不上。
5. **相对深度按「被改文件」算** —— 预编译 `resources/styles/index.css` 的图片目录是 `../images/`，
   按 `edge.prodPath`（指向 .vue）算会写成 `../resources/images/`，预览 404。
6. **`<template>` 伪节点排除** —— 它与内层容器渲染集完全相等，参与建图会在"取最外层"时抢走容器位（classes 为空）。

## 11. 结论：`2:8418`（面板根「底图」420×425）不该下载

- **归属**：Figma 节点 `2:8417 "cp-设备监测"` 的第一个子节点 `2:8418`，`VECTOR`，名 `bg`，尺寸 420×425 = 与面板根 frame 完全一致。
  对应产物：`mc-lab-1793884417940-83cfb20e`（设备监测·第 1 次）与 `mc-lab-1793887106819-c91f6190`（设备监测·第 2 次），
  同源同一节点（fileKey `1t7Dmmpsl5i0PC8BJt2QLf` / node `2:8417`）。**不是**环境监测（2:7879）、重点车辆（2:7952）、流量监测（2:9778）。
- **fills 实测**：4 条填充里 3 条 `GRADIENT_LINEAR` 全部 `visible:false`，唯一可见的是
  `SOLID` `rgb(0.929, 0.957, 0.984)` ≈ `#EDF4FB`、`opacity 0.7`；另有可见 `DROP_SHADOW`（offset 0/4, radius 10, `rgba(74,117,141,0.25)`）。
  **没有任何 `IMAGE` fill ⇒ 不存在可下载的位图**，把它导成 png 等于把"纯色 + 阴影"栅格化，比 CSS 复现更差。
- **为什么它本来就不在下载清单**：`downloadAssets` 走命名启发式（节点名 / id 后缀），该节点名就叫 `bg`、无 id 后缀 ⇒ 不会产出 `bg-8418.png`。
  所以"未下载"正常，不构成漏下载 bug；它也不会进 E2N 的 bg 候选（需 `bg-*` 文件名 + `containerLevel`）。
- **🔴 处置（用户 2026-11-05 定性纠正）：根内容容器不该有背景，不是"回填真值色"。**
  微码语义：`base-panel` 外壳负责面板底色/圆角/阴影，默认插槽里的内容区必须透明；
  所以 `2:8418` 的 `#EDF4FB`@0.7 + `DROP_SHADOW` **属于外壳职责，不应下沉到产物内容区**。
  三会话实测该位置现状均为 lite 臆造浅色：`.c-equipment-monitor-content{background:#E3ECF8}`（83cfb20e / c91f6190）、
  `.c-environment-monitoring-content{background:#E4EEF5}`（6e59a0d4）——
  硬编码浅色在深色主题下会破色（外壳深、内容浅），属**主题隔离缺陷**，不只是视觉偏差。
  正确动作 = 在管线里对该规则**清除背景**（置 `transparent` / 删声明），计数 `rootContentBgCleared`；
  判据只认微码语义（`base-panel` 默认插槽的第一层根元素类），不查 Figma 真值，也不许用产物数值反向授权。
  归属：与 `relocatePanelTitle` 同类（微码语义后处理），独立于 M2 的"容器底色回填"——那一类要补的是**卡片级**容器。

## 12. 三项补强（M1 收尾，2026-11-05 夜）

### 12.1 根内容容器背景清除（新通道 `clearRootContentBackground`）
- **约束来源**：用户定性「微码组件面板的根内容容器本身不应该有背景」。
- **判据**：元素 = `base-panel` **默认插槽**的第一层根元素（跳过 `#title-left` 等具名插槽）；
  规则 = 该元素的**单类**选择器（归一后只含一个类 token，挡掉 `.x .y` 后代规则）。
- **动作**：删 `background` / `background-color` / `background-image`，置 `background: transparent`。
  不查 Figma 真值、不用产物数值反向授权（与"规则体是视觉分析产物"纪律一致）。
- **地位**：与 `relocatePanelTitle` 同类的微码语义后处理，新增 Stage **C2e**（放在 C2d 之后、快照同步之前）。
- **为什么必须最后跑**：C2c 容器 fill 可能把颜色写回来。

### 12.2 E2N 提前到图标挂载之前
- 原顺序 `C2(命名/尺寸) → C2a(E2N)` 会让旧通道先占位、E2N 只能 `skipAlreadyUrl` 让位 ⇒ **错误落点被锁死**。
- 现顺序 `C2a(E2N) → C2(命名/尺寸兜底) → C2b(AI) → C2c(fill) → C2d(标题) → C2e(清背景)`。
- 配套：旧通道新增 `bgSkipAlreadyUrl` 让位保护 —— 原实现遇到规则体已含 `url(...)` 会**再拼一条**，
  `background: url(A) url(B)` 是 multiple background（两张图叠加），必须跳过。

### 12.3 `<template>` 分类修正
- 原实现「排除全部 template」过狠：`<template #title-left>` 是**具名插槽**，内容是真实渲染的，
  被一起排掉导致 83cfb20e 的「设备监测」标题整条 miss（`prodNodes` 里查无此文本）。
- 现按属性分类：无 `#`/`v-slot` = 结构包裹层 → 不建节点但**直系文本上移**给最近已建祖先；
  带 `#`/`v-slot` = 具名插槽 → 正常建节点。

### 12.4 本轮踩到的两个真机坑
1. 🔴 **`@import` 污染选择器**：`<style>` 首条规则的 `selNorm` 是
   `"\n@import '../resources/styles/index.less';\n\n/* 注释 */\n.c-…-content"`。剥注释后仍残留 at-rule，
   其中 `.less` 被 `/\.[\w-]+/g` 算成**第二个类 token** ⇒ 永远判"多类"漏清。
   修法：选择器归一取**最后一个 `;` 之后**的部分（`split(';').pop()`），`selKeyOf` 与清背景两处同改。
2. 🔴 **祖先判据写反**：`effectiveParent(n)` 对未跳过节点返回**自身**，若用它判"c 是不是 node 的子"
   （`effectiveParent(c) === node`）永远不成立 ⇒ 12 条 vfor-unit 边全丢。正确判据是
   `effectiveParent(c.parent) === node`。
