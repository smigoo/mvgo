# 2026-11-05 bg 挂载投影组漏网：`.dark` 主题副本被误判歧义（83cfb20e 实锤）

## 背景

mc-lab-1793884417940-83cfb20e（设备监测）汇总双卡背景图 bg-8788/bg-8807 未挂载，用户问「为什么没用 Figma 静态资源」。

## 根因（证据链）

AI 兜底三候选 label 全对（bg-8788→「总数:56302 隧道设备 异常数:5」等），真机报告 `bgAiSkipNoBgKey=3`，但产物 css 里 `.c-equipment-monitor-summary-card--blue/--gray` 规则体**明明有**渐变 background 键（index.css:87/91）。

路径还原（truth-matcher.ts `findBgRuleForClasses`，1258-1260 行）：

1. label 命中模板叶子 → 祖先回溯到 `.summary-card--blue`
2. hits 收集到**同文件两条**规则：light 主体 `.c-equipment-monitor-summary-card--blue`（87 行）+ `.dark .c-equipment-monitor-summary-card--blue`（361 行，末端 token 同样命中）
3. 投影组歧义判定 `byFile count>1 → continue`（「歧义只认同文件多条」）
4. 回溯继续向上，整链无 bg 键 → `skipNoBgKey`

反差佐证：478f0758 真机 `bgAiAnchored=1` 挂载成功——其产物 css **没有** `.dark` 主题副本，投影组判定未触发。83cfb20e 生成器（LLM）多产出了 dark 副本才踩中。

**查重结论**：478f0758 投影组语义（同文件同名规则=同一规则的多投影）是既有方案，本次是其判定口径的漏网场景——**续接原方案补全**，不另起炉灶。

## 修法

投影组 key 从「文件路径 + 原始选择器」改为「文件路径 + **剥主题前缀后的选择器**」：

- `.dark X` / `.light X` / `X` → 同一逻辑规则的投影，全部同步替换
- 剥前缀后仍同 key（同文件真重复）才判歧义弃权

两处同构判定同改（同一根因）：
1. `aiAnchorBackgroundAssets#findBgRuleForClasses`（AI 兜底，~1258 行）
2. `mountBackgroundAssets` 命名锚定 `hits.length > 1`（~972 行）——`--blue` 类命中 light+dark 两条同样会被 bgSkipAmbiguous 挡住

## 判据（假设，以真机/spec 阳性对照为准）

- 主题前缀正则：选择器剥 `^\.(dark|light)\s+`（可叠加）；歧义 key = 文件路径 + `::` + 剥后选择器
- 阳性对照：构造 light+dark 副本同文件的规则 + bg 资产 → 应挂载且**两条投影都换 url**
- 阴性对照：同文件两条非主题变体同名规则 → 仍歧义弃权
