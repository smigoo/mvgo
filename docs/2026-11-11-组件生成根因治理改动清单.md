## 1. 根因 D（**主根因**）：过粗展开器误触发

### 1.1 现状

`utils/over-coarse-section-expander.js`

- `isOverCoarseAnchor(anchorNode)`（L79-122）判据四条：① 直接子容器**垂直依次堆叠**；② 堆叠序列**覆盖锚点高 ≥80%**；③ 每个子高 ≥ 锚点 10%；④ 每个子树有实质内容。

### 1.4 改动

**文件**：`src/ai-engine/utils/over-coarse-section-expander.js`

**① 段标题条豁免（新增判据，零硬编码）**

在 `isOverCoarseAnchor` 的堆叠序列校验通过后、返回 `{over:true}` 之前，插入：

```

  (a) sorted[0].box.h <= ab.h * 0.25
  (b) sorted[0] 子树含 TEXT 节点
  (c) sorted[0] 子树 TEXT 数 <= 2 且不含数字主导的指标文本
=> return { over:false, reason:'section-header-body-pattern' }
```

理由：这是「段标题条」的结构指纹（高瘦、含文字、文字是标题不是数据）。命中即说明该锚点**已是最小业务段**，拆它只会有损。

**② 已有内部语义豁免**

```
若 anchorNode 的对应 section 满足任一：
  · 段名以 slot- / section- 开头（pipeline 自身业务命名，非 Figma 自动名）
  · 段携带 body.responsibility 或 headerRelation

```

理由：展开器只该处理「vision 只给了一个**无内部语义**的粗段」的场景；已有业务语义的段不需要也不允许被重推结构。

**③ 展开必须补齐下游契约元数据（无条件，与 ①② 独立）**

`figmaHeightPx` 已在（`section-tree.js:2575 / 2787` 自带），真正缺的是 **`layoutMetadata`**（实测恒 `null`，见 1.2.1）。在 L196-201 的 `for (const k of kids)` 内用 `index` 重建：

```js

const kb  = getFigmaBox(raw)
if (kb) {
  k.figmaBox = kb
  k.absoluteBoundingBox = kb
  k.styles = { ...(k.styles || {}), figmaHeightPx: kb.height }
  k.layoutMetadata = buildLayoutMetadata(raw, kb)   // ← 见下「单一事实源」

// 保留原 L196-199 的清零语义，交给 applyFigmaHeightGrow 按真值重算

**方向零猜测**（按优先级取事实，不命名、不枚举业务值）：

```

layoutMode === 'VERTICAL'   → 'column'
否则：≥2 个子块 y 单调不减 → 'column'；否则 'row'

**单一事实源（根治理硬要求）**：`layoutMetadata` 的形状由 `subcomponent-planner.js:902 extractLayoutMetadata()` 定义（键：`direction / alignItems / justifyContent / gap / height / padding`）。展开器**不得另写一套**——把 `extractLayoutMetadata` 提到共享工具（如 `utils/layout-metadata.js`）导出，`subcomponent-planner` 与 `over-coarse-section-expander` 同 import。否则两处键名一旦漂移，展开段会再次静默隐形。

理由：`layoutMetadata` 是 `applyFigmaHeightGrow`（L2454 `if (!meta) continue`）／方向判定／`microcode-engineer` 高度提示块的**唯一入口**；不回填 = 展开段在整条下游链上隐形。**这条即便 ①② 全做了也要保留**（真展开场景同样需要）。

**④ 展开后自检 + 回滚（fail-closed）**

展开完若 `kids` 中存在「h ≤ 锚点 25% 且子树含 TEXT 且不含图表/图片节点」的子段 → 视为误拆，`out.push(sec)` 原样保留原段（reason: `'expanded-looks-like-header'`）。

## 2. 根因 G（P0）：`runtimeBuilder` 裸用致渲染崩溃

### 2.1 现状

`src/ai-engine/roles/microcode/code-validator.js:2161-2197`，vue3 任务后处理：

```js
const isVue3 = options.componentType === 'vue3';
if (isVue3 && content.includes('$mcComponentBuilder')) {          // L2167 ← 前置条件
  content = content.replace(/\$mcComponentBuilder\(\)/g, '(...)'); // L2168
  content = content.replace(/runtimeBuilder\?\.\s*publishEvent/g, '/* no-op */ null && null'); // L2173

```

**两道门都漏**：

1. **L2167 前置条件**：`content.includes('$mcComponentBuilder')` —— 产物里没有这个标识符时，**整块兜底连执行都不执行**；
2. **L2173 正则**：只匹配 `runtimeBuilder?.publishEvent`（**带可选链**）。

### 2.2 铁证

`mc-max-1794361185516-c0a936d8/package/components/StatsSection.vue:41`

```js
const emitLoadEvent = () => {
  runtimeBuilder.publishEvent('c-vehicle-monitor-onload', {...})   // ← 无 ?.
}
onMounted(() => { emitLoadEvent() })
```

该文件内**既无** `$mcComponentBuilder()` 解构、**也无** `let runtimeBuilder` 声明 ⇒ `onMounted` 抛 `ReferenceError` ⇒ **整个组件白屏**。
更关键：正因为没有 `$mcComponentBuilder`，**L2167 前置条件为假 ⇒ L2168/L2173 的替换一行都没跑** ⇒ 兜底机制在「最需要它的场景」下完全不设防。这是「**守卫条件与病灶条件互斥**」的典型 —— 写得像防护，实际只在不会出事的场景生效。

### 2.2.1 改动后的正确形态

兜底不应由「是否出现 `$mcComponentBuilder`」驱动，而应由「**是否出现微码运行时标识符**」驱动：

```
标识符集 RUNTIME_IDENTS = ['runtimeBuilder', '$mcComponentBuilder', 'componentProps', 'businessProps', 'componentApi']
触发条件：isVue3 && RUNTIME_IDENTS.some(id => content 含该标识符)
```

### 2.3 改动

0. **修正 L2167 触发条件（最关键的一条）**：`content.includes('$mcComponentBuilder')` → 改为「含 `RUNTIME_IDENTS` 任一标识符」的谓词。**不改这条，1、2 两条改了对本样本仍是零作用。**
1. **正则放宽**：`/runtimeBuilder\s*\??\s*\.\s*publishEvent/g`（同时覆盖 `runtimeBuilder.publishEvent` / `runtimeBuilder?.publishEvent` / `runtimeBuilder . publishEvent`）。
2. **新增硬校验（BLOCK 级）**：产物任一 `.vue` 中：
   - 出现标识符 `runtimeBuilder`（或 `$mcComponentBuilder` / `componentProps` / `businessProps` / `componentApi`）
   - **且**该文件既无 `$mcComponentBuilder()` 调用也无对应 `let/const` 声明
   ⇒ 记 BLOCK（错误码建议 `CODE-026-UNDECLARED-RUNTIME-IDENT`），并自动注入 `const runtimeBuilder = null` 兜底（与既有 L2197 同款）。

### 2.4 验收

- 3 个组件产物中不再出现裸用；`gateScore` 不再因此扣分；
- 组件预览 `onMounted` 无 ReferenceError。
