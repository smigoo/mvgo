### 1.1 入口与字段事实

| 项 | 事实 | 位置 |

### 1.2 三个字段对照表

| # | 字段 | 前端变量 | 请求体字段 | 占位/文案 | 限制 |
|---|---|---|---|---|---|
| 1 | 组件 ID | `advUserId` | `userComponentId` | 「如 c-sales-dashboard（小写字母/数字/短横线，以 c- 开头）」 | `maxlength=64`，**前端无正则/无格式校验**（`components.vue:1152-1159`、`:3411`） |
| 2 | 补充提示词 | `advExtraPrompt` | `extraPrompt` | 「对生成结果的额外要求…优先级低于 Figma 设计稿」 | `maxlength=4000` + 实时计数（`:1167-1174`、`:3412`） |
| 3 | 需求文档 | `advDocText` / `advDocName` | `requirementDocText` | 「选填 · .md / .txt / .html · ≤1MB」 | `accept=.md,.txt,.html`，前端 **1MB 硬门禁**（超限报「需求文档超过 1MB，请精简后再上传」）`components.vue:1176-1212`、`:1880-1898` |

**下发条件**：仅 `compType === 'microcode'` 时下发三字段（`:3404`）；**vue3 不下发**。
**批量模式不下发**：`goBatch()` 只传 `panelType` / `requirementDoc`（`:3477-3495`）。

### 1.3 后端消费链路（决定「填了到底有没有用」）

| 字段 | 最终影响 | 证据 |
|---|---|---|
| `userComponentId` | ① `declare.json` 的 `componentId`；② CSS class 前缀；③ Lite 产物目录 `custom-components/<id>`；④ Mongo 组件记录 ID；⑤ **不追加 8hex 尾段 ⇒ 同名重生成 ID 恒定** | `ai-engine/utils/component-naming.js:243-255`（规范化）、`:331-354`（用户指定为终态）；`roles/microcode/code-generator.js:1763-1765`；`lite/lite.service.ts:563-569`、`:832-838` |
| `extraPrompt` | 拼进 **microcode-engineer 的每个分块 prompt**（`# 📎 用户补充需求` 段） | `ai-engine/utils/user-addendum.js:13-28`；`roles/microcode-engineer.js:1002-1015` |
| `requirementDocText` | ① 同上以文本进 prompt；② 额外启动 **文档子管线**（S9/S10）：`docAnalyzer.analyze(...)`，产出 `docAnalysis` 再进 S8 / L0-B / engineer | `ai-engine/graphs/mc-component-graph-phase2.js:718-760`（**要求 ≥20 字**）、`:1822` |

**规范化规则（用户看不到，但会改结果）**——`component-naming.js:243-255`：

- 非法字符 → 静默替换为 `-`，连续 `-` 折叠，去首尾 `-`（**不报错**）
- 无 `c-` 前缀自动补；截断至 64 字符
- 长度 < 4、命中保留字 `component|unknown-component|test|temp`、纯 8 位 hex → **一律静默回退自动生成**（`generate-lite.dto.ts:233` 注释口径）

## 2. 功能二：同组件对比实验

### 2.1 口径（已拍板，2026-11-06 修正）

**「同组件对比实验」= 同一微码组件（同 Figma node）分别跑 lab 管线（lite-lab 真值回填实验管线）与 Max 管线，人工对比两份产物的效果。**

两条管线的事实底座：

| 侧 | 管线 | 入口 | sessionId 特征 | 说明 |
|---|---|---|---|---|
| A | **lab（lite-lab 真值回填）** | 生成页「实验面板」`TruthLabPanel` → `POST /lite-lab/run` | `mc-lab-*` / `mv-lab-*` | lite 布局 + **Figma node 真值回填**（颜色/字号/尺寸/资产四开关全开），产物带 `lab: 'truth-backfill'` 标记 |
| B | **Max** | 生成页主表单，档位选 Max → `POST /lite/generate`（`generationTier: 'max'`） | `mc-max-*` | phase2 完整管线（文档子管线 / 多 agent / 门禁） |

代码里没有一键对比页面（无 `compare` 路由/接口/集合），本协议用现有功能人工对比，**零新增代码**。lab 任务与正式任务**共存于任务列表**（`components.vue:3746,3750` 按正则识别），两边产物都能从组件详情页查看。

### 2.2 执行步骤

1. 选一个**结构适中**的 Figma frame（含头部/统计卡/图表/列表至少三类，能拉开管线差距）
2. **跑 lab 侧**：生成页实验面板（`TruthLabPanel`）粘贴同一 Figma URL，组件类型选微码，点运行 → 记录任务号 `S-lab`（`mc-lab-*`）；轮询 2s×120 次上限，完成后 `GET /lite-lab/report/:sessionId` 有报告
3. **跑 Max 侧**：生成页主表单，同一 Figma URL、类型=微码、**组件 ID 手填** `c-cmp-<日期>`（如 `c-cmp-1106`）、档位 Max → 记录任务号 `S-max`（`mc-max-*`）
4. 建议各跑 2 次取稳定态（管线含 LLM 抖动）
5. 打开两份产物（组件详情页预览 + `declare.json`；lab 产物在 `temp-components/<group>/<sessionId>/`，另有 `truth-backfill-report.json` 留档），按 2.3 维度表逐项填对比结论

**注意事项**：

- lab 面板与 Max 主表单**不要同时填**提示词/文档之类的附加输入——本对比只比「管线本身」；lab 侧四开关（颜色/字号/尺寸/资产）保持默认全开
- 两侧必须用**同一 Figma URL**（同 fileKey + nodeId），两遍之间不要改设计稿
- lab 管线是 **dev-only**（非 dev 环境全端点 404）且 `generationTier` 写死 lite——这是设计使然，不是 bug
- 两侧产物**不要用同名组件 ID**：lab 产物 ID 按 `mc-lab-*` session 命名，与 Max 手填 ID 各自独立，避免互相覆盖

### 2.3 对比维度表（每个组件填一份）

| 维度 | 看什么 | 记录方式 |
|---|---|---|
| 视觉还原 | 与设计稿并排截图：布局结构 / 高度比例 / 颜色 / 字号 / 图表类型 | 截图 + 差异点列表（lab 一份、Max 一份） |
| 真值符合度 | lab 侧重点看：颜色/字号/尺寸是否与 Figma 真值一致（lab 的核心卖点）；报告 `truth-backfill-report.json` 的回填命中数 | lab 报告 + 逐项对照 |
| 配置完整度 | `declare.json` 四配置计数：事件 / 状态 / businessConfig / CSS 变量 | 计数对照（可参照 `DocComparePanel` 的口径） |
| 图表 | echarts 是否生成、type 是否与设计一致、min-height 比例是否合理 | 逐图记录 |
| 静态资源 | 图片是否全部落盘并正确挂载（无破图/无 CSS 圆点冒充图片）；lab 侧重点验刚修的三类 icon 缺陷 | 数破图数 |
| 门禁 | Max 侧看任务详情页最终 verdict（`runtimeGate` / `finalQualityScore` 如有）；lab 侧看报告 verdict | 分数对照 |
| 稳定性 | 各跑 2 次，看两次产物差异大小 | 主观评价：稳 / 抖 |
| 成本 | 两边任务耗时、日志里的模型调用与 token（如可见） | 耗时 s / token 数 |
| 交付可用性 | 「推送到 GitLab」两份产物是否都能走通（lab 产物 `workspaceSynced` 是否 true） | 通过/失败 |

### 2.4 判定口径（建议）

- **lab 明显优**：真值符合度（颜色/字号/资产）≥2 项胜 ⇒ 说明「真值回填」路线价值大，考虑把回填能力反哺进主管线
- **Max 明显优**：配置完整度、图表、门禁中 ≥2 项胜 ⇒ lab 定位收窄为「真值校准参考线」
- **各有胜场**：按维度拆结论——典型预期是「lab 赢在颜色/资产真值，Max 赢在配置/图表/门禁」，把每个维度的赢家记下来作为管线演进依据
- **某侧不稳定**：同输入二次生成差异大 ⇒ 记录抖动点，走反馈通道带日志

### 2.5 顺带回归（跑主对比时顺手验，非本轮主口径）

**a. lite-lab 三条刚修的根因**（lab 侧跑的时候顺便看）：

| # | 根因 | 验证方法 |
|---|---|---|
| 1 | 反哺判据改 `ref` 优先（原按节点名正则，遇中文名恒不匹配 ⇒ 图片下载成功却不进 `truth.assets`） | 选一个图标节点名为**中文**的设计稿，看报告里资产是否回填 |
| 2 | 去重塌缩（6 个 icon GROUP 合成 2 个文件 ⇒ 6 卡只有前 2 张有图） | 跑 6 卡统计卡设计稿，数每张卡的 icon |
| 3 | `icon: ''` 空字段破图（挂载层按「空字段数 === 候选数」回填） | 产物里逐个 icon 是否都有图 |

**b. 文档纠偏并排的三个疑点**（`DocComparePanel`，仅微码）：

| 疑点 | 事实 | 验证方法 |
|---|---|---|
| 回读形状不匹配 | 新版回读按**文件名作键**取值，但接口返回的是**文件元数据数组**（`DocComparePanel.vue:214-215`） | 纠偏完成后看右列「新版」计数是否**恒为 0**；为 0 即命中此 bug |

## 3. 功能三：任务详情页 · 反馈给管理员

### 3.1 用户侧入口与表单

### 3.2 服务端规则（决定边界用例怎么写）

| 规则 | 值 | 来源 |
