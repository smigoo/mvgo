**两条折叠判据对该形态系统性失明**：

### 缺口①（最上游）：分组启用判据对 vision 段恒 false
`groupSections`（collapser.js:157-190）：
```js
const geo = !!geoBox(sec) && getChildren(sec).length > 0   // :180
```
- `geoBox(sec)` 裸读内联 box（**无 figmaRoot 兜底**）——2026-11-03 的 geoBoxWithRoot
  兜底加在 :299/:376/:427（排序/形状），**分组启用处漏网**；
- `getChildren(sec).length > 0` 对 items 形态段（统计卡 body.items=1、children=0）恒 false；
- ⇒ **g.geo=false ⇒ ② 几何同构组永不启用**（对全部 vision 顶层段）。

### 缺口②：精确签名组对「条目数不同」恒不成立
`sectionRepeatSignature = name|kids.length|逐子 shape`（:65-68）：
- 三段名不同（战略合作/优质/普通厂商）；
- **kids.length 6/12/15 各不相同**（分组厂商数不同是设计常态）⇒ 签名必不同；
- ⇒ ① 组永不成立。

### 缺口③：横排唯一同构几何
`isGeoIsomorphic`（:141-154）：`y ±4px 必须同行` ⇒ **纵排统计卡/纵列分组永不命中**
（即便①②修好，纵排仍折不了）。

### 缺口④：minRepeat=3 硬门槛
统计卡仅 2 张 ⇒ 数量不足（即便同构证据充分）。

**结果**：5 段全部原样下发 → LLM 每段写一个组件 → 5 个 ContentSection「多份」。

## 3. 治本方案：新增③ 内容同构组（不修改①②③既有判据）

在 `groupSections` 的② 之后追加第三判据组（新增判据，旧判据逐字不动=零回潮）：

**判据（四重，全部命中才折叠）**：
1. **内容同构签名**：逐成员段取其内容项（body.items[0] 或 body.children[0..N]）经
   `canonicalListItem`（section-semantics 单一来源）归一，签名 =
   `{texts:N, stats:N, icon:bool}` 的序列形态（条目数不同但逐项结构相同即同构——
   6/12/15 条目的分组列表逐项都是 `{texts:2, stats:0}`）；
2. **内容健康**：所有成员归一非空（texts+stats>0），空 ⇒ fail-open 不折
   （折叠后 fg-list 接管需要完整 items 真值，归一不全折叠=内容塌陷）；
3. **几何同方向**：用 `geoBoxWithRoot`（figmaRoot 兜底）取成员 box，统一为
   横排（y±4 同行为主）或纵排（x±4 同列 + y 递增），方向不一致不折；
   尺寸门槛沿用 isBusinessItem（宽≥80 高≥24，防小装饰误折）；
4. **数量 ≥2**（内容同构签名已是强证据——文本不同但结构相同的统计卡折叠成
   循环正是用户期望形态；minRepeat=3 的旧门槛只服务①②组）。

**出口**：折叠产物 `buildCollapsedSection`（既有单一出口）→
`decideCollapsedShape`（已有纵排→`type:list/vertical`）→ fg-list 接管（2 项 v-for 一组件）。
**statrow 不动**（不同层）。

## 4. 影响面

- **直接调用方**：`collapseSectionsDeep` 唯一入口（planner :3055 前递归折叠）；
- **判据方向**：折得**更多**——风险 = 误折异构段。护栏：签名不同即不折、
  归一空即不折、装饰尺寸门槛保留、方向不一致不折；
- **双端**：fg-list 接管 microcode/vue3 双端共用模板，无新增端差异；
- **刀71 依赖**：统计卡归一 `{texts:1, stats:1}` 依赖刀71 已部署的分区（否则
  texts:2/stats:0 签名仍同构可折，但折叠后渲染回退到连排缺陷——**刀71 是渲染正确性
  前提，本刀是收敛前提**）；
- **风险分级 B 档**（核心收敛判据扩展，影响所有顶层段规划）。
