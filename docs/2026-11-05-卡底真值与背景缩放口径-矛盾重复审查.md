## 3. ② bg-size 几何口径：两套真·重复（已全语料实测，方向已裁决）

| 口径 | 位置 | 规则 | 输出集 |
|---|---|---|---|
| 面积覆盖面 | `utils/background-size-inference.js:156 inferBackgroundSize`（`COVER_RATIO = 0.9`:42） | `coverage ≥ 0.9` → `100% 100%`，否则 `Wpx Hpx` | 仅 `100% 100%` / `Wpx Hpx` |
| 轴向比值 | `roles/visual-parser.js:2681 _calculateBackgroundSizing` | `0.8 ≤ wR,hR ≤ 1.2` → `100% 100%`；`hR < 0.3` → `100% auto` + `repeat-x`；两值 `< 0.5` → `contain`；任一 `> 1.2` → `cover` | 含 `cover` / `contain` / `100% auto` / `auto 100%` |

**同一 `(bgBox, parentBox)` 可给出不同结论**。例：bg `100×20` ∈ parent `100×100`
- 面积口径：`coverage = 0.2` → **`100px 20px`**
- 轴向口径：`wR = 1.0, hR = 0.2` → **`100% auto` + `repeat-x`**

且轴向口径会产出面积口径**不可能产出**的 `cover` / `contain` ⇒ 一旦产物落在 legacy 改写器链尾（§4），`cover` 又会被无条件改写成 `100% 100%`，「两套口径 + 一个改写器」三段各有主张。

**现状可达性**：`_calculateBackgroundSizing` 是视觉解析期的**初产者**（LLM 生成路径），`inferBackgroundSize` 是写盘前的**裁决者**。二者目前不互相校验。

> **对照性质声明**：954 条是「**同一几何下两口径各会写出什么**」的推演对照，**不是线上终值实测** —— 语料中 `cssValue` 仅 45 条有值且全部不含 `background-size`（存的是资源引用），`backgroundInferredBy` 为 `geometry` 的也只 87 条（9.1%）、`scaleMode` 6 条。因此本节证明的是「两套口径必然分歧 73.5%」，而非「线上已经错 73.5%」。

## 5. ④⑤⑥ 逐项界定

### 5.1 非重复：`backgroundImageOf` vs `isBackgroundResource` / `isIcon`

| 函数 | 位置 | 回答的问题 | 判据 |
|---|---|---|---|
| `backgroundImageOf` | `folded-grid:1505` | 「这个节点**是**不是背景图？」 | `resourceFile` 非空 + `downloadStatus ∉ {failed, missing}` + 命中 `BG_RESOURCE_FLAGS`（`:1487`：`usage ∈ {backgroundStyle, backgroundBlock}`、`role ∈ {bg, container}`） |
| `isBackgroundResource` | `folded-grid:1493` | 「这条资源**属于**背景用途？」 | 同上扁平判据（是 `backgroundImageOf` 的判据子集） |
| `subtreeBackground#isIcon` | `folded-grid:1561` | 「这个节点是不是**图标**（应跳过）？」 | `e.figmaNodeId === n.id && !isBackgroundResource(n, mapping)` |

三者共用 `BG_RESOURCE_FLAGS` 是**有意的单一来源**，不是重复。界限须成文（**本节即为成文**）：`isIcon` 是**反向排除**判据，`backgroundImageOf` 是**正向命中**判据；漏掉 `isIcon` 里的 `!isBackgroundResource` 一条，就等于「把整卡底当图标跳过」（历史事故，见 `:1565` 注记）。

### 5.2 非矛盾：grid 新通道 vs `file-writer#_fgFinal` 终裁覆写

- 终裁点：`roles/microcode/file-writer.js:2044` `_fgFinal = options.fgTakeoverFiles`，在**所有内容级自愈之后、写盘 / diff 之前**用确定性版本**整包覆写**（`microcode-engineer.js:5656` 透传；`Vue3Engineer extends MicrocodeEngineer`，`vue3-engineer.js:126`，复用同一 `writeFiles`）。
- 复核：`grep "fgTakeover|FG_TAKEOVER"` 对 `pre-write-self-healing.js` / `post-process.js` / `layout-style-refiner.js` / `style-refiner.js` / `layout-refiner.js` **返回空**（命中的只有 `mc-health-validator.js` / `font-size-normalizer.js`，走 `FG_TAKEOVER_CLASS_RX` 类名跳过，非文件豁免）。
- ⇒ **四件套写入者本身不认 fg 豁免，靠终裁覆写兜底**。grid 新通道写 `inferBackgroundStyle` 真值四件套因此安全。
- **风险标注**：grid 通道由此成为「同一文件的第 N 个写入者」。将来若新增**非终裁**写入路径（晚于 `_fgFinal` 或走别的写盘口），真值会被推翻 —— 见 §7「明确不做」的约束。
